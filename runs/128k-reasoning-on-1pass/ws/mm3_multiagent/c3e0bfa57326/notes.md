
## ideation
**Core difficulty**

The operation “choose a balanced substring and replace it by its reverse‑complement” is not a simple reversal; it also swaps each parenthesis type.  
Understanding its effect on the hierarchical structure of a valid parenthesis sequence is the key.  
Once we view the string as a rooted ordered tree (pairs of matching parentheses become nodes, children are the immediate inner pairs), the operation can be expressed as elementary actions on a node’s children:  

* Toggle a single child (apply the operation to a block of length 1).  
* Reverse the order of a contiguous block of children and toggle every child inside the block (apply to a block of length ≥ 2).

From these elementary moves we can obtain **any signed permutation** of the children – i.e., any permutation together with the ability to independently replace each child by its dual.  
Thus the reachable strings of a subtree are exactly the strings generated by independently choosing a string for each child (from its own set of reachable strings) and then arranging those children in any order.

**Counting for a subtree**

For a node with children grouped by type (the shape of the child’s subtree), let  

* `cnt[t]` – number of children of type `t`,  
* `DP[t]` – number of distinct strings reachable for a child of type `t`.

If the node has `k = Σ cnt[t]` children, the number of distinct strings for the whole subtree is  

```
DP[v] = k! · ∏_t ( DP[t]^{cnt[t]} / cnt[t]! )
```

The `k!` accounts for all possible orders of the children, and the division by `cnt[t]!` removes over‑counting of identical children.  
The formula can be justified by a simple generating‑function argument or by Burnside’s lemma.

**Dynamic programming on the tree**

* Parse `S` into a forest of real nodes (each pair of matching parentheses) and create a dummy root whose children are the top‑level blocks.  
* Process nodes in reverse topological order (children first).  
  * For each node, count how many children of each type it has.  
  * Compute `DP[v]` using the formula above.  
  * Create a canonical key = sorted list of `(type, cnt)` pairs.  
  * Nodes with the same key are identical in shape; they receive the same type id and the same `DP` value. This “type compression” keeps the DP table small and ensures that subtrees with identical structure are counted only once.  
* Finally apply the same formula to the dummy root; the result is the number of distinct strings reachable from the whole original string.

**Pitfalls to watch for**

* **Interpretation of the operation** – it is reverse *and* complement; forgetting the complement leads to an incorrect group of transformations.  
* **Root handling** – the original string may be a concatenation of several primitive blocks; a dummy root without surrounding parentheses is needed.  
* **Modular arithmetic** – division by `cnt[t]!` is performed using modular inverses, so pre‑computing factorials and inverse factorials modulo `998244353` is essential.  
* **Type consistency** – two nodes with the same multiset of child types must obtain the same `DP` value; otherwise the product over types would be wrong.  
* **Complexity** – the tree has at most `N/2` nodes, and each node processes its children once. Sorting the distinct child types per node is the only non‑linear part, giving `O(N log N)` time, well within limits.  
* **Edge cases** – `N = 2` (single pair), `N = 0` is impossible (valid sequence length is even), and very deep trees must be handled without recursion depth issues (use an iterative stack or process nodes in reverse order).

## worker: finalize
The string is interpreted as a rooted ordered tree (or forest) of matching parentheses.  
For a node, its children are the immediate inner pairs.  
The operation “reverse‑complement of a balanced substring” acts on a contiguous block of children as follows: it toggles every child inside the block and reverses their order. By applying this to single children we can toggle them, and by applying it to pairs we can swap two adjacent children (and toggle both). Consequently the reachable configurations of the children of any node are exactly all signed permutations of the original child list.

If a node has `k` children, with `cnt[t]` children of type `t` (type = shape of the subtree) and `DP[t]` reachable strings for a child of type `t`, then the number of distinct strings for the whole node is  

\[
DP[v] = k!\,\prod_{t}\frac{DP[t]^{cnt[t]}}{cnt[t]!}\pmod{998244353}.
\]

The formula follows from choosing an arbitrary reachable string for each child (`DP[t]^{cnt[t]}` ways) and then permuting the children arbitrarily (`k!`), with division by `cnt[t]!` to avoid over‑counting identical children of the same type.

The algorithm processes the tree bottom‑up (parents after children). For each node it builds a frequency map of its children’s types, computes `DP[v]` using the formula, creates a canonical key from the multiset of child types, and stores the DP for that shape. This “type compression” ensures that nodes with identical structure share the same DP.

Finally the dummy root (the concatenation of the top‑level blocks) is treated exactly like a normal node, and its DP is the answer.

Complexities:  
- Parsing: `O(N)`  
- For each node: sorting at most its degree (total `O(N log N)`) and a few modular multiplications.  
- Memory: `O(N)`.

All operations are performed modulo `998244353`.
