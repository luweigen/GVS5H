For any subarray, the optimal final array is its running prefix maximum, so the minimum operations are `sum(prefix_max[i] - nums[i])`. This cost is monotone: extending the right end never decreases it, and moving the left end right never increases it, enabling a two-pointer count of valid windows. To get `cost(l,r)` in `O(log n)`, preprocess next strictly greater element and binary-lift over record-high chains to sum running maxima quickly, then subtract the ordinary prefix sum. Use 64-bit/Python integers and aim for `O(n log n)` total.
