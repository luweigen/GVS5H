
## ideation
Core difficulty: swaps and prefix-deletions interleave, so the cost is not just “number of runs” or “sort each value together.” A deletion only removes the current first run; deleting a proper prefix of that run is almost surely useless because the leftover equal value still blocks the prefix. Same-value elements are indistinguishable, so a strategy can be viewed as choosing an order of monochromatic deletion batches: swaps pay the Kendall/inversion distance from the original remaining sequence to that batch order, and deletions pay the number of batches. The hard part is that batches of the same value might be split or merged depending on swap cost, and local improvements can change future local patterns.

Useful observations to prove/refute: adjacent swaps only matter at boundaries of unequal values; a swap changes the run count by at most 2; the clearly profitable primitive is a 4-run alternation `x y x y` whose two middle runs have length 1, collapsible by one swap into `x x y y`, reducing runs by 2 for net gain 1. If middle run lengths are `b,c`, merging the surrounding equal runs costs about `b*c` swaps to save 2 deletions, so only tiny cases are profitable. However, sample 3 warns against over-greedy collapsing: alternating length 11 has 11 runs but answer 8, i.e. only net saving 3, so chain/overlap effects and growing run lengths must be handled exactly.

Pitfalls: assuming each value is deleted in one batch; counting swaps after deletions with stale indices; ignoring that moving a block across another block costs product of lengths, not number of runs; relying on confluence of local collapses without proof; needing O(total N log N) or better across up to 1e5 cases; remembering all-distinct sequences have answer N and base “delete each run” gives an initial upper bound equal to the run count.

## worker: Implement the final O(N) solution: DP over disjoin
- **Model.** By the proven reduction, `ans = min_B [runs(B) + inv(A,B)]` over multiset permutations B (stable occurrence matching). The structural analysis (clean-zipper property: some optimal B has block spans with max openness ≤ 2 and no nesting, crossings only between B-adjacent blocks) plus the profitability argument (merging equal runs at distance ≥ 2 costs ≥ 2 swaps but saves ≤ 2 deletions, so only *unit* collapses `x y x y → x x y y` are strictly profitable; break-even longer moves never strictly help and can be untangled) implies an optimal B is always reachable by a set of **disjoint adjacent swaps**. Each such swap contributes exactly 1 to `inv(A,B)`, so the answer is `min` over matchings of adjacent transpositions of `(#swaps + runs of the resulting sequence)`.
- **DP.** Decide `d_j ∈ {0,1}` for each adjacent pair `(j, j+1)` with `d_j + d_{j+1} ≤ 1`. The final value at position `i` depends only on `d_{i-1}, d_i`, and the previous position's value only on `d_{i-2}, d_{i-1}`, so the feasible state `(d_{i-2}, d_{i-1}) ∈ {(0,0),(1,0),(0,1)}` (3 states) suffices to accumulate the run count incrementally while adding swap costs. Transitions: choose `d_i` (forced 0 if `d_{i-1}=1` or `i=N-1`), compute the new run contribution by comparing against the reconstructed previous value.
- **Verified by hand** on all samples: `11212 → 3` (swap pair (3,4): runs 2, cost 1+2), `4213 → 4` (all distinct, no swap helps), alternating length 11 `→ 8` (3 disjoint swaps + 5 runs), plus the known tricky cases `12112 → 4`, `212313 → 5` (two disjoint swaps), `1212 → 3`.
- **Complexity.** O(N) time and O(1) extra space per test case; O(ΣN) = O(2×10^5) total, fast input via `read().split()`.
