Treat each value `x` as needing `d(x)=floor(log4(x))+1` hits (for `x>=1`) before it becomes zero. One operation can apply one hit to two elements, and zeros can be used as harmless partners, so a query reduces to: given hit-counts for all numbers in `[l,r]`, the minimum rounds equal `max(max_hit, ceil(total_hits/2))`. The maximum hit is always `d(r)`, and `total_hits` can be computed by summing base-4 digit-length blocks over `[1,r]` minus `[1,l-1]`. Since `r <= 1e9`, there are at most about 15 base-4 blocks, so each query is `O(log r)` and overall is easily fast enough.
