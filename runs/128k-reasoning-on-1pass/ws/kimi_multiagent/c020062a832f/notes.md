
## ideation
Core difficulty: computing inversion counts for all M cyclic shifts `(A_i + k) % M` efficiently; naive recomputation is `O(M N log N)` or worse. Key observation: from `k` to `k+1`, only elements with `A_i = M-1-k` wrap from `M-1` to `0`; all other relative orders are preserved. For each wrapping position `p`, its inversion contribution changes from `N-p` to `p-1`, so delta is `2*p - N - 1`; equal wrapped values cancel internally when summed. The provided PLAN matches this: compute base inversions with Fenwick (`seen - bit.sum(a+1)` counts previous `> a`), group positions by value, set `delta[v] = sum(2p-N-1)` for positions with value `v`, then apply `delta[M-1-k]` on transition `k -> k+1`. Complexity is about `O((N+M) log M + N)`, fine for `2e5`. Main pitfalls: 1-indexed BIT off-by-one, using the wrong value index for the wrap (`M-1-k`), ties/equal values must not be counted as inversions, `M=1` edge case, large answer magnitude in fixed-width languages, and memory/time of `pos = [[] for _ in range(M)]` is acceptable but should be built carefully.

## worker: Implement the Python solution per the validated pl
Implemented the validated transition idea. The initial inversion count is computed with a Fenwick tree by counting, for each element, how many previous values are strictly greater. When moving from `k` to `k+1`, only elements equal to `M-1-k` wrap from maximum to minimum; every such position `p` changes its contribution by `(p-1) - (N-p) = 2*p - N - 1`, while all other relative orders stay fixed. These deltas are precomputed per value and applied cumulatively. Complexity is `O(N log M + N + M)` time and `O(N + M)` memory; handles `M=1` naturally.
