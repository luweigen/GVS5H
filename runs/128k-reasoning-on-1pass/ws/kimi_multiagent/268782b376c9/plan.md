Because all `points[i]` are positive, extra moves never hurt, so we can think in terms of exactly `m` visited positions. Binary search the target minimum score `T`; for a fixed `T`, each index needs at least `need[i] = ceil(T / points[i])` visits. The core subproblem is: starting from `-1` on a path graph, what is the minimum number of moves needed to give every index at least `need[i]` visits? Solve that feasibility test in `O(n)` using path/flow structure, then binary search over `T` for an overall `O(n log answer)` algorithm.
