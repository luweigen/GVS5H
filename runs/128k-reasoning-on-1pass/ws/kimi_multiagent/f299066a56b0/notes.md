- Restate constraint: top size `a`, bottom size `b` valid iff `a <= b/2`, i.e. `2*a <= b` (use integer arithmetic, avoid floats). Since sizes are positive, `a < b` strictly, so in every pair the smaller mochi is the top and the larger is the bottom; equal sizes can never be paired.
- Core difficulty: maximum matching under a ratio constraint on a sorted array. The sorted order lets us avoid general matching: there is always an optimal solution where the `K` tops are the `K` smallest chosen mochi and the `K` bottoms are the `K` largest chosen mochi (exchange argument: swapping a larger top for a smaller unused one, or a smaller bottom for a larger unused one, never breaks feasibility).
- Feasibility criterion for a candidate `K`: `K` pairs are achievable iff for every `i` in `[0, K)`, `2*A[i] <= A[N-K+i]` (pair `i`-th smallest with `i`-th among the `K` largest). This is monotone in `K`, enabling binary search (`O(N log N)`), but a direct greedy is `O(N)`.
- Direct greedy (preferred): let `half = N//2`. Treat indices `[0, half)` as candidate tops and `[half, N)` as candidate bottoms. Two pointers `i=0`, `j=half`, `ans=0`. While `i < half` and `j < N`: if `2*A[i] <= A[j]`, match (`ans+=1; i+=1; j+=1`); else `j+=1` (current bottom too small for this top, discard it). Answer is `ans`, automatically `<= N//2`.
- Why restricting tops to the first `half` is safe: at most `floor(N/2)` pairs exist, and the best possible tops are the smallest elements; any optimal can be transformed so tops come from the lower half and bottoms from the upper half without reducing `K`.
- Pitfalls: duplicates (equal values cannot pair — greedy naturally rejects since `2a <= a` is false); `N` odd (use `half = N//2`, bottoms count is `ceil(N/2)`); input size up to `5e5` so use fast buffered reading; `2*A[i]` up to `2e9` is fine in Python but keep it integer; answer can be `0`.
