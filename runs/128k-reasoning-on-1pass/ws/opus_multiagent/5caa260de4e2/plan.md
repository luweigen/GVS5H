Use prefix sums `P` for nums and `C` for cost. The awkward `k*i` multiplier is removed by re-attributing it: total `Σ_i k*i*(cost of segment i)` equals `k * Σ_{segment starts s} (C[n] - C[s])`, since segment i's cost is counted once for each segment index ≤ i. Then a simple prefix DP works: `dp[j] = min_{0≤i<j} dp[i] + P[j]*(C[j]-C[i]) + k*(C[n]-C[i])`, with `dp[0]=0` and answer `dp[n]`. With n ≤ 1000 the O(n²) transition (≤10⁶ ops) is fast enough in Python if written with local variables and tight loops; optionally add convex-hull/Li-Chao or divide-and-conquer optimization as a safety/perf upgrade. Validate against both provided examples plus a brute-force partition enumerator on tiny random arrays.
