Use a standard digit‑DP: define `count(N)` = number of beautiful integers in `[1, N]`, then answer = `count(r) - count(l-1)`. Process the decimal digits of `N` left to right with state `(pos, tight, started, digit_sum, digit_product)`, where `started` distinguishes leading zeros (which must contribute neither to sum nor product) from real digits. At the end (pos == len), a number counts iff `started` and `digit_product % digit_sum == 0` (note product 0 is divisible by any positive sum, so any number containing a real 0 digit is automatically beautiful). The state space is small: sum ≤ 90 and the reachable products are only 0 plus numbers of the form 2^a·3^b·5^c·7^d, so `functools.lru_cache`/dict memoization on the non‑tight states is fast enough (≤ 10 digits). Optionally short‑circuit: once product hits 0 while not tight, the remaining suffixes are all valid, contributing 10^(remaining). Validate against the given examples and brute force on small ranges.
