Reduce the geometry to a 1‑D circular problem. Map every boundary point to its perimeter coordinate (circumference `L = 4*side`); key lemma: since `k >= 4` and the selected points are in convex position, the closed L1 tour has length ≤ `2*(width+height) = 4*side`, so the answer `d* <= 4*side/k <= side`; and for any `d <= side`, "Manhattan distance ≥ d" is **equivalent** to "cyclic perimeter distance ≥ d" (same/adjacent sides ⇒ Manhattan = perimeter distance; opposite sides ⇒ Manhattan ≥ side ≥ d). Hence the problem becomes: pick `k` of the given circular positions maximizing the minimum cyclic gap, which is solved by binary searching `d` in `[1, 4*side//k]` and a greedy feasibility check. The check tries every start index, jumping to the first position ≥ current + d (correct greedy because gaps are monotone on a line/circle), doing `k-1` jumps and finally verifying the wrap gap `pos_start + L - pos_last >= d`. Vectorize the check with numpy (`searchsorted` for the jump table on a doubled position array, then `k-1` fancy-index gathers over all starts) so total cost is ~`31 * O(n log n + k*n)` and runs fast for `n = 15000, k = 25`.
