Reduce each query to a prefix–prefix cross sum using an index-blocking (sqrt-style) decomposition: with block size S, let x0 = (X//S)*S and y0 = (Y//S)*S, then
Σ_{i≤X,j≤Y}|A_i−B_j| = cumF_{y0}[X] + (cumG_{x0}[Y] − cumG_{x0}[y0]) + rem×rem,
where F_{y0}[i] = Σ_{j≤y0}|A_i−B_j| (over all i), G_{x0}[j] = Σ_{i≤x0}|A_i−B_j| (over all j), and rem×rem = Σ_{x0<i≤X}Σ_{y0<j≤Y}|A_i−B_j| involves fewer than S elements on each side. F and G are computed for a boundary in O(N log N) vectorized numpy work (sorted prefix + prefix sums + searchsorted: Σ|a−b| = a·(2·pos−m) − 2·PB[pos] + PB[m]), so only ~N/S boundaries (≈100) are ever built, and each query's leftover block is handled by sorting ≤S values. Group the K queries by y0 (for F) and by x0 (for G) so each boundary array is built once. Everything must be int64 (max answer ≈ 2·10^18, still safe) and fully numpy-vectorized to survive N=10^5, K=10^4 in Python.
