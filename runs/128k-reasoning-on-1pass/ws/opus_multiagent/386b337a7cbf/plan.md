Model the search as a DP over states (parity of the count of chosen elements so far, current product capped at an "over-limit" sentinel, current alternating sum). Since sums are bounded by ±(150·12) and the product only takes values that are products of numbers ≤ 12 bounded by `limit` (plus 0 and an OVER sentinel), the reachable (parity, product) pairs number only a few hundred; therefore we store, for each (parity, product) pair, the set of achievable alternating sums as a Python big-integer bitmask, and each array element's transition becomes a single bit-shift (left by `num` when parity is even → element added at an even index with `+`, right by `num` when parity is odd → `-`). Process elements left to right, at each step also allowing a brand-new subsequence to start with the current element (guaranteeing non-emptiness). Product update: `0` if `num == 0`, else `prod*num` if that is ≤ limit, else the OVER sentinel (OVER·anything ≥1 stays OVER, OVER·0 becomes 0). At the end, answer = max product `p != OVER` such that bit `k + OFFSET` is set for some parity; return -1 if `|k| > 1800` or no state matches.
