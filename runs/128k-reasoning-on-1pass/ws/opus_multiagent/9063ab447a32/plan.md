Greedy/exchange argument: buying the k-th unit of product i costs an incremental (marginal) price of (2k−1)·P_i, and these marginals are increasing per product, so the optimal solution is "buy every unit whose marginal price is ≤ some threshold x", plus possibly a few units priced exactly x+1 with the leftover money. Define f(x) = total cost and g(x) = total units when taking all units with marginal price ≤ x; for product i the count is k_i = ((x // P_i) + 1) // 2 and its cost is P_i·k_i². Binary search the largest x with f(x) ≤ M over [0, 2·10^14] (this bound is safe since f is monotone and f(2·10^14) > 10^18 ≥ M), then add min(c, (M − f(x)) // (x+1)) extra units, where c = #{i : (x+1) % P_i == 0 and ((x+1)//P_i) odd} is the number of units whose marginal price is exactly x+1. All heavy work must be vectorized with numpy (N up to 2·10^5, ~48 binary-search steps), with careful int64 overflow control: reject early when P_i·k_i² would exceed M, and sum exactly using a high/low bit split.
