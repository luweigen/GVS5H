Key insight: with increments only, the minimum cost to make subarray `nums[l..r]` non‑decreasing is `sum_{i=l..r} (max(nums[l..i]) - nums[i])`, and this cost is monotone (non‑increasing as `l` grows, non‑decreasing as `r` grows), so a sliding window works. To make the cost cheaply updatable when the right end moves, reverse the array: for reversed `b`, the window cost becomes `sum_{j=l..r} (max(b[j..r]) - b[j])`, i.e. a *suffix*-max form whose values only change for the trailing (smaller) elements when a new element `x = b[r]` is appended. Maintain a monotonic non‑increasing stack of `(value, count)` groups over the window: on push, pop all groups with `value < x`, adding `(x - value) * count` to the running cost, merging their counts, then push `(x, merged+1)`. Shrink from the left while `cost > k` by subtracting `(bottom_value - b[l])` and decrementing/popping the bottom group. Each valid window contributes `r - l + 1` subarrays; total O(n) time, O(n) space.
