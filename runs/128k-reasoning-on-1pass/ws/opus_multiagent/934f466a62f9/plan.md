Reduce the pairing problem to a labeling problem: an optimal solution is equivalent to choosing 2K cakes, giving each a label in {X,Y,Z}, such that each label is used an **even** number of times, maximizing the sum of the labeled coordinate values (pairs are then formed inside each label class; `max` of a pair is always ≥ the labeled sum, and taking each pair's argmax coordinate as the label proves the converse). Ignoring parity, the optimum is simply `M = sum of the top 2K values of m_i = max(X_i,Y_i,Z_i)`, each cake labeled by its argmax; if all three label counts are even, the answer is `M`. Otherwise exactly two counts (p, q) are odd, and the loss `M − answer` decomposes into non-negative elementary "ops": relabel a selected cake a→b (cost m_i − v_ib), drop a selected cake with label a (cost m_i), add an unselected cake with label b (cost −v_jb); these are arcs of a 4-node graph {A0,A1,A2,W} with all cycles non-negative. One can prove the optimal fix is the min-cost op set with imbalance one of only 4 vectors: (−1,+1,0),(+1,−1,0),(−1,−1,+2),(+1,+1,−2) on (p,q,r), and it uses at most 6 ops, so only the best 6 cakes per op-list are ever needed. Build a tiny min-cost-flow network on those ≤ ~70 candidate cakes and evaluate the 4 imbalances exactly with SSP (SPFA-based, no negative cycles), then output `M − min loss`.
