Binary search on the answer T (the minimum achievable score) and greedily check feasibility with a single left-to-right sweep. For target T, index i needs `need_i = ceil(T / points[i])` visits; when standing at i we can bounce (i → i+1 → i) to fund extra visits, each bounce costing 2 moves and granting one free visit to i+1. So sweeping left to right with `carry` = free visits already granted to the current index: if `need = ceil(T/points[i]) - carry <= 0`, spend 1 move to step forward (0 moves if i is the last index) and set carry = 0; otherwise spend `2*need - 1` moves and set carry = `need - 1`. Abort early once the move count exceeds m. Binary search T in [0, (m//n + 1) * max(points)], returning the largest feasible T.
