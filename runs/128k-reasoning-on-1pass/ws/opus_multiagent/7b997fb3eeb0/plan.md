Since the array is sorted, for a query segment `[L,R]` (size `m`) the optimum is the classic greedy: the answer `K` is feasible iff pairing the `K` smallest elements of the segment in order with the `K` largest works, i.e. `2*A[L+t] <= A[R-K+1+t]` for all `t=0..K-1`; feasibility is monotone in `K`, so we binary search `K` in `[0, m//2]`. Precompute `f[i] = ` first index `j` with `A[j] >= 2*A[i]` (via `searchsorted`) and `g[i] = f[i] - i`; then the condition `2*A[L+t] <= A[R-K+1+t]` for all `t` becomes simply `max(g[L..L+K-1]) <= m - K` (0-indexed), so each feasibility test is one range-max query. Build a sparse table on `g` for O(1) range max, giving O((N+Q) log N) overall. To meet Python speed limits, do all `Q` binary searches simultaneously with NumPy: ~18 vectorized rounds, each doing two fancy-index lookups into the sparse table. Read input with `sys.stdin.buffer` and output with `'\n'.join` / `np.savetxt`-style joining.
