Sort the intervals by right endpoint (carrying original indices) and run a classic weighted-interval-scheduling DP extended with a "count of chosen intervals" dimension (0..4). Define `dp[i][k]` = best result using the first `i` intervals in sorted order with at most `k` picks, where a "result" is the pair (total weight, sorted list of original indices ≤ 4 long). Transition: either skip interval `i` (`dp[i-1][k]`) or take it and jump to `p(i)` = number of intervals whose right endpoint is `< l_i` (found by `bisect_left` over the sorted right endpoints), i.e. `dp[p(i)][k-1] + (w_i, index_i)`. Compare candidates by higher weight first, then by lexicographically smaller index list (Python tuple/list comparison gives exactly the required rule, and because all weights are positive, no equal-weight list can be a strict prefix of another, so this greedy tie-break composes correctly). Answer is the index list stored in `dp[n][4]`; complexity O(n log n + 4n) time and O(4n) small lists of memory, which is fine for n = 5·10⁴.
