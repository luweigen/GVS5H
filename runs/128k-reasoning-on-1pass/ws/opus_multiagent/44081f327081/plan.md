Key reduction: for index *i*, the answer is the largest `d` dividing `A_i` such that `cnt[d] = #{j : d | A_j} >= K` (any K elements divisible by `d` give a gcd that is a multiple of `d`, and the optimum gcd itself is such a `d`). So we need (1) `cnt[d]` for all `d ≤ M = max(A)` via a harmonic-sum divisor sieve, (2) `f[v] = max{d : d | v, cnt[d] ≥ K}` for all `v ≤ M`, computed by iterating good `d` in increasing order and writing `d` onto all multiples (later/larger `d` overwrite), (3) output `f[A_i]`. Pure-Python loops over ~1.4·10⁷ (d, multiple) pairs are too slow, so everything must be vectorized with NumPy; a plain `for d in range(M)` NumPy loop is also too slow (10⁶ call overheads), so use a hybrid: direct strided slice ops for small `d` (`d < S ≈ 2000`) and *block* processing by `t = M//d` for large `d`, where each block `d ∈ (M//(t+1), M//t]` is handled with `t` fancy-indexed vector operations. Total NumPy call count drops to ~5·10⁴ while element work stays ~10⁷. Care is needed with ordering (small `d` first, then blocks with `t` descending = `d` ascending) and with proving no index collisions inside one block.
