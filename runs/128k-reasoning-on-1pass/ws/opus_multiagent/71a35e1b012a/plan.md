The key insight is that the reachable minimum cost is always 1, 2, 3, or the task is impossible — so no interval-covering DP/greedy is needed. Cost 1 requires some interval equal to [1,N]. Cost 2 happens in exactly three ways: (a) two op1 intervals [1,a] and [b,N] with b ≤ a+1; (b) op1 on interval i and op2 on interval j (i≠j) with [L_j,R_j] ⊆ [L_i,R_i]; (c) op2 on two disjoint intervals (union of complements = everything, i.e. max L > min R). If none of these hold, the intervals form an antichain (no containment, hence all L distinct and R sorted the same way) and pairwise intersect, so with M ≥ 3 we can always achieve cost 3: op2 on the min-L interval and the max-L interval (leaving only [L_max, R_min] uncovered) plus op1 on any third interval, which necessarily contains [L_max, R_min]. If M ≤ 2 in that situation, the total budget is at most 2 operations, so the answer is -1. Implementation is O(M log M) (only for the containment check) with fast I/O.
