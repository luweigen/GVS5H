Binary search (or linear scan, since n ≤ 1000) over the candidate answer k ∈ [1, n], using a monotone feasibility check `cost(k) ≤ numOps`. For k = 1 the string must alternate, so the cost is `min(mismatches vs "0101...", mismatches vs "1010...")` — this case is special because splitting runs isn't enough (adjacent runs of length 1 of the same char across a flip still matter, so the alternating-pattern formula is the correct one). For k ≥ 2, greedily split each maximal run of identical characters of length L: inserting a flipped character every k+1 positions costs `L // (k + 1)` flips, and these choices never interact across runs since flipping an interior character of a run cannot merge with a neighboring different-character run in a harmful way (the flipped char is isolated, length 1 ≤ k). Total cost is the sum over runs; feasibility is monotone non-increasing in k, so binary search over k works, giving O(n log n) (O(n²) brute force is also fine at n = 1000).
