Reformulate the problem: since cost is `sum |s[i] - t[i]|`, we just need the target string `t` in which every maximal run has length ≥ 3, minimizing that sum, then lexicographically smallest among all minimizers. Use a suffix DP over 26 characters with two tables: `g[i][c]` = min cost of suffix `i` when a **new** run of char `c` starts exactly at `i` (so positions `i, i+1, i+2` are forced to `c`, valid only if `i+3 <= n`), and `h[j][c]` = min cost of suffix `j` given the run ending at `j-1` has char `c` and length already ≥ 3. Recurrences: `g[i][c] = |s[i]-c|+|s[i+1]-c|+|s[i+2]-c| + h[i+3][c]` and `h[j][c] = min(|s[j]-c| + h[j+1][c], min_{d≠c} g[j][d])`, with `h[n][c] = 0`, computed backward (at each `j` compute `g[j]` from `h[j+3]`, then `h[j]` from `h[j+1]` and `g[j]`); the `min_{d≠c}` term is handled with min/second-min of the `g[j]` vector. Reconstruct greedily left to right: start with the smallest `c` achieving `min_c g[0][c]`, and at each later position pick the smallest character among "continue current char `c`" (valid iff `|s[j]-c|+h[j+1][c] == h[j][c]`) and "start new run with `d≠c`" (valid iff `g[j][d] == h[j][c]`), forcing three copies when a new run starts — greedy is exact because the DP value fully determines the optimal remainder. Return `""` when `n < 3`; performance is handled by vectorizing the 26-length inner vectors (numpy int arrays, incremental update of the 3-window cost vector `A_j = A_{j+1} - cost[s[j+3]] + cost[s[j]]`).
