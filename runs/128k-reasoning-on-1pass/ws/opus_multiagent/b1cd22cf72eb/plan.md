Since every operation reduces total tooth length by exactly 1, and the final configuration must satisfy `u_i + d_i = H` for all i, the cost is `S - N*H` where `S = Σ(U_i + D_i)`; thus we only need the **maximum feasible H**. For a fixed H, each index has an allowed range `lo_i = max(0, H - D_i) ≤ u_i ≤ hi_i = min(U_i, H)`, plus the Lipschitz chain constraint `|u_i - u_{i+1}| ≤ X`. Feasibility is monotone in H (given a solution for H, `u'_i = min(u_i, H-1)` works for H-1), so binary search H over `[0, min_i(U_i+D_i)]` (H=0 is always feasible). Feasibility for fixed H holds iff `lo_i ≤ hi_i` for all i and for all pairs `lo_i - hi_j ≤ X·|i-j|`, which reduces to prefix/suffix max checks: `cummax(lo_i + X·i) ≤ hi_j + X·j` and `revcummax(lo_i - X·i) ≤ hi_j - X·j`. Implement checks with numpy (`np.maximum.accumulate`) for O(N log(maxH)) total with tiny constant, using int64 (values up to ~2e14, answer up to ~4e14).
