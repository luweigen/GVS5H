Simulating insertions forward is O(N²), so reverse the process: the element inserted last (N) is final-position P_N in the length-N array; deleting it leaves exactly the array that existed before its insertion, so element i must occupy the P_i-th *still-free* slot when we process i = N, N-1, …, 1 over N slots that are initially all free. Thus the whole task reduces to N operations of "find the k-th free slot, then mark it occupied", which is a classic Fenwick (BIT) problem: the BIT stores 1 for free slots, and the k-th free slot is found by binary lifting (descend) in O(log N), then a point update sets it to 0. Total complexity O(N log N) with tiny constants, feasible for N = 5·10⁵ in CPython if the descend/update loops use only local variables and plain lists. Input must be read with `sys.stdin.buffer.read().split()` and output emitted with a single `' '.join(map(str, A))` write. Finally, validate on the samples plus edge cases (N=1, all P_i=1 → reversed array, P_i=i → identity) and time a worst-case random input.
