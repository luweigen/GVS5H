Model the process as choosing a final target multiset‑arrangement T of A: every deletion removes one maximal group, and the minimum number of adjacent swaps to turn A into T (equal values matched in order) equals the inversion count, so **cost = runs(T) + inv(A→T) = N − [merges(T) − inv]**. Hence we must maximize the "gain" = (adjacent‑equal pairs created in T) − (swaps used). Since one swap can create at most two new equalities, the only profitable move is a *double‑merge swap* at index i with `A[i-1]==A[i+1]` and `A[i]==A[i+2]` (swap i,i+1 gains 2 merges for 1 swap); two such swaps interfere iff their indices are less than 3 apart. This gives the conjecture **answer = runs(A) − (max set of such indices pairwise ≥3 apart, found greedily left→right)**, which reproduces the three samples (3, 4, 8). The team must validate this conjecture with an exhaustive brute force before shipping, then implement it with heavy‑IO‑safe linear code (sum N ≤ 2·10⁵, T ≤ 10⁵).
