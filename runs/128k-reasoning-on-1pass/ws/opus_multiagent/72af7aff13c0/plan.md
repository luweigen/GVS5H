Transpose the grid if needed so the number of columns `W = min(H,W) ≤ √(2·10^5) ≈ 447` (rows become the long axis; remap directions `L↔U`, `R↔D`, and swap `sh,sw`). Maintain two DP tables by rows: `F[i][k]` = sum of path-products from (0,0) to (i,k) inclusive (`F[i][k] = A[i][k]·(F[i-1][k] + F[i][k-1])`, with virtual row `F[-1] = [1,0,…,0]`) and `G[i][k]` = sum from (i,k) to (H-1,W-1) inclusive (`G[i][k] = A[i][k]·(G[i+1][k] + G[i][k+1])`, virtual `G[H] = [0,…,0,1]`). The key identity is that the answer with the walker at row `r` is a single dot product: `ans = Σ_k F[r][k]·G[r+1][k] = Σ_k F[r-1][k]·G[r][k]`. Writing `A[r][c]=a` only invalidates `F[r..]` and `G[..r]`, so keeping pointers `pf` (F valid on `0..pf`) and `pg` (G valid on `pg..H-1`) and using one-step lookahead on the next query's direction (recompute `F[r]` if the next move is Down/horizontal, `G[r]` if it is Up) costs exactly **one row scan (length ≤ 447) + one dot product per query**, plus an O(HW) initial build. Everything must be written as extremely tight CPython loops (local variable caching, `zip`, `list.append` bound to a local, `sum(map(mul, …))` for dots) because the worst case is ~2·10^5 × 447 elementary modular operations.
