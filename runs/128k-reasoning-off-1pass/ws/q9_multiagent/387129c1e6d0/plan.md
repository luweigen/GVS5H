The problem requires tracking Santa's path on a 2D grid and counting how many distinct houses lie on the segments traversed. Since $N$ and $M$ are up to $2 \times 10^5$, we cannot check every point on every segment. Instead, we will simulate the movement to determine the start and end points of each segment. For each segment, we will check if it passes through any house by verifying if the segment's bounding box contains a house and if that house lies on the line defined by the segment. To efficiently query houses, we can sort the houses by coordinate and use binary search or a hash set to check existence. Given the constraints and the nature of the movement (axis-aligned), we can simply check the four potential houses that might lie on a segment if we pre-process the houses into a set for $O(1)$ or $O(\log N)$ lookups, but since the segment can be long, we need a better approach: for each segment, we determine the range of coordinates covered and check if any house lies exactly on the line within that range. A robust method is to store houses in a set and for each segment, iterate over the relevant houses? No, that's too slow. Better: For each segment, we know the line equation. We can check if any house lies on this line segment. Since the movement is axis-aligned, a segment is either horizontal or vertical. For a horizontal segment from $(x_1, y)$ to $(x_2, y)$, we only care about houses with $Y_i = y$ and $X_i$ between $x_1$ and $x_2$. We can pre-sort houses by Y, then by X, and use binary search to find candidates.
