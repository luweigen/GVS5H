The problem requires transforming a string into a "good caption" (groups of at least 3 identical consecutive characters) with minimum operations, breaking ties by lexicographical order. Since we can change any character to its neighbor in the alphabet, the cost to change a character `c` to `target` is `abs(ord(c) - ord(target))`. The key insight is that for a string to be a good caption, it must consist of blocks of length at least 3. Given the constraint $N \le 50,000$, we cannot try all partitions. However, notice that if we fix the target character for a block, the optimal strategy is to make the entire block that character. The problem can be modeled as finding a partition of the string into segments where each segment is converted to a single character $c$ such that the segment length $\ge 3$, minimizing total cost. Since the alphabet size is small (26), we can iterate over all possible target characters for each segment. But a more efficient approach is dynamic programming: `dp[i]` = minimum cost to make prefix `i` a good caption. For each `i`, we try all possible previous split points `j` such that the substring `caption[j:i]` can be converted to a single character with cost calculated, and the length `i-j >= 3`. To handle the lexicographical requirement, we store not just the min cost but also the resulting string or reconstruct it carefully. Given the constraints and the need for lexicographical smallest, we might need to store the best character choice for each segment length or use a greedy reconstruction after finding the min cost. Actually, since we want the lexicographically smallest result among those with min cost, we should prioritize smaller characters when costs are equal. We can compute the min cost first, then reconstruct the string by greedily choosing the smallest valid character for the first segment that allows completing the rest with the remaining cost.
