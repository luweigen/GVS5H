
## ideation
The problem asks for the sum of distances between two nodes $u$ and $v$ over all $(N-1)!$ possible trees generated by the specific parent selection rule ($P_i \in \{1, \dots, i-1\}$).

**Core Difficulty**: Calculating the contribution of each edge to the total distance efficiently. Since $N, Q \le 2 \times 10^5$, an $O(N^2)$ or $O(Q \cdot N)$ solution is too slow. We need an $O(1)$ or $O(\log N)$ per query solution.

**Candidate Approaches**:
1.  **Linearity of Expectation / Contribution Technique**: The total distance is the sum of weights of edges on the path. We can sum the contribution of each edge $i$ (connecting $i$ to $P_i$ with weight $A_i$) across all valid trees. An edge $i$ contributes to the path between $u$ and $v$ if the path passes through it.
2.  **Combinatorial Probability**: For a fixed edge $i$, determine the probability (or count) that it lies on the path between $u$ and $v$ in a randomly generated tree.
    *   Based on analysis of small cases and the structure of the tree generation (similar to random recursive trees):
        *   If $i < \min(u, v)$ or $i > \max(u, v)$, the edge never lies on the path.
        *   If $i = \max(u, v)$, the edge always lies on the path (since $u, v$ must connect, and $i$ is the largest index, it must be connected to something smaller, effectively being the "lowest" common point or part of the chain if $i$ is one of the endpoints). Actually, if $i = \max(u, v)$, the edge $(i, P_i)$ is always on the path because $i$ is a descendant of $P_i$, and to reach any node $< i$ from $i$, one must go through $P_i$.
        *   If $i = \min(u, v)$, the edge lies on the path with probability $1/i$.
        *   If $\min(u, v) < i < \max(u, v)$, the edge lies on the path with probability $1/i$.
    *   This leads to the formula:
        $$ \text{Total Distance} = (N-1)! \times \left( A_{\max(u, v)} + \sum_{i=\min(u, v)}^{\max(u, v)-1} \frac{A_i}{i} \right) $$
        (Note: If $\min(u, v) = 1$, the term $A_1/1$ is invalid as there is no edge 1. The sum should start from $i=2$).

3.  **Implementation Details**:
    *   Precompute factorials and modular inverses for $1 \dots N$.
    *   Precompute prefix sums of the sequence $B_i = A_i \times \text{inv}(i)$ to answer range sum queries in $O(1)$.
    *   Handle the boundary case where $\min(u, v) = 1$ carefully (start sum from 2).
