The key observation is that inserting elements from 1 to N in order is equivalent to building the array by repeatedly inserting at specific positions. However, a direct simulation would be O(N^2) due to array shifts, which is too slow for N up to 5×10^5. Instead, we can work backwards. Consider that the last element inserted is N, and it is placed at position P_N. Before that, N-1 was inserted at P_{N-1}, etc. We can use a Fenwick tree (Binary Indexed Tree) or a Segment Tree to efficiently find the k-th empty position. Specifically, we maintain an array of N empty slots. For i from N down to 1, we find the P_i-th empty slot, place i there, and mark that slot as filled. The Fenwick tree can track the number of empty slots in ranges, allowing us to binary search for the P_i-th empty slot in O(log N) time. This gives an overall O(N log N) solution.
