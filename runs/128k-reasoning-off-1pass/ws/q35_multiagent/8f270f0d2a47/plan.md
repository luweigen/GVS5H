The constraints (up to 10^9) mean we cannot iterate through all numbers. We must use digit dynamic programming (digit DP). The key insight is that for a number to be "beautiful", the product of its digits must be divisible by the sum of its digits. The sum of digits for numbers up to 10^9 is at most 9*9=81 (for 999,999,999). We can iterate over all possible sums S from 1 to 81. For each fixed sum S, we count how many numbers in [1, N] have digit sum S AND digit product divisible by S. We can use digit DP where the state includes: current digit position, current sum of digits, current product of digits (modulo some value? No, we need exact divisibility), and whether we are tight to the upper bound. However, the product can be very large. Instead, we can observe that if the product is divisible by S, then product % S == 0. We can track product % S in the DP state. Since S <= 81, the modulus is small. The state would be (pos, current_sum, current_product_mod_S, is_tight). We also need to handle leading zeros carefully. We'll implement a helper function `count(N, S)` that counts numbers in [1, N] with digit sum S and digit product % S == 0. Then the answer for beautiful numbers in [l, r] is sum over S=1 to 81 of (count(r, S) - count(l-1, S)).
