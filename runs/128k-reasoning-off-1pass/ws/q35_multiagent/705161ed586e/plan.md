This problem can be solved using dynamic programming. We need to partition the string into contiguous groups where each group consists of the same character and has length at least 3. For each position in the string, we track the minimum cost to form valid groups up to that point, along with the resulting string (or enough information to reconstruct it) to ensure lexicographical minimality. Since n is up to 50,000, we cannot store full strings in DP states. Instead, we store the cost and the last character used for the current group. To handle lexicographical order, we can use a DP state `dp[i][last_char]` = minimum cost to make prefix `i` valid, ending with a group of `last_char`. When transitioning, we try extending the current group or starting a new group (if the previous group had length >= 3). We also need to reconstruct the answer, so we store parent pointers. The cost to change a character to another is the absolute difference in their ASCII values. We iterate through each position and for each possible current character (a-z), we consider all possible previous characters and group lengths. To optimize, we can limit the group length search since very long groups might not be optimal, but worst-case we might need to check up to n. However, with 26 characters, the state space is manageable if we process efficiently. We'll use a 2D DP array of size (n+1) x 26.
