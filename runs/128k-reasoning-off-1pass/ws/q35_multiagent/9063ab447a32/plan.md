1. Use binary search on the total number of units $K$ we want to buy. The range for $K$ is $[0, M+1]$ since even buying 1 unit of the cheapest product costs at least 1, so max units is at most $M$ (actually bounded by $M$ because min cost per unit is 1).
2. For a fixed $K$, we need to check if it's possible to buy $K$ units with total cost $\leq M$. To minimize cost, we should greedily assign units to products with the smallest marginal cost. The marginal cost of the $j$-th unit of product $i$ is $P_i \times (2j-1)$ (since cost of $k$ units is $k^2 P_i$, the incremental cost from $k-1$ to $k$ is $k^2 P_i - (k-1)^2 P_i = (2k-1)P_i$).
3. However, directly simulating the greedy assignment for large $K$ is too slow. Instead, for a fixed $K$, we can use binary search on the "threshold" marginal cost. Alternatively, we can observe that for a fixed total $K$, the optimal strategy is to buy units such that the marginal costs are as small as possible. We can binary search on the maximum marginal cost $C$ allowed, and for each product, compute how many units we can buy such that all marginal costs are $\leq C$. Specifically, for product $i$, the $j$-th unit has marginal cost $(2j-1)P_i$. We need $(2j-1)P_i \leq C \Rightarrow j \leq (C/P_i + 1)/2$. So the max units from product $i$ with marginal cost $\leq C$ is $\lfloor (C/P_i + 1)/2 \rfloor$.
4. For a fixed $K$, we binary search on $C$ to find the minimum $C$ such that the total units we can buy with marginal cost $\leq C$ is at least $K$. Then we compute the actual minimum cost for buying exactly $K$ units by summing up the costs of the cheapest $K$ marginal costs. But this is complex.
5. A simpler approach: Binary search on $K$. For a fixed $K$, we want to minimize $\sum_{i=1}^N k_i^2 P_i$ subject to $\sum k_i = K, k_i \geq 0$. This is a convex optimization problem. The optimal solution satisfies that the marginal costs are as equal as possible. We can binary search on a threshold $T$ such that we buy all units with marginal cost $< T$, and some units with marginal cost $= T$. For each product $i$, the number of units $k_i$ is determined by finding the largest $k$ such that the $k$-th marginal cost $(2k-1)P_i \leq T$. Let $k_i(T) = \lfloor (T/P_i + 1)/2 \rfloor$. Then total units $S(T) = \sum k_i(T)$. We find $T$ such that $S(T) \geq K$ and $S(T-1) < K$ (approximately). Then the cost is $\sum_{i=1}^N k_i(T)^2 P_i$ minus the excess units' costs. This is still complex.
6. Actually, a more direct method: Binary search on $K$. For a fixed $K$, we can use a priority queue or binary search on the marginal cost threshold to compute the minimum cost. Given the constraints, binary search on $K$ with an efficient check is needed. The check for a fixed $K$: Binary search on $T$ (the maximum marginal cost used). For each $i$, $k_i = \max(0, \lfloor (T/P_i + 1)/2 \rfloor)$. Sum $k_i$ should be $\geq K$. Find the smallest $T$ such that $\sum k_i(T) \geq K$. Then the cost is $\sum_{i=1}^N k_i(T)^2 P_i$ but we might have bought too many units. We need to remove the most expensive units among those bought. The units bought have marginal costs up to $T$. We can compute the total cost for $k_i(T)$ units and then subtract the cost of the excess units. The excess units are those with marginal cost closest to $T$. This is feasible in $O(N \log (\text{max\_T}))$ per check, and binary search on $K$ adds another $\log M$. Total complexity $O(N \log M \log (\text{max\_T}))$. Since $T$ can be up to $2 \cdot 10^{18}$, $\log T \approx 60$. $N=2 \cdot 10^5$, so $2 \cdot 10^5 \cdot 60 \cdot 60 \approx 7.2 \cdot 10^8$ which might be tight.
7. Alternative: Binary search on $K$ directly. For each $K$, we can compute the minimum cost by binary searching on $T$. The range for $T$ is $[1, 2 \cdot 10^{18}]$. The check function: Given $K$, binary search $T$ to find min $T$ such that $\sum_{i=1}^N \lfloor (T/P_i + 1)/2 \rfloor \geq K$. Let this sum be $S$. If $S > K$, we have bought $S$ units but only need $K$. The cost is $\sum k_i^2 P_i$ where $k_i = \lfloor (T/P_i + 1)/2 \rfloor$. But we need to remove $S-K$ units. The units to remove are those with the highest marginal cost, which are all equal to the marginal cost of the last unit bought for each product, which is $(2k_i-1)P_i$. These are all $\leq T$. We need to remove the $S-K$ units with the largest marginal costs. This requires sorting or a selection algorithm, which is $O(N \log N)$ per check, making it too slow.
8. Better approach: Notice that the function $f(K) = \text{min cost to buy } K \text{ units}$ is convex. We can binary search on $K$. For the check, we can use the fact that the optimal $k_i$ for product $i$ when buying $K$ units total is approximately proportional to $\sqrt{K/N}$ but weighted by $1/\sqrt{P_i}$. Actually, we can use Lagrange multipliers: the marginal cost should be equal. $(2k_i-1)P_i \approx \lambda$. So $k_i \approx \lambda/(2P_i)$. Sum $k_i = K \Rightarrow \lambda \sum 1/(2P_i) = K \Rightarrow \lambda = 2K / \sum (1/P_i)$. Then $k_i = \lambda/(2P_i) = K / (P_i \sum (1/P_j))$. This gives a real-valued solution. We can round and adjust. But this is approximate.
9. Given the time, let's stick with binary search on $K$ and for each $K$, binary search on $T$ to find the threshold, and then compute the cost exactly. To handle the excess units, note that if we set $T$ such that $\sum k_i(T) = K$ exactly, we are done. If not, we can adjust. Actually, we can binary search on $T$ to find the largest $T$ such that $\sum k_i(T) \leq K$. Then we buy $k_i(T)$ units for each product, and we have $K - \sum k_i(T)$ units left to buy. These remaining units should be bought from the products where the next unit has the smallest marginal cost. The next unit for product $i$ has marginal cost $(2k_i(T)+1)P_i$. We can find these costs and pick the smallest ones. This is $O(N \log N)$ per check due to sorting, which is too slow.
10. Final plan: Binary search on $K$. For each $K$, we binary search on $T$ to find the threshold. The check function will:
    a. Binary search $T$ in $[1, 2 \cdot 10^{18}]$ to find the smallest $T$ such that $\sum_{i=1}^N \lfloor (T/P_i + 1)/2 \rfloor \geq K$.
    b. Let $k_i = \lfloor (T/P_i + 1)/2 \rfloor$. Let $S = \sum k_i$.
    c. The cost is $\sum_{i=1}^N k_i^2 P_i$.
    d. If $S > K$, we need to remove $S-K$ units. The units to remove are those with the highest marginal cost among the units bought. The marginal cost of the $j$-th unit of product $i$ is $(2j-1)P_i$. The last unit bought for product $i$ has marginal cost $(2k_i-1)P_i$. We need to remove the $S-K$ units with the largest marginal costs. Since all these marginal costs are $\leq T$, and we want the largest, we can collect all $(2k_i-1)P_i$ for each product, sort them, and subtract the top $S-K$ costs from the total cost. But sorting is $O(N \log N)$.
    e. To avoid sorting, note that we only need to remove units with marginal cost close to $T$. We can find the threshold for the marginal costs of the units to remove. This is getting complicated.
