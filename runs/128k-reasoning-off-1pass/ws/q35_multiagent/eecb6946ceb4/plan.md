1. Sort the input array S to easily iterate through potential middle elements B.
2. For each element B in the sorted array, we want to count pairs (A, C) such that A and C are also in S, A < B < C, and B - A = C - B (which implies A + C = 2*B).
3. Use a boolean array (or hash set) for O(1) lookup of whether a number exists in S. Since max(S_i) is 10^6, a boolean array of size 10^6+1 is efficient.
4. Iterate through each B in S. For each B, iterate through possible values of A that are less than B and present in S. Then check if C = 2*B - A is in S and C > B. To avoid double counting and ensure efficiency, we can iterate A from the smallest element up to B, but this might be O(N^2) in worst case.
5. Better approach: For each B, we can use two pointers or simply iterate over all possible A < B in S. However, N is up to 10^6, so O(N^2) is too slow.
6. Optimized approach: Since the values are bounded by M = 10^6, we can use a frequency array (or boolean array) `exists`. For each B in S, iterate over all possible A in S such that A < B. Check if C = 2*B - A exists in S and C > B. But iterating all A for each B is still potentially O(N^2).
7. Alternative: Iterate over all possible differences d. For each d, count triplets (B-d, B, B+d) where all three are in S. The maximum difference d can be up to M/2. For each d, iterate over all B such that B-d >= 1 and B+d <= M. Check if B-d, B, B+d are all in S. This is O(M * (M/d)) which sums to O(M log M). Since M = 10^6, this is feasible.
8. Specifically: Create a boolean array `present` of size 10^6+1. Mark all S_i as present. Initialize count = 0. For d from 1 to M//2: For B from d+1 to M-d: if present[B-d] and present[B] and present[B+d], increment count. This is O(M^2/d) which is O(M log M). With M=10^6, M log M is about 20*10^6, which is acceptable.
