The solution uses the critical points approach. The key steps are:
1. **Critical Points Identification**: We identify squares that are either the start (1), the end (N), or the first safe square after a bad interval ($R_i + 1$). These are the only squares where the "state" of reachability might change significantly.
2. **Reachability Precomputation**: Since the jump range $[A, B]$ is small ($B \le 20$), we precompute which distances can be formed by sums of integers in $[A, B]$. We use dynamic programming up to a threshold (2000) and then use the property that all sufficiently large distances are reachable if we have a contiguous block of reachable distances of length $B$.
3. **Graph Construction**: We group critical points into safe segments (contiguous ranges of safe squares). We then build a graph where edges exist between critical points in the same segment if the distance between them is reachable.
4. **BFS**: We perform a BFS on this graph to determine if N is reachable from 1.

The main potential performance issue is the $O(K^2)$ edge construction where $K$ is the number of critical points. However, given the constraints and the nature of the problem, this should be acceptable for most cases. The use of `bisect` for segment assignment ensures $O(K \log M)$ complexity for that part.
