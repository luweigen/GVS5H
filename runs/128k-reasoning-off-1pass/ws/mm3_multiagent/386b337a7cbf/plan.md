So product becomes 0. This is fine. However, if we have multiple zeros, we might generate many states with product 0. But product 0 is the minimum, so we only need to keep the maximum product for each (d,s). Since 0 is the only product for those states, we can just set it to 0. But we also have states with product >0. For those, adding a zero will make product 0, which is worse. So we don't need to keep states with product 0 if we already have a state with the same (d,s) and product >0. So in the update, we only update if the new product is greater than the existing one. But if existing is >0 and new is 0, we don't update. That's correct.

Now, we need to optimize for speed. The number of states in dp can be large. We can use a dict, but the key (d,s) is a tuple of two integers. To speed up, we can encode (d,s) into a single integer. Since d is in range [-150,150], s in [-1800,1800], we can map d to an offset: d_idx = d + 150, s_idx = s + 1800. Then key = d_idx * 3601 + s_idx. But we need to ensure the range. total_sum = sum(nums) but we can compute the maximum possible sum: max_possible_sum = sum of all positive numbers. Since nums are non-negative, the maximum sum is the sum of all numbers. But the maximum absolute sum is that. We can compute total_sum = sum(nums). Then SHIFT = total_sum. But wait, the sum can be negative as well, so range is [-total_sum, total_sum]. So size = 2*total_sum+1. We can compute SHIFT = total_sum. Then s_idx = s + SHIFT. d range: we don't know the maximum d beforehand, but it's at most n. We can set D_SHIFT = n. So d_idx = d + n. Then key = d_idx * (2*total_sum+1) + s_idx. But total_sum can be up to 12*150=1800, so 3601. n=150, so d_idx up to 300. Total keys up to 301*3601=1.08M. This fits in an integer. We can use a dict with integer keys, and store the max product as the value. This might be faster than tuples.

Also, we can use a list of dicts for different d to reduce the key computation. But let's stick with the integer key.

We also need to handle the case where v=0 specially to avoid many states? But it should be fine.

Let's implement with integer keys.

Steps:
- Compute n = len(nums)
- Compute total_sum = sum(nums)
- Compute SHIFT = total_sum
- Compute D_SHIFT = n
- Compute size_s = 2*total_sum+1
- Initialize dp as an empty dict.
- For each v in nums:
    new_dp = dp.copy()  # this is slow if dp is large. We can instead create a new dict and update.
    # To avoid copying, we can start new_dp as a dict, then add skip, take alone, and extend.
    new_dp = {}
    # skip: add all from dp
    for key, prod in dp.items():
        if key not in new_dp or new_dp[key] < prod:
            new_dp[key] = prod
    # take alone
    if v <= limit:
        # A: d=1, s=v
        d_idx = 1 + D_SHIFT
        s_idx = v + SHIFT
        key = d_idx * size_s + s_idx
        if key not in new_dp or new_dp[key] < v:
            new_dp[key] = v
        # B: d=-1, s=-v
        d_idx = -1 + D_SHIFT
        s_idx = -v + SHIFT
        key = d_idx * size_s + s_idx
        if key not in new_dp or new_dp[key] < v:
            new_dp[key] = v
