We need minimum total cost to turn A into B using flips. Each flip of position i incurs cost equal to sum over k of A_k*C_k *after* the flip. This is a classic problem reducible to greedy: for each i where A_i != B_i, we can decide whether to do an immediate flip (cost = current A sum * C_i, but C_i gets swapped in value) or postpone by using a "delayed flip" via another mismatched index. The known solution: traverse positions, for each i if A_i != B_i, compare C_i with the next mismatched position's C (or use min C of remaining mismatches). The optimal is to pair flips in non-decreasing order of C: process mismatches in increasing C, paying current prefix sum of A*C. Specifically, compute D_i = B_i - A_i (in {-1,0,1}) and prefix sums; the answer is sum over flips of (current total A*C) using the next minimum C among remaining mismatches. Simpler: process mismatches sorted by C ascending; for each mismatched i, cost += current total * C_i, then update total by toggling sign of A_i*C_i contribution (add 2*B_i*C_i - 2*A_i*C_i). Implementation O(N log N).
