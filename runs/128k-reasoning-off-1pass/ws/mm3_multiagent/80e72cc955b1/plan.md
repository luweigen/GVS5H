We need the minimum number of pairwise floor-division-by-4 operations to reduce every number in `[l, r]` to 0. A single operation can reduce two numbers by one "level" (where level = number of times you must divide by 4 to reach 0). So the answer is `ceil(total_levels / 2)`, where total_levels = sum over x in [l, r] of `level(x)`, with `level(0) = 0` and for `x > 0`, `level(x) = 1 + level(floor(x/4))`. This is equivalent to counting how many times 4 fits into x, i.e., the position of the most significant base-4 digit.

Computing the sum of levels for an interval `[l, r]` can be done in O(log r) using a helper `count_levels(r) - count_levels(l-1)`, where `count_levels(n)` returns the total levels of all numbers in `[1, n]`. For a block of 4^k numbers starting at 4^k, each level appears exactly 4^k / 4 = 4^(k-1) times. So `count_levels(n)` can be computed by iterating k from 0 upward, subtracting full blocks of size 4^k, adding `4^(k-1)` per block, and finally handling the remainder with a similar loop. This yields O(log n) per query and works for n up to 1e9 easily. Summing across up to 1e5 queries remains efficient.
