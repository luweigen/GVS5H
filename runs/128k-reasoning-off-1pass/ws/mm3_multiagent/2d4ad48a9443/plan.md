So the algorithm works. Now we need to implement it efficiently.

Steps:
1. Precompute `nxt` using a monotonic stack.
2. Precompute `seg_cost` and prefix sums.
3. Precompute binary lifting `up` and `cost_up`.
4. For each `l` from 0 to n-1, binary search the maximum `r` in `[l, n-1]` such that `cost(l, r) ≤ k`.
5. Sum the counts.

Edge cases: k can be up to 1e9, but cost can be large (up to 1e14), so use 64-bit integers.

Binary search for each `l`: we can use a while loop. Since the cost is monotonic in `r`, we can also use a two-pointer to avoid binary search, but binary search is O(log n) per `l`, total O(n log n) evaluations. Each evaluation is O(log n) due to binary lifting. So O(n log^2 n) = 1e5 * 17 * 17 = 3e7, which is fine.

But we can optimize the binary search by noting that for each `l`, the valid `r` is at least `l`. We can start with `lo = l`, `hi = n-1`. While `lo < hi`, take `mid = (lo+hi+1)//2`. Compute cost(l, mid). If cost ≤ k, `lo = mid`; else `hi = mid - 1`. Then count `lo - l + 1`.

Now, we need to implement the cost function `get_cost(l, r)`:
```python
def get_cost(l, r):
    if l == r: return 0
    current = l
    total = 0
    for j in range(max_log, -1, -1):
        nxt_node = up[current][j]
        if nxt_node <= r:
            total += cost_up[current][j]
            current = nxt_node
    # Now current is the last peak <= r
    partial = nums[current] * (r - current) - (ps[r+1] - ps[current+1])
    return total + partial
```
But careful: when we jump, we are adding `cost_up[current][j]`. However, we need to ensure that we don't jump past `r`. The condition `nxt_node <= r` is correct. But what if `nxt_node` is `n`? Then it's not ≤ r (since r ≤ n-1), so we won't jump. That's fine.

But wait: when we jump from `current` to `nxt_node`, we are adding the cost of the segments starting at `current` and the subsequent `2^j - 1` ancestors. This assumes that all those segments are fully contained within the range. Since `nxt_node <= r`, the last segment that is fully traversed is the one that ends at `nxt_node - 1`. Since `nxt_node <= r`, that segment is indeed fully within `[l, r]`. So it's correct.

One detail: `cost_up[current][j]` should be the sum of `seg_cost` for the `2^j` segments starting at `current`. But if `current` is such that some of those segments are not fully contained? No, because we only use it when `up[current][j] <= r`, which means all those `2^j` segments are fully within `[current, r]`. So it's correct.

We also need to handle the case where `current` becomes `n`? Actually, `up[current][j]` could be `n` if we jump past the end. But we only jump if `up[current][j] <= r`. Since `r < n`, `n` is never ≤ r. So we never jump to `n`. So `current` will always be < n. Good.

Now, we need to precompute `up` and `cost_up` for all `i` and `j` up to `max_log`. `max_log` can be `ceil(log2(n)) + 1`. For n=1e5, max_log = 17.

Let's write the code.

```python
class Solution:
    def countNonDecreasingSubarrays(self, nums: List[int], k: int) -> int:
        n = len(nums)
        # Compute nxt
        nxt = [n] * n
        stack = []
        for i in range(n-1, -1, -1):
            while stack and nums[stack[-1]] <= nums[i]:
                stack.pop()
            nxt[i] = stack[-1] if stack else n
            stack.append(i)
        
        # Prefix sums
        ps = [0] * (n + 1)
        for i in range(n):
            ps[i+1] = ps[i] + nums[i]
