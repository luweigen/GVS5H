1. Build intervals [L_i, R_i] for each vertex i. Two vertices are adjacent iff their intervals are disjoint.
2. Sort vertices by L_i ascending, then by R_i ascending. Use a sweep line with a segment tree or Fenwick tree to efficiently add edges between current vertex and all previously visited vertices whose R_j < L_i (i.e., intervals that end before L_i starts). However, N=2e5, building explicit edges is too many.
3. Key insight: the graph is an **interval graph complement** – the complement of a proper interval graph (since intervals are in [1,2N] and overlapping vs disjoint is well-defined). We need shortest path on this complement.
4. Better approach: Use a **Dijkstra-like** search but build a sparser structure. For each vertex i, we can connect it to the "next" vertex in sorted order of L and R, forming a graph with O(N) edges, then run Dijkstra. This is a known technique for interval-complement graphs: sort by L ascending, then for each i, add edges to i+1 and i-1 in L-order, and similarly sort by R and add edges; this yields a graph where shortest path distances equal the true distances.
5. Build two orderings: orderA = vertices sorted by L ascending, breaking ties by R ascending. orderB = vertices sorted by R ascending, breaking ties by L ascending. For each ordering, add edges between consecutive vertices. This creates a graph with 2(N-1) edges.
6. Run Dijkstra on this sparse graph to answer all queries offline (read all queries, run Dijkstra from each unique source, or run multi-source if needed; since Q up to 2e5, run Dijkstra from each unique s_i).
7. For each query, output distance[s_i][t_i] or -1.
