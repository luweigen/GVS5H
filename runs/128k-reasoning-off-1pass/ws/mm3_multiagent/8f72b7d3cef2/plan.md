We need for each index K the maximum size the K-th slime can achieve by absorbing adjacent smaller slimes repeatedly. This is equivalent to finding, for each position K, the maximal contiguous subarray containing K such that when merging all elements in the subarray using a stack-like greedy process (always absorbing from the side with the smaller "next" element), the K-th element eventually consumes everything.

Standard approach: process the array twice — once left-to-right, once right-to-left — using a monotonic stack to compute for each position the largest segment it can dominate. For each K, answer = prefix_max_left[K] + suffix_max_right[K] - A_K, where prefix_max_left[K] is the total size K can absorb when expanding leftwards (precomputed via stack) and suffix_max_right[K] similarly for rightwards. This is a known O(N) solution.
