We can freely replace `-1` entries with any non-negative integers and permute A arbitrarily. Let `a_fixed` be the multiset of fixed A-values, and `b_fixed` of fixed B-values. Let `x = number of -1 in A`, `y = number of -1 in B`. The sum of the N target constants `S = A_i + B_i` is `sum(a_fixed) + sum(b_fixed)` plus whatever non-negative values we assign to the `-1` positions. Since the per-index `A_i` values can be rearranged, the only structural constraint is that we can pair each fixed A-value with some fixed B-value (or a new A) such that all pair sums are equal.

If `x == 0` and `y == 0`, no rearrangement is possible: A's order is fixed. Then the answer is simply "check if A[i] + B[i] is already constant for all i".

Otherwise, when at least one side has a `-1` or rearrangement is possible, we can freely reorder A, so the feasibility condition reduces to a sorting-based matching: sort `a_fixed` ascending and `b_fixed` ascending, then a single target sum `S` exists iff the pairwise sums `a_fixed[i] + b_fixed[i]` are all equal (and non-negative). If they are all equal to some `S`, then the `x` flexible A-slots and `y` flexible B-slots must be fillable so that every index ends with sum `S`: this is possible exactly when `x + y == 0` (already covered) or when `x == 0` (then B has y slots we must fill with `S - a_fixed[i]`, requiring `S >= a_fixed[i]`, but since the sorted check already pairs B's with the largest A's via sort, if all pair sums equal S, the remaining B-only slots automatically get `S` value, no new constraints) — equivalently, the sorted-pair check captures everything. When both `x>0` and `y>0`, the leftover flexible slots can simply use `0` and `S` respectively, which always works.

A single check: if `x>0` or `y>0`, answer is "Yes" iff sorted pair sums of fixed values are all equal. If both are zero, answer is "Yes" iff all `A[i]+B[i]` are already equal.
