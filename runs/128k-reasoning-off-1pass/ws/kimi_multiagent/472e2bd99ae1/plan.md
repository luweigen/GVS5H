Binary search on the answer value X: count how many triples (i,j,k) give A_i·B_j + B_j·C_k + C_k·A_i ≥ X, and find the largest X with count ≥ K. For a fixed pair (i,j), the expression is linear in C_k: B_j·C_k + C_k·A_i = C_k·(A_i+B_j), so the count over k is the number of C values ≥ ceil((X − A_i·B_j)/(A_i+B_j)), computable in O(log N) after sorting C. Since K ≤ 5·10⁵, the answer is among the top-K values of the pairwise sums P_ij = A_i·B_j, so we only need the K largest products A_i·B_j, obtainable in O(K log N) with a max-heap over sorted A and B. For each candidate threshold, sum counts over those ≤K pairs in O(K log N); binary search over the value range (~60 iterations) gives O(K log N log MAX), feasible in PyPy with tight code. Edge care: use integer ceil-division via bisect on sorted C, and 128-bit-safe Python integers natively.
