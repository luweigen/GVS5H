**Core difficulty:** We must answer, after each of Q up to 2e5 updates, the sum over all monotone (right/down) paths of the product of cell values. The classic DP is S(h,w) = A[h,w]·(S(h−1,w) + S(h,w−1)), computable in O(HW). HW ≤ 2e5, but Q ≤ 2e5 too, so O(HW) per query (≈4e10 ops) is impossible. We need near-linear total work.

**Key structural facts:**
- HW ≤ 2e5, so min(H,W) ≤ √200000 ≈ 448. The grid is "thin" in at least one dimension.
- The sequence of updated cells forms a *walk*: consecutive updates hit adjacent cells. Each update changes exactly one cell (the destination).
- The answer is a linear function of each cell value (in fact, answer = Σ over paths of products; changing one cell scales all paths through it).
- Contribution decomposition: if we know G1(h,w) = sum of path-products from (1,1) to (h,w) *including* A[h,w], and G2(h,w) = sum of path-products from (h,w) to (H,W) *excluding* A[h,w] (i.e., with A[h,w] treated as 1), then changing A[h,w] from old to new changes the answer by (new − old)·G1'(h,w)·G2(h,w), where G1' excludes A[h,w]. So a point update's effect on the answer is computable in O(1) given prefix/suffix DP tables — but those tables themselves change after the update, which is the real problem.

**Candidate approaches:**
1. **Small-dimension transfer matrices:** Transpose so W = min(H,W) ≤ 448. Segment tree over the long dimension; each node stores a W×W transfer matrix (linear map from top boundary vector to bottom boundary vector). Point update = O(log N) node recomputes. Problem: composing two children matrices is general matrix multiplication O(W³) ≈ 9e7 — too slow per merge in Python. No obvious O(W²) composition because the matrices are dense.
2. **Offline reverse processing + incremental repair:** Simulate the walk fully to know every (cell, time, value) update. Process queries in reverse, maintaining DP tables, and "repair" the DP cone (down-right region) affected by each revert. Worst case still O(HW) per revert (e.g., repeatedly updating (1,1)-ish cells), but the walk constraint may bound amortized cost — risky, unproven.
3. **Sqrt decomposition on time (divide & conquer with rollback):** Standard "dynamic DP with point updates" via D&C over time: at each node of the time segment tree, apply all updates active in that node, recurse, rollback. Each update applied O(log Q) times; each application requires a DP repair whose cost is the cone size — still unbounded.
4. **Recompute-from-scratch per query but only over the minimal "staircase" region:** Since the walk moves one step per query, between consecutive answers only one cell changed; the set of cells whose S-value changes is the down-right cone of the updated cell.
