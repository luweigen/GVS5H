
## ideation
The core difficulty is combining a weighted interval scheduling DP (with up to 4 picks) with lexicographic tie-breaking over original indices. Sorting by right endpoint changes the index order, so every DP state must carry the original indices and comparisons must be: higher weight first, then lexicographically smaller tuple of indices. A subtlety: the lexicographic rule says a shorter array wins if it's a prefix, but since we maximize weight and all weights are positive, an optimal answer typically uses as many intervals as beneficial — however, we must still compare candidates of different lengths correctly (Python tuple comparison handles the prefix rule naturally). Another subtlety: "non-overlapping" means intervals sharing a boundary point ARE overlapping, so the previous-compatible interval must satisfy r_prev < l_curr (strict), i.e., binary search for rightmost interval with r < l_i. The DP is over sorted intervals: dp[i][k] = best (weight, tuple of original indices) using intervals among first i sorted intervals with exactly k picks (or at most k — need care). Transition: skip interval i (take dp[i-1][k]) or take it (dp[p(i)][k-1] + weight_i, appending index i). Since intervals are processed in sorted order and we append original indices, the resulting index list is in increasing sorted-order but NOT necessarily increasing original-index order — the answer likely needs indices in the order chosen, but lexicographic comparison is on the array as given. Looking at examples: output [2,3] and [1,3,5,6] are increasing original indices, and chosen intervals are disjoint so their sorted-by-right order corresponds to some index order; the expected output appears to be indices sorted ascending. Actually since intervals are non-overlapping, sorting by right endpoint gives a fixed order; the answer array should probably be sorted ascending by index (as examples show). Safest: build the tuple in chronological (sorted-by-right) order, then sort the final indices ascending before returning — but lexicographic comparison during DP should then be on the sorted-ascending tuple to match the final output format. Since a set of disjoint intervals has a unique chronological order, comparing sorted-ascending index tuples is well-defined; simplest is to compare on sorted tuples. Pitfalls: (1) boundary overlap strictness; (2) comparing tuples of different lengths where one is a prefix — Python handles it, but weight comparison dominates anyway; (3) n up to 5·10^4 with k up to 4 → O(n·k) DP fine, but storing full tuples in every state is O(n·k·k) memory/time worst case ~5e4·4·4 copies, acceptable in Python if careful, but better to store tuples only (immutable, shared via concatenation creates new tuples of length ≤4, so cost is fine). (4) "up to 4" — answer may use fewer than 4 intervals; track best over k=0..4 at the end. (5) Empty tuple vs. weight 0: weights ≥ 1 so more intervals always increase weight, but overlaps may limit count.
