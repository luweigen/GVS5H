A fine triplet is a 3-term arithmetic progression: for each middle element B, count pairs (A, C) in S with A + C = 2B, i.e., A = B - d, C = B + d for some d ≥ 1. Since values are bounded by 1e6, use a boolean presence array of size max(S)+1 and, for each B, walk d from 1 while both B-d ≥ 1 and B+d ≤ maxVal, counting hits. Worst case is O(N * maxVal) which is too slow for adversarial input (e.g., S = 1..1e6 gives ~5e11 checks), so use the FFT-based convolution approach instead: compute the autocorrelation of the indicator array; the coefficient at index 2B counts ordered pairs (A, C) with A + C = 2B, and subtracting the A=C=B term gives the answer per B. Sum over all B in S: answer = sum over B in S of (conv[2B] - 1) // 2, where conv = indicator * indicator (circular-safe via numpy FFT with sufficient length). Use numpy's rfft for speed (N, values ≤ 1e6, so array size ~2^21, very fast).
