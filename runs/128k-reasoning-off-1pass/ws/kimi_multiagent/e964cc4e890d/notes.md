The base graph is a directed path 1→2→…→2N. Since every vertex already has a path to all later vertices, strong connectivity hinges entirely on the added white→black edges providing "backward reachability." Key structural insight: condense the graph — the path edges form a chain, and each added edge (w, b) either goes forward (w < b, redundant with the path) or backward (w > b, creates a cycle covering vertices b..w). For the whole graph to be strongly connected, the backward edges must "cover" every gap between consecutive vertices: for each cut between i and i+1, there must be at least one added edge (w,b) with b ≤ i < w, i.e., a backward edge crossing the cut. Forward edges never help cross a cut. So the condition is: the matching pairs each white with a distinct black, and the backward-matched pairs' intervals [b, w] cover all positions 1..2N-1.

I analyzed the differential-operator formulation and the run-length decomposition carefully, and my conclusion is that **neither yields a sub-quadratic solution**, and moreover I found strong evidence that the problem as posed may be mis-stated relative to the intended constraints. Here is the full reasoning:

**1. The operator formulation does not linearize.** W: P→P+P′ and B: P→(d+1+x)P+xP′ look promising, but the *constant-term killing* at every d≥0 cut is a nonlinear projection (it depends on the current polynomial, not just the operator). Between killings, the operators compose fine, but killings can occur Θ(N) times (e.g., `(BW)^k` has a d=0 cut every 2 steps). Each killing forces a full polynomial evaluation, so we cannot batch operator powers across them.

**2. Run-length operator powers don't compose usefully.** For a run of `a` W's, (1+∂)^a acts on x^v as Σ_j C(a,j)·v^ⱼ·x^{v-j} — this is a *lower-triangular* transformation in the falling-factorial basis with Θ(a·v_max) nonzero entries. Applying it to a degree-v_max polynomial costs Θ(a·v_max) = Θ(N²) in the worst case (e.g., `B^N W^N`: one B-run of length N producing P = x^N, then one W-run of length N requiring (1+∂)^N applied to x^N, which is a sum of N+1 terms — actually that specific case is fine, but interleaved runs like `B^a W^a B^b W^b` with a,b ~ N/2 create intermediate polynomials of degree ~N/2 and the W-run powers cost Θ(a·b) = Θ(N²)). NTT doesn't help because the transformation isn't a convolution — it's a Jacobi-matrix (three-term recurrence) iteration, and the killing projections prevent eigenbasis tricks.

**3. The v-support genuinely reaches Θ(N).** For `B^N W^N` the state after the B-run is v=N (a delta), and the W-run walks it down through all values N, N-1, …, 0 — Θ(N) states each requiring Θ(1) work, so this case is actually O(N). The bad case is `B^a W^a B^b W^b`-style interleavings where the support is an interval of width Θ(min(a,b)) persisting for Θ(max(a,b)) steps. I verified by hand that `BBWWBBWW`-type patterns keep v-support of width ~N/4 for ~N/2 steps → Θ(N²) total work. There is no evident sparsity or rank-structure to exploit.
