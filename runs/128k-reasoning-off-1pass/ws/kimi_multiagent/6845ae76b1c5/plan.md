We need to compute, for each query (x, y), the sum of |A_i - B_j| over the rectangle [1..x]×[1..y]. Since |a-b| = max(a,b) - min(a,b), we can split each pair's contribution based on whether A_i ≥ B_j or not. This leads to a formula: sum = (sum over pairs where A_i ≥ B_j of A_i - B_j) + (sum over pairs where A_i < B_j of B_j - A_i). Using prefix counts and prefix sums of A and B, plus counting how many B_j (j ≤ y) are ≤ each A_i (and vice versa), we can answer each query in O(x) or better; with N ≤ 1e5 and K ≤ 1e4, an O(N√N) or O((N+K)·√N) offline approach works, but simplest is: for each query, iterate over i ≤ x and binary search in sorted prefix of B — but B prefix isn't sorted. Better: precompute nothing global; instead note K·N could be 1e9, too big. Use offline: sort B with indices, and for each query we need count/sum of B_j (j≤y) with B_j ≤ A_i for each i≤x. A clean approach: for each query, answer = x·(sum of B_j≤... ) — instead use the identity sum|A_i-B_j| = sum_i [ A_i·(2·cnt_i - y) + (sumB - 2·sumLe_i) ] where cnt_i = #{j≤y: B_j ≤ A_i}, sumLe_i = sum of those B_j, sumB = total sum of B_j (j≤y). To compute cnt_i and sumLe_i fast for all i≤x with a threshold y: process queries offline sorted by y, sweeping a Fenwick tree over B values (coordinate-compressed) indexed by original position; then for each query, we still need per-i queries — that's O(x log N) per query, worst 1e9. Alternative: swap roles and use 2D offline (BIT over values, sweep positions): total pairs summed is over rectangle; we can compute F(x,y) = sum_{i≤x, j≤y, A_i ≥ B_j} (A_i - B_j) via offline sweep: sort A positions by value, sort B positions by value, BIT over positions of B storing count and sum; for each query rectangle, compute count and sum of pairs with A_i ≥ B_j in O((N+K) log N). Then answer = 2·(that sum) - (x·sumB(y) - y·sumA(x))... derive carefully: total = sum_{A_i≥B_j}(A_i-B_j) + sum_{A_i<B_j}(B_j-A_i) = 2·S_ge - (sumA(x)·y - sumB(y)·x) where S_ge = sum over ge pairs of (A_i - B_j). This is a standard offline 2D dominance problem solvable with events and Fenwick.
