Model each cell as a tile with ports on its four edges (N/E/S/W). Type A (corner) connects one adjacent pair — 4 rotations; Type B (straight) connects an opposite pair (N-S or E-W) — 2 rotations. The "no dead ends on torus" condition means: for every grid edge between adjacent cells, both sides either have a port or neither does — i.e., port indicators must match across every edge. This is exactly counting configurations where each cell's port-set is one of its allowed shapes and all edge constraints agree. This is a classic transfer-matrix over rows: a row state is the W-bit mask of south ports; given north mask (from previous row's south), count tilings of the row consistent with horizontal matching, then transition to the next south mask. Since H,W can both be large but HW ≤ 1e6, we need an efficient method: observe the constraints decompose — each cell's allowed port sets are "even-degree" subsets, and the matching condition forces the whole configuration to be a disjoint union of cycles on the toroidal grid graph where each cell picks an allowed pairing. Key simplification: the condition is equivalent to choosing, independently per row-edge and column-edge, whether a line crosses it (binary variables), such that at each cell the set of chosen incident edges is one of the allowed shapes (A: exactly the 4 adjacent pairs; B: the 2 straight pairs). This is a "degree-constrained subgraph" (perfect matching of ports) count on a grid — solvable via transfer matrix with width min(H,W) using plug DP (bracket-free since only parity/matching matters), but with 1e6 total cells and up to 1e5 tests, we need O(HW * 2^min(H,W)) worst case which is fine when min dimension is small, but both can be ~1000. Better: use the known result that this equals counting cycle covers, which for this specific tile set reduces to a product formula via the number of connected components — investigate deriving a closed form using the structure: A-tiles are turns, B-tiles are straights; configurations are unions of loops on the torus. The intended solution likely uses transfer matrix with the smaller dimension ≤ ~20... but constraints don't guarantee that. Actually HW ≤ 1e6 total suggests an O(HW * poly) or O(HW * 2^min) with min small isn't guaranteed; the safe intended approach is likely the "loop model = Ising-like" reduction: each configuration corresponds to choosing edge variables with even degree at A/B cells per allowed sets, and the count factorizes as 2^(number of free cycles) — workers should derive and verify against samples.
