This is a matching problem: pair small mochi (tops) with large mochi (bottoms) where top*2 <= bottom. A greedy two-pointer approach works: use the smallest available mochi as tops and the smallest valid bottoms. Since the array is sorted, we can split into two halves conceptually — match the smallest K mochi as tops against the largest K as bottoms. The optimal strategy: iterate tops from the beginning, bottoms starting from the middle (or use binary search on K, checking feasibility greedily). Simplest: binary search K, check if A[i]*2 <= A[N-K+i] for all i in 0..K-1.
