Model the problem as a directed graph on the 26 letters: for each position i, S[i] must eventually map to T[i], so add a requirement edge S[i] -> T[i]. If any letter has two different required targets, it's impossible. Each letter's final image is determined by following the chain of edges; if following the chain from a letter ends at a letter with out-degree 0, that's its final value, and consistency with T must hold. Cycles in the requirement graph need one extra "buffer" operation to rotate (like a temp variable in cycle swaps), unless some letter in the cycle never actually appears in S at a position needing change. The answer is: number of letters c with an edge c -> f(c) where f(c) != c (each needs one operation), plus 1 for each non-trivial cycle that is "real" (all its letters appear in S and require changing), with the exception that a cycle containing a letter not present in S can be rotated using that letter as buffer without the extra operation.
