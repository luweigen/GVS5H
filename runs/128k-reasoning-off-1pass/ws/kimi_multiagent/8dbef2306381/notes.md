## worker: Implement the full Python solution: sliding B-bit 
- **State**: `bits` is a B-bit integer (B ≤ 20); bit `k` records whether square `cur - k` is reachable. Only the last B positions matter because the maximum step is B.
- **Advance over free space**: for each new square `p = cur+1`, `reach(p) = OR` of bits `[A-1, B-1]` (positions `p-B .. p-A`), extracted with `(bits >> (A-1)) & wmask`; then shift the window. O(1) per square on tiny integers.
- **Saturation jump**: if a free run is longer than `B² + B` and the window is nonempty, the reachable set is guaranteed to become "all positions" by `target`: from any reachable `x`, `x+B` is reachable in one jump; from a point `p0 > cur`, after `t` steps the reachable set is the whole interval `[p0+tA, p0+tB]`, which contains B consecutive squares once `t ≥ (B-1)/(B-A)` (within distance ≤ B²); B consecutive reachable squares imply every later free square is reachable (induction: `p-A` lies in the reachable window). So set the window to all-ones. If the window is empty, nothing beyond is reachable → `No`.
- **Crossing a block `[L,R]`**: shifting `bits` left by `R-L+1` inserts zeros for the blocked squares (they are unreachable) while preserving pre-block positions at the correct offsets; the subsequent free-run advance naturally computes jump-overs (including jumps landing inside `(R, R+B]` via other such landings, since the recurrence just continues).
- **A == B**: the path is forced to `1 + kA`; answer is `Yes` iff `(N-1) % A == 0` and no blocked interval contains a square `≡ 1 (mod A)` (checked via the smallest such square ≥ L).
- **Complexity**: O(M · B²) ≈ 2·10⁴ · 420 ≈ 8.4·10⁶ cheap operations; memory O(1) besides input.
