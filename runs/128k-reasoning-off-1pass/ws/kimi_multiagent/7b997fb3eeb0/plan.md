For a fixed subarray, the optimal matching pairs the smallest available mochi as tops with the smallest valid bottoms: greedily match the first half (sorted ascending) against the second half, counting pairs where 2*top ≤ bottom. This gives answer = max K such that the K smallest elements can each be matched to K distinct elements each at least twice as large, which reduces to checking A[L+i]*2 ≤ A[mid+i] style conditions. The count can be computed per query in O(m log m) with two pointers, but with N,Q ≤ 2e5 we need near O((N+Q) log N): use the greedy matching structure — pair smallest tops with smallest feasible bottoms — and answer each query via binary search on K with a range condition check (e.g., persistent/segment structure or offline processing). Workers should first derive and verify the greedy, then design an efficient per-query check.
