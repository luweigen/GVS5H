Model each block as a node; at floor level X, walkways connect adjacent blocks whose F ≥ X at zero stair-cost, while stairs change X at cost 1 per floor. The key insight: the answer equals the minimum, over all "levels," of |Y − L| + |Z − L| plus the stair-cost needed to travel between the two blocks at level L — and traveling at level L is free (walkways only) along any path where every block has F ≥ L. So define d(u,v) = minimum over paths of (number of "deficit" adjustments); equivalently, the answer is min over paths P from source to target of min_L (|Y−L| + |Z−L|) subject to L ≤ min F on P. This reduces to: answer = min over paths P of cost(P, Y, Z) where the path's bottleneck m(P) = min F on P gives cost = |Y−Z| if Z ≤ m(P)... more precisely cost = (Y + Z − 2·min stuff) — the clean formulation: answer = min over paths P of f(minF(P)) where f(m) = |Y − clamp| = distance from Y and Z down/up to feasible level: if both Y,Z ≤ m: |Y−Z|; else you must descend to m: cost = (Y−m)+ (Z−m) if both above, etc. To compute efficiently: process queries offline sorted by decreasing level, using DSU (Kruskal-style) adding blocks in decreasing F order; for each query, binary search the highest level L such that source and target are connected using only blocks with F ≥ L, but cost also includes |Y−L|+|Z−L| which decreases as L decreases toward Y,Z — so the true answer is min over the connectivity threshold. The standard solution: answer = min( |Y−Z| with constraint, or via meeting at low level ). Concretely: let T = max L such that s,t connected in subgraph of blocks with F ≥ L (found by offline DSU + binary search or parallel binary search). Then answer = min( |Y−Z| if max(Y,Z) ≤ T... ) — actually answer = min over L ≤ T of (cost to bring Y down to L) + (bring Z to L) where if L ≥ Y cost 0 for that endpoint (can go up? no—stairs cost both ways; but you could also go UP from Y to L if L ≤ F_s). Full cost at level L: |Y−L| + |Z−L|, valid if L ≤ F_s, L ≤ F_t, and L ≤ T (connectivity). Since |Y−L|+|Z−L| is convex in L, optimum L is clamp of median(Y,Z) region into [1, T]: if T ≥ max(Y,Z): answer |Y−Z|; if T between min and max: answer = max(Y,Z) − T + (max−min? ) — compute directly: L* = clamp(any value between min(Y,Z) and max(Y,Z), 1, T). So per query: find T via parallel binary search with DSU (rollback or rebuild per round), O((HW + Q) log) total.
