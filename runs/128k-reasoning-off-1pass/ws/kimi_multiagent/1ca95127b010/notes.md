The operations swap adjacent blocks: A swaps "0^X 1^Y" → "1^Y 0^X" (a 01-boundary moves right by X−Y... precisely, the boundary between the zero-block and one-block shifts), B is the inverse swapping "1^Y 0^X" → "0^X 1^Y". Both preserve the total number of 1s, so equal popcount is necessary. In run-length terms, an operation at a 0-run/1-run boundary transfers (X−Y) worth of length between adjacent runs — but only when the runs are long enough (≥X zeros before, ≥Y ones after for A). Key subtleties: (1) when X=Y the operation swaps equal blocks and the net effect on run structure is that a boundary can effectively move by 0 but the string changes — actually with X=Y, A turns 0^X1^X into 1^X0^X, which is a genuine change (boundary moves by 0 in run lengths but bits flip); wait — run lengths: 0-run loses X, 1-run gains X on the left... need care: with X=Y, "0^X 1^X" → "1^X 0^X" means the boundary between these runs moves left by X within the combined run pair, i.e., a 0-run of length a and following 1-run of length b become 0-run a−X, 1-run b+X — so the boundary slides by X. So generally a boundary between a 0-run (length a) and 1-run (length b) can slide right by (X−Y) if a≥X,b≥Y (op A: a→a−X+... hmm need exact derivation) — the clean invariant is likely: positions of boundaries modulo g = gcd-related quantity, plus feasibility constraints. Pitfalls: runs can be created/destroyed when a run length hits 0 (boundaries merge), X=Y case, N < X+Y (no moves possible), and the first/last runs behave asymmetrically. The reachability question on a line with local moves often reduces to: same popcount AND same set of "boundary positions mod g" treated as a cyclic/reflecting system, or equivalently the sequence of run lengths can be adjusted by transferring multiples of g across each boundary provided intermediate feasibility. Counterexample: `n=4, X=1, Y=2` (g=1): popcount-1 strings split into two components `{1000}` and `{0100,0010,0001}`, yet all have 0 or 1 boundaries with identical mod-1 residues — the tuple cannot distinguish a frozen leading `1` from a movable one. The first/last runs act as walls with length thresholds (a leading 1-run of length < Y cannot participate in operation B, and a leading 0-run of length < X cannot participate in operation A), so end-run lengths relative to X and Y are part of the true invariant.

**(3) Greedy push-left canonical form: NOT bijective.** Multiple components can map to the same canonical form, and (less often) one component can map to multiple fixpoints depending on scan order. The failure mode is exactly the frozen-end case: `1000` under (X=1,Y=2) is already a push-left fixpoint (no applicable op), and `0100` also reaches a fixpoint, but the greedy sum-of-positions criterion cannot shuttle a `1` past a too-short end run, so strings from different components can land on the same canonical string while strings in the same component occasionally land on different ones. The greedy heuristic is therefore insufficient as a decision procedure.

**Conclusions for the algorithm:** The true invariant must incorporate (a) popcount, (b) the sequence of interior boundary positions modulo g = |X−Y| (with slide unit X when X=Y), and (c) the lengths of the first and last runs relative to the thresholds X and Y (which determine whether boundaries can be absorbed/ejected at the ends). A correct O(N) check likely needs the run-length transfer model with explicit end-run handling rather than the simple tuple or greedy canon.
