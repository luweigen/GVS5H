For a fixed subarray, the minimum operations to make it non-decreasing equals the sum of positive "deficits" when scanning left to right, raising each element to at least the running maximum; equivalently cost(l,r) = sum over i in (l..r) of max(0, max(nums[l..i-1]) - nums[i]). We need to count subarrays with cost ≤ k. Since extending a subarray to the right only adds nonnegative cost, for each left endpoint the feasible right endpoints form a prefix, enabling a sliding-window / two-pointer count. The challenge is maintaining the incremental cost as the window's left edge moves, because the running-max structure changes; this can be handled with a monotonic stack that tracks "segments" where a new maximum dominates, storing each segment's contribution so we can add/remove in O(1) amortized. Overall target: O(n) time, O(n) space.
