
## ideation
The core difficulty is characterizing valid Snowflake Trees and efficiently finding the best one to keep. A Snowflake Tree has exactly 3 layers: center (red), x neighbors (blue), and each blue vertex has exactly y leaf children (green). Key insight: for a fixed center c, root the tree at c. Each neighbor v of c can serve as a blue vertex only if we keep exactly y of its children (grandchildren of c), which requires deg(v)−1 ≥ y. Any vertices at depth ≥3 from c must always be deleted, so they don't affect the choice. For fixed c and y: kept(c,y) = 1 + (1+y)·cnt_c(y), where cnt_c(y) = #{neighbors v of c : deg(v)−1 ≥ y}. Answer = N − max over all c, y≥1 of kept(c,y). Pitfalls: (1) y must be ≥1 and each kept blue vertex needs EXACTLY y leaves — neighbors with fewer children must be entirely deleted (contribution 0), not partially kept; (2) the center can be any vertex including a leaf of T (sample 2: center is endpoint); (3) for the sweep, (1+y)·cnt(y) is maximized at y equal to some neighbor's deg−1 value, since cnt is constant between consecutive distinct values and (1+y) increases; (4) keeping a neighbor with enough children is always strictly better than deleting it (depth≥3 deletions happen either way), so no trade-off to consider; (5) feasibility is guaranteed since N≥3 ensures some path of length 2 exists (kept≥3 always achievable).

- Characterization: a Snowflake Tree with center c has all kept vertices within distance 2 of c; each kept neighbor (blue) must have exactly y kept leaf children, requiring deg(v)−1 ≥ y. Depth ≥3 vertices are always deleted regardless, so they don't influence the choice.
