Model the problem as a shortest-path search on the state space of ordered pairs (position of A, position of B) with A≠B. The start state is (S,T) and the goal is (T,S); each move changes one coordinate to an adjacent vertex while keeping the two coordinates distinct, so BFS on this product graph gives the minimum number of operations. A naive BFS over O(N²) states is too large, so exploit structure: the answer relates to moving the two tokens past each other, which is only possible if the graph is not just a path (needs a cycle or branching to "swap"). Key insight: if the graph is a path, swapping is impossible unless... actually on a path two tokens cannot pass each other, so it's impossible. For general graphs, compute distances and check whether a swap is feasible via the existence of a vertex with degree ≥3 or a cycle allowing the exchange, then derive the distance formula. The intended solution: answer = dist(S,T) based formula — BFS on the line graph of configurations can be reduced to computing shortest path distances d(x,y) via one BFS from S and one from T, with the answer being 2*dist(S,T)+something depending on parity/girth. Simplest correct approach within constraints: run BFS on the pair-state graph but prune using the fact that only relative configuration matters — implement BFS over (a,b) pairs using adjacency and early termination, which is O(N·M) worst case and may be too slow, so instead derive: minimum = dist(S,T) + 2*(extra moves needed to pass), where passing requires a cycle; if the graph is a tree, tokens can swap only if there's a branching vertex on/near the path.
