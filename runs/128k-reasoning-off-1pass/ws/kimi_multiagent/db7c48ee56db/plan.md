Since C(N,K) ≤ 10^6, we can enumerate all K-combinations of indices directly and compute each XOR, taking the maximum. Use itertools.combinations over indices (or values) and a running XOR; complexity O(C(N,K) * K) worst-case 10^6 * small K, but K can be large when C(N,K) is small (e.g., K=N gives 1 combination), so O(C(N,K)*K) ≤ about 10^6 * N is too high in theory — better to compute XOR incrementally or note C(N,K) ≤ 10^6 bounds K heavily (K ≤ ~20 unless K near N). Safest: iterate combinations and XOR the K values directly; total work sum over combos of K = K*C(N,K) ≤ 10^6 * K, and K ≤ N but when K large C(N,K) tiny (e.g., K=N-1 gives N combos each of size N-1 → N^2 = 4*10^10 too slow). Handle that by complement trick: XOR of K chosen = total XOR ⊕ XOR of the N-K unchosen, so enumerate combinations of min(K, N-K) elements. Then total operations = min(K,N-K) * C(N, min(K,N-K)) ≤ ~2*10^7, fine.
