Binary search on the answer L (the minimized longest run length). For a candidate L, compute the minimum flips needed so that no run of identical characters exceeds L, and check if it is ≤ numOps. The key subproblem: given a run of identical characters of length len, the minimum flips to break it into runs of size ≤ L is len // (L + 1) (place a flipped character every L+1 positions). However, flipped characters of adjacent same-value runs can merge across boundaries, so a greedy/DP over runs is safer: process runs left to right, and when flipping inside a run, prefer positions that also break the neighboring run of the same character after a single opposite char. A clean correct approach: DP over positions with state = current run length, or simpler—since n ≤ 1000, do DP[i][j] = min flips considering prefix ending at i with last run length j, but that's O(n²) per check which is fine (10⁶ × log n). Simpler still: the per-run formula len // (L+1) summed is actually correct except when two runs of the same char are separated by a single opposite char and flips can be shared — handle via DP over run boundaries with small state.
