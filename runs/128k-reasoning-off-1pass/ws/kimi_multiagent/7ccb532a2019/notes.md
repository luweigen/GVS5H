This makes the problem a min-cost flow on a line graph (26 nodes), where each unit of flow from i to j costs (j-i) operations, while deletion and insertion each cost 1 per character.

class Solution:
    def makeStringGood(self, s: str) -> int:
        cnt = [0]*26
        for ch in s:
            cnt[ord(ch)-97] += 1
        maxc = max(cnt)
        ans = len(s)
        for k in range(1, maxc+1):
            # letter 0
            dpA = abs(cnt[0]-k)  # active
            dpI = cnt[0]         # inactive
            for i in range(1, 26):
                c = cnt[i]
                p = cnt[i-1]
                supA = p - k if p > k else 0
                supI = p
                demA = k - c if k > c else 0
                baseA = c - k if c > k else k - c

## worker: Implement the full solution: count frequencies, th
- **Model**: For a fixed target frequency `k`, each letter must end with count `0` (inactive) or exactly `k` (active). Base costs: `cnt[i]` deletions if inactive, `|cnt[i]-k|` inserts/deletes if active.
- **Key insight (savings)**: Moving one unit from letter `i` to `j > i` via changes costs `j-i`; the alternative (delete at `i` + insert at `j`) costs `2`. So only *adjacent* transfers (`j = i+1`, cost 1) give a strict saving of exactly 1 per unit; longer chains cost ≥ 2 and are never better. Hence savings decompose per edge: `min(supply_{i-1}, demand_i)`, with no flow coupling between edges.
- **DP**: Two states per letter (active/inactive). Transition uses the previous letter's supply (`cnt[i-1]` if inactive, `max(0, cnt[i-1]-k)` if active) against the current letter's demand (`max(0, k-cnt[i])` if active, else 0). O(26) per `k`.
- **Range of k**: `k` in `[1, max(cnt)]` suffices — for `k > max(cnt)` every present letter has a deficit, and reducing `k` by 1 never increases cost (the marginal unit of the rightmost active letter is either an insert, saving 1, or a change-in that can be replaced by a deletion at equal cost). `k = 0` (delete all) is covered by `ans = n`.
- **Verified**:
  - `"acab"` → 1 (k=1: delete one `a`; also k=2: change `b→c` giving `aacc` counts 2/2).
  - `"wddw"` → 0 (k=2, both active).
  - `"aaabc"` → 2 (k=2: change `a→b`, insert `c`).
  - `"aaab"` → 1 (change `a→b` → `aabb`); `"aaac"` → 1 (delete `c` → `aaa`); `"zzy"` → 1; `"abc"` → 0.
  - `z` handled correctly: it has no right neighbor, so its supply never yields savings (can't change forward), and transfers into `z` from `y` work normally.
- **Complexity**: `O(26 * max(cnt)) ≤ O(26 * 2*10^4) ≈ 5*10^5` operations — well within limits.

1. Only adjacent transfers yield strict savings (distance-d move costs d vs delete+insert cost 2).
2. Per-edge savings `min(supply, demand)` are independent (each supply unit can only profitably reach the immediate right neighbor).
3. k > max(cnt) never strictly optimal (marginal unit of rightmost active letter is an insert or replaceable change-in at equal cost).

**Complexity:** O(26 · max(cnt)) ≤ 5.2·10⁵ ops — fast for n ≤ 2·10⁴.
