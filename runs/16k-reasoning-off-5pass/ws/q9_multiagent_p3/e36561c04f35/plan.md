The problem asks for the minimum operations to empty the sequence using adjacent swaps and prefix deletions of equal elements. The key insight is that adjacent swaps allow us to reorder elements arbitrarily at a cost equal to the number of inversions (or simply the distance elements need to move). However, the deletion operation is highly restrictive: it can only remove a prefix where all elements are identical. This implies that to delete a group of identical numbers, they must eventually be gathered at the very beginning of the array. Since we want to minimize operations, we should process groups of identical numbers from left to right. For each distinct value, we calculate the cost to move all its occurrences to the current front (which is effectively the number of elements currently preceding it that are not yet deleted) and then delete them. The total cost is the sum of these movement costs plus the number of distinct values (for the deletion operations themselves). A greedy approach processing distinct values in their original relative order works because moving a later group before an earlier group would only increase the swap cost without providing any benefit, as the earlier group blocks the deletion of the later one until it is moved.
