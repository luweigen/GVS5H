The problem requires calculating the inversion count for $M$ different sequences where each element $A_i$ is shifted by $k$ modulo $M$. A naive $O(N^2)$ or even $O(N \log N)$ per $k$ approach will be too slow since $M$ can be up to $2 \times 10^5$. Instead, we observe that as $k$ increases by 1, the relative order of elements only changes when two elements wrap around the modulus $M$ (i.e., $A_i + k \ge M$ while $A_j + k < M$). We can pre-calculate the initial inversion count for $k=0$ using a Fenwick tree or Merge Sort. Then, we simulate the transition from $k$ to $k+1$ by identifying pairs that change their relative order due to the modulo wrap-around. Specifically, pairs $(i, j)$ where $A_i \ge A_j$ initially contribute to inversions but stop contributing once $A_i$ wraps around while $A_j$ does not, and vice versa. We can efficiently update the total inversion count by tracking the number of such "crossing" pairs.
