We need to calculate the inversion count for $M$ different sequences where each element $A_i$ is shifted by $k$ modulo $M$. Since $N$ and $M$ are up to $2 \times 10^5$, an $O(N \cdot M)$ solution is too slow. We can observe that the relative order of elements only changes when an element wraps around modulo $M$ (i.e., when $A_i + k \ge M$). We will first compute the initial inversion count for $k=0$ using a Fenwick tree (or Merge Sort). Then, we will simulate the process of incrementing $k$ from $0$ to $M-1$. In each step, we identify the elements that wrap around (those where $A_i + k \ge M$). For each such element, we update the inversion count by removing its contribution with respect to elements that are now smaller than it (due to the wrap) and adding its contribution with respect to elements that are now larger. This allows us to update the answer in $O(N \log N)$ total time or more efficiently using a Fenwick tree over the values.
