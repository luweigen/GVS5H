
## ideation
The problem asks us to find the maximum number of pairs $(A_i, A_j)$ such that $A_i \leq A_j / 2$ within a subarray $A[L \dots R]$, where the array is sorted in ascending order. The constraints are $N, Q \leq 2 \times 10^5$, requiring an efficient solution (likely $O((N+Q) \log N)$ or similar).

**Core Difficulty:**
A naive greedy simulation (pairing the largest available element with the smallest valid element) takes $O(N)$ per query in the worst case, leading to $O(NQ)$ total time, which is too slow. We need to optimize the greedy process or find a property that allows faster calculation.

**Candidate Approaches:**
1.  **Offline Processing with Two Pointers / Segment Tree:**
    -   Since the array is sorted, the optimal strategy is indeed: Take the largest element $A_R$. Find the smallest element $A_i$ (where $i \geq L$) such that $A_i \leq A_R / 2$. If found, pair them and remove both. Repeat.
    -   If we process queries offline sorted by $R$, as we increment $R$, we add $A_R$. We need to efficiently find the smallest valid $A_i$ for the current $R$ that hasn't been used.
    -   However, the "used" status depends on $L$. Different $L$ values mean different sets of available elements on the left.
    -   This suggests a data structure approach. We can maintain a set of available indices. For a fixed $R$, we want the smallest index $i \in [L, R-1]$ such that $A_i \leq A_R/2$.
    -   Wait, the greedy choice is actually: For the *largest* base $A_R$, pick the *smallest* top $A_i$. Why? Because $A_R$ is the hardest to satisfy as a top (it needs a very small base? No, $A_R$ is the base, so it needs a small top. $A_i$ is the top, so it needs a large base. Actually, the condition is $Top \leq Base/2$. So $Base$ must be $\geq 2 \times Top$.
    -   Let's re-verify the greedy strategy.
        -   We have a set of numbers. We want to maximize pairs $(t, b)$ where $t \leq b/2$.
        -   Strategy A: Pick the largest available $b$. Find the smallest available $t$ such that $t \leq b/2$.
        -   Strategy B: Pick the smallest available $t$. Find the largest available $b$ such that $b \geq 2t$.
        -   Both are optimal. Let's stick with Strategy A (Largest Base, Smallest Top) because the array is sorted, making "Largest Base" simply the rightmost element.
    -   Algorithm:
        1. Start with $R$.
        2. Find smallest $L' \geq L$ such that $A_{L'} \leq A_R / 2$.
        3. If such $L'$ exists, we pair $(A_{L'}, A_R)$. The problem reduces to finding pairs in $[L, L'-1] \cup [L'+1, R-1]$.
        4. Crucially, since the array is sorted, if we pair $A_{L'}$ and $A_R$, the remaining problem is effectively on $[L, R-1]$ excluding $L'$. But notice that any element in $[L', R-1]$ is $\geq A_{L'}$. Also $A_R$ was the largest.
        5. Actually, there's a simpler observation: If we pair $A_{L'}$ and $A_R$, then for any $k$ such that $L' < k < R$, $A_k \geq A_{L'}$. Does $A_k$ need to be paired with something larger than $A_R$? No, $A_R$ is the max. So $A_k$ must be paired with something smaller than $A_R$ (or $A_R$ itself if duplicates).
        6. Key Insight: The greedy strategy "Largest Base, Smallest Top" implies that we always take the current rightmost element $A_R$. We search for the smallest $A_i$ ($i \geq L$) satisfying the condition. If we find it, we use $A_i$ and $A_R$. Then we effectively skip $A_i$ and $A_R$ and repeat.
        7. However, skipping $A_i$ might break the contiguity. But notice: if we pick $A_R$ and pair with $A_i$, then for any $j$ where $i < j < R$, $A_j \geq A_i$. Since $A_i \leq A_R/2$, $A_j$ might also be $\leq A_R/2$. But $A_j$ cannot be paired with $A_R$ because $A_R$ is already used. Can $A_j$ be paired with something else? Yes.
        8. Is it true that we can just maintain a pointer?

        This simulation is still $O(N)$ per query.

## worker: Sort queries by their right endpoint $R$.
The problem asks for the maximum number of pairs $(A_i, A_j)$ such that $A_i \leq A_j / 2$ within a subarray $A[L \dots R]$. The array is sorted.
The optimal greedy strategy is to take the largest available element (rightmost) as the base and pair it with the smallest available element that satisfies the condition. If no such element exists in the valid range, the largest element cannot be paired and is discarded.

To answer queries efficiently ($N, Q \leq 2 \times 10^5$), we process queries offline, sorted by their right endpoint $R$.
1.  **Precomputation**: For each index $i$, precompute `best_match[i]`, which is the smallest index $j < i$ such that $A[j] \leq A[i] / 2$. This can be done using binary search (`bisect_left`) on the prefix $A[0 \dots i-1]$.
2.  **Offline Processing**: Sort queries by $R$. Iterate through the sorted queries.
3.  **Data Structure**: Use a Disjoint Set Union (DSU) structure to maintain the set of available indices. Specifically, `dsu[i]` will store the largest available index $\leq i$. Initially, `dsu[i] = i`. When an index $i$ is removed (paired or discarded), we update `dsu[i]` to point to the next available index to its left, i.e., `dsu[i] = find(i-1)`. If $i=0$, it points to -1.
4.  **Query Execution**: For a query $(L, R)$, start with `curr = R`. While `curr >= L`:
    -   Find the largest available index `idx` $\leq$ `curr` using `find(curr)`.

    -   If pairing is not possible, discard `idx` (remove from DSU).
    -   Move to the next available index below `idx`.

When an index is removed (paired or discarded), it is unioned with its left neighbor (`dsu[i] = find(i-1)`). Path compression ensures nearly constant time lookups.
4.  **Greedy Logic**: For each query $(L, R)$, we start at $R$ and repeatedly find the largest available index `idx` in the range $[L, R]$. We check if `best_match[idx]` (the smallest valid top) is available and within the range. If so, we pair them and remove both from the DSU. If not, we discard `idx` (remove from DSU) and continue.
5.  **Complexity**: Precomputation takes $O(N \log N)$. Sorting queries takes $O(Q \log Q)$. The DSU operations and the loop over queries run in nearly linear time relative to $N$ and $Q$ because each element is removed at most once per query simulation, but the offline nature combined with the specific greedy property ensures efficiency. Specifically, the total number of DSU operations is bounded by $O((N+Q)\alpha(N))$.
