
## ideation
The problem asks for the maximum total price of K disjoint pairs, where the price of a pair (i,j) is `max(X_i+X_j, Y_i+Y_j, Z_i+Z_j)`. N can be up to 1e5, so an O(N log N) or O(N) solution is needed. The sum of N over all test cases is at most 1e5.

Core difficulty: The weight of a pair is the maximum of three linear functions, each being a sum of a component from each cake. This is not a simple additive weight, making standard maximum weight matching algorithms (like Hungarian) too slow. The key is to find a way to decompose or transform the problem so that the optimal matching can be found greedily.

Candidate approaches:
1. **Lagrangian Relaxation / Parametric Search**: For any weights α,β,γ≥0 with α+β+γ=1, the pair price is at least α(X_i+X_j)+β(Y_i+Y_j)+γ(Z_i+Z_j). Thus the maximum total price is at least the maximum over all matchings of this linear combination. For fixed α,β,γ, the linear combination decouples into a sum of vertex scores s_i = αX_i+βY_i+γZ_i. The maximum matching is then simply the 2K vertices with the largest s_i. So the lower bound is max_{α,β,γ} sum_{top 2K} s_i. This is a concave piecewise linear function of α,β,γ, and its maximum over the simplex occurs at an extreme point (a vertex). So the bound is max( sum top 2K X_i, sum top 2K Y_i, sum top 2K Z_i ). However, sample 2 shows the answer can be strictly greater than this bound, so the bound is not always tight. But it might be used in a more sophisticated way, e.g., by considering that each pair can be assigned to one of the three components that actually achieves the max.

2. **Assignment by component**: For each pair, exactly one of the three components is the maximum (or there could be ties, but we can break them arbitrarily). If we assign each pair to the component that is the max, the total price is the sum of that component's sums over the pairs. The assignment must be consistent with the max conditions: e.g., if a pair is assigned to X, we must have X_i+X_j ≥ Y_i+Y_j and X_i+X_j ≥ Z_i+Z_j. This is equivalent to (X_i-Y_i)+(X_j-Y_j) ≥ 0 and (X_i-Z_i)+(X_j-Z_j) ≥ 0. Let u_i = X_i-Y_i, v_i = Y_i-Z_i, w_i = Z_i-X_i (note w_i = -u_i-v_i). Then the conditions become linear inequalities on the sums of these differences. The problem becomes: select 2K vertices and partition them into K pairs, each pair assigned a label (X, Y, or Z), such that the label's conditions hold, and maximize the sum of the label's component sums. The label's component sum is, e.g., for X: X_i+X_j = Z_i+Z_j + (u_i+v_i)+(u_j+v_j). This is still a matching problem with constraints.

3. **Transformation to two components**: We can rewrite the price using one component as base. For example, using Z as base: price = Z_i+Z_j + max(0, (X_i-Z_i)+(X_j-Z_j), (Y_i-Z_i)+(Y_j-Z_j)). Let a_i = X_i-Z_i, b_i = Y_i-Z_i. Then price = Z_i+Z_j + max(0, a_i+a_j, b_i+b_j). This is the sum of Z_i+Z_j plus the max of three additive functions: 0, a, b. The total price is sum_{i in M} Z_i + sum_{pairs} max(0, a_i+a_j, b_i+b_j). The first term is constant given the set M of 2K vertices. The second term is the maximum weight perfect matching on the complete graph of M with edge weight max(0, a_i+a_j, b_i+b_j). This is a simpler problem: given a set of points (a_i, b_i) in 2D, find a perfect matching to maximize sum of max(0, a_i+a_j, b_i+b_j). This is a two-dimensional version of the original, but with a constant 0 component. Can we solve this? The weight max(0, a, b) is the max of three numbers. We can try to express it as a sum of constants and a term that depends only on some ordering. For two numbers, max(0, a) = (a+|a|)/2. For three, max(0, a, b) = max( max(a,b), 0 ) = (max(a,b) + |max(a,b)|)/2. And max(a,b) = (a+b+|a-b|)/2. So max(0, a, b) = ( (a+b+|a-b|)/2 + |(a+b+|a-b|)/2| )/2. This is not a simple linear combination of absolute differences.

4. **Greedy with sorting and priority queue**: Given the structure, a plausible solution is to sort the cakes by some derived value (e.g., X-Y, or Y-Z, or X-Z), and then use a data structure to greedily pair the best candidates. Since the weight is the max of three sums, we can think of it as: for each cake, it has a "value" in each component. We want to pair cakes such that for each pair, the sum of at least one component is large. This is similar to the problem of maximizing the sum of max(A_i+A_j, B_i+B_j) which is solved by sorting by A_i-B_i. For three components, maybe we can sort by one difference and then use a priority queue to match with the best available cake that maximizes the max of the remaining two components.
