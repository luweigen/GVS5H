We need the maximum XOR of any K-element subset of A, with the constraint that the total number of subsets C(N,K) ≤ 10^6. Since N can be up to 2e5 but the subset count is small, we can enumerate all K-subsets directly (or via recursion/backtracking) and compute their XOR, tracking the maximum. The naive O(C(N,K) * K) is fine because C(N,K) ≤ 1e6 and K ≤ N ≤ 2e5, but we must avoid O(K) per subset by using incremental XOR updates during enumeration. We'll generate subsets via a recursive combination builder that maintains the running XOR and the current size, pruning when size exceeds K. The recursion depth is at most K ≤ N, and total states visited equals C(N,K) (plus some overhead), well within limits.
