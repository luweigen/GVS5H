We need to minimize the maximum run length after at most `numOps` flips. For any target maximum run length `L`, we can check feasibility: can we ensure no run of identical characters exceeds `L` using ≤ `numOps` flips? This is a classic "break long runs" problem. For each maximal run of length `len`, we need to flip at least `ceil(len / (L+1))` characters inside it (placing flipped bits every `L+1` positions) to split it into pieces of length ≤ `L`. Summing these required flips over all runs gives the minimum flips needed. If that sum ≤ `numOps`, then `L` is achievable. Binary search on `L` from 1 to `n` to find the smallest feasible `L`. Complexity O(n log n), well within n ≤ 1000.
