We need to count connected components in a graph where two nodes are connected if LCM(nums[i], nums[j]) ≤ threshold. Since threshold ≤ 2*10^5 but nums[i] can be up to 10^9, any nums[i] > threshold can only be isolated (LCM with anything is at least nums[i] > threshold). For nums[i] ≤ threshold, LCM(a,b) ≤ threshold iff a * b / gcd(a,b) ≤ threshold. The key insight: after dividing out common factors, two numbers are connected iff their product divided by gcd ≤ threshold. We can use Union-Find. Iterate over pairs where nums[i] ≤ threshold; for each such number, try to union it with multiples of its small factors that are also in the set. Concretely, for each nums[i] ≤ threshold, for each divisor d of nums[i] where d ≤ threshold, find multiples m of d up to threshold; if m is in the nums set, union them. Complexity: O(n * sqrt(max(nums))) worst, but average manageable. Alternative: bucket numbers by value and iterate multiples. Given n up to 1e5 and threshold up to 2e5, the multiple iteration per divisor is bounded by threshold/d, and sum of threshold/d over all (d, nums[i]) pairs is manageable using a visited sieve over the threshold range.

Simpler practical approach: precompute an array `pos[v] = index` for v in nums if v ≤ threshold. For each v in [1..threshold] where pos[v] is set, iterate multiples k = 2v, 3v, ... ≤ threshold, and union pos[v] with pos[k] when pos[k] exists. This is the classic "union by small-to-large multiples" trick: total work is O(threshold * log threshold) via harmonic sum, since each integer is visited as a multiple O(threshold/v) times. With threshold = 2*10^5, this is ~2*10^5 * (1 + 1/2 + 1/3 + ...) ≈ 2*10^5 * ln(2*10^5) ≈ 2.4*10^6, very fast. Numbers > threshold are each their own component.
