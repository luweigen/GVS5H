We need to find k non-overlapping contiguous windows of length x in `nums` such that each window is made constant with minimum total L1 adjustments. The classic approach uses DP with "min cost to make window i..i+x-1 constant" plus a segment tree / divide-and-conquer DP optimization (Aliens-style DP with monotonicity). Since k ≤ 15, we can compute for each starting index `i` the cost `cost[i] = minimum operations to make nums[i:i+x] equal`. Then we run a DP `dp[t][i]` = min cost to choose t non-overlapping windows among first i positions, with O(k·n) states and O(k·n) transitions. The naive O(k·n) transitions become O(k·n^2), too slow for n=1e5. We use the divide-and-conquer DP optimization (or a segment tree DP) because `cost` is a "concave" structure suitable for divide-and-conquer optimization. The divide-and-conquer DP runs in O(k·n log n) or O(k·n) with monotone opt. Simpler robust method: for each `t` layer, do a divide-and-conquer DP where the optimal start point for `dp[t][i]` lies in a monotonic range. Complexity O(k·n log n) fits easily.

Steps:
1. Precompute sliding-window cost: for each window of length x, the cheapest way to make all elements equal is to move them all to the median. Using prefix sums, compute cost in O(1) per window after O(n) preprocessing of medians via two heaps or sorting positions incrementally (or simply O(n log x) by extracting each window, sorting, computing cost).
2. Build `cost[i]` for i = 0..n-x.
3. DP: `dp_prev[i] = cost[i]` (one window). For t = 2..k: run divide-and-conquer recursion to compute `dp_cur[i] = min over j < i of dp_prev[j] + cost[i]` (j is previous window's start, must not overlap → j + x ≤ i). Standard divide-and-conquer DP with monotonic opt is valid because the transition is `dp_prev[j] + cost[i]` where cost is "concave-ish". However, to be safe with generic convexity, we can use a Li Chao tree / segment tree per DP layer, but that would be O(k·n log n) as well. The simplest reliable O(k·n log n) is to maintain a segment tree over `dp_prev` values, and for each `i` we query minimum over range `[0, i-x]`. That gives O(k·n log n) and avoids monotonicity assumptions. Given n=1e5 and k=15, this is ~1.5e6 log operations, very fast.
4. Return `dp_prev[n-x]` (minimum cost to place k windows within first n-x positions; the last window must end ≤ n-1, so its start ≤ n-x). Or keep answer as min over `dp_cur[end]` after k layers. Since windows cannot extend past the array, we restrict indices accordingly.
