We need to transform a string into one where every maximal run of equal characters has length ≥ 3, using minimum number of unit-cost "adjacent alphabet" changes, and among minimum-cost solutions pick the lexicographically smallest result. The constraints (n ≤ 5·10^4, alphabet size 26) suggest a DP that for each position decides the final character and ensures runs are long enough, while the cost of converting index `i` from original `c` to target `ch` is the absolute alphabet distance `|c - ch|`.

The classic way to enforce "no run of length 1 or 2" is to track, for each position and chosen character, the length of the current run modulo 3 (i.e., 1, 2, or ≥3). We DP over `i` and `(ch, run_len)`, where `run_len` is 1, 2, or 3 (meaning "≥3"). The transition either continues the same character (increasing run length, wrapping 2→3) or starts a new character different from the previous one (run length resets to 1). Cost adds distance from `caption[i]` to the chosen character.

To recover the lexicographically smallest optimal string, we store, in addition to the minimum cost, the lexicographically smallest resulting string for each state (or a back-pointer) and tie-break by comparing strings. Since n is 5·10^4 and alphabet 26, the DP table has size `O(26·3·n) ≈ 4·10^6`, which is fine. The lexicographic comparison is O(n) in the worst case per transition, which would be too slow if done naively; we instead store back-pointers (`prev_index`, `prev_char`, `prev_run`) and after computing the final optimal end state, we reconstruct the string once in O(n).

For final answer: the last position can end in any `(ch, run_len)` with `run_len == 3` (i.e., last run length ≥ 3). Pick the state with minimum cost; ties broken by reconstructing each candidate and picking the lexicographically smallest. We can do the tie-breaking during reconstruction by comparing only the few candidates that achieve the minimum (there are at most 26). Complexity: O(26·3·n) time, O(26·3) back-pointer memory plus O(n) for the answer.
