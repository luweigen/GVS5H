We need the minimum total cost to sort a permutation using adjacent swaps where the swap at position i (between indices i and i+1) costs i. This is a classic assignment: sort by moving each element to its target index using adjacent swaps, and the minimum cost corresponds to the sum over all inversions of (min of the two positions involved, i.e., the cost of crossing that edge). The optimal strategy is to perform a stable bubble-sort-like process from left to right: for each i from 1 to N-1, bubble the element that should be at position i to that position by repeated swaps at cost i each time. The total cost equals sum_{i=1}^{N-1} i * (number of elements originally to the right of i that are less than the element ending up at position i). Equivalently, it's sum over all pairs (a,b) with a before b in original array but a > b of min(position_a, position_b). We can compute this efficiently with a Fenwick tree (BIT) or segment tree while iterating from right to left, maintaining counts of seen elements and their positions. For each element x at position p, query how many already-seen elements y have y < x and position > p; their contribution is p. Then add x to the BIT. The total answer fits in 64-bit (up to roughly N^3/2 but N≤2e5 gives ≤~1.3e16, fits in signed 64-bit). This yields an O(N log N) solution.
