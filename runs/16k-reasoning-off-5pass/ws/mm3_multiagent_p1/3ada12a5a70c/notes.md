
## ideation
The core difficulty is maximizing the minimum Manhattan distance among k selected points constrained to the square's boundary. Since all points lie on the boundary, the Manhattan distance between any two boundary points equals the shortest path along the perimeter (the boundary forms a cycle of length 4*side). This allows mapping each 2D point to a 1D coordinate representing its position along the perimeter (starting at (0,0) and going clockwise). The problem then becomes: given points on a circle of circumference C = 4*side, select k points to maximize the minimum pairwise circular distance. This is the classic "aggressive cows on a circle" / "maximize minimum distance on a cycle" problem. The standard approach is binary search on the answer D, with a greedy check: place points starting from the smallest coordinate, always jumping exactly D ahead, and wrapping around the circle. The check succeeds if we can place k points such that the last placement completes the cycle (i.e., the total arc covered is ≤ C). Constraints (k ≤ 25, n ≤ 15000) make O(n log n) per check efficient. Pitfalls: correctly computing the perimeter coordinate for each point based on which side it lies on; handling the wrap-around carefully in the greedy check; ensuring the binary search bounds are appropriate (0 to C).
