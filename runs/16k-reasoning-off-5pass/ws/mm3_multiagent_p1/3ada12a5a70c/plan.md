We need to maximize the minimum Manhattan distance among k chosen points on the square boundary. Since points lie on the boundary, Manhattan distance between two boundary points simplifies: if they are on the same side, it's |x1-x2| or |y1-y2|; if on opposite sides, it's side + |x1-x2| or side + |y1-y2|; if on adjacent sides, it's side - |x1-x2| or side - |y1-y2| depending on orientation. The key observation: Manhattan distance on the boundary is essentially the shortest path along the perimeter (since interior distance equals perimeter distance for boundary points). So we can map each boundary point to its perimeter coordinate (distance along the perimeter from (0,0) going clockwise). Then the Manhattan distance between any two boundary points equals the minimum of their clockwise and counterclockwise perimeter distances. This transforms the problem into: given points on a circle (perimeter) of length 4*side, select k points maximizing the minimum pairwise circular distance. This is the classic "maximize minimum distance on a circle" problem, solvable by binary search on distance D and checking if we can place k points with pairwise circular distance >= D. The check is greedy: start from the smallest perimeter coordinate, place a point, then skip ahead by D, wrap around, and repeat up to k times. Since k <= 25 and points <= 15000, binary search with O(n log n) per check is efficient.
