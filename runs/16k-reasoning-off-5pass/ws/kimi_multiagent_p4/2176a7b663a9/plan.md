This is AtCoder ABC 304 F-style... actually it's the "Interval Graph Connectivity with Min Path Weight" problem (typical solution: the graph where edges mean disjoint intervals). Key observations: intervals on a line; two vertices are adjacent iff intervals are disjoint (one ends before the other starts). The complement structure lets us characterize connected components: sort intervals by L; a "chain" of overlapping intervals forms one component, and components are separated by gaps where max R so far < next L. Within a component, shortest path (vertex weights) between s and t can be computed via Dijkstra on an auxiliary graph built with segment-tree-like edges, but there's a classic trick: any shortest path uses at most a few intermediate vertices, and the answer is min over paths s -> k -> t or direct edge, using sparse structures. The robust approach: build graph with O(N log N) edges using two segment trees (edges from each vertex to all vertices whose intervals end before L_i, and all whose intervals start after R_i), then run multi-query Dijkstra — but Q up to 2e5 forbids per-query Dijkstra. Instead, prove that within a connected component, the min-weight path between s and t is min(W_s+W_t if edge exists, W_s+W_t+min weight of a common neighbor, or via two intermediates), and compute these with sorted structures + sparse tables. Workers should verify the small-path characterization, implement connectivity via sweep, and implement the candidate-minimum queries with RMQ structures.
