The rating function f(x) after all contests is monotone non-decreasing in x, and each contest adds at most 1. Key observation: f(x) - x is non-increasing in x (once your rating passes R_i you stop gaining from contest i). So we can binary search, for each query X, the answer directly: simulate is O(N) per query — too slow. Instead, note f(x) = x + (number of contests where rating stays in range). Standard trick: process contests and maintain breakpoints. Equivalent known solution: answer = X + k where k can be found by checking, for a candidate increment, consistency via binary search on a piecewise structure. Simplest robust approach: binary search the final answer Y for each query using the inverse property — compute, for a given target, the minimal initial rating needed (process contests in reverse: to end at ≥ y after contest i with increment condition, pre-image of threshold is an interval). Reverse simulation of a threshold: define g(y) = minimal starting rating to finish at ≥ y; process contests in reverse: if y <= L_i - 1... actually pre-image: rating before contest i must be in [L_i, R_i] to get +1, so to have after ≥ y: before ∈ [y, ∞) (no increment) or before ∈ [max(L_i, y-1), R_i] (with increment). The minimal before-value is: if y-1 <= R_i and max(L_i, y-1) <= R_i then min over options = min(y, max(L_i,y-1) if y-1<=R_i else inf). Then answer for query X is the largest y with g(y) <= X, found by binary search per query: O((N+Q) log MAX).
