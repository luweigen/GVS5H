
## ideation
The core difficulty is counting, for each element nums[i], how many subarrays of length ≤ k have nums[i] as the minimum (and symmetrically as the maximum), without double-counting ties. Standard "sum of subarray minimums" uses previous smaller element (PSE) and next smaller element (NSE) distances: contribution = nums[i] * left * right where left = i - PSE(i), right = NSE(i) - i. But here subarrays are length-capped at k, so the left/right extension counts must be clamped: a subarray starting at position s ∈ [i-left+1, i] and ending at e ∈ [i, i+right-1] must satisfy e - s + 1 ≤ k. So the count is the number of pairs (a, b) with a ∈ [1..left], b ∈ [1..right] (a = i-s+1, b = e-i+1) such that a + b ≤ k + 1. This count is a closed-form function f(left, right, k): if L = min(left, k), R = min(right, k), count pairs a∈[1..L], b∈[1..R], a+b ≤ k+1. This equals: for a from 1 to L, b can go up to min(R, k+1-a). Sum = Σ_{a=1}^{L} max(0, min(R, k+1-a)). Since a ≤ L ≤ k, k+1-a ≥ 1, so it's Σ_{a=1}^{L} min(R, k+1-a). Closed form: let t = k+1-R (threshold where min switches). For a ≤ t, term is R (if t ≥ 1); for a > t, term is k+1-a. Compute in O(1) with arithmetic series. Same f applies for maximum contributions with previous/next greater elements. Tie-breaking: for minimums use strictly smaller on one side and smaller-or-equal on the other (e.g., PSE strict "<", NSE "<="), and for maximums use ">" and ">=" consistently. Pitfalls: (1) negative numbers — contributions can be negative, no modular arithmetic needed here (no mod specified), just use Python ints. (2) Make sure the clamping uses min(left, k) correctly since a subarray containing nums[i] can extend at most k-1 beyond i total. (3) Verify f against brute force on small cases. (4) Edge case k=1: only singletons, answer = 2*sum(nums). (5) Monotonic stack gives distances to boundaries as n (or -1) when no smaller/greater element exists.
