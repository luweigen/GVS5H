Map each boundary point to a 1D position along the square's perimeter (arc length from (0,0), going clockwise). The Manhattan distance between two boundary points equals the shorter arc distance along the perimeter (since cutting through the interior is never shorter than the boundary path for points on the square's edge — verify this claim carefully, as it's the crux). Then binary search on the answer D: check feasibility greedily by selecting points around the circle such that consecutive chosen points (including wrap-around) are at least D apart. The greedy check on a circular sorted array tries each candidate starting point (or uses the fact k ≤ 25 to bound work) and runs in O(n) per start, with O(log side) binary search iterations.
