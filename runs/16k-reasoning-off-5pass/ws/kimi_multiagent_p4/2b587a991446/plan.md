Model the problem as a shortest-path search on the "configuration graph" whose vertices are ordered pairs (a, b) with a != b, where a is piece A's vertex and b is piece B's vertex. A move changes exactly one coordinate to an adjacent vertex, keeping the two coordinates distinct; the goal is (T, S) from (S, T). The full state space is O(N^2), too large, so exploit structure: BFS on this product graph can be done implicitly — from state (a,b), neighbors are (a', b) for a' ~ a, a' != b, and (a, b') for b' ~ b, b' != a. Use multi-level BFS with early termination, or reduce via the known trick: answer relates to shortest path distances d(S,T) with parity/obstruction analysis. The safe general approach is BFS over the pair-state graph with adjacency generated on the fly, using hashing of visited pairs, and pruning via the observation that BFS depth is bounded by answer; but worst case O(NM) states may be too big — instead use the structural result: the swap is possible iff the graph is not just the edge S-T with N=2 (more generally, iff there exists a path allowing "passing"), and minimum moves equal a function of dist(S,T) and detour lengths. Implement BFS on pairs with visited set of a* (N+1)+b encoded integers, which is fast enough when answer is small, but to guarantee performance derive the formula: minimum = dist(S,T) + 2 * (minimum extra detour needed to let pieces pass), where passing requires a vertex with degree >= 3 or a cycle reachable appropriately.
