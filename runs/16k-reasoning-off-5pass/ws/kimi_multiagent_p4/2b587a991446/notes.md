
## ideation
The problem is a two-token swapping puzzle on a graph: state = ordered pair (a, b), a != b; moves slide one token along an edge without collision; goal is the swapped state (T, S) from (S, T). Core difficulty: the naive state space is O(N^2) (up to ~4e10), so direct BFS is infeasible in general; we need either an implicit/pruned BFS or a structural characterization.

Key observations and candidate theory:
- This is the classic "15-puzzle on graphs" (Wilson 1974) for two labeled tokens. Feasibility: on a 2-connected (biconnected) non-bipartite graph, any configuration is reachable; on bipartite biconnected graphs, reachability is governed by parity (the permutation parity of tokens must match the parity of total moves; with two tokens, swapping A and B is an odd permutation, so total moves must be odd — equivalently dist parity constraints). On graphs with articulation points, tokens cannot pass each other within a "path-like" (bridge) region; they can only swap if there's a cycle (or a vertex of degree >= 3 providing a "parking" spot) accessible.
- For two tokens specifically, a cleaner mental model: they need to "pass" each other. Passing is impossible on a path (tokens preserve order along a path). They can pass iff there is a cycle or a branching vertex (degree >= 3) that both tokens can use as a passing bay. Sample 2 (single edge, N=2) is impossible — consistent.

- **Model.** A state is an ordered pair `(a, b)` with `a != b` (piece A on `a`, piece B on `b`). A move slides exactly one piece along an edge to a vertex not occupied by the other piece. The goal `(T, S)` is reached from `(S, T)`. BFS on this implicit configuration graph yields the exact minimum number of operations, or `-1` if unreachable. This is unconditionally correct.
- **Feasibility characterization (validated against all worked examples).**
  - If the graph is a **path** (all degrees ≤ 2 and `M = N-1`, including the `N = 2` single edge of Sample 2), the two pieces can never change their order along the path, so the swap is **impossible** → `-1`.
  - If the graph contains a **cycle reachable as a "bay"**, order reversal is always possible: both pieces travel into the cycle, one loops around while the other waits, then they exit in swapped order (lollipop example: 10 moves; C4 with adjacent S,T: 4 moves; C_n adjacent: `n` moves).

- **Cost structure.** Total moves = `len(walk_A) + len(walk_B)`, lower-bounded by `2·dist(S,T)`. Extra cost arises only from *passing*:
