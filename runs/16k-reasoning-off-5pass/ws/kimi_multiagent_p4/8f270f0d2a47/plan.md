We need count of n in [l,r] with digit-product % digit-sum == 0. Since r < 1e9, numbers have at most 9 digits, so digit-sum ≤ 81 and digit-product ≤ 9^9 ≈ 3.9e8 — too big for a DP state directly, but we only need product mod sum, and sum ≤ 81. Key insight: any number containing digit 0 has product 0, which is divisible by any positive sum — handle zeros as an absorbing state. Use digit DP with state (position, sum, product_mod_sum_started?) — but sum isn't known until the end. Instead, enumerate the final digit-sum s (1..81) and run a DP tracking product mod s, with a flag for "has zero digit" (then automatically valid). Answer = f(r) - f(l-1) where f(x) counts beautiful numbers in [1, x].
