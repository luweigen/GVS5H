We need to simulate N insertions where each new element i is inserted at position P_i. A naive list insertion is O(N) per operation, leading to O(N^2) total time which is too slow for N=5×10^5. We can process the operations in reverse: if we know the final position of each element, we can reconstruct the array. When processing element i (from N down to 1), it was inserted at position P_i among the current elements (which are 1..i-1). In the final array, its position is the P_i-th "available" slot. We can use a Fenwick tree (Binary Indexed Tree) to track available slots and find the k-th available slot efficiently in O(log N) time. Alternatively, a balanced binary search tree or order statistic tree can achieve the same. We will implement the Fenwick tree approach for O(N log N) performance.
