The key insight is that in a good caption, each "run" of identical characters must have length at least 3. Since we can change any character to any other character (with cost = alphabet distance), the problem becomes: partition the string into blocks of length >= 3, assign each block a target character, minimizing total cost (sum of distances), with lexicographic tie-breaking. This is a classic DP where dp[i] = best result for prefix of length i, transitioning from dp[j] where i-j >= 3, and the block caption[j..i-1] is converted to some character c. For each block, the optimal single character is the median (minimizes sum of absolute deviations), but for lexicographic tie-breaking we may need to consider all 26 characters — since alphabet is only 26, we can afford O(26) per block endpoint. With n up to 5*10^4, block lengths can be large, so we need prefix sums per character (26 prefix arrays) to compute block conversion cost in O(26). Total: O(n * 26 * 26) or O(n*26) with median tricks — O(n * 26^2) = ~3.4*10^7 which is acceptable, but we can also limit block length consideration since splitting into length-3 blocks is always at least as good... actually no: longer blocks forced to one char can be worse, but DP over all split points handles it. However, a key optimization: any block of length >= 6 can be split into two blocks of length >= 3 with cost no greater (each sub-block picks its own best char), so we only need to consider block lengths 3, 4, 5. This makes DP O(n * 3 * 26). For lexicographic smallest among min-cost, store the resulting string in DP (or do tie-break comparisons carefully).
