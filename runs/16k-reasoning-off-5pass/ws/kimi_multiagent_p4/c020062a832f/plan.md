Adding k modulo M rotates each value; an element A_i becomes (A_i+k) mod M, which wraps around when A_i >= M-k. The relative order of two elements only changes depending on whether each has wrapped, so we can compute the inversion count for k=0 with a Fenwick tree, then derive a delta when moving from k to k+1. When k increases by 1, exactly the elements with value M-1-k wrap from the top to 0; each such element's contribution change equals (number of non-wrapping elements before it) minus (number after it), which we can compute from positions. We precompute for each value v the sum over its occurrences of (2*position - N - 1) style terms so each transition is O(1) after O(N log M) preprocessing. Finally we output the running inversion count for all k.
