
## ideation
The core insight is already given in the plan: N = p^{2a} q^{2b} = (p^a q^b)^2, so 400 numbers are exactly squares of integers m that have exactly two distinct prime factors. The main difficulty is efficiency: Q up to 2×10^5 queries with A up to 10^12 means we need O(log n) per query after precomputation. Enumerating all m up to 10^6 and counting distinct prime factors via an SPF sieve is O(10^6 log log 10^6), which is fine. The count of valid numbers is modest (m must have exactly 2 distinct prime factors; density is low), so the sorted list will be small enough for bisect. Pitfalls: (1) m itself must have exactly two distinct prime factors — m=1 or prime powers give squares with only 0 or 1 distinct prime factors, exclude them. (2) The exponents a,b ≥ 1, so both primes must actually appear in m — that's automatic if m has exactly 2 distinct prime factors. (3) Edge case: smallest 400 number is (2·3)^2 = 36, matching constraint A ≥ 36. (4) Use integer arithmetic; m^2 up to 10^12 fits in Python int trivially. (5) Sieve: compute distinct prime factor count for all m ≤ 10^6 with a linear or SPF sieve — a simple approach: cnt array, for each prime p, for multiples j of p, cnt[j] += 1. That's O(n log log n), fast enough. (6) Answer via bisect_right on sorted list.

## worker: Implement the complete solution: sieve distinct-pr
- A 400 number N = p^{2a} q^{2b} = (p^a q^b)^2, so N is a perfect square whose root m has exactly two distinct prime factors. Conversely, any m with exactly two distinct prime factors gives a valid 400 number m^2.
- Sieve: `cnt[p] == 0` identifies primes; each prime increments `cnt` for all its multiples, yielding the number of distinct prime factors for every m ≤ 10^6. Complexity O(n log log n).
- Collected m^2 for all m with cnt[m] == 2; since m iterates upward, the list is sorted. Its size is small (~6×10^4), so per-query `bisect_right` is O(log n).
- Correctness check against samples: 404 → 400, 36 → 36, 60 → 36, 10^12 → 10^12 (root 10^6 = 2^6·5^6 has exactly 2 distinct primes), 123456789 → 123454321 = 11111^2 (11111 = 41·271).
- Edge cases: A ≥ 36 guaranteed, and 36 = (2·3)^2 is the smallest 400 number, so `bisect_right` never returns index 0. Python ints handle 10^12 trivially.
