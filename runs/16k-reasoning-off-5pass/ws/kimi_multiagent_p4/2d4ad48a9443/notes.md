from collections import deque
from typing import List

class Solution:
    def countNonDecreasingSubarrays(self, nums: List[int], k: int) -> int:
        n = len(nums)
        dq = deque()  # [value, count], strictly decreasing values front->back
        cost = 0
        left = 0  # in reversed coordinates
        ans = 0
        for j in range(n - 1, -1, -1):
            x = nums[j]
            right = n - 1 - j
            cnt = 1
            while dq and dq[-1][0] <= x:
                v, c = dq.pop()
                cost += (x - v) * c
                cnt += c
            dq.append([x, cnt])
            while cost > k:
                v, c = dq[0]
                y = nums[n - 1 - left]
                cost -= (v - y)
                if c == 1:
                    dq.popleft()
                else:
                    dq[0][1] = c - 1
                left += 1
            ans += right - left + 1
        return ans

## worker: Implement the full O(n) two-pointer solution in th
**Key identity.** For a subarray `a`, the minimum increments to make it non-decreasing is `sum(max(0, prefix_max_i - a_i))` — raise each element only to the running prefix maximum. Reversing the array converts this into a **suffix-max** cost: `cost(nums[l..r]) = sum(suffix_max_i - b_i)` over the corresponding window of `b = reversed(nums)`, because "non-decreasing by increments" in `nums` ⟺ "non-increasing by increments" in `b`, whose optimal cost uses suffix maxima.

**Why reversal matters (the crux).** In the reversed window, the suffix-max sequence is strictly decreasing front→back when grouped, and both updates become clean:
- **Append right** (`x`): only groups with value `≤ x` (a suffix of the deque) get their suffix max raised to `x`; pop and merge them, adding `(x - v) * c` to cost. New element contributes 0.
- **Remove left** (`y`): the leftmost element always lies in the front group (groups partition the window contiguously), whose value `v` is the window max. Its contribution was exactly `(v - y)`. Removing it never changes other elements' suffix maxima: if `v` still occurs later (count > 1) the group just shrinks; if the group empties, the next group's max is attained inside itself, so it's unaffected. This is exactly what fails in the forward direction (recomputing prefix maxima after the max leaves), and reversal fixes it.

**Two pointers.** For a fixed right end, cost is monotonic non-increasing as `left` advances, and extending `right` never decreases cost — so `left` only moves forward. For each `right`, all windows `[left..right]` in b-coordinates are valid, contributing `right - left + 1`. Each b-window corresponds bijectively to a `nums` subarray with equal cost.

**Verification.** Hand-traced both examples: Example 1 (`[6,3,1,2,4,4], k=7`) yields per-right counts `1+2+3+4+5+2 = 17` ✓; Example 2 (`[6,3,1,3,6], k=4`) yields `1+2+3+4+2 = 12` ✓. Also stress-checked tricky cases: strictly increasing array with `k=0` gives `n(n+1)/2`; `[2,2,1], k=0` gives 4 (correctly excluding `[2,1]` and `[2,2,1]`).

**Complexity.** Each element is pushed/popped from the deque at most once and each pointer moves ≤ n times: **O(n) time, O(n) space**. Costs fit easily in Python ints (≤ ~1e14).
