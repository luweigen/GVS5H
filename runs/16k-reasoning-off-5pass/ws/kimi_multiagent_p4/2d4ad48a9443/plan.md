For a fixed subarray, the minimum increments to make it non-decreasing is sum over i of max(0, running_max_so_far - nums[i]), i.e., we only raise elements to the prefix maximum. We need to count subarrays whose cost ≤ k. Since extending a subarray to the right never decreases its cost, for each left endpoint the valid right endpoints form a prefix — enabling a two-pointer/sliding-window approach. The challenge is maintaining the cost incrementally as the window expands/shrinks; this can be done with a monotonic stack that tracks "segments" where the running max is constant, storing each segment's contribution. When the left pointer moves, we must lazily remove the leftmost element's effect, which requires the stack to support popping from the front — use a deque of (value, count) groups and recompute cost deltas. Overall target O(n) or O(n log n).
