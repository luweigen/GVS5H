The game ends exactly when the last unvisited index is first chosen; moves on already-visited indices are just "passes" that consume tokens. Model this as: players alternately either claim a new index (progress) or spend a token on an already-claimed index (stall). The key insight is that once k indices are claimed, the total remaining tokens on claimed indices determine how many stall moves are available, so the game reduces to a parity/strategy analysis on the order in which indices get claimed. Concretely, sort indices by A_i and analyze: the player who is forced to claim the last index wins, and optimal play reduces to comparing the minimum A_i against the number of remaining indices (a "timing" argument where claiming early gives the opponent stall moves equal to the tokens you leave behind).
