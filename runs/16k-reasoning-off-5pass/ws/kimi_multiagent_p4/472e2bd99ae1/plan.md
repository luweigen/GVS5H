Rewrite the expression as A_i(B_j+C_k) + B_j·C_k, so for each pair (j,k) the value is linear in A_i; since A_i > 0, the K-th largest overall can be found by binary searching the answer value X and counting triples with value ≥ X. The counting step can be done by sorting A and, for each (j,k), binary-searching how many A_i satisfy A_i ≥ ceil((X − B_jC_k)/(B_j+C_k)) — but N² pairs is too many, so instead we count smarter: for each j, sort the values C_k and use two pointers / binary search over k with a monotonic structure. A cleaner classic approach: binary search on X (range up to ~3×10¹⁸), and for counting, fix j and note the condition in (i,k) is A_i(B_j+C_k) ≥ X − B_jC_k; iterate over sorted A and for each i count k's via binary search on derived thresholds of C — the threshold depends on B_j + C_k which is monotone in C_k, enabling an O(N log N) count per check by sweeping j and maintaining a pointer over sorted C combined with order-statistics on A. Overall: O(log MAX · N log N) with careful derivation, K ≤ 5·10⁵ also permits a selection-style pruning alternative.
