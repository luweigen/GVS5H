We need the k-th lexicographic permutation of [1..n] where adjacent elements differ in parity. Since n ≤ 100 but k ≤ 10^15, we cannot enumerate; instead we build the permutation digit-by-digit (factoradic-style), at each position trying candidate values in increasing order and counting how many valid completions exist, skipping blocks until we land in the block containing k. The counting subproblem is: given remaining odd count `o`, even count `e`, and the parity required for the next position (opposite of last placed, or free for the first), count alternating arrangements — this is a simple combinatorial formula: if the next parity is fixed, the remaining sequence's parities are forced into one pattern (or two patterns at the start), and the count is o!·e! when the pattern is feasible, else 0. We cap counts at k (or 10^15) to avoid huge big-int blowup, though Python handles big ints fine. Total work is O(n^2) candidate checks with O(1) counting each (factorials precomputed).
