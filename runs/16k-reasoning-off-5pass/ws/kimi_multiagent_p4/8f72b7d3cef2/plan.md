For a fixed starting slime K, the optimal strategy is greedy: repeatedly absorb the smaller of the two adjacent neighbors (or the only absorbable one), since absorbing a smaller slime never hurts and only increases size. The process for K expands a segment [L,R] outward; the final size is the sum of a maximal segment absorbable starting from K, stopping when both boundary neighbors are >= current sum. We need answers for all K in O(N log N) or O(N). Key idea: process slimes in increasing order of A (like union-find / DSU on sorted values), maintaining components of "activated" slimes with their total sums; when activating a slime, merge with active neighbors whose component sum < A_i... Actually the known solution: sort indices by A_i, use DSU where each component stores its sum; when adding position i, merge with adjacent active components, and while a neighboring component's sum < current component's sum, absorb it — but absorption condition depends on the moving slime's current size, which equals the component sum. Equivalent: simulate each K greedily using precomputed "next greater-or-equal" jumps with prefix sums, achieving near O(N log N) via binary lifting: from current segment [L,R] with sum S, the next absorbable slime is the nearest position outside with A < S; use sparse tables / monotonic stack to jump. Simplest robust approach: for each K, greedy expansion using prefix sums and RMQ (sparse table) to find the nearest element < S on each side, giving O(N log N) total.
