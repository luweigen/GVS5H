1. The problem asks for the sum of (max + min) for all subarrays of length 1 to k.
2. A naive O(n^2 * k) or O(n^2) solution will be too slow given n <= 80,000. We need an O(n) or O(n log n) approach.
3. We can decompose the problem into two separate parts: calculate the sum of maximums of all subarrays of length 1 to k, and the sum of minimums of all subarrays of length 1 to k.
4. For each part, we can use a monotonic stack to find the contribution of each element as the max/min. Specifically, for each element `nums[i]`, we find the range `[L, R]` where `nums[i]` is the max (or min).
5. However, the constraint "at most k elements" means we only consider subarrays starting at `s` and ending at `e` where `e - s + 1 <= k`. This complicates the standard "contribution technique" because the range of valid subarrays where `nums[i]` is the max/min is intersected with the length constraint.
6. A more robust approach for the length constraint is to iterate through each possible subarray length `len` from 1 to k, and for each length, compute the sum of maxs and mins of all subarrays of that length. But this is still O(n*k) in worst case if not careful.
7. Actually, we can use a sliding window with two deques (monotonic queues) to maintain the max and min for the current window of size `k`. But we need sums for *all* subarrays of size 1 to k, not just size k.
8. Alternative: Use the standard "sum of subarray minimums/maximums" technique but restrict the contribution of each element to only those subarrays that have length <= k. For an element `nums[i]`, let `left[i]` be the distance to the previous smaller/larger element, and `right[i]` be the distance to the next smaller/larger element. The number of subarrays where `nums[i]` is the min/max is `left[i] * right[i]`. But we must subtract those subarrays with length > k.
9. For each element `i`, the subarrays where it is the min/max start in `[i - left[i] + 1, i]` and end in `[i, i + right[i] - 1]`. The length is `end - start + 1`. We need to count pairs `(start, end)` such that `end - start + 1 <= k`.
10. This counting can be done in O(1) per element using arithmetic series formulas. For a fixed `i`, the number of valid starts is `L = left[i]` and valid ends is `R = right[i]`. The condition is `end - start + 1 <= k` => `end <= start + k - 1`.
11. We can iterate `start` from `i - L + 1` to `i`. For each `start`, the valid `end` values are from `i` to `min(i + R - 1, start + k - 1)`. The number of such ends is `max(0, min(i + R - 1, start + k - 1) - i + 1)`. Summing this over all `start` gives the count. This sum can be computed in O(1) by splitting into cases based on whether `start + k - 1 >= i + R - 1`.
12. We'll implement a helper function `sum_of_extremes(nums, k, is_max)` that computes the sum of maxs (or mins) for all subarrays of length 1 to k. Then return the sum of both.
