Model the rating process as a sequence of N intervals where each contest increments the rating by 1 if the current rating lies within that interval. The rating is a monotonic walk that only increases, so we can precompute a "next" function `next[i]` = smallest rating ≥ i such that after processing all contests from some point the walk eventually becomes at least `next[i]`. The classic approach: process contests from last to N down to 1, maintaining a segment tree or BIT over positions 1..5e5+ N to quickly find the smallest rating still ≤ some threshold. For each i, after contest i the rating will be either unchanged (if current rating not in [L_i, R_i]) or incremented by 1. We want to know the maximum possible starting rating that still results in rating ≤ k after this contest and all later ones. A well‑known solution uses an array `to[x]` = earliest rating that can be reached if we start at x, computed backwards with a segment tree supporting range `max(to[L_i..R_i])` queries and point updates. Then for a query X we simply output `to[X]`. Complexity O((N + maxR + Q) log MAX).
