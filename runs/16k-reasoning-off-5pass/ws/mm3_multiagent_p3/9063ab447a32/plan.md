The cost for buying k units of product i is k²·P_i. Since P_i values are large (up to 2e9) and M up to 1e18, k per product is small. We binary search the answer X (total units). To check if X is feasible, we use a greedy approach: for each product, compute the minimum number of units we can take from it while still being able to reach X total. If we take x_i units from product i, remaining needed is R = X - x_i, and we need cost ≤ M. The cheapest way to obtain the remaining R units across all products is to take floor(R² / something)... 

Better approach: For a target total X, we need to distribute x_i ≥ 0 with sum x_i = X, minimizing sum of x_i²·P_i. Sort products by P_i ascending. Process in order: for product i (sorted), take as many units as possible from it since it's cheapest, but we also need to ensure future (more expensive) products can fill the rest. Use the check: start R = X, for each P_i in sorted order, max units we can take is floor(sqrt(M_rem / P_i)), but we also need at least (remaining_products_count) units distributed among remaining products. So x_i = min(R - (n-i-1), floor(sqrt(M_rem / P_i))). Subtract cost, update R.

If after processing all products R == 0, feasible.
