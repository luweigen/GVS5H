We need each `t` in `target` to have at least one element in `nums` that is a multiple of `t`. We can only increment `nums` (never decrement), and want to minimize total increments. Since `target` is tiny (≤ 4) but `nums` is large (≤ 5e4), we can think of each `num` being "assigned" to cover one or more targets after rounding it up to a common multiple. For any fixed set of targets, the optimal value for a `num` is the cost of raising it to the LCM of those targets (or 0 if it already divides some). We need to choose an assignment of each `num` to a non-empty subset of `target` (or none) minimizing total cost. This is a min-cost covering problem; since `target` is tiny, we can DP over subsets of `target`: for each `num`, decide which subset to cover (2^|target| states). Complexity O(n * 2^m) where m ≤ 4, which is fast enough.
