We need to compute, for each possible value `x` that could be removed (including "no removal"), the maximum subarray sum of the array with all occurrences of `x` deleted. Brute force over all `x` is too slow. Instead, we can precompute prefix and suffix maximum subarray sums that ignore any single value. Specifically, for each index `i`, compute the best subarray sum that ends at `i` and does not include any occurrence of a chosen value. The key insight: the optimal subarray after removing `x` will be a contiguous segment of the original array that contains no `x`. So we can compute, for each position, the best subarray sum that ends at that position and contains no `x`, and similarly the best that starts at that position. Then for each `x`, the answer is the maximum over all positions of `suffix_max_starting_at[i] + prefix_max_ending_at[i-1]` where `nums[i] != x`. We can precompute arrays `left[i]` = max subarray sum ending at `i` (standard Kadane) and `right[i]` = max subarray sum starting at `i` (reverse Kadane). Then for each distinct `x`, we iterate through the array, maintaining the best `left` value seen so far at a position where `nums[j] != x`, and compute candidate = best_left + right[i] for positions where `nums[i] != x`. Also consider the case of no removal (just standard Kadane). Complexity O(n log n) or O(n) with hashmap of distinct values.
