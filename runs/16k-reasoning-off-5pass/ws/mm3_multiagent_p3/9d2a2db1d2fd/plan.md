So the formula works for the sample.

Now, we need to implement: build maximum spanning tree on grid with N=H*W nodes. Each node is a cell. Edge weight = min(F[u], F[v]) for adjacent cells. We need to sort edges in decreasing order and union-find. There are about 2*N edges. N up to 250k, so sorting 500k edges is fine. Then we have a tree. We need to answer Q queries: for each query, given A=(a,b), C=(c,d), find the minimum edge weight on the path in the tree. We can precompute LCA with binary lifting. For each node, we store its parent and the edge weight to parent. Then to find min on path, we do LCA and take min of the edge weights along the path. Since we need the minimum, we can store for each node the minimum edge weight to each ancestor at 2^k. That is O(N log N) preprocessing. Then each query is O(log N). Q up to 2e5, so total O((N+Q) log N) is fine.

But wait: is the maximum spanning tree necessary? We need the maximum bottleneck path. The maximum bottleneck path between two nodes is the minimum edge weight on the path in the maximum spanning tree. So yes.

However, we must be careful: the maximum spanning tree is not unique. But any maximum spanning tree will give the same bottleneck value for any pair? Actually, the maximum bottleneck between two nodes is the same regardless of which maximum spanning tree we take. So we can take any.

So the algorithm:
1. Read H, W, and F.
2. Generate all edges between adjacent cells (up, down, left, right). For each edge, weight = min(F[u], F[v]).
3. Sort edges in decreasing order of weight.
4. Use DSU to build the tree. For each edge, if the two cells are in different components, union them and add this edge to the tree. We need to store the tree edges. We can store an adjacency list for the tree: for each node, store (neighbor, weight). Also, we need to know the parent for each node to build LCA. We can do a BFS/DFS on the tree to set parent and depth.
5. Preprocess binary lifting: parent[k][v] and minWeight[k][v] = minimum edge weight on the path from v to its 2^k-th ancestor.
6. For each query:
   - Map (a,b) to node id = a*W + b (0-indexed). Similarly for (c,d).
   - Find the minimum edge weight on the path between the two nodes using LCA.
   - Let m = that minimum.
   - Let Y and Z be given.
   - Compute answer: if m >= min(Y,Z): ans = abs(Y-Z); else: ans = Y+Z - 2*m.
   - Output ans.

We need to be careful with 1-indexing/0-indexing.

Let's test with a simple case: H=1, W=2. F1=5, F2=3. Edge weight = min(5,3)=3. The tree has one edge weight 3. For query from (1,1,Y=4) to (1,2,Z=2). m=3. min(Y,Z)=2. m=3 >=2, so ans = |4-2|=2. Path: go down from 4 to 2? But we need to cross the edge. To cross, we must be at height <=3. So we can go down to 2, cross, then up? Actually, from 4, we can go down to 2 (cost 2), cross at 2, then we are at floor 2 in the second building, which is Z=2, so cost 2. Correct.

What if query from (1,1,Y=4) to (1,2,Z=4). m=3, min=4, m<4, so ans = 4+4-6=2. Path: go down to 3, cross at 3, then up to 4. Cost: |4-3| + |3-3| + |3-4| = 1+0+1=2. Correct.

What if query from (1,1,Y=5) to (1,2,Z=5). m=3, min=5, ans=5+5-6=4. Path: go down to 3, cross, up to 5. Cost: 2+0+2=4. Correct.

So the formula works.

Now, we must ensure that the maximum spanning tree indeed gives the maximum bottleneck. In a graph, the maximum bottleneck path between two nodes is equal to the minimum edge weight on the path between them in any maximum spanning tree. This is a known fact. So we are good.

But wait: is the graph connected? The grid is connected. So the tree spans all nodes.

Now, complexity: O(H*W log(H*W)) for sorting and DSU, O(N log N) for LCA preprocessing, O(Q log N) for queries. N <= 250k, Q <= 200k, so fine.
