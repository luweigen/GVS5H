We need to maximize the minimum value across all `gameScore[i]` after at most `m` moves, where each move adds `points[currentIndex]` to the current cell's score and moves ±1 (or starts from index -1 by moving to 0). Since `points[i]` are positive, every visit strictly increases the cell's score. The challenge is that `m` can be up to 1e9 while `n` is up to 5e4, so we cannot simulate moves directly. Instead, we binary-search on the answer `ans` (the target minimum score). For a candidate `ans`, we check feasibility: is there a walk starting from -1, staying within [0, n-1], with ≤ m steps, that guarantees every cell i is visited at least `need[i] = ceil(ans / points[i])` times? The optimal strategy to minimize total steps while ensuring each cell reaches its required visit count is a greedy sweep: go from left to right, on each cell do its required visits, then move to the next, possibly doing a final pass to cover the last cell. This reduces to checking whether the total required moves ≤ m in O(n) time. Then binary search the maximum feasible `ans` over the range [0, max_possible].
