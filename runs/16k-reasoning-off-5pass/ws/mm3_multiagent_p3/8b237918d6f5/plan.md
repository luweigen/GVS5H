We need to maximize the shortest path distance from 1 to N by selecting exactly K edges to set weight=1 (others weight=0). Since N ≤ 30 and M ≤ 100, we can binary search the answer L. For a candidate L, we ask: is there a choice of K edges such that every path from 1 to N has length > L (i.e., all paths use more than L unit-weight edges)? Equivalently, can we mark exactly K edges as heavy so that any 1→N path uses at least L+1 heavy edges? This is a classic min-cut with costs: we construct a flow network where picking an edge costs 1 (must be among K chosen) and we need to enforce that all paths from 1 to N pass through at least L+1 chosen edges. We use node-splitting and min-cost flow: each vertex v is split into v_in, v_out with edge capacity INF and cost 0. For each graph edge e=(u,v): add edge u_out → v_in with capacity=1, cost=1 (cost incurred if we select it), and also with capacity=1, cost=0 (don't select). For source s=1_in, sink t=N_out, we need to send L+1 units of flow from s to t. The total cost of min-cost flow = minimum number of selected edges needed to achieve L+1 edge-disjoint s-t flows. If min-cost ≤ K, then it's feasible (we can pad extra selections arbitrarily), else infeasible. Binary search L from 0..M.
