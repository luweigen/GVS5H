1.  **Graph Construction Insight**: The graph has $N$ vertices. An edge exists between $i$ and $j$ if $[L_i, R_i] \cap [L_j, R_j] = \emptyset$. This condition is equivalent to $R_i < L_j$ or $R_j < L_i$.
2.  **Connectivity Analysis**: Instead of building the graph explicitly (which could have $O(N^2)$ edges), we analyze the connectivity structure. The complement graph $\bar{G}$ has edges where intervals intersect. The connected components of $\bar{G}$ can be found efficiently. However, we need the shortest path in $G$.
3.  **Shortest Path Strategy**: The weight of a path is the sum of vertex weights. Since all weights are positive, the shortest path between two nodes in the same connected component of $G$ will likely be a direct edge if it exists, or a path of length 2 (via an intermediate node) if a direct edge doesn't exist but connectivity does. Paths of length $>2$ are generally suboptimal because adding intermediate nodes increases the total weight, unless the direct edge is missing and no "cheap" intermediate node exists.
4.  **Component Decomposition**: We can decompose the problem by analyzing the intervals. Two intervals are disjoint if one is completely to the left of the other. We can sort intervals by $L_i$ and $R_i$.
5.  **Efficient Query Processing**: For each query $(s, t)$, check if they are in the same connected component of $G$. If not, output -1. If yes, the minimum weight path is either:
    -   Direct edge $s \to t$: Weight $W_s + W_t$.
    -   Path $s \to k \to t$: Weight $W_s + W_k + W_t$, where $k$ is a node such that $[L_s, R_s]$ is disjoint from $[L_k, R_k]$ and $[L_k, R_k]$ is disjoint from $[L_t, R_t]$. We want to minimize $W_k$.
6.  **Finding the Best Intermediate Node**: For a fixed $s$ and $t$, we need a $k$ such that $k$ is disjoint from both $s$ and $t$. This means $k$'s interval must be to the left of both, to the right of both, or between them (if they don't overlap, but here $s$ and $t$ are connected, so they might overlap or not). Actually, if $s$ and $t$ are connected, there is a path. The shortest path in such interval graphs often involves at most 2 hops if we consider the "extremal" intervals. Specifically, we can precompute the minimum weight node that is disjoint from a given interval on the left and on the right.
7.  **Algorithm**:
    -   Sort intervals to efficiently find nodes disjoint to the left/right.
    -   For each node $i$, find the minimum weight node $k$ such that $R_k < L_i$ (left disjoint) and the minimum weight node $j$ such that $L_j > R_i$ (right disjoint).
    -   For a query $(s, t)$, check if a direct edge exists. If so, candidate weight is $W_s + W_t$.
    -   Check if there is a path $s \to k \to t$. This requires $k$ to be disjoint from $s$ and $t$. We can iterate over possible "types" of $k$: left of both, right of both, or between them.
    -   To handle "between", note that if $s$ and $t$ overlap, any $k$ disjoint from both must be either entirely to the left of $\max(L_s, L_t)$ or entirely to the right of $\min(R_s, R_t)$? No, if they overlap, the union is $[\min(L), \max(R)]$. A disjoint $k$ must be outside this union. So $k$ is either left of $\min(L_s, L_t)$? No, disjoint from $s$ AND disjoint from $t$.
    -   Actually, a simpler approach for shortest path in this specific graph: The graph $G$ is the complement of an interval graph. Interval graphs are chordal. The complement of an interval graph is a co-interval graph. Shortest paths in co-interval graphs can be solved by checking direct edges and 2-hop paths via "extremal" nodes.
    -   We can precompute for each node the minimum weight node to its left (disjoint) and right (disjoint). Then for query $(s, t)$, the answer is $\min(W_s+W_t \text{ if edge}, W_s + \min(W_k) + W_t \text{ for } k \text{ disjoint from both})$.
    -   To find min $W_k$ disjoint from both $s$ and $t$:
        -   Case 1: $k$ is to the left of both. $R_k < \min(L_s, L_t)$.
        -   Case 2: $k$ is to the right of both. $L_k > \max(R_s, R_t)$.
        -   Case 3: $k$ is between them? If $s$ and $t$ are disjoint, say $R_s < L_t$, then $k$ could be between $s$ and $t$? No, $k$ must be disjoint from $s$ and $t$. If $k$ is between, it must be disjoint from $s$ (so $L_k > R_s$) and disjoint from $t$ (so $R_k < L_t$). This is only possible if $R_s < L_t$ and there is a gap. But if $R_s < L_t$, then $s$ and $t$ are directly connected! So if a direct edge exists, we take it. If not, $s$ and $t$ overlap. If they overlap, any $k$ disjoint from both must be outside the union $[\min(L_s, L_t), \max(R_s, R_t)]$.
    -   So, if direct edge exists, ans = $W_s + W_t$.
    -   Else, ans = $W_s + W_t + \min(\min_{k: R_k < \min(L_s, L_t)} W_k, \min_{k: L_k > \max(R_s, R_t)} W_k)$.
    -   We need to efficiently query the minimum weight in a range of sorted intervals.
