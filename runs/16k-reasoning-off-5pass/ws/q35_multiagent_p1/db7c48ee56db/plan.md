The key constraint is that $\binom{N}{K} \le 10^6$, which means we can iterate through all possible combinations of $K$ elements from the sequence $A$. Since $N$ can be up to $2 \times 10^5$, a naive $O(N \cdot \binom{N}{K})$ approach might be too slow if we recompute XORs from scratch for each combination. However, we can use `itertools.combinations` in Python, which generates each combination efficiently. For each combination, we compute the XOR sum. To optimize, we can use `functools.reduce` or a simple loop, but given the total number of combinations is only $10^6$, and each XOR operation is on 60-bit integers (very fast), the total time complexity will be roughly $O(K \cdot \binom{N}{K})$. With $K$ potentially large, we need to be careful. However, note that if $K$ is large, $\binom{N}{K}$ is small only if $N$ is close to $K$ or $K$ is small. Actually, the worst case for $K \cdot \binom{N}{K}$ is when $K$ is around $N/2$, but the constraint $\binom{N}{K} \le 10^6$ limits this. For example, if $N=20, K=10$, $\binom{20}{10}=184756$, and $10 \times 184756 \approx 1.8 \times 10^6$ operations, which is very fast. If $K=1$, it's $N$ operations. If $K=N$, it's 1 operation. So the total work is bounded by $O(K \cdot \binom{N}{K})$, which is acceptable given the constraints. We will generate all combinations, compute their XOR sum, and track the maximum.
