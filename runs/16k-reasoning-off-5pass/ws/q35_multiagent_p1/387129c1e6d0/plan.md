1. **Simulate Santa's path**: Track Santa's current position $(x, y)$ and process each move $(D_i, C_i)$ to update his position.
2. **Track visited houses**: For each move, determine if any house lies on the line segment from the previous position to the new position. Since moves are axis-aligned, we can check if a house's coordinate matches the constant coordinate of the segment and if its other coordinate lies within the range of the segment.
3. **Efficient house lookup**: To efficiently check if a house is on a segment, we can store houses in a set for O(1) or O(log N) lookup. However, checking all houses for each segment is too slow ($O(N \cdot M)$). Instead, we can pre-process houses into a hash set (or sorted structure) and for each segment, only check houses that *could* be on it. But since segments are long and sparse, we cannot iterate all houses. 
   - Alternative: Use a spatial index or simply note that for horizontal/vertical segments, we can check specific coordinates. But with $N, M$ up to $2 \times 10^5$, we need a better approach.
   - Insight: We can store houses in a set for direct lookup. For each segment, we don't iterate houses. Instead, we can't easily find houses on a segment without checking. 
   - Better Insight: The problem is that we need to count distinct houses on the union of all segments. We can collect all segments, then for each house, check if it lies on any segment. But that's $O(N \cdot M)$ worst case if we check each house against each segment.
   - Optimized approach: Store houses in a hash set. For each segment, we need to find houses on it. Since segments are axis-aligned, for a horizontal segment from $(x_1, y)$ to $(x_2, y)$, we need houses with $Y=y$ and $X$ between $\min(x_1,x_2)$ and $\max(x_1,x_2)$. We can pre-group houses by their Y-coordinate (for horizontal checks) and X-coordinate (for vertical checks). Then for each horizontal segment, we look up the group of houses with that Y, and check which ones have X in the range. But iterating the group can be large.
   - Actually, we can use a balanced BST or sorted list for each Y-coordinate (for horizontal segments) and each X-coordinate (for vertical segments). Then for each segment, we do a range query. But we need to mark houses as visited. We can use a set to track visited houses. For each segment, we query the relevant group for houses in the range, and for each house found, if not visited, mark it and increment count. But if many houses are on one segment, this could be $O(N)$ per segment in worst case, leading to $O(N \cdot M)$.
   - However, note that each house is counted at most once. So the total number of "found and marked" houses is at most $N$. The issue is the cost of finding them. If we use a sorted list and remove houses once visited, then each house is processed once. For each segment, we query the range and remove visited houses from the data structure. This way, the total work over all segments is $O((N + M) \log N)$.
