Reconsider: The constraints on `nums[i]` are small (0-12). The maximum alternating sum magnitude is bounded by $150 \times 12 = 1800$. So we can shift the sum index by 1800. Let `offset = 1800`. Then `dp[s + offset][p]` stores the maximum product for alternating sum `s` and next parity `p`. Initialize `dp` with -1 (or 0 if no product possible). Start with `dp[offset][0] = 1` (empty subsequence, next element is at even index 0, product 1). For each number `x` in `nums`, update the dp table: for each state `(s, p)` with product `prod`, we can either skip `x` or include `x`. If we include `x`, the new alternating sum becomes `s + x` if `p==0` (adding to even index, so positive) or `s - x` if `p==1` (adding to odd index, so negative). The new parity becomes `1-p`. The new product is `prod * x`. We only keep the product if it is $\le$ `limit`. We want to maximize the product.

Finally, the answer is the maximum product in `dp[k + offset][0]` and `dp[k + offset][1]`? Actually, the subsequence ends at some parity. The alternating sum is fully determined. The parity `p` in our state indicates the parity of the *next* element to be added. So if we have a subsequence of length `L`, the last element was at index `L-1`. If `L-1` is even, then `p` becomes 1. If `L-1` is odd, then `p` becomes 0. But the alternating sum is already computed. So we just look at `dp[k + offset][0]` and `dp[k + offset][1]` and take the max. If both are -1 (or 0, but we use -1 to indicate invalid), return -1.
