The problem can be modeled as a shortest path problem on a state graph where each state is defined by `(vertex, orientation)`, with orientation being 0 (original) or 1 (reversed). We have two types of transitions: moving along an edge (cost 1) and reversing all edges (cost X). Specifically, from state `(v, 0)`, we can move to `(u, 0)` if there's an edge `v->u` in the original graph, and we can reverse to `(v, 1)` with cost X. From state `(v, 1)`, we can move to `(u, 1)` if there's an edge `u->v` in the original graph (i.e., `v->u` in the reversed graph), and we can reverse to `(v, 0)` with cost X. We can use 0-1 BFS or Dijkstra's algorithm to find the minimum cost to reach `(N, 0)` or `(N, 1)`. Since edge weights are either 1 or X (which can be large), Dijkstra is safer. The number of states is 2N and edges are roughly 2M + 2N, so Dijkstra will run in O((N+M) log N).
