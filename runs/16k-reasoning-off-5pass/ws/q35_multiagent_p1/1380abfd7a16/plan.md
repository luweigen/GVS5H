The key observation is that inserting elements from 1 to N in order is inefficient if we simulate directly (O(N^2)). Instead, we can work backwards. Consider the final array of size N. The last element inserted was N, which was placed at position P_N. This means that in the final array, the element at position P_N is N. The remaining N-1 positions are filled by elements 1 to N-1 in the order they were inserted. 

More generally, if we process from i = N down to 1, we can determine where each number i ends up. At step i (processing from N down to 1), the array has i positions available (initially all empty). The value i was inserted at position P_i among the current i positions. So, we need to find the P_i-th empty slot in the current array and place i there.

To efficiently find the P_i-th empty slot and mark it as filled, we can use a Binary Indexed Tree (BIT) or Segment Tree. The BIT will track how many empty slots exist in ranges. We initialize the BIT with 1s at all positions (indicating all slots are empty). To find the k-th empty slot, we can binary search on the BIT (or use binary lifting on the BIT structure) to find the smallest index such that the prefix sum of empty slots equals k. Once found, we mark that position as filled (update BIT by -1 at that index).
