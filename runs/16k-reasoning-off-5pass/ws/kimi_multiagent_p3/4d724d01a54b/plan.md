Each adjacent swap at position i costs i, and swapping adjacent elements is the only operation, so the number of times each pair of elements is swapped is fixed by the inversion structure, but we can choose the order of swaps to minimize cost. Key insight: moving an element left past k elements requires swaps at positions determined by current locations; the total cost equals the sum over all inversions of the position where that swap occurs. Model it as: process elements in order 1..N (or N..1), and each element must cross a certain set of others; the crossing position cost can be computed via a Fenwick tree tracking positions. The known result for this AtCoder problem (ABC/ARC "Sort with weighted adjacent swaps") is: answer = sum over i of (number of elements smaller than P_i to the right of i) weighted appropriately — specifically, compute for each element the cost of moving it to its correct place using a BIT over positions, summing min-cost routing. The cleanest formulation: iterate i from 1..N, maintain BIT of positions of already-placed elements; the cost contribution is the sum of indices crossed, computed as prefix sums.
