A fine triplet is a 3-term arithmetic progression: for middle B, count pairs (A, C) in S with A + C = 2B. Since values are bounded by 1e6, use a boolean presence array over the value range. For each B in S, count d ≥ 1 such that both B-d and B+d are present, and sum over all B. This is O(N + V·avg_range) worst case O(V^2) if done naively per element, so instead iterate d per B bounded by value range — worst case ~5e11, too slow; better: for each B, loop d from 1 to min(B-1, V-B) which in worst case (all values 1..1e6 present) is sum of min distances ≈ V^2/4 = 2.5e11 — still too slow. Use convolution (FFT/NTT): the count of pairs (A,C) with A+C=2B is the autocorrelation; compute f*f via FFT where f is the indicator array, then answer = sum over B in S of conv[2B] (excluding the A=C=B term, which contributes 1 when 2B = B+B, i.e., conv[2B] includes the (B,B) pair, so subtract 1 for each B). This gives O(V log V).
