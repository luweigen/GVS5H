Rewrite the expression as A_i·B_j + C_k·(A_i + B_j). For each pair (i,j) define P = A_i·B_j and S = A_i + B_j, so the value is P + C_k·S. Since C_k > 0, for a fixed pair the best k is the one with maximum C, but we need the K-th largest overall with K ≤ 5·10^5. Use binary search on the answer value V: count triples with P + C_k·S ≥ V. For counting, sort pairs by S and process C values in descending order with a Fenwick tree over P values (coordinate-compressed), giving an O((N² + N) log N) count — but N² is too large, so instead we only ever need the top-K relevant pairs. Key observation: for the K-th largest triple, only pairs (i,j) with large A_i·B_j matter; we can enumerate candidate pairs lazily with a max-heap over sorted A and B (top ~K pairs of products), then for each candidate pair the values over k are P + C_k·S, and we select the K-th largest among K·N candidates via binary search with sorted C and per-pair counting in O(log N).
