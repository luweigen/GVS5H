
## ideation
Core structure: vertices are intervals; edge i–j exists iff intervals are disjoint, i.e. R_i < L_j or R_j < L_i. Sorting intervals by L (indices 1..N in sorted order, keeping a mapping to original ids), vertex at sorted position p has edges exactly to a prefix of positions with R_q < L_p and a suffix of positions with L_q > R_p. So each vertex's neighborhood is a prefix ∪ suffix — a very structured "interval graph complement" (this is the incomparability/disjointness graph of intervals).

Key consequences:
- The graph is dense (up to ~N²/4 edges), so we must never materialize edges. Range-update Dijkstra with a lazy segment tree (or two pointer-sweeps with sets) is the standard trick: from vertex u with distance d, we relax all unvisited vertices in prefix range [1, a_u] and suffix range [b_u, N] with value d + W_v (charging vertex weight on entry). Each vertex is extracted once and each relaxation removes a vertex from the "unvisited" structure, so total work is O(N log N) per Dijkstra.
- Vertex weights: dist over vertices where cost of moving into v is W_v; answer for query (s,t) = dist[t] + W_s, with dist[s] = 0.
