Intervals are disjoint iff one ends before the other begins, so G is the incomparability graph of intervals ordered by position. Sort intervals by L; then i<j (sorted) are adjacent iff R_i < L_j. Key structural fact: in sorted order, the graph is "interval-like" — edges from i go to a contiguous suffix [k_i, N] where k_i = first index with L > R_i. This means BFS/Dijkstra from a source visits vertices in a way where distances to a contiguous range can be updated at once, enabling a Dijkstra with lazy segment-tree range relaxation (like "Dijkstra on interval graphs"). Vertex-weighted path cost: convert to edge costs by charging W_v when entering v; answer = dist[t] + W_s (or fold W_s in at start). Multi-query: run this fast Dijkstra per connected component only as needed — but Q up to 2e5 requires answering each query via one Dijkstra from s_i bounded by component, which is too slow worst case; instead note queries only need min over paths, and the special structure (suffix edges) yields that shortest path distances depend on component structure — we run Dijkstra per distinct source component using the segment-tree Dijkstra in O((N+Q) log N) total by processing each query independently with early termination, relying on the fact that each Dijkstra only explores its component; worst case is still heavy, so we cap with the observation that repeated sources can be cached (memoize full distance arrays per unique source only when cheap). Final approach: per query run segment-tree Dijkstra from s_i with early exit at t_i; to stay within limits, dedupe identical s_i by caching computed distances.
