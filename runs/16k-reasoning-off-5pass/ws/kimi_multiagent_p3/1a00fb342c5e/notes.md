
## ideation
The core insight is that XOR constraints decompose bitwise: for each bit k (0..29 since Z_i ≤ 1e9 < 2^30), the constraint A_{X_i} ⊕ A_{Y_i} = Z_i becomes a GF(2) linear equation: bit_k(A_{X_i}) + bit_k(A_{Y_i}) = bit_k(Z_i). Each bit is an independent system, but feasibility must hold for all bits, and the objective (minimize sum of A_i) also decomposes bitwise since sum A_i = sum over bits of 2^k * (number of variables with bit k set).

Key difficulty: efficiently handling 30 bits × up to 2e5 variables × 1e5 constraints. A DSU with parity (weighted union-find) per bit is natural: 30 DSUs each of size N, total memory ~30 * 2 * 2e5 integers ≈ 1.2e7 — feasible in Python with arrays/lists but must be careful with speed. Alternative: process each bit separately, reusing a fresh DSU per bit (30 × O((N+M) α)) ≈ 30 * 3e5 = 9e6 union/find operations — borderline but okay in Python with iterative path compression and union by size, especially using sys.setrecursionlimit-free iterative find.

Pitfalls:
1. Self-constraints X_i = Y_i: equation becomes 0 = bit_k(Z_i); if Z_i has bit k set, inconsistent. DSU parity handles this naturally (find(x)==find(y), parity must equal z bit).
2. Bits beyond 29: Z_i ≤ 1e9 < 2^30, so bits 0..29 suffice; higher bits of A_i must be 0 for minimality (any solution with higher bits can have them removed... actually constraints never force higher bits since Z_i < 2^30, so setting them 0 is always feasible and optimal). Wait — need care: if Z_i = 1e9, bit 29 may be set (2^29 ≈ 5.4e8, 2^30 ≈ 1.07e9 > 1e9), so bits 0..29 cover it. Actually 1e9 < 2^30, so bits 0..29 suffice.
3. Minimization per component per bit: once DSU built, each variable's bit = parity(x) XOR root_bit. Count variables with parity 0 and parity 1 in each component; choosing root_bit=0 makes parity-1 variables have bit 1 (count = c1), root_bit=1 makes parity-0 variables have bit 1 (count = c0). Choose min. This is independent per component and per bit — greedy is optimal because the only freedom per component is the single root bit flip.
4. Reconstruction: A_i = sum over bits of 2^k * (parity_k(i) XOR chosen_root_bit_k(component of i in bit k)). Need to store per bit the DSU parent/parity to compute final values, or process bits one at a time and accumulate into A_i. Better: for each bit, build DSU, check consistency, then for each component decide root bit, then for each i compute bit value and add 2^k * v to A[i]. But iterating all N per bit = 30 * 2e5 = 6e6 — fine.
5. M=0: all A_i = 0.
6. Duplicate constraints (sample 3 has them) — DSU handles naturally.
7. Performance: building DSU per bit from scratch requires N parent init per bit → 6e6 assignments, fine. Union operations: M per bit → 3e6 finds with path compression. Should run in a few seconds. Optimization: only process bits that appear in any Z_i? No — even if all Z_i have bit k = 0, constraints still link variables (forcing equal bits), which matters for... actually for minimization, if all z bits are 0, the optimal is all bits 0, contributing nothing, and no inconsistency possible. So we can skip bits where all Z_i have 0 — but careful: skipping is fine because setting bit k of all A_i to 0 satisfies all constraints with z-bit 0 and is optimal. So only process bits where at least one Z_i has that bit set. This can reduce work significantly.
8. Memory: store X, Y, Z arrays; per-bit DSU as lists of size N+1.

Edge: inconsistency detection — during union, if x and y already in same set and parity(x)^parity(y) != zbit → print -1.

## worker: Implement the complete solution: parse input with 
- Implemented a single weighted DSU where `parity[x]` is a 30-bit mask: bit k = XOR of bit k of `A_x` and bit k of `A_root`. This processes all bits simultaneously in one DSU, avoiding 30 separate DSUs.
- Union of constraint (x, y, z): after finds, required relation is `px ^ w ^ py = z` where w is the parity mask assigned to the attached root; set `w = px ^ py ^ z`. If x, y already share a root, check `px ^ py == z`, else infeasible → print -1.
- Find uses iterative path compression while XOR-accumulating masks so `parity[x]` always denotes mask relative to current root.
- After all unions, group variables by root. For each component and each bit b: members with parity bit 1 (`c1`) would have bit b = 1 if root bit = 0; members with parity bit 0 (`c0 = size - c1`) would have bit b = 1 if root bit = 1. Choose root bit = 1 iff `c1 > c0`, minimizing `min(c0, c1) * 2^b` contribution. This per-component, per-bit greedy is optimal since the only degree of freedom per component is the global root mask, and bits are independent in both constraints and objective.
- Reconstruct `A_v = parity_mask(v) ^ root_mask[comp(v)]`. Since Z_i ≤ 1e9 < 2^30, bits ≥ 30 are never forced and are set to 0 (optimal).
- Complexity: O((N + M) α(N)) for unions plus O(N · 30) for counting/reconstruction — well within limits. Handles M=0 (all zeros), self-loops (x==y requires z==0), and duplicate constraints naturally.
