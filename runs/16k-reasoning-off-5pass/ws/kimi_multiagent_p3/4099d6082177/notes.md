
## ideation
Core problem: partition a tree on NK vertices into N vertex-disjoint simple paths of exactly K vertices each (K-1 edges). Output Yes/No only.

Edge cases:
- K=1: always Yes (each vertex alone is a path of length 1 vertex).
- N=1: Yes iff the tree is itself a path (max degree ≤ 2). Actually the general algorithm should handle this too, but worth keeping in mind.
- K=2: this is exactly "does the tree have a perfect matching" — a useful sanity check for any algorithm.

Key structural idea: root the tree arbitrarily, process bottom-up. Each subtree returns to its parent the length of a "dangling chain" — an unmatched partial path that ends at the current node and extends upward. At each node:
- Collect chain lengths from children (each child returns a value in [0, K-1], where 0 means the child's subtree was fully decomposed with nothing dangling).
- The node itself adds 1 vertex that must join some chain.
- We can pair up child chains (plus possibly the node itself) so that pairs sum to K (forming a complete K-path through the node, or the node extends one chain).
- At most one chain can remain dangling upward; its length must be < K.

The tricky part: at a node with many children returning various chain lengths, deciding which to merge is a matching problem.
