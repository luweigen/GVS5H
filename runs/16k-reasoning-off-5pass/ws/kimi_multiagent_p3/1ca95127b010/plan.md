The operations swap a block of X zeros with an adjacent block of Y ones (A: 0^X 1^Y → 1^Y 0^X) or its inverse (B: 1^Y 0^X → 0^X 1^Y). Key insight: these moves preserve the cyclic order of individual bits if we treat each 0 and each 1 as distinguishable tokens — operation A moves Y ones left past X zeros, operation B moves Y ones right past X zeros. So the relative order of the zeros among themselves and ones among themselves never changes; hence a necessary condition is that the sequence of "which positions are 1" can be matched token-wise: the k-th 1 in S must be able to become the k-th 1 in T, and similarly for zeros. Each operation changes the position of a 1-token by ±X (jumping over X zeros) or a 0-token by ±Y. The reachability reduces to: for every k, the k-th 1 in S and k-th 1 in T differ by a multiple of gcd considerations — actually since a 1 can move left/right by X only when there are X zeros adjacent on that side, the standard result (this is AtCoder AGC/ARC-style) is: answer is Yes iff for all k, (pos_S of k-th 1) ≡ (pos_T of k-th 1) (mod g) where g = gcd(X, Y)... need care: moves of 1s are by ±X, moves of 0s by ±Y, but 1s can only pass zeros and vice versa, so the parity/gcd condition on each token's displacement is both necessary and sufficient.
