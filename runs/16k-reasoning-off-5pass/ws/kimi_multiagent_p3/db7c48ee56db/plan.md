The key constraint is C(N,K) ≤ 10^6, which means either K is small (≤ ~3-4) or N-K is small. Since XOR of K elements equals XOR of all N elements XOR'd with the XOR of the complementary N-K elements, we can choose whichever side is smaller. For small K (or small N-K), we can enumerate combinations directly if C(N,K) is small enough, or use a meet-in-the-middle / greedy basis approach. The cleanest approach: if C(N,K) ≤ 10^6, brute-force enumerate all K-combinations with early termination; otherwise use the complement trick. Actually since C(N,K) = C(N,N-K) ≤ 10^6 always, we can always enumerate the smaller side directly — total work is at most 10^6 × (cost per combination). Use itertools.combinations over indices, computing XOR incrementally via recursion/DFS to keep it O(1) amortized per combination.
