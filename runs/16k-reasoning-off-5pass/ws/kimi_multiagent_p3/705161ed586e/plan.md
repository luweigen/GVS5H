Model the problem as a shortest-path / DP over positions, where the state is the current character and the length of the current run (capped at 3, since runs longer than 3 can be treated as "3+" for validity). The cost of setting position i to character c is |ord(caption[i]) - ord(c)|, and a caption is good iff every maximal run has length >= 3. Use DP with parent pointers to reconstruct the lexicographically smallest minimum-cost string; when costs tie, prefer the lexicographically smaller resulting string (compare candidates carefully, e.g., by tracking the reconstructed string or a tie-break key). n up to 5*10^4 with 26 letters and 3 run-length states gives O(n * 26 * 3 * 26) transitions worst case, which is ~1.2e8 — too slow in Python, so optimize transitions: from state (char c, runlen k), next char is either c (extend run, runlen -> min(k+1,3)) or a different char d starting a new run (only allowed if k == 3), giving O(n * 26 * 26) with runlen dimension folded, or O(n * 26 * 3 + n * 26 * 26) ≈ 3.4e7 which is borderline but feasible with arrays and precomputed costs; alternatively note only runlen states 1,2,3 matter and transitions are simple. Handle impossibility: if n < 3 return "" (also n not partitionable... actually any n except 1,2,5 can be split into 3s and 4s; DP naturally returns infinity for impossible cases like n=1,2,5).
