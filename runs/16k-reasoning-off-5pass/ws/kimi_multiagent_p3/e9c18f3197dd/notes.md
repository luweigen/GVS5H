The core difficulty is that one nums element can simultaneously satisfy multiple target values (by becoming a common multiple), so this is a set-cover-like optimization. Since target.length ≤ 4, we can enumerate all non-empty subsets of target (at most 15). For each subset, compute the cheapest cost to make some nums element a multiple of the LCM of that subset. Then use subset DP to find the minimum total cost to cover all targets.

Pitfalls:

## worker: Implement the full Solution class: sort nums, comp
- **Approach**: Since `target.length ≤ 4`, enumerate all non-empty subsets (≤15). For each subset, compute the cheapest way to satisfy all its targets with a *single* nums element raised to a common multiple of their LCM `L`. Then subset DP partitions the full target set into groups, each group covered by one nums element (elements are distinguishable and each group uses a "fresh" element — this is valid because using the same element for two groups is exactly captured by merging them into one group with a combined LCM).
- **cost[mask] computation**: For LCM `L`, the cost of raising `x` to a multiple of `L` is `ceil(x/L)*L - x`. For multiples `m = L, 2L, ... ≤ max(nums)`, the best `x` is the largest `nums[j] ≤ m` (found via `bisect_right` on sorted nums). If `L > max(nums)`, every element is below `L`, so the cheapest is `L - max(nums)`. Early exit when cost 0 is found.
- **DP**: `dp[mask] = min over non-empty submask sub of dp[mask ^ sub] + cost[sub]`. Complexity: 2^k masks × 2^k submasks = 3^k ≤ 81 iterations; cost computation is O(2^k × max(nums)/L × log n) ≤ trivial.
- **Verification against examples**:
  - `[1,2,3], [4]`: L=4, multiples {4}, largest ≤4 is 3 → cost 1. ✓
  - `[8,4], [10,5]`: cost({10})=2 (8→10), cost({5})=1 (4→5), cost({10,5}) with L=10 → 2 (8→10 covers both). dp picks 2. ✓
  - `[7,9,10], [7]`: 7 is already a multiple of 7 → cost 0. ✓
- **Edge cases handled**: duplicate targets (LCM of duplicates is fine), zero-cost coverage (early break), LCM > max(nums) (raise largest element to L), single-element nums (bisect still works), LCM overflow capped at 10^16 (any L that large exceeds max(nums) ≤ 10^4, so only the first multiple matters and the cap doesn't affect correctness since `l - max_num` is computed on the true LCM before capping... note: the cap only triggers when partial LCM already exceeds 10^16, and the loop breaks with `l` being the first partial product exceeding the cap — but since any L > max(nums) uses only `L - max_num` and DP would never prefer such an expensive option over individual coverage (each individual target t ≤ 10^4 costs at most ~10^4), correctness is preserved. To be fully safe, the cap is set high enough that the DP would never select such subsets anyway).
