For a fixed subarray of length m, the maximum number of pairs is found by a greedy two-pointer match: pair the smallest available "top" mochi with the smallest "bottom" mochi that is at least twice as large, scanning with two pointers; this yields the maximum K in O(m). Since queries are arbitrary ranges, we need something faster than O(m) per query. Key structural fact: the greedy matching on a sorted array pairs tops from the left half with bottoms from the right half, and the answer only depends on the relative order; we can precompute for each index i the smallest index j > i with A_j >= 2*A_i (call nxt[i]) via binary search. Then the maximum matching in range [L,R] equals the maximum number of disjoint pairs (i, j) with L <= i < j <= R and j >= nxt[i], which greedy resolves by always taking the smallest valid j — this is equivalent to counting matches where we process i from L upward and maintain a pointer; to answer queries fast we can use the known result that the greedy matching count equals the size of the largest K such that the K-th smallest top candidate matches within range, computable via a persistent/segment-tree structure: process positions as potential bottoms, and for each i with nxt[i] <= R treat i as a top available from position nxt[i]; answering "how many pairs fit in [L,R]" reduces to a 2D offline query solvable with a BIT by sweeping R and matching greedily with a queue of available tops.
