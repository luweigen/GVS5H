The cost for product i is convex (k²·P_i), so the marginal cost of the k-th unit of product i is (2k−1)·P_i, which increases with k. The optimal strategy is to buy units in order of cheapest marginal cost, which is equivalent to: for a candidate total K, each product contributes k_i = floor(sqrt(M/P_i)) capped units... more precisely, to check if K units are achievable within budget M, buy from each product the number of units minimizing cost, i.e., for each product the marginal costs are increasing, so the minimum cost to obtain K total units is sum over products of k_i²·P_i where we greedily take cheapest marginals — equivalently, find threshold T such that we take k_i = max(0, floor((T/P_i + 1)/2)) units... A cleaner approach: binary search on answer K; for the check, compute the minimum cost to buy K units by summing, for each product, units taken via a marginal-cost threshold found by another binary search, or directly: for given K, min cost = sum over i of k_i² P_i where k_i = min(cap_i, ...) — simplest correct method: binary search K, and in check binary search the marginal threshold X such that total units with marginal cost ≤ X is ≥ K, then compute exact cost adjusting for ties.
