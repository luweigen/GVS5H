We need to compute, for each query (x, y), the sum of |A_i - B_j| over the rectangle [1..x]×[1..y]. Sorting A and B lets us use the identity |a-b| = (a-b) when a≥b, so the total over a rectangle can be expressed via prefix sums of sorted arrays and counts of elements below thresholds. Concretely, sum_{i≤x, j≤y} |A_i - B_j| = sum over sorted prefix of A of (a * countB≤a - sumB≤a) + symmetric term for B, which can be computed offline by sweeping a pointer over sorted values. Since queries are on prefixes of the *original* order, we instead precompute prefix answers: define f(x, y) for all needed query pairs by processing queries sorted by x, maintaining a Fenwick/segment structure over B prefix... Simpler: for each query, f(x,y) = gA(x,y) + gB(x,y) where gA sums over i≤x of (A_i * cntB(y, ≤A_i) - sumB(y, ≤A_i)); we can answer by sorting queries and using two Fenwick trees over coordinate-compressed B values, inserting B_j as y grows, and similarly swapping roles. Each query then costs O(log N), giving O((N+K) log N) overall.
