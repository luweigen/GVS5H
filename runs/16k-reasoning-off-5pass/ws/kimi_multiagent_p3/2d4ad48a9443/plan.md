For a fixed subarray, the minimum increments to make it non-decreasing is computed by scanning left to right and raising each element to at least the running maximum; the cost is the sum of these raises. We need to count subarrays whose cost is ≤ k. Since extending a subarray to the right never decreases its cost, for each left index the set of valid right endpoints is a prefix, enabling a sliding-window/two-pointer approach. The challenge is maintaining the cost incrementally as the window's right edge moves and left edge shrinks; this can be done with a monotonic stack that tracks "segments" where the running maximum stays constant, storing each segment's contribution so both expansion and contraction update the total cost in amortized O(1). Overall this yields an O(n) solution.
