We need to simulate N insertions where inserting i at position P_i shifts later elements right; N up to 5e5 rules out O(N^2) list insertion. Process operations in reverse: the final position of value i is determined by starting with pos = P_i and, for each later-inserted value j > i (processed in reverse order), if its final position is ≤ pos, increment pos. This is equivalent to: iterate i from N down to 1, and insert i into an answer list at index P_i - 1 — but that's still O(N^2) with a plain list. Instead, use a Fenwick tree / order-statistics structure: maintain which final slots are occupied; for i from N down to 1, the final index of i is the (P_i)-th empty slot from the left. Find it via binary search on prefix sums of the Fenwick tree (find-by-order), then mark it occupied. Total O(N log N).
