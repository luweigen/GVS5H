We need the k-th lexicographic permutation of [1..n] where adjacent elements alternate in parity. Since n ≤ 100, we cannot enumerate; instead we build the answer position by position using counting. At each step, try the smallest unused number whose parity differs from the previous element, count how many valid completions exist if we fix it, and skip blocks until we land in the block containing k. The count of completions depends only on how many odd and even numbers remain (order within each parity class is free), giving a simple formula: if remaining odds = evens, count = odds! × evens!; if they differ by one, the larger class must occupy the ends appropriately, also giving factorial products; otherwise zero. Factorials up to 100! fit in Python integers, and k ≤ 10^15 lets us early-cap counts to avoid waste.
