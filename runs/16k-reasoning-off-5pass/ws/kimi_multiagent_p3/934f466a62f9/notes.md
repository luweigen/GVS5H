
## ideation
The core difficulty is the max-of-three-sums pair price, which is not linear, so greedy/DP on a single key doesn't directly apply. Key insight: max(P,Q,R) = max over the 8 sign patterns s∈{±1}³ of (±P±Q±R). So define, for each pattern s, weight w_i^s = s_x·X_i + s_y·Y_i + s_z·Z_i. For a fixed pattern, maximizing the sum of weights over K disjoint pairs is solved by sorting weights descending and pairing adjacent among the top 2K (classic exchange argument). The true optimum equals max over the 8 patterns of (the actual total price of that pattern's optimal pairing): upper bound because any pairing's total ≤ sum over pairs of (its dominant pattern weight sum) ≤ max over patterns of (that pattern's best pairing weight sum) — and the greedy pairing's actual price equals its weight sum only if each pair's dominant coordinate matches the pattern... Careful: the safe argument is: for any pairing, total = Σ max(...) ≤ Σ over pairs of max over patterns (w^s_a + w^s_b) ≤ max_s (best pairing weight sum for s). And for each pattern s, the greedy pairing's actual total price ≥ its weight sum? No — actual price of pair = max over patterns of weight sums ≥ w^s_a + w^s_b, so actual total ≥ weight-sum total. Hence actual total of greedy-s pairing ≥ (best weight sum for s) ≥ ... combined gives equality: answer = max_s (actual price of greedy pairing under s). Both directions hold, so evaluating actual prices of the 8 greedy pairings and taking the max is exact.

Pitfalls: (1) Must compute actual pair prices, not weight sums, when evaluating each pattern's pairing. (2) Pairing adjacent after sorting descending is optimal for sum of pair-sums (any pairing of top 2K gives the same weight total actually — sum of all top-2K weights regardless of pairing! Since pair weight = w_a + w_b, total = sum of the 2K weights, independent of pairing). So for a fixed pattern, ANY pairing of the top-2K weight cakes gives the same weight sum, but different actual prices; we need actual price ≥ weight sum, which holds for any pairing. So we can pair adjacent (or arbitrarily) among top 2K and compute actual prices. (3) Ties/selection: must pick exactly 2K distinct cakes with largest weights; sorting descending and taking first 2K works. (4) Complexity: 8 sorts per test case, O(8 N log N), total N ≤ 1e5, fine. (5) Values up to 1e9, sums up to 2e9, totals up to 2e9·K — use 64-bit (Python int fine).

## worker: Implement the complete solution: fast I/O parsing,
- Pair price `max(X_a+X_b, Y_a+Y_b, Z_a+Z_b)` equals `max over the 8 sign patterns s∈{±1}³ of (s·cake_a + s·cake_b)`, since flipping all signs doesn't change the max.
- For a fixed pattern s with weights `w_i = s·cake_i`, any pairing's total weight is just the sum of the chosen cakes' weights, so the best weight-sum is achieved by the top-2K weight cakes (any pairing of them).
- Correctness: for any pairing, each pair's price equals its own dominant pattern's weight sum, so total ≤ max over patterns of (best weight sum for that pattern). Conversely, for each pattern, the actual price of each greedy pair is `max over patterns ≥ w_a+w_b`, so the actual total of the greedy pairing ≥ best weight sum for that pattern. Hence `answer = max over 8 patterns of (actual price of top-2K greedy pairing)`.
- Implementation: for each of 8 patterns, compute weights, sort indices descending, take top 2K, pair adjacent, sum actual prices (max of the three coordinate sums), take max over patterns.
- Complexity: O(8·N log N) per test case; total N ≤ 1e5, well within limits. Python ints handle the magnitude (up to ~2e9 per pair, K up to 5e4).
