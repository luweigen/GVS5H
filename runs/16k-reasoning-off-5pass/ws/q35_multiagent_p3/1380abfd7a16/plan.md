The key insight is to process the operations in reverse order. When we insert the i-th number at position P_i, it shifts all subsequent elements. If we work backwards from N down to 1, we can determine the final position of each number. Specifically, the last inserted number (N) ends up at position P_N in the final array. The second-to-last (N-1) ends up at position P_{N-1} in the array of size N-1, but since N was inserted after it or before it, we need to track positions carefully.

A better approach: Use a Binary Indexed Tree (BIT) or Segment Tree to manage available positions. Initially, all positions 1 to N are "empty". For i from N down to 1, the number i should be placed at the P_i-th available (empty) position. We can use a BIT to efficiently find the k-th empty position and mark it as occupied. This allows us to determine the final position of each number i, then construct the result array.
