The key insight is that each operation reduces two numbers by dividing them by 4 (floor). To minimize operations, we should pair numbers such that they become zero as quickly as possible. For a single number $x$, the number of divisions by 4 needed to reach 0 is $k = \lfloor \log_4(x) \rfloor + 1$ if $x > 0$, but more precisely, it's the smallest $k$ such that $\lfloor x / 4^k \rfloor = 0$. Actually, we can think in terms of "cost" per number: each number $x$ requires a certain number of "half-operations" (since one operation handles two numbers). Specifically, if we define $f(x)$ as the number of times we need to divide $x$ by 4 to get 0, then $f(x) = \lfloor \log_4(x) \rfloor + 1$ for $x \ge 1$, with $f(0)=0$. But note: one operation processes two numbers. So if we have an array, the total number of operations is $\lceil (\sum f(x)) / 2 \rceil$? Not exactly, because we can pair numbers strategically. Actually, the optimal strategy is to always pair the largest remaining numbers. The total number of operations is determined by the sum of the "depths" of all numbers. Let $d(x)$ be the number of divisions needed for $x$ to become 0. Then the total operations is $\lceil (\sum_{x \in nums} d(x)) / 2 \rceil$. We need to compute $\sum_{x=l}^{r} d(x)$ efficiently for each query. Since $r$ can be up to $10^9$, we use digit DP or a mathematical formula to compute the sum of $d(x)$ for $x$ in $[l, r]$. Note that $d(x) = k$ for $x \in [4^{k-1}, 4^k - 1]$ for $k \ge 1$, and $d(0)=0$. So we can precompute powers of 4 and use a function `count_ops(n)` that returns $\sum_{x=1}^{n} d(x)$. Then for each query $[l, r]$, the sum is `count_ops(r) - count_ops(l-1)`, and the answer for the query is $\lceil \text{sum} / 2 \rceil$.
