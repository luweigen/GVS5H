1.  **Understand the Structure**: A Snowflake Tree has a specific hierarchical structure: Center -> `x` Neighbors -> `y` Leaves per Neighbor. The total number of vertices is $1 + x + x \cdot y$. The center has degree $x$. Each intermediate node has degree $y+1$ (1 connection to center, $y$ to leaves). The leaves have degree 1.
2.  **Iterate Over Potential Centers**: Since the center is unique in a Snowflake Tree (unless $x=1, y=1$ where symmetry exists, but the structure is still defined by the center), we can iterate over every vertex in the tree and consider it as the potential center of the Snowflake Tree.
3.  **For Each Center, Determine Optimal `x` and `y`**:
    - If we fix the center `c`, its neighbors in the original tree are candidates for the intermediate nodes. Let the neighbors be $n_1, n_2, \dots, n_k$.
    - For each neighbor $n_i$, if we select it as an intermediate node, we can keep up to $y$ of its children (in the subtree rooted at $n_i$ when `c` is the root) as leaves. The number of leaves we can keep from $n_i$ is $\max(0, \text{degree}(n_i) - 2)$ if we consider the edge to `c` and potential other connections, but more accurately, in the context of the whole tree, if `c` is the center, the "leaves" attached to $n_i$ must be vertices that are only connected to $n_i$ in the final Snowflake Tree.
    - Actually, a simpler view: If we pick center `c` and a subset of its neighbors as intermediate nodes, say $S \subseteq \text{neighbors}(c)$ with $|S|=x$, then for each $n \in S$, we can keep a subset of its other neighbors as leaves. To minimize deletions, we should keep as many vertices as possible.
    - For a fixed center `c` and a fixed set of intermediate neighbors $S$, the number of kept vertices is $1 + |S| + \sum_{n \in S} (\text{number of leaves attached to } n)$. The leaves attached to $n$ are the neighbors of $n$ excluding `c`. However, these "leaves" must not have any other children in the Snowflake structure. This implies that if we keep a neighbor $m$ of $n$ (where $m \neq c$) as a leaf, we cannot keep any of $m$'s other neighbors.
    - Therefore, for each neighbor $n$ of `c`, if we decide to make it an intermediate node, we can gain $1$ (for $n$ itself) plus the number of its neighbors (excluding `c`) that we can keep as leaves. But wait, the definition says "attach y leaves". This implies all intermediate nodes must have exactly the same number of leaves $y$.
    - So, for a fixed center `c`, we look at its neighbors. For each neighbor $n_i$, let $L_i$ be the number of "leaf-capable" vertices attached to it. Specifically, if we treat `c` as root, the subtree at $n_i$ consists of $n_i$ and its descendants. The vertices that can be leaves are the children of $n_i$ that are leaves in the original tree? No, the problem says we delete vertices. We can keep a vertex as a leaf in the Snowflake Tree if it has degree 1 in the Snowflake Tree.
    - Let's re-evaluate: For a fixed center `c`, and a chosen $y$, we can only select intermediate nodes $n$ that have at least $y$ neighbors (other than `c`) that can serve as leaves. A neighbor $m$ of $n$ ($m \neq c$) can be a leaf if we don't select any of $m$'s other neighbors as intermediate nodes. To maximize kept vertices, if we pick $n$ as intermediate, we should pick exactly $y$ of its non-center neighbors as leaves. Which ones? Any ones. But picking a leaf $m$ prevents us from using $m$'s other neighbors. Since $m$ is a leaf, it contributes 1 vertex.
    - Actually, the cost is minimized when we maximize kept vertices. For a fixed center `c` and fixed $y$, each neighbor $n_i$ of `c` can potentially be an intermediate node. If $n_i$ is an intermediate node, it must have at least $y$ available "leaf slots". The number of available leaf slots for $n_i$ is the number of its neighbors excluding `c`. Let $deg(n_i)$ be the degree of $n_i$ in the original tree. The number of neighbors excluding `c` is $deg(n_i) - 1$. If $deg(n_i) - 1 \ge y$, we can use $n_i$ as an intermediate node and keep $y$ of its other neighbors as leaves. The number of vertices kept from this branch is $1 (for n_i) + y (leaves)$. If $deg(n_i) - 1 < y$, we cannot use $n_i$ as an intermediate node for this $y$.
    - So, for a fixed center `c` and fixed $y$, we count how many neighbors $n_i$ satisfy $deg(n_i) - 1 \ge y$. Let this count be $K$. We can choose any $x$ intermediate nodes from these $K$ candidates, where $1 \le x \le K$. The total kept vertices would be $1 + x + x \cdot y = 1 + x(y+1)$. To maximize kept vertices, we should choose the largest possible $x$, which is $K$. So kept = $1 + K(y+1)$.
    - We iterate over all possible centers `c` and all possible $y$ values. The possible values for $y$ are from $0$ to $\max(\text{degree})$. Note: $y$ must be a positive integer? The problem says "positive integers x,y". So $y \ge 1$.
    - The answer is $N - \max_{c, y} (1 + K_c(y) \cdot (y+1))$, where $K_c(y)$ is the number of neighbors of `c` with degree $\ge y+1$.

4.  **Optimization**:
    - Iterating over all $c$ and all $y$ might be slow if not careful. $N$ is up to $3 \times 10^5$.
    - For each center `c`, we have a list of degrees of its neighbors. Let this list be $D_c$.
    - For a fixed $y$, $K_c(y)$ is the count of $d \in D_c$ such that $d - 1 \ge y \iff d \ge y+1$.
    - We can sort $D_c$ and use binary search or prefix sums to quickly calculate $K_c(y)$ for all relevant $y$.
    - The maximum degree is $N$. The number of distinct $y$ values to check for a center `c` is bounded by the number of neighbors or the max degree.
    - Alternatively, iterate over all possible $y$ from $1$ to $N$. For each $y$, iterate over all centers? That's $O(N^2)$.
    - Better: For each vertex `c`, sort its neighbor degrees. Let the sorted degrees be $d_1 \le d_2 \le \dots \le d_k$.
    - For a specific $y$, the number of valid neighbors is the count of $d_i \ge y+1$.
    - We can iterate $y$ from $1$ to $\max(D_c)$.
    - Total complexity: $\sum_{c} \text{deg}(c) \log(\text{deg}(c))$ or similar. Since $\sum \text{deg}(c) = 2(N-1)$, this is efficient.
