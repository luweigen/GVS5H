1. Sort the input array S to easily iterate through elements in increasing order.
2. For each element B in S (which will serve as the middle element of the triplet), we need to count pairs (A, C) such that A and C are also in S, A < B < C, and B - A = C - B (which implies A + C = 2*B).
3. Since N can be up to 10^6, an O(N^2) approach is too slow. However, the values of S_i are also bounded by 10^6. We can use a boolean array (or set) for O(1) lookups to check if a number exists in S.
4. For each B, iterate through possible values of A (where A < B and A is in S). Then C = 2*B - A must also be in S and C > B. Since A < B, C = 2*B - A > B is automatically satisfied if A < B. So we just need to check if C is in S.
5. To optimize, note that for a fixed B, A ranges from min(S) to B-1. But iterating all A for each B is still O(N * max_value) in worst case which might be too slow if not careful. Actually, since we only care about A that are in S, we can iterate over all A in S that are less than B. The total complexity would be sum over B of (number of elements less than B). In the worst case (S is dense), this is O(N^2). Given N=10^6, O(N^2) is 10^12 which is too slow.
6. Better approach: Use the fact that values are bounded by M=10^6. We can use FFT (Fast Fourier Transform) to count pairs. Create a binary array P where P[i]=1 if i is in S, else 0. The number of pairs (A,C) with A+C=K is the coefficient of x^K in P(x)*P(x). We need sum over all B in S of (coefficient of x^(2B) in P(x)^2) but excluding cases where A=B or C=B or A=C. Since elements are distinct, A!=C. Also A!=B and C!=B since A<B<C. So we just need the coefficient of x^(2B) for each B in S. However, this counts all pairs (A,C) with A+C=2B, including A=C=B (if B is in S, which it is) and A=C!=B. But since A<C is required for distinct triplets with A<B<C, and A+C=2B with A<C implies A<B<C. The pair (A,C) and (C,A) are both counted in the convolution. So the coefficient of x^(2B) gives 2 * (number of pairs with A<C and A+C=2B) plus 1 if 2B=2*B and B is in S (i.e., A=C=B). Since we require A<B<C, we exclude A=C=B. So for each B, the number of valid (A,C) with A<C and A+C=2B is (coeff[2B] - (1 if B in S else 0)) / 2. Since B is always in S, it's (coeff[2B] - 1) / 2.
7. Use FFT to compute the convolution of the binary array with itself. The maximum value is 10^6, so 2B can be up to 2*10^6. We need FFT size at least 2^21 (2*10^6 < 2^21=2097152). This is feasible.
