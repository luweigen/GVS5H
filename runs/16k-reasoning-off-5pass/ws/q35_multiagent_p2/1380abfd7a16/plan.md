The key insight is to reverse the process: instead of simulating insertions from 1 to N (which would be O(N^2) due to array shifts), we determine the final position of each number by working backwards from N to 1. At step i (going backwards), we know that number i was inserted at position P_i in an array of size i. This means that in the final array of size N, the number i occupies the P_i-th "available" (not yet assigned) position. We can use a Fenwick tree (Binary Indexed Tree) or a Segment Tree to efficiently find the k-th available position and mark it as occupied. Specifically, we initialize a BIT with 1s at all positions 1 to N. For i from N down to 1, we find the P_i-th position that still has a 1 in the BIT (using binary lifting on the BIT), assign A[pos] = i, and update the BIT at pos to 0. This approach runs in O(N log N).
