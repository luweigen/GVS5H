This is a classic partition DP problem. Let dp[i] be the minimum cost to partition the first i elements. The transition involves considering the last subarray nums[j..i-1]. The cost of a subarray depends on the total sum of nums up to its end, plus k times the subarray index, multiplied by the sum of cost in the subarray. Since the subarray index equals the number of subarrays used so far plus one, we can incorporate the k * index term by noting that each subarray contributes k * (sum of cost in that subarray) * (its index). This suggests a DP where we track both the partition cost and the accumulated k-weighted cost sums, or use the standard trick: dp[i] = min over j of dp[j] + (prefixNums[i] + k * segments) * (prefixCost[i] - prefixCost[j]), where segments is the number of subarrays in the optimal dp[j] solution. Because the segment count matters, we track dp[i] as a pair (minCost, and we need the segment count) — but since k * index * costSum is additive, we can define dp[i] = min total cost for first i elements, and transition dp[i] = min over j of dp[j] + prefixNums[i] * (prefixCost[i] - prefixCost[j]) + k * (prefixCost[i] - prefixCost[j]) * (seg[j] + 1). To handle seg, we store for each i the pair (cost, segments) choosing lexicographically minimal cost, and among ties fewer segments. With n ≤ 1000, O(n²) DP is acceptable.
