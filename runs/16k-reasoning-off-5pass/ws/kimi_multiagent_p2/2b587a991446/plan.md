Model the problem as a shortest-path search on the "configuration graph" whose vertices are ordered pairs (a, b) with a != b, where a is A's position and b is B's position; edges correspond to moving one piece to an adjacent vertex without colliding. The state space is N*(N-1) which is too large for full BFS, so we need structure: the answer relates to distances d(S,T) and whether the graph allows the pieces to "pass" each other. Key insight: if the graph has a cycle (M >= N, i.e., not a tree) or more precisely if there's enough room (a vertex of degree >= 3 or the graph isn't a path-like obstruction), the pieces can swap; on a tree, swapping is possible iff there's a branching point on/accessible from the S-T path. The intended solution: BFS from S and T to get distances; the minimum moves equal 2*d(S,T) + something, or analyze via the "15-puzzle"-style token swapping on graphs — two labeled tokens swapping is possible iff graph is not a path with S,T at ends blocking... Actually simplest robust approach: BFS on product graph is too big, but we can prove answer = 2*dist(S,T) - 1 or + adjustments based on parity/cycles.
