Each operation divides two numbers by 4 (floor), so a number x needs ceil(log4(x+1)) "hits" to become zero — equivalently, x requires k operations where k is the number of times you can divide by 4 before reaching 0 (x in [4^(k-1), 4^k - 1] needs k hits). Since each operation handles exactly two elements, the minimum operations for one query equals ceil(total_hits / 2), where total_hits is the sum over all numbers in [l, r] of their required hits. We can compute total_hits quickly by grouping numbers into ranges [4^(k-1), 4^k - 1] and counting how many fall in each band within [l, r]. With at most ~16 bands (since r ≤ 1e9 < 4^15), each query is O(log r). Sum results over all queries.
