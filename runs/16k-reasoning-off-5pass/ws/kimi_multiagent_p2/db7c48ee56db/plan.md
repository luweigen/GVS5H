The key observation is that C(N,K) ≤ 10^6, which means either K is small (≤ ~20) or K is very close to N (since C(N,K) = C(N,N-K)). If K > N/2, we can use the complement trick: XOR of K chosen elements = (XOR of all elements) ⊕ (XOR of the N-K not chosen), reducing to choosing N-K elements. After this reduction, K ≤ ~20 and C(N,K) ≤ 10^6 allows a meet-in-the-middle approach: split K into K1 = K/2 and K2 = K-K1, enumerate all C(N,K1) and C(N,K2) partial XORs via recursion/combinations, then for each left XOR find the right XOR maximizing their XOR using a binary trie. Total complexity is roughly O(C(N,K1) * 60 + C(N,K2) * 60) which fits easily.
