The core difficulty is that N can be up to 2×10^5 and A_i up to 2^60, so brute force over all C(N,K) subsets is impossible in general — but the constraint C(N,K) ≤ 10^6 is the key. This forces K to be either small (≤ ~20) or very close to N. If K > N/2, use the complement trick: XOR of K chosen = (total XOR of all) ⊕ (XOR of the N-K unchosen), reducing to choosing K' = N-K ≤ N/2 elements. After this, C(N,K) ≤ 10^6 with K small.

Candidate approach: meet-in-the-middle. Split K into K1 = K//2 and K2 = K - K1. Enumerate all C(N,K1) left XORs and C(N,K2) right XORs via itertools.combinations (each count ≤ C(N,K) ≤ 10^6, actually much less). Build a binary trie (60 bits) of right XORs; for each left XOR, greedily query the trie for the value maximizing XOR. Complexity O((C(N,K1) + C(N,K2)) × 60), fine.

- **Reduction**: If K > N/2, XOR of the K chosen elements equals (XOR of all elements T) ⊕ (XOR of the N−K unchosen). Since choosing K from N bijects with choosing N−K from N, the problem reduces to K′ = min(K, N−K) with a constant T folded in. Constraint C(N,K) ≤ 10⁶ with K′ ≤ N/2 forces K′ ≤ 11 (since C(2K′,K′) ≤ 10⁶).
- **Meet-in-the-middle by index split**: Split the array into left/right halves at mid. For each j (number of picks from the left), enumerate XORs of j-combinations of the left and (K′−j)-combinations of the right. Crucially, the cross product size |LA|·|RB| = C(mid,j)·C(n−mid,K′−j) ≤ C(N,K′) ≤ 10⁶, and summing over all j gives exactly C(N,K′) ≤ 10⁶ pair evaluations — so brute-forcing all cross pairs is guaranteed cheap; no trie needed.
- **Folding T**: (T ⊕ a) ⊕ b = T ⊕ (a ⊕ b), so precomputing ta = T ^ a per left value is correct; when no complement is used, T = 0 (no-op).
- **Edge cases**: K′ = 0 (K = N) → answer is just T. K = 1 works naturally (one side is the empty combination with XOR 0). N = 1, K = 1 verified.
- **Correctness**: Every K′-subset has exactly j elements in the left half for some j in [j_lo, j_hi], and is counted exactly once as a pair (left part, right part); we take the max of T ⊕ (subset XOR) over all of them, which by the complement bijection equals the answer.
- **Complexity**: Enumeration O(K′·C(N,K′)) C-level XORs (≤ ~1.1×10⁷) plus exactly C(N,K′) ≤ 10⁶ Python-level pair ops → well under time limits. Memory O(C(mid, K′)) small.
