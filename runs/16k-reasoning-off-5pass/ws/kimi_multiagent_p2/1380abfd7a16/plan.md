We need to simulate N insertions where inserting i at position P_i shifts later elements right. A naive list insert is O(N) per operation, too slow for N=5e5. Instead, process insertions in reverse: after all operations, the final position of value i can be determined by starting with position P_i and, for each later value j>i, if its insertion position P_j <= current position, increment the current position. Equivalently, use a Fenwick tree over final slots: process i from N down to 1, find the P_i-th currently-empty slot (order-statistics on a BIT of available positions), and place i there. This gives O(N log N) total. Implement BIT with find_kth via binary lifting.
