Model the process as a shortest path problem on the hypercube of states: each state is a bitmask of length N, each flip of bit i is an edge from state x to x XOR (1<<i) with cost equal to the weighted sum (by C) of the new state. This graph is a weighted hypercube where edge costs decompose per-coordinate, so Dijkstra from the initial state A to target B over 2^N states is infeasible for N=2e5 — instead exploit structure: the cost of flipping bit i depends only on the current weighted sum S = sum of A_k*C_k, and flipping i changes S by +C_i (0->1) or -C_i (1->0). Key insight: since costs are always positive and depend only on total S, an optimal sequence flips each index at most once (flipping twice is wasteful — prove via exchange argument), reducing the problem to choosing an order of the set D of differing indices. The total cost then equals sum over flipped i of (S_initial + contributions of previously flipped bits), and minimizing this ordering cost becomes: process 0->1 flips and 1->0 flips in an order minimizing sum of prefix sums — solvable greedily by sorting (ascending C for additions, descending C for removals, with removals first when beneficial).
