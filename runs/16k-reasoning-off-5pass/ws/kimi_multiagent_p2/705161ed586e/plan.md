Model the problem as a shortest-path/DP over positions: the final string must be partitionable into blocks of identical characters, each block of length ≥3, and the cost of turning a segment into character c is the sum of |caption[i]-c| over the segment. Since each block has length ≥3, we can do DP where dp[i] = best result for prefix of length i, transitioning from dp[j] with j ≤ i-3, choosing the best character c for segment [j, i). To get lexicographically smallest among minimum-cost answers, store (cost, string) tuples and compare lexicographically, or store parent pointers with tie-breaking. A key optimization: for a fixed segment, the cost as a function of target char c is convex (sum of absolute deviations), minimized at the median character; but we need min over all 26 chars, which is O(26) per segment — too slow if done naively over all O(n²) segments. Use the structure: only need dp transitions from i-3, i-4, i-5 (since any block of length ≥6 can be split into blocks of 3,4,5 — actually lengths 3,4,5 suffice because any length ≥3 except... 3,4,5,6=3+3,7=3+4,8=3+5 or 4+4, etc. — every length ≥3 except... 3,4,5 cover all via combinations, and splitting never increases cost? Splitting is always allowed since each piece is independently optimized, so dp over blocks of length exactly 3,4,5 suffices). Then each transition evaluates 26 chars over a segment of length ≤5 using prefix sums of counts per letter, giving O(n·26·5) time. Tie-break by storing the resulting string or by careful parent tracking with lexicographic comparison.
