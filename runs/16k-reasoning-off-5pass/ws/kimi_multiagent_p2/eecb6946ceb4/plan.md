A fine triplet is a 3-term arithmetic progression: for each middle element B, count pairs (A, C) in S with A = B-d, C = B+d. Since values are bounded by 1e6, use a boolean presence array over the value range and, for each B in S, sum over d while both B-d and B+d stay in range. Worst case this is O(N * V) which is too slow if done naively for all B, but the total work sum over B of min(B-1, V-B) can reach ~N*V/2 in the worst case (e.g., all values 1..1e6 present gives ~2.5e11), so we need a faster method. Use convolution (FFT/NTT): the number of triplets equals sum over B of (f * f)[2B] where f is the indicator array, counting ordered pairs (A,C) with A+C=2B; subtract the A=C=B self-pair contributions. Compute convolution of the indicator array with itself via FFT (numpy) or NTT, then answer = sum_{B in S} (conv[2B] - 1) // 2, since each unordered pair {A,C} with A≠C appears twice and the (B,B) pair contributes 1.
