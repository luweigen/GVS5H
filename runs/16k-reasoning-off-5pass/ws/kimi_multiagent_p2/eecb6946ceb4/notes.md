
## ideation
Core difficulty: counting 3-term arithmetic progressions in a set of up to 1e6 distinct values in [1, 1e6]. Naive per-middle iteration over d is O(N*V) worst case (~2.5e11 for a full range), so we need convolution. With indicator array f over values 0..V, conv = f*f gives, for each B, conv[2B] = number of ordered pairs (A,C) in S with A+C=2B. This includes the pair (B,B) exactly once when B∈S. Each valid unordered pair {A,C}, A≠C, appears twice (as (A,C) and (C,A)). So answer = sum_{B∈S} (conv[2B] - 1) // 2. Pitfalls: (1) FFT floating-point precision — values up to 1e6, convolution entries up to 1e6, length ~2^21; double FFT rounding is typically fine for coefficients up to ~1e6 with rounding, but safer to use NTT or split-FFT; numpy's FFT with rounding to nearest int is generally reliable here since coefficients ≤ 1e6 << 2^53 and error grows like O(eps * n * maxcoef) ~ 1e-16 * 2e6 * 1e6 ≈ 2e-4, acceptable. (2) Must subtract the self-pair (B,B) before halving. (3) Indices: 2B can be up to 2e6, convolution length must cover 2*V. (4) Memory/time: numpy FFT of size 2^21 is fine. Alternative without numpy: implement iterative NTT with a suitable modulus (e.g., 998244353) — coefficients up to 1e6 fit within modulus, no overflow issue since max coefficient value is N ≤ 1e6 < mod. Pure-Python NTT of size 2^21 might be slow (~2e7 butterfly ops in Python ≈ too slow). Better to rely on numpy FFT, or PyPy-friendly approach. Given typical AtCoder-style environment (this looks like an AtCoder problem), numpy may be available; but to be safe, a pure-Python NTT in PyPy could be borderline. Another angle: since coefficients ≤ 1e6, we could use FFT with rounding. I'll go with numpy FFT, with a fallback pure-python NTT if numpy is unavailable — but fallback would be slow; still include it for correctness. Actually simpler: just use numpy; most judges for this problem (typical "fine triplet" tasks) allow numpy. I'll write numpy-based solution with careful rounding: conv = np.rint(np.fft.irfft(fft(f, n)**2, n)).astype(int). Use rfft/irfft for speed.
