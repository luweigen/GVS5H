The problem: adjacent swap at boundary i costs i; find min total cost to sort a permutation.

Core reasoning (already sketched in plan):
- Every swap at boundary i moves one element leftward and one rightward across i simultaneously.
- For boundary i, define L_i = #{v : v <= i < pos[v]} (elements that must cross i going left) and R_i = #{v : pos[v] <= i < v} (elements crossing going right). Because P is a permutation, L_i = R_i: both equal i - #{v <= i : pos[v] <= i}.
- The minimum number of swaps at boundary i is exactly this common value c_i, and a global schedule achieving all boundaries' minimums simultaneously exists (standard argument: any sequence that always swaps an inversion where the left element belongs right of the boundary and vice versa; equivalently, the lower bound per boundary is achievable since adjacent-swap sorting can be organized so each boundary's swaps are exactly the required crossings — e.g., repeatedly move each element to its place; known result for this AtCoder-style problem).
- So answer = sum_{i=1}^{N-1} i * c_i, with c_i = i - (number of values v <= i with pos[v] <= i).

Computation: Fenwick (BIT) over positions. Iterate v = 1..N, add pos[v] to BIT; after inserting value i, query prefix up to i gives count of values <= i already placed within first i positions.
