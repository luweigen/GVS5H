Model the process as moving each value v from its initial position pos[v] to its target position v using adjacent swaps, where swapping across boundary i costs i. Each boundary i must be crossed by exactly the elements that start on one side and end on the other; the number of crossings of boundary i is fixed: c_i = |{v : (pos[v] - i) * (v - i) < 0}|, i.e., elements with pos[v] <= i < v or v <= i < pos[v]. The key insight: crossings of a boundary can be "shared" — a swap at boundary i simultaneously moves one element leftward and one rightward, so the number of swaps at boundary i equals max(L_i, R_i) where L_i = #{v : v <= i < pos[v]} (elements needing to move left across i) and R_i = #{v : pos[v] <= i < v} (elements moving right across i). Since the permutation is a bijection, L_i = R_i always (both equal #{v <= i} - #{v <= i with pos[v] <= i}), so swaps at i = that common count. Answer = sum over i of i * c_i where c_i = (# of values <= i) - (# of values <= i positioned in first i slots). Compute with a Fenwick tree over positions: iterate values v = 1..N, marking pos[v]; for each boundary i, count of values <= i placed within first i positions is prefix query. Total per boundary i: c_i = i - query(i)... but careful: # values <= i is exactly i, so c_i = i - bit.query(i). Sum i * c_i for i = 1..N-1. This is O(N log N).
