The bad intervals are sorted and disjoint, so the free squares form at most M+1 gaps. Within a gap, reachability with steps in [A, B] is a classic sliding-window DP: position x is reachable iff some reachable position exists in [x-B, x-A]. Since B ≤ 20, we can carry a small bitmask of the last B reachability states and process positions in bulk. For each free gap, we only need to simulate until either the gap ends or a run of B consecutive unreachable positions occurs (after which nothing further is reachable, since any future position needs a reachable cell within the last B). We also must handle the transition across bad intervals: when resuming after a bad segment, the sliding window naturally carries over if we treat bad cells as unreachable and continue the bitmask update position by position — but bad segments can be huge, so we instead note that after B or more consecutive unreachable cells the window becomes all-zero, and we can reset. Process each gap with fast-forwarding: simulate step by step but a gap could be length up to 1e12; however once a streak of B consecutive reachable positions occurs, all subsequent positions in the gap are reachable (since step A ≤ B always lands within the last B reachable streak... need care: with a streak of B reachable cells, x+A has x+A-B..x+A-A covering the streak end, so reachable). So per gap we simulate at most ~2B steps after the first reachable cell appears, plus we need the first reachable cell: scan from gap start using the carried window, which is all-zero if the preceding bad segment had length ≥ B, else we simulate through the short bad segment. Total work is O(M·B).
