For a fixed prefix R, the answer as a function of X is the LIS length of the prefix restricted to values ≤ X; this is a classic "LIS ending value" structure: define f_R(v) = length of longest increasing subsequence of prefix R whose last element equals v (only for v present). The answer for query (R, X) is max over values v ≤ X of f_R(v), i.e., a prefix maximum over the value axis. We process queries offline sorted by R, sweeping a pointer over the array and maintaining a data structure over compressed values that supports: point update at position A_i with the LIS length ending at A_i (computed as 1 + query over values < A_i), and prefix-max queries over values ≤ X. A Fenwick tree (BIT) for range-max with point updates handles both operations in O(log N). Sorting queries by R and answering each with one BIT prefix-max query gives O((N+Q) log N) total.
