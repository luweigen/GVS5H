
## ideation
The core difficulty is efficiently counting distinct houses lying on up to 2e5 axis-aligned segments among 2e5 houses. A naive per-segment scan is O(NM), too slow. Since every move is horizontal or vertical, a house is hit exactly when its fixed coordinate matches the segment's fixed coordinate and its other coordinate lies within the segment's inclusive range. This reduces to orthogonal range counting on lines: group houses by y (for horizontal moves) and by x (for vertical moves), keep sorted coordinate lists, and for each move binary-search the relevant list to enumerate all houses in the interval. Because a house can be passed multiple times (e.g., at intersections or repeated traversals), we must deduplicate globally with a visited set of house indices. Pitfalls: inclusive endpoints (houses at the start point of a segment count as "arrived at" — note the start has no house initially, but later segment starts may coincide with houses and must be counted); ranges must be normalized (min/max) since moves can go in negative directions; Python ints avoid overflow, but the final position can reach 3e9+ in magnitude; using bisect with lo/hi bounds lets us enumerate only the matched houses rather than scanning whole lists, keeping total cost O((N + total hits) log N), and total hits bounded by N plus repeats which are cheap since each enumeration is over actual matches.

## worker: Write the complete Python solution: parse input, b
- **Parsing**: Read all tokens at once for speed; directions are bytes, decoded per move.
- **Data structures**: `by_x` maps each house x-coordinate to a sorted list of `(y, index)` pairs; `by_y` maps each y-coordinate to sorted `(x, index)` pairs. Sorting enables binary search.
- **Simulation**: For each move, compute the endpoint, normalize the covered interval (min/max handled by direction), then use `bisect_left`/`bisect_right` on the appropriate group's sorted list to find all houses whose varying coordinate lies in the inclusive range `[start, end]`. Each matched house index is added to a global `visited` set for deduplication.
- **Correctness of bounds**: Using tuple comparisons `(coord, -1)` and `(coord, N)` ensures the full inclusive range of coordinates is captured regardless of duplicate coordinates (houses are distinct but share x or y freely).
- **Complexity**: Sorting is O(N log N). Each move costs O(log N + k) where k is the number of houses on that segment. Total work is O((N + M) log N + total matches), well within limits. Python integers handle positions up to ~3×10⁹ (and beyond) without overflow.
- **Edge cases handled**: houses at segment endpoints (inclusive ranges), repeated visits (set dedup), no house at the start (guaranteed, but the algorithm would count it anyway if it were passed later), missing coordinate groups (`dict.get` returns None).
