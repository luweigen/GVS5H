The key insight: after deleting all occurrences of value x, the array splits into segments separated by positions where nums[i] == x. The max subarray sum of the resulting array is the max over segments of the max subarray sum within that segment (Kadane's). For each distinct value x, we need the maximum segment-wise Kadane sum over segments delimited by x. Doing this naively per distinct value is O(n·k); instead, for each value x, we can compute the answer in O(occurrences of x + segments) time, and since segments for x relate to occurrences, total work across all distinct x is O(n) if we process positions grouped by value. Concretely: for value x with occurrence positions p1<p2<...<pk, the segments are [0..p1-1], [p1+1..p2-1], ..., [pk+1..n-1]; we need max subarray sum within each segment, which can be computed with prefix sums: max subarray sum in segment [l..r] = max over j in [l..r] of (prefix[j+1] - min prefix[i] for i in [l..j]). Precompute prefix minima structures to answer segment max-subarray queries in O(1) each via sparse tables / RMQ, giving O((n + total segments) log n) or O(n) with careful preprocessing. Also consider not deleting (answer for original array via Kadane). Edge case: x cannot be deleted if it removes everything (x is the only distinct value).
