The problem requires finding the maximum GCD of a subset of size K that includes a specific element $A_i$ for each $i$. Since $N$ and $A_i$ are up to $1.2 \times 10^6$ and $10^6$ respectively, an $O(N^2)$ or $O(N \sqrt{\max A})$ per query solution is too slow. Instead, we can precompute the frequency of each number and then for each possible GCD value $g$, count how many multiples of $g$ exist in the array. For each $A_i$, the answer is the largest $g$ such that $A_i$ is a multiple of $g$ and the count of multiples of $g$ in the array is at least $K$. We can iterate $g$ from $\max(A)$ down to 1, calculate the count of its multiples, and if the count $\ge K$, mark all multiples of $g$ as having answer $g$. To optimize, we only need to check $g$ that are divisors of $A_i$, but iterating $g$ downwards and updating all multiples is efficient enough if done carefully (similar to a sieve). Specifically, we can compute `cnt[g]` for all $g$, then iterate $g$ from max down to 1; if `cnt[g] >= K`, we update the answer for all multiples of $g$ that haven't been set yet.
