The problem asks for the minimum number of edit operations (insert, delete, replace) to transform string S into string T, which is the classic Levenshtein distance. Since K is very small (≤ 20) but string lengths are large (up to 500,000), a standard O(N*M) dynamic programming approach will time out. We must use the "Small K" optimization: instead of computing the full DP table, we only compute the band of cells where the edit distance is at most K. This reduces the complexity to O((N+M)*K). We will implement this band-limited DP to check if the final distance is ≤ K.
