We need to count numbers in [l, r] where `product of digits % sum of digits == 0`. Since r < 10^9 (max 9 digits), a DFS over digit positions with state tracking the current sum and product is feasible, but product can overflow — we only care about whether product is divisible by sum, and digits are 0–9. Key observation: if the number contains a zero digit, the product of digits is 0, which is divisible by any sum (sum > 0), so any number with a zero digit is automatically beautiful. That drastically reduces the search space and the product overflow concern.

We'll implement a digit-DP that counts beautiful numbers ≤ X, then answer is `f(r) - f(l-1)`. The DP tracks position, tight flag, leading-zero flag, current sum, and whether a zero digit has appeared (which forces a "beautiful" outcome regardless of sum). Since the condition only needs to be evaluated at full length, we can prune: if a zero has appeared, we just need to count all completions without further constraint on product/sum. We'll memoize on (pos, tight, started, sum_mod? no — sum, has_zero) with sum up to 9*9=81, manageable.

To handle the divisibility check efficiently: we keep the actual product (it stays small because once it's large we can cap it) and actual sum, then at the leaf check `sum != 0 and product % sum == 0`. Capping product at sum (or a safe max) helps, but since we also have the zero-digit shortcut, product is bounded when no zero appears and all digits are nonzero (max 9^9 ≈ 387M, fits in 64-bit).
