We need to minimize the length of the longest run of identical characters after at most `numOps` flips. The key observation: we only care about the maximum run length `L`. We can binary search on the answer `L` (1..n) and check feasibility: can we make all runs ≤ L using ≤ numOps flips? To check feasibility efficiently, treat runs of alternating characters. For a run of 0s of length `a` and adjacent run of 1s of length `b`, we need to break each into pieces of length ≤ L by flipping some characters inside them. The minimum flips needed in a run of length `a` to ensure no sub-run exceeds L is `ceil(a / L) - 1`. This holds because we can place at most L same chars consecutively before needing to flip one to break the run. So total flips needed = sum over all runs of `ceil(len / L) - 1`. If this sum ≤ numOps, L is achievable. Binary search yields the minimum L.
