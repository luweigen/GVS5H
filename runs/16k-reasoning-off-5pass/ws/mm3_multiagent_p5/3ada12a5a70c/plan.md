We need to maximize the minimum Manhattan distance among any k selected points that lie on the boundary of an axis-aligned square. Because Manhattan distance is not rotationally invariant, but the boundary points are constrained to the four edges of a square, we can exploit the "city block" structure: along each edge, Manhattan distance reduces to absolute difference in the coordinate that runs along the edge (since the other coordinate is either 0 or side and is constant on that edge). However, points from different edges have Manhattan distance that includes both coordinate differences.

A practical approach for the given constraints (k ≤ 25, points ≤ 15,000, side ≤ 1e9) is to binary search the answer D and check if we can select k points with pairwise Manhattan distance at least D. The check is a maximum independent set in a conflict graph (vertices = points, edge = Manhattan distance < D). This is a classic NP-hard problem, but with k ≤ 25 the graph is small enough to solve with a branch-and-bound / backtracking with pruning, similar to maximum clique on the complement. This is feasible because we only need to find any independent set of size k, not necessarily the maximum.

We'll build an adjacency bitmask: for each point i, compute `conflict[i]` as a bitmask of points that are within distance < D (i.e., cannot be simultaneously chosen). Then perform recursive backtracking trying to add points while maintaining that we can still reach size k. Use ordering by degree (fewer conflicts first) for pruning, and early termination when remaining candidates are insufficient.
