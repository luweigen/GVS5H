We need to determine if S can be transformed to T using at most K edit operations (insert, delete, replace), where K ≤ 20 and |S|,|T| ≤ 500,000. The classic edit distance algorithm is O(|S|·|T|) which is too large. However, K is small, so we can use a BFS/DP over edit distance states, exploring only states within distance K. Specifically, we can use bidirectional BFS on the edit graph (Levenshtein automaton) using A* with heuristic = |remaining length difference| + mismatch count (hamming-like), or simpler: Dijkstra limited to distance K. Since K ≤ 20, even Dijkstra exploring nodes up to distance K is feasible: each node is a pair (i,j) with i in [0,|S|], j in [0,|T|], and we only visit nodes whose distance from start ≤ K. The branching factor is 3, so worst-case nodes ~3^K, which is fine for K=20. We'll use a priority queue, pop nodes with smallest distance, and stop early if we reach (|S|,|T|) with distance ≤ K, or if minimum possible remaining cost > K.
