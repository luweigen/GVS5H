The operation divides two numbers by 4 (floor). The key insight is that each number's "depth" — the number of times it must be divided by 4 to reach 0 — determines its contribution. An element `x` needs `ceil(log4(x+1))` operations on its own, but pairing allows two numbers to be reduced in a single step. The optimal strategy pairs numbers so the total operations equals `ceil(sum_of_depths / 2)`, since each operation reduces the combined depth by 2. So for each query `[l, r]`, we need to compute `S(r) - S(l-1)`, where `S(n)` is the total depth sum of all integers from 1 to n. The answer per query is `ceil((S(r) - S(l-1)) / 2)`.

The core work is computing `S(n)` efficiently. Numbers in `[4^k, 4^{k+1}-1]` have depth `k+1`. We can find the largest power of 4 ≤ n, compute prefix sums analytically in O(log n) per query.
