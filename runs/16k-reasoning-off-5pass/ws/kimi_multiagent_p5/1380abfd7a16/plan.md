We need to simulate N insertions where each new element i is placed at position P_i. A naive list insertion costs O(N) per operation, leading to O(N²) which is too slow for N=5×10⁵. Instead, process the operations in reverse: start from the final array and remove elements N down to 1. When processing i in reverse, we know it was inserted at position P_i among the first i elements, so in the current array (which contains exactly elements 1..i), element i is at index P_i-1. We need a data structure that supports "remove and return the element at index k" efficiently. A Fenwick tree (BIT) over positions 1..N can track which positions are still occupied and find the element at a given rank via binary lifting in O(log N). Alternatively, use a balanced structure; BIT with order-statistics is simplest and fast enough in Python with pypy-style optimization.
