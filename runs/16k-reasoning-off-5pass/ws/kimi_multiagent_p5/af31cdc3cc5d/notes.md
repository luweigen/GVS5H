
## ideation
The operation of repeatedly removing adjacent pairs is exactly equivalent to choosing a **non-crossing perfect matching** on the line: pairs (i,j) matched such that no two pairs interleave (i<k<j<l forbidden). Total score = sum of |A_i - A_j| over matched pairs. If N is odd, one element is left unmatched (length "at most 1").

Core difficulty: the naive interval DP `dp[l][r] = max(dp[l+1][r-1] + |A[l]-A[r]|, max_k dp[l][k]+dp[k+1][r])` is O(N²) (or O(N³)), far too slow for N=3×10⁵. We need an O(N log N) or O(N) structural insight.

Key structural question: can the non-crossing constraint be dropped? For plain sum of |a−b|, the unconstrained optimum pairs sorted extremes (largest with smallest, etc.), giving `sum(top half) − sum(bottom half)`. That pairing is *crossing*, not directly feasible. However, there is a known result (this is AtCoder-style, e.g., ABC/ARC problem "max sum of |differences| with adjacent removal") that the answer equals `sum of largest ⌊N/2⌋ values − sum of smallest ⌊N/2⌋ values`... but wait — Sample 1: A=(1,2,5,3), sorted (1,2,3,5), top half sum=8, bottom half=3, difference=5. Matches sample output 5. Sample 2: A=(3,1,4,1,5,9,2), N=7, floor=3 pairs, sorted (1,1,2,3,4,5,9): top 3 sum=18, bottom 3 sum=4, diff=14. Matches! Sample 3: all ones → 0. Matches.

So the conjectured formula: **answer = sum of the ⌊N/2⌋ largest elements − sum of the ⌊N/2⌋ smallest elements**. Need to double check the non-crossing feasibility: is the unconstrained max always achievable by a non-crossing matching? Exchange argument: given any two crossing pairs (i,j),(k,l) with i<k<j<l, we can re-pair as (i,l),(k,j) — nested — without decreasing total? |A_i−A_l| + |A_k−A_j| vs |A_i−A_j|+|A_k−A_l|: not always ≥. Hmm, the standard rearrangement says crossing → uncrossing preserves or improves for *convex* costs... Actually for |·| on a line, uncrossing (i,l),(k,j) gives |A_i−A_l|+|A_k−A_j| ≥? Not in general. But the known result for this exact problem (it's a known AtCoder problem, "HHKB2020"? or "code festival"?) — the formula sum(top half) − sum(bottom half) is indeed the claimed answer and matches all three samples. The justification: upper bound via each pair contributing at most... each matched pair |a−b| can be written as integral over thresholds t of [a≤t<b], so total = ∫ (number of pairs crossing threshold t) dt. For any threshold t, pairs crossing t form a non-crossing matching across a cut... the number of pairs crossing threshold t is at most min(count of elements ≤ t, count of elements > t) — actually at most min(#≤t, #>t) but also non-crossing constraint might lower it; regardless, integrating min(#≤t,#>t) over t gives exactly sum(top half) − sum(bottom half). And achievability: greedy stack-based pairing achieves it (pair elements to saturate every threshold). This is the classic "integral / layer-cake" argument, and it is known the bound is tight for non-crossing matchings on a line (can be shown by induction: there always exists an adjacent pair whose removal is consistent with the optimal layered structure... e.g., find adjacent i,i+1 with A_i ≤ t < A_{i+1} for the "median threshold" appropriately).

Alternative if formula were wrong: O(N²) DP with divide-and-conquer optimization — but the cost doesn't obviously satisfy quadrangle inequality, so that's risky. The threshold-integral argument gives both upper bound and (with a constructive greedy) lower bound, so I'm fairly confident.

Let me sanity-check the upper bound argument once more: For any threshold t, define cut between values ≤ t and > t. Each matched pair contributes 1 to the integral over t in [min,max) of the pair. Total score = ∫₀^∞ (pairs with one endpoint ≤ t and other > t) dt. For fixed t, let L = set of indices with A_i ≤ t, R = rest. Any pair crossing the cut has one endpoint in each. Number of crossing pairs ≤ min(|L|,|R|) trivially, and also ≤ ⌊N/2⌋. ∫ min(|L(t)|,|R(t)|) dt = sum over elements of distance from the median region = sum of top ⌊N/2⌋ − sum of bottom ⌊N/2⌋ (standard identity). So upper bound holds regardless of non-crossing. Achievability with non-crossing matching: known/greedy — e.g., process with a stack pairing "low-high" adjacent in a transformed sense.
