
## ideation
Core difficulty: N up to 1.2e6 and A_i up to 1e6, so per-element divisor enumeration must be cheap and the global counting must be near-linear-ish (sieve). Key insight: answer for index i = max divisor d of A_i such that cnt[d] >= K, where cnt[d] = number of elements divisible by d. Since A_i itself is divisible by d, choosing A_i plus any K-1 other multiples of d works iff cnt[d] >= K. So the problem reduces to: (1) compute cnt[d] for all d up to M=max(A) via divisor sieve: for d in 1..M, for multiple m, cnt[d] += freq[m] — that's M*(1/1+1/2+...) ≈ M log M ≈ 1.4e7 ops, fine in PyPy if written with tight loops (or use numpy vectorization). (2) For each element, find the largest divisor d of A_i with cnt[d] >= K. Enumerating divisors per element via sqrt loop is O(N sqrt(M)) ≈ 1.2e9 — too slow. Better: precompute best[v] for each value v present (at most 1e6 distinct) by enumerating divisors of v — still up to ~240 divisors each worst case, but number of distinct values ≤ 1e6 and divisor enumeration via SPF factorization is fast; worst-case sum of divisor counts over all values 1..1e6 is about 1e6 * ~100 average? Actually sum_{v<=M} d(v) ≈ M log M ≈ 1.4e7 — so enumerating divisors for every value v from 1..M via SPF factorization costs ~M log M total, acceptable. Even simpler: only enumerate divisors for distinct values present in A (≤ min(N, M)). Alternative cleaner approach: compute good[d] = (cnt[d] >= K), then best[v] = max divisor d of v with good[d]; can compute via reverse sieve: for d from M down to 1, if good[d], then for each multiple m of d, if best[m] unset, best[m] = d. Total work sum over good d of M/d; worst case all good → M log M again ≈ 1.4e7. Then each query is O(1): answer = best[A_i]. This avoids per-element divisor enumeration entirely. Pitfalls: (a) Python speed — need fast I/O (sys.stdin.buffer.read), tight loops, possibly numpy for the cnt sieve (numpy slicing: cnt[d-1::d] += freq[d-1::d] style) to hit time limits; typical AtCoder problem (this looks like ABC/AGC style) with 2s limit — pure Python sieve loops of 1.4e7 may be borderline but okay in PyPy (~2-4s); numpy is much faster. (b) The reverse-sieve "best" fill also costs up to M log M; combined ~3e7 primitive ops — numpy helps a lot. (c) Edge cases: K=1 → answer is A_i itself (cnt[A_i] >= 1 always, and no divisor larger than A_i). K=N → answer is gcd of all elements... actually max d dividing every element and dividing A_i = overall gcd, consistent. (d) Memory: arrays of size 1e6+1 of int32 — fine.

## worker: Implement the full solution: parse input with fast
- **Reduction**: For index i, answer = max divisor d of A_i with cnt[d] ≥ K, where cnt[d] = # elements divisible by d. Since A_i is divisible by d, we can pick A_i plus any K−1 other multiples of d.
- **cnt sieve**: `cnt[d] = freq[d::d].sum()` — total work Σ M/d ≈ M log M ≈ 1.4×10⁷, vectorized per-d with numpy slicing (each is a C-level sum over a strided slice).
- **best fill**: For each good d (ascending), `best[d::d] = np.maximum(best[d::d], d)`; since we iterate d ascending, larger divisors overwrite smaller ones, leaving the maximum good divisor per value. Queries are then O(1) via fancy indexing `best[A]`.
- **Edge cases**: K=1 → best[A_i] = A_i (cnt[A_i] ≥ 1). K=N → overall gcd. d=0 excluded from the good-index loop (index 0 of nonzero is 0, skipped via `if d`).
- **Fallback**: Pure-Python double-sieve version included if numpy is unavailable (slower but correct).
