The graph is bipartite (no odd cycle), and adding an edge without creating an odd cycle means adding an edge between vertices on the same side of the bipartition within each connected component. Each connected component with bipartition sizes (a, b) can accept a*b - (existing edges in it) more edges, and these moves are independent across components, so the game is a disjoint sum of "take one token" piles — the total number of legal moves is fixed regardless of play order. Therefore the winner is determined purely by the parity of the total number of addable edges: Aoki wins iff the total is odd. Compute each component's bipartition side counts via BFS/DFS or DSU-with-parity, sum a*b - edges_in_component over all components, and check parity.
