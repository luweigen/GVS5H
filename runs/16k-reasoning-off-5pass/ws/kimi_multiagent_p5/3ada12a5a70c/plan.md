Map each boundary point to a 1D perimeter coordinate t in [0, 4*side) by walking clockwise around the square; Manhattan distance between boundary points equals the perimeter distance along the shorter arc, i.e. min(|t1-t2|, 4*side-|t1-t2|). The problem becomes: choose k points on a circle of circumference L=4*side maximizing the minimum circular spacing. Binary search the answer d and use a greedy feasibility check: for each starting point, walk clockwise always taking the next point at distance >= d; if any start yields k selections within one full loop, d is feasible. Feasibility is monotone in d, so binary search works. With n <= 15000 and k <= 25, an O(n log n) check per step (two pointers or bisect per start) is fast enough.
