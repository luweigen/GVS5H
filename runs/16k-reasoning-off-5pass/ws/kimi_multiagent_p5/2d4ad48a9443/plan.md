For a fixed subarray, the minimum operations to make it non-decreasing is the sum over i of max(0, running_max_so_far - nums[i]), since we can only increment elements (never decrement), so each element must be raised to the max of all preceding elements. We need to count subarrays whose cost is ≤ k. The cost function is monotonic when extending a subarray to the right (cost only grows), which suggests a sliding window / two-pointer approach: for each left endpoint, find the maximal right endpoint with cost ≤ k. The challenge is maintaining the cost incrementally as the window expands and shrinks, which can be done with a monotonic stack that tracks "segments" where the running max changes, allowing O(1) amortized cost updates when adding or removing elements.
