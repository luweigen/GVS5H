Model each ball color independently: a ball at box i moves along the functional graph of permutation P (red) or Q (blue) when we operate on the box currently holding it. Operating on box i is the only way to move balls out of i, and it moves everything in i simultaneously, so the sequence of operations on a box forms a "wave" that pushes all balls currently there one step along their color's permutation. Key insight: the process is equivalent to choosing, for each box i, how many times to operate on it; balls initially at i then sit at P^{k_i}(i) (red) / Q^{k_i}(i) (blue), but balls arriving later may need further pushes — however since operating more times on a box only helps push things further, the problem reduces to a constraint-propagation on the permutation cycles: each box with a ball must be operated enough times that the ball reaches X, and operating a box propagates the requirement to predecessors. Concretely, for each color, on each cycle of the permutation, compute for each node the distance to X (if X is on that cycle); a ball at node v needs the box operated (dist mod cycle) times, but operations on a box also push balls that arrived from predecessors, which is automatically consistent if we define k_i = required number of operations = max over balls passing through i of (their remaining distance at arrival). Since all balls in a box move together, k_i must equal the distance from i to X along the cycle for any ball that ends exactly at X — actually each ball at i needs exactly d(i) operations on the boxes along its path, meaning box i must be operated at least once if any ball is at or passes through i, and the exact count per box equals the number of distinct "arrival times" of balls. The clean formulation: process boxes in reverse order along each cycle starting from X; maintain a counter of balls that must pass through each node; the number of operations on node i equals the number of balls currently destined through i that haven't been pushed yet — equivalently, simulate: each ball needs to travel its full distance to X, and each operation on a box advances all present balls by one, so the total operations on box i equals the number of balls whose path to X passes through i at the moment they are at i... this simplifies to: answer per color per cycle = sum over nodes of (number of balls at node with distance d) requires operations equal to, for each node, the count of balls that need to leave it, which is all balls at nodes from which the path to X passes through — every ball not already at X must leave its current box exactly once per step, and each step is one operation on that box; multiple balls in the same box share the operation. So the minimal operations = for each box, the number of times it must be operated = the number of distinct distances-at-arrival of balls passing through it, which on a single cycle targeting X equals: balls arrive at node i at times determined by their start; since all movement is synchronous per-box, the number of operations on box i = number of balls whose path includes i, minus sharing when two balls occupy i simultaneously. Balls on the same cycle moving toward X at the same rate never catch each other (they preserve relative order/gaps), so sharing never happens between balls on the same cycle; hence operations on box i = number of balls (of both colors, summed over cycles through i) whose path to X passes through i, i.e., balls at i or at predecessors of i within distance < their distance. Wait — a ball passes through i iff i is on the path from its start to X, i.e., start is in the predecessor chain of i. So operations on i = total balls located at nodes in i's predecessor subtree (on the cycle, the segment behind i up to but not including X-side). Then total answer = sum over i of that count, but each operation on i moves all balls present, and balls present at i at different times require separate operations — balls pass through i at different times, so each passing ball forces one operation on i: operations on i = number of balls passing through i (including starting at i). Total = sum over balls of distance to X. But careful: a box may contain balls from both colors and from different cycles (P-cycle and Q-cycle differ), and one operation moves both colors simultaneously — so operations on box i = number of distinct "waves" = max over colors? No: each operation moves all balls in the box; a red ball and blue ball sitting in i simultaneously are moved by one operation. They arrive at i at the same time only if their distances from start are equal. So operations on i = number of distinct arrival epochs = size of { distances of balls whose path passes through i, measured as (their distance to X) - (distance from i to X) }... i.e., the set of times at which some ball is at i. Time t ball at i means ball started at distance d, at node with distance d - t = dist(i), so d = dist(i) + t. Distinct t values = distinct values of d - dist(i) over balls passing through i = distinct (d) values shifted. So operations on i = number of distinct distances d among balls whose path passes through i (d ≥ dist(i)). Total answer = sum over boxes of count of distinct distances of balls passing through. This is computable per cycle with a sliding window / difference-array technique in O(cycle length). Feasibility: every ball must be on a cycle containing X (for its color's permutation); also X itself: balls at X can stay (distance 0, no operation needed). If any ball's color-cycle doesn't contain X → -1.
