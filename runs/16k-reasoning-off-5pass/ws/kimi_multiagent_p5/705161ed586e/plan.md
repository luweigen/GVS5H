Model the problem as a shortest-path / DP over positions, where the state is the current character and the length of the current consecutive run (capped at 3, since runs of length ≥3 are "complete"). Transition cost from character c to c' is |c - c'| (each operation moves one step in the alphabet). A run can only be closed (reset to length 1 with a new character) when its length is ≥3. Use DP with parent pointers to reconstruct the lexicographically smallest minimum-cost string: process left to right storing (cost, tie-break info), then recover the answer by backtracking, choosing lexicographically smallest among equal-cost options via careful comparison (store the actual suffix string or use greedy forward selection). Impossible cases (like n < 3) naturally yield no valid terminal state.
