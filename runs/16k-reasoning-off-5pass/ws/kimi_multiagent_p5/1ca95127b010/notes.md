- Both operations are the same reversible local rewrite on a length `X+Y` window:
  `0^X 1^Y <-> 1^Y 0^X`.
  Operation A moves a block of `Y` consecutive ones left across `X` zeros; B is its inverse.
- Orienting the rule as `0^X1^Y -> 1^Y0^X` strictly decreases the number of `(0 before 1)` inversions by `X*Y`, so it terminates.
- The left-hand side `0^X1^Y` has no nontrivial self-overlap: two occurrences cannot overlap, because the `1^Y` part of the left occurrence would have to intersect the `0^X` part of the right occurrence. Thus a leftmost-greedy reduction is valid; after rewriting at position `i`, newly created redexes can only start at or after `i-X`, so the scan backs up `X` positions.

- Complexity: each rewrite decreases inversions by `X*Y`, and the scan index moves forward except for bounded backups after rewrites; the implementation is effectively linear for the given constraints in the intended model, and uses O(N) memory.
