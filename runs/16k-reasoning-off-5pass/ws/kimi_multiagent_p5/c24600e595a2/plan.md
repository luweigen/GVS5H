We need to flip exactly the set of indices where A_i != B_i, but the order matters because each operation's cost is the dot product of the current A with C. Flipping a bit from 0→1 adds C_i to all subsequent operation costs, while flipping 1→0 removes C_i from subsequent costs. This is a sequencing problem: process all 1→0 flips (which only reduce future costs) before any 0→1 flips, and within each group order by C descending (for removals) or ascending (for additions) by exchange argument. Compute the total cost by simulating this optimal order with a running sum S = sum of A_k*C_k, updating S as we flip and accumulating costs.
