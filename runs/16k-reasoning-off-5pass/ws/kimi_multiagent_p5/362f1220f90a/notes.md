
## ideation
Core difficulty: 'T' constraints force exact characters (word[i+k] = str2[k]), which may conflict with each other — must detect conflicts. 'F' constraints are "negative": each F-window must differ from str2 in at least one position. Lexicographically smallest result means greedy left-to-right filling with 'a' preferred, but we must never let an F-window become fully equal to str2.

Key observations:
- After placing T-forced chars, an F-window may already be "broken" (some forced char differs from str2 at the aligned offset) — such windows need no further attention.
- For an unbroken F-window, positions not forced by any T are "free"; we need at least one free position to eventually differ. If an unbroken F-window has zero free positions → impossible → return "".
- Greedy: process positions j = 0..n+m-2 left to right. If forced, char is fixed — but we must check it doesn't "use up" the last free slot of an unbroken F-window while matching str2 (actually forced chars are fixed; if a forced char matches str2 at that offset and it was the window's last free hope... wait, forced positions aren't free — free means unforced. Refined: for each unbroken F-window, count of unforced positions within it that could still be set to differ. When we fill an unforced position j, consider all F-windows containing j that are still unbroken and where j is their last remaining unforced position: then j must differ from str2 at the aligned offset for those windows. So candidate char = 'a' unless some such window requires word[j] != str2[j-i], in which case pick the smallest char != str2[j-i] (if multiple windows require differing from possibly different aligned chars, pick smallest char avoiding all forbidden values — at most 26 letters, and forbidden set could in worst case cover many letters, but m ≤ 500 and windows overlapping j with "last chance" status could forbid up to 26 chars; if all 26 forbidden → impossible... but can that happen? Each such window forbids exactly one char (str2[j-i]); multiple windows could forbid multiple distinct chars. If 26 distinct forbidden → no valid char → return "").
- Maintaining "last remaining unforced position" per F-window: for each unbroken F-window i, count unforced positions in [i, i+m-1]. When we fill position j, decrement count for every unbroken F-window containing j. Windows containing j: i in [max(0, j-m+1), min(j, n-1)]. Naively O(m) per position → O((n+m)*m) = up to 10^4 * 500 * ... n+m-1 ≤ ~10500 positions, times 500 = ~5.25M ops — acceptable in Python? ~5M simple ops is fine (borderline but okay). Actually n ≤ 10^4, word length = n+m-1 ≤ 10499. 10499*500 ≈ 5.2M — fine.
- Alternative smarter approach: process and only track windows where j is the last free position using a "rightmost free position" per window. But the simple O(m) per position decrement is fine given constraints.
- Pitfall: when filling j with a char that differs from str2 aligned char, all unbroken F-windows containing j become broken — mark them so we stop decrementing/caring. Need to handle that: once broken, remove from consideration. With the simple loop, we can keep a boolean broken[] and skip broken windows.
- Pitfall: forced positions also can break windows — precompute broken status after placing T's, and count free (unforced) positions only for unbroken windows. Also if forced char at j equals str2 aligned char, nothing happens; if it differs, window broken.
- Pitfall: when choosing char for unforced j: default 'a'. Compute forbidden set from windows where count == 1 (j is last chance) and not broken: forbid str2[j-i]. Also note: choosing a char that differs from str2[j-i] breaks those windows (good). Choose smallest char not in forbidden set. If forbidden set size == 26 → impossible.
- Edge: after greedy fill, double-check all F-windows broken (they should be, since any unbroken window with count ≥ 1 gets its last free position filled with a differing char... careful: when j is last chance for window, we forbid str2[j-i], so chosen char differs → window breaks. Yes, invariant holds).
- Also T-conflict detection: when placing str2 at position i, if result[i+k] already set to a different char → return "".

Complexity: O(n*m) for placement + O((n+m)*m) for greedy ≈ 10^7 worst — acceptable.

## worker: Implement the full solution in the starter code: (
- **T-placement**: For each `i` with `str1[i]=='T'`, write `str2` into `res[i..i+m-1]`; a mismatch with an already-placed character means conflicting T-constraints → return `""`.
- **F-window precomputation**: For each F-window, check whether a forced character already differs from `str2` at the aligned offset (`broken[i]`), and count unfilled positions (`free_cnt[i]`). An unbroken window with zero free positions is fully forced to equal `str2` → impossible → `""`.
- **Greedy fill**: Positions are processed left to right. For an unfilled position `j`, any still-unbroken F-window covering `j` with `free_cnt == 1` has `j` as its last chance to differ, so `str2[j-i]` is forbidden there. The smallest character not in the forbidden set is chosen (at most 26 candidates; if all forbidden → `""`). Placing a character that differs from the aligned `str2` character marks the window broken; otherwise its free count is decremented. This guarantees every F-window ends up broken while keeping the string lexicographically minimal.
- **Verification**: A final scan confirms no F-window equals `str2`.
- **Complexity**: O(n·m) for placement/precomputation and O((n+m)·m) for the greedy loops — at most ~1.5·10⁷ simple operations for n ≤ 10⁴, m ≤ 500, fine in Python.

## worker: Test on the three examples plus edge cases: all 'T
- **Test coverage implemented:**
  1. **Three provided examples** — all pass (`"ababa"`, `""`, `"a"`).
  2. **Single-char strings** — `"T"/"a"→"a"`, `"F"/"a"→"b"` (must differ, smallest non-'a'), `"F"/"z"→"a"`.
  3. **All-T periodicity conflicts** — `"TT","abab"→"ababab"` (period-2 compatible overlap); `"TTT","ab"→""` (offset-1 overlap incompatible); `"TTTT","aa"→"aaaaa"` (period-1 always compatible); `"TT","abcab"→"abcabcab"` (period-3); `"TFT","abcab"→""` (offset-2 mismatch).
  4. **All-F cases** — `"FF","a"→"bb"`, `"F","ab"→"aa"`, `"FF","ab"→"aaa"` (greedy defers the "differing" char as far right as possible per window, which the last-chance mechanism handles).
  5. **Mixed/tricky** — F-window already broken by forced chars (`"TF","ab"→"aba"`), F-window needing exactly one free char (`"FT","ab"→"bab"`), and the key impossibility case `"TFT","aa"→""` where an F-window is fully forced by T's to equal `"aa"`.
  6. **Randomized brute-force cross-check** — 400 random small cases (n≤5, m≤4, alphabet {a,b}) compared against exhaustive enumeration for both validity *and* lexicographic minimality. All match.
  7. **Performance sanity** — n=10⁴, m=500: random T/F (~0.4s), all-F worst case for window tracking (~0.5s), all-T with heavy periodic overlap (~0.05s). All well within limits; produced words pass full constraint validation.
- **Correctness argument confirmed by brute force:** the greedy never paints itself into a corner because the only way a free position is forced away from `'a'` is when it's some window's last chance, and choosing any non-forbidden char either breaks that window (if it differs) or is safe. The brute-force agreement on 400 cases (including impossibility claims) validates both the lexicographic-minimality and the impossibility-detection logic.
