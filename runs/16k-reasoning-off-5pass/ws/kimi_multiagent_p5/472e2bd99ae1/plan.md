The value factors as A_i·B_j + B_j·C_k + C_k·A_i = (A_i + C_k)·B_j + A_i·C_k. For a fixed pair (i,k), define s = A_i + C_k and p = A_i·C_k; then the value over j is s·B_j + p, which is monotone in B_j (s > 0). Binary search the answer X: count triples with value ≥ X by, for each (i,k) pair, counting how many B_j satisfy B_j ≥ ceil((X − p)/s) via binary search on sorted B. Since N² pairs is too many, we need the counting to be faster — but K ≤ 5·10⁵ is small, so instead we can use a selection approach: note that for each (i,k) pair the values over j are sorted, and we only need the K-th largest overall, so a binary search on X with an O(N² log N) count is too slow; instead, we cap the count at K and use the fact that only the top-K B values matter per pair... The intended efficient route: binary search on X (range up to ~3·10¹⁸, ~62 iterations) with counting done by iterating over N² pairs is 4·10¹⁰ — infeasible, so we restructure: for each j, value = B_j·(A_i + C_k) + A_i·C_k, and we count over (i,k) pairs using sorted structures of A and C. Concretely, for fixed j and threshold X, we need #{(i,k): A_i·C_k + B_j·(A_i+C_k) ≥ X}; for each i this is a linear inequality in C_k, so sorting C allows O(log N) per (i,j) — still O(N² log N) total. Given constraints, the practical solution is binary search on X with counting over (i,k) pairs but early-terminating once the count exceeds K, combined with sorting and restricting to candidate large elements; workers should validate feasibility and optimize the counting loop (e.g., numpy vectorization or limiting to top elements since K ≤ 5·10⁵ means only the largest ~K values matter, so we can trim A, B, C to their top ~K elements first, reducing N to ≤ 5·10⁵... still large). Key insight to explore: trimming each array to its top-K elements is valid (any triple using an element outside top-K of its array is dominated), giving N' ≤ 5·10⁵ but N'³ still huge; binary search with O(N'²) counting capped at K via early exit may pass since counting stops early for high X and the binary search range near the answer has counts near K.
