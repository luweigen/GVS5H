
## ideation
The problem reduces to checking whether a non-increasing integer sequence r[1..N] (row black-counts) exists with per-row bounds L[x] ≤ r[x] ≤ U[x], where L[x] = max y among B-precolored cells in row x (0 if none), U[x] = min(y−1) among W-precolored cells in row x (N if none). A monotone sequence between lower/upper bounds exists iff for every prefix boundary k, max(L[1..k]) ≤ min(U[k..N]) — equivalently, scanning left to right maintaining the running max of L, it must never exceed the suffix min of U. Standard check: define suffix minimum of U, then for each x require prefix_max_L[x] ≤ suffix_min_U[x] (with appropriate indexing, including boundary at N+1 where L-side is 0). Per-row conflicts L[x] > U[x] are subsumed.

Pitfalls:
- N up to 1e9, M up to 2e5 → must compress coordinates; only rows with constraints matter, but the "gap" rows contribute L=0, U=N which are inert. However, careful: suffix min of U over compressed rows must still work because inert rows never tighten U below N nor raise L above 0. Coordinate compression with sentinel rows works.
- Off-by-one: W at (x,y) means r[x] ≤ y−1.
- Duplicate constraints in same row must be merged (max of B's y, min of W's y−1).
- Edge cases: row with both B at y and W at y' with y' ≤ y → impossible. Also all-white (r=0) and all-black (r=N) rows allowed.
- Alternative viewpoint: condition is equivalent to "no B cell strictly southeast of a W cell" pattern... actually the precise condition: there must not exist B at (x1,y1) and W at (x2,y2) with x1 ≥ x2 and y1 ≥ y2... let me verify: B at (x1,y1) forces r[x1] ≥ y1; W at (x2,y2) forces r[x2] ≤ y2−1. If x2 ≤ x1 then r[x2] ≥ r[x1] ≥ y1, so need y1 ≤ y2−1, i.e., y1 < y2. So conflict iff exists B(x1,y1), W(x2,y2) with x2 ≤ x1 and y2 ≤ y1. That's a clean 2D dominance check: no W dominates (weakly northwest of) a B. This can be checked by sorting events and sweeping, which may be simpler and avoids compression subtleties. Both approaches are O(M log M).

## worker: Write the final Python solution: parse input, buil
- Reduced the problem to a 2D dominance check: a conflict exists iff there is a B at (x1,y1) and a W at (x2,y2) with x2 ≤ x1 and y2 ≤ y1 (W weakly northwest of B). This follows because row black-counts r[1..N] must be non-increasing, B forces r[x1] ≥ y1, W forces r[x2] ≤ y2−1, so feasibility requires y1 < y2 whenever x2 ≤ x1.
- Sufficiency: if no such pair exists, define r[x] = max B-y in row x (0 if none); for any W at (x,y), absence of conflict with the row's own B's gives r[x] < y, and monotonicity conflicts are exactly cross-row dominance pairs, so a valid coloring exists (fill each row's leftmost r[x] cells black; any residual monotonicity violation would be a detected pair). Hence the check is necessary and sufficient.
- Implementation: sweep rows in increasing x, maintaining minW = minimum y among W cells in rows ≤ x (updated with the current row's W before checking that row's B's, since x2 = x1 is allowed). For every B y in the row, require y < minW. O(M log M) time, O(M) memory; N's magnitude is irrelevant since only constrained rows matter.
- Sample checks: (1) W's: (3,2); B's: (4,1),(1,3). Sweep: row1 minW=INF, B y=3 ok; row3 minW=2; row4 B y=1 < 2 ok → Yes. (2) row1: minW=2; row2: B y=2 ≥ 2 → No. (3) single W, no B → Yes. (4) contains e.g. W(1789,211) and B(1814,712): x2=1789 ≤ 1814, y2=211 ≤ 712 → conflict → No.
