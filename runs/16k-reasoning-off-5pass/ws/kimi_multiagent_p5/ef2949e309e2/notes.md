
## ideation
The core difficulty is that for each middle index i, we must count quadruples (a,b,c,d) with a<b<i<c<d such that value v=nums[i] occurs strictly more times than any other value in the 5-tuple. Since the middle contributes 1 occurrence of v, the left pair can contribute lv ∈ {0,1,2} occurrences of v and the right pair rv ∈ {0,1,2}; total v-count = 1+lv+rv. Every other value x≠v has total count lx+rx (split across sides), and we need lx+rx < 1+lv+rv for all x≠v. Total v-count ranges 1..5; the binding constraint is on the max count of any other value.

Candidate approach: for each i, enumerate left pair (a,b) (O(n²) total) and count valid right pairs (c,d) via precomputed per-index right-side data. For a right pair, define rv = number of elements equal to v, and mx = max count of any single value x≠v within the pair (mx ∈ {0,1,2}; mx=2 means both equal same x≠v; mx=1 means pair has some x≠v; mx=0 means both equal v). Given left pair's (lv, and for each value its count), the condition is: for every x≠v, lx + rx ≤ lv+rv (strict: 1+lv+rv > lx+rx). The tricky part: left pair may contain a value x (lx≥1) that also appears in right pair — per-value coupling. But note left pair has at most 2 distinct values, so coupling is limited: right pair's values only matter if they equal v, or equal one of the (≤2) left values, or are "other" (then rx≤2 but need lx=0 so rx ≤ lv+rv; rx=2 only if both right elements equal same other value).

So per left pair with distinct non-v values set S (|S|≤2) and lv: count right pairs (c,d) by categories: both v; one v one x; both same x; two distinct non-v; with special handling when x∈S. We can precompute for each i: cntV = # v's on right; pairs by (value) counts; number of pairs both equal to a specific value x (using right frequency C(f,2)); number of pairs with exactly one v; total pairs; pairs with two distinct non-v values where neither in S — computable via total minus categories. Constraints per case:
- lv=2 (both left = v): need every x count ≤ 2+rv... wait need lx+rx ≤ lv+rv = 2+rv. Any right pair has rx≤2 ≤ 2+rv always. So ALL right pairs valid: C(n-i-1,2).
- lv=1 (one left = v, other = y≠v): need y: 1+ry ≤ 1+rv → ry ≤ rv; other x≠v,y: rx ≤ 1+rv. rx=2 (both same x) requires rv≥1; rx≤1 fine if rv≥0. Count right pairs: both v (rv=2): all fine. one v one x (rv=1): x=y needs ry=1≤1 ok; x other: rx=1≤2 ok → all C(cntV,1)*(n-i-1-cntV) valid... wait x=y gives ry=1, rv=1, 1+1 ≤ 1+1 ok. both non-v: same value x twice: x=y → ry=2 > rv=0 invalid; x other → rx=2 > 1 invalid. two distinct non-v: y + other: ry=1>0 invalid; two others each 1 ≤1 ok; so only pairs of two distinct values both ∉{v,y}. Count = C(m,2) - cntV*(m-cntV) - (m-cntV) + ... better: pairs from right excluding v's, minus pairs containing y, minus same-value pairs. Let m = right length, f = right freq. Non-v pairs total = C(m-cntV,2). Subtract pairs containing y: f[y]*(m-cntV-1)... pairs with at least one y among non-v elements: C(f[y],2) + f[y]*(m-cntV-f[y]). Subtract same-value pairs Σ C(f[x],2) for x≠v,y. Remaining = valid.
- lv=0 (left has values y,z possibly equal, y,z≠v): need rv ≥ rx - ... condition: for x∈{y,z}: lx+rx ≤ rv; for others rx ≤ rv. rv must be ≥ max needed. If y=z (lx=2 for y): need rv≥2 → both right = v: 1 way category C(cntV,2). If y≠z: need rv≥1 (since lx=1 each, need 1+rx≤rv → rx≤rv-1; with rv=1 need rx=0 for y,z and others rx≤1; with rv=2 need rx≤1 for y,z, rx≤2 others). rv=2 (both v): valid. rv=1 (one v, one x): x must not be y or z (else rx=1 > 0)... wait rv=1: need for y: 1+ry ≤ 1 → ry=0. So x∉{y,z}: count cntV*(m - cntV - f[y] - f[z]). rv=0: need lx+rx ≤ 0 impossible since lx≥1. So total = C(cntV,2) + cntV*(m-cntV-f[y]-f[z]).

So per middle i, iterate over all left pairs (a,b), classify, and compute right-pair counts using right frequency map f and cntV. Need per-i: right freq map (maintain by sliding i), m = n-i-1, cntV = f[v], Σ C(f[x],2) over x≠v (maintainable incrementally), and C(m-cntV,2) etc. Each left pair handled O(1). Total O(n²) = 10^6 for n=1000. Fine.

Pitfalls: (1) strict inequality direction — unique mode means v's count strictly greatest, i.e., other counts ≤ vcount-1 = lv+rv. (2) Case lv=1, both-non-v distinct values where one is y: invalid as computed; double-check pair (y, other): ry=1, rv=0 → 1+1=2 > 1+0=1 invalid. Yes. (3) Case lv=1, pair both equal v fine; pair (v, y): ry=1, rv=1 → 1+1 ≤ 1+1 ok. (4) Case lv=0, y≠z, rv=1, x∈{y,z} invalid — excluded. (5) Mod arithmetic with subtraction — add MOD. (6) Maintaining Σ C(f,2) while sliding middle: when moving i from left side to... standard technique: iterate i, move nums[i] from right map to left map, update counts. But we iterate left pairs naively O(n²) anyway, so we just need right freq map per i; rebuild by sliding: start i with right map = all elements right of i. Update sumC2 = Σ C(f[x],2) incrementally on removals. Also need sumC2 excluding v: sumC2 - C(f[v],2). And pairs both equal specific value: C(f[x],2). All O(1) queries.

Alternative cleaner formulation: iterate over left pairs (a,b) for each i — that's Σ i ≈ n²/2 = 5·10^5 iterations, each O(1). 

Edge: values up to 1e9 — use dict/Counter, fine.

Verify with examples mentally later during implementation. Example 1: nums all 1, i=2: left pairs all (v,v) lv=2 → all right pairs C(3,2)=3; left pairs count C(2,2)=1 → 3. i=3: left C(3,2)=3 pairs lv=2, right C(2,2)=1 → 3. Total 6. ✓ matches.

## worker: Implement the full solution: sliding right-frequen
- For each middle index `i` with value `v`, we enumerate all left pairs `(a, b)` (`a < b < i`) and count valid right pairs `(c, d)` (`i < c < d`) in O(1) using the right-side frequency map.
- The condition "v is the unique mode" means every other value's total count is at most `lv + rv` (since v's total is `1 + lv + rv`), where `lv`/`rv` are the number of v's in the left/right pair.
- Case analysis on the left pair:
  - **lv = 2** (both equal v): any right pair works → `C(m, 2)`.
  - **lv = 1** (one v, one w ≠ v): valid right pairs are (v,v), (v, anything), and pairs of two distinct non-v values neither equal to w. The last count = `C(nonV,2) − pairs containing w − same-value pairs among values ∉ {v, w}`, computed via the incrementally maintained `sumC2 = Σ C(f[x],2)`.
  - **lv = 0, both left equal w ≠ v**: only (v,v) works → `C(cntV, 2)`.
  - **lv = 0, left values y1 ≠ y2 (both ≠ v)**: valid pairs are (v,v) plus (v, x) with `x ∉ {y1, y2}` → `C(cntV,2) + cntV·(nonV − f[y1] − f[y2])`.
- The right frequency map and `sumC2` are maintained by sliding `i` from left to right, removing `nums[i]` from the right side each step (O(1) per step).
- Complexity: O(n²) time (≈ 5·10⁵ inner iterations for n = 1000), O(n) space.
- Verified against the examples: `[1,1,1,1,1,1] → 6`, `[1,2,2,3,3,4] → 4`, `[0..8] → 0`. The formulas were derived so that strict-greater mode condition holds in every sub-case (e.g., lv=1 excludes right pair (w,w) since w would tie/beat v; lv=0 with distinct y's requires rv ≥ 1 and the non-v element to avoid y1, y2).
