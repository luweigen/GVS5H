For each pair (i, j) with i < j, the contribution to the inversion count for shift k depends only on A_i, A_j: the pair is an inversion iff (A_i + k) mod M > (A_j + k) mod M. If A_i > A_j, the pair is an inversion for k in [0, M-1-A_i] ∪ [M-A_j, M-1]; if A_i ≤ A_j, it is an inversion only for k in [M-A_j, M-1-A_i] (non-empty only when A_i < A_j... actually when A_i ≤ A_j the wrap interval is [M-A_j, M-1-A_i] which is non-empty iff A_i < A_j; equal values never invert). Each pair contributes +1 over one or two contiguous k-intervals, so we can build a difference array over k of length M and prefix-sum it. The total work is O(N²) pairs which is too slow for N=2e5, so instead we process per element: for each j, count prior elements in value ranges using a Fenwick/BIT over values, translating each j's contribution into range updates on the k-difference array. Specifically, for each new element x = A_j, prior elements y > x contribute intervals [0, M-1-y] and [M-x, M-1]; prior elements y < x contribute [M-x, M-1-y]. Aggregating counts of prior elements by value via BIT prefix sums lets us add these as O(1) range-increments per element, giving O((N+M) log M) total.
