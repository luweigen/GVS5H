Simulating each query over N contests is O(NQ), too slow. Instead, for every possible initial rating v (bounded by 5e5), compute f(v) = final rating after all N contests, then answer queries in O(1). The key observation: the map v -> (rating after contest i) is monotone non-decreasing and shifts by at most 1, so we can process contests in reverse maintaining breakpoints. Concretely, work backwards: maintain a piecewise function g(v) = rating after suffix of contests; contest i transforms g into g(v + [L_i <= v <= R_i]). Since g is monotone with slope 0 or 1 pieces, we can represent it by an array over the value domain and rebuild efficiently, or use the equivalent forward formulation: precompute for each starting value the number of increments by tracking, for each value v, the contests where the running value hits [L_i, R_i]. A simpler robust method: process contests in reverse, maintaining ans[v] for all v in [1, 5e5 + N]; each reverse step does ans[v] += 1 if L_i <= ans[v] <= R_i... which is still O(N * V). Better: note the final answer for initial X equals X + (number of contests where the trajectory lands in range); trajectories for different X never cross, so final(X) is non-decreasing in X with final(X+1) - final(X) in {0,1}; we can binary-search boundaries: for each contest the set of initial values that get incremented forms an interval, and these can be found by simulating the inverse map. The cleanest known solution: process contests in reverse maintaining a function via a sorted list of "critical values" using the fact that applying contest i to the identity-like monotone function only modifies values in [L_i, R_i] by +1, which in inverse terms shifts breakpoints; implement with a Fenwick/segment tree over value domain computing, for each initial v, final value by processing contests and using the monotonicity to batch: maintain lo[v] = minimal initial value that currently maps to v. Equivalent and simple: compute F(X) = X + count of i with L_i <= current <= R_i; define G(t) over contests; known AtCoder ABC solution: for each value v from 1..5e5, simulate is O(N) each — too slow, so use the reverse-difference trick: maintain array A where A[x] = final rating for initial x, initialized A[x]=x; process contests forward, for contest i we need A[x] += 1 iff L_i <= A[x] <= R_i; since A is monotone non-decreasing with consecutive differences 0/1, the set {x : L_i <= A[x] <= R_i} is a contiguous index range [p, q] findable by binary search on A; then we add 1 to A[p..q], which preserves the 0/1-difference property. Use a lazy-propagation structure (e.g., a Fenwick on differences plus binary search via prefix sums, or a balanced structure) to do range-increment and order-statistics queries in O(log V) per contest, total O((N+Q) log V).
