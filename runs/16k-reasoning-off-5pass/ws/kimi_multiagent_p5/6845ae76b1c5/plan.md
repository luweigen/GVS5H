The key identity: for sorted arrays, sum over pairs |a-b| can be computed with prefix sums by counting, for each element, how many elements on the other side are ≤ it. Since queries are over prefixes A[1..X], B[1..Y], we need a 2D offline structure: process elements in sorted order and use two Fenwick trees (count and sum) over positions of A and B. For each query (X,Y), answer = sum over i≤X,j≤Y |A_i-B_j|, which decomposes into contributions where A_i≥B_j plus where B_j>A_i. Offline, sort all A_i, B_j values; sweep in increasing value, inserting A-positions into BIT_A and B-positions into BIT_B; each query's answer can be computed as (sum over pairs with A≥B) + (sum over pairs with B>A) using prefix queries on the BITs at the right sweep states — but a single sweep doesn't directly give both directions per query. Instead, per query we compute: sumA over i≤X of A_i * (count of B_j≤A_i, j≤Y) − (sum of those B_j) + symmetric term. This requires, per query, summing over i≤X a function of A_i against threshold Y in B — a 2D offline problem solvable by sorting queries and elements by value and using Fenwick trees keyed on positions, doing two passes (one for A_i ≥ B_j term, one for the strict opposite), each pass O((N+K) log N).
