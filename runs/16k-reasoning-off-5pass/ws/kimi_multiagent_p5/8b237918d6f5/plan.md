We want to choose K edges to make weight 1 so the shortest 1→N path (counting chosen edges) is maximized. Equivalently, for a candidate distance D, check feasibility: can we pick ≤K edges such that every 1→N path uses at least D chosen edges. A clean way is to binary-search D and test via min-cut: split each vertex into layers 0..D (vertex v at distance-layer i), edge (u,v) becomes infinite-capacity arcs from u_i to v_{i+1} for i<D (these are "free" traversals we must not allow to bypass), and a capacity-1 arc from u_{D-1}... Actually simpler: build a graph where each original edge is a unit-capacity arc between consecutive layers of a (D+1)-layered vertex copy, plus infinite-capacity arcs keeping vertices within the same layer connected; then min s-t cut = minimum number of edges to weight 1 to force distance ≥ D. Feasible iff min-cut ≤ K; binary search D up to M (or N... bounded by M). With N≤30, M≤100, max flow on ~30*101 nodes is trivial.
