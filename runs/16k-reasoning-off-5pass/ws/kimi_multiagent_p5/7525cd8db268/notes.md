
## ideation
The core difficulty is efficiently evaluating the effect of deleting each conflicting pair without recomputing the O(n) subarray count per pair (which would be O(n·m)). Key insight: for a fixed pair set, sweep r = 1..n; each pair (a,b) with max(a,b) ≤ r forbids left endpoints ≤ min(a,b), so the smallest allowed left is L(r) = max over active pairs of (min(a,b)+1) (or 1 if none). Contribution at r is r - L(r) + 1. Deleting a pair p only matters at positions r ≥ max(p) where p's (min+1) is the strict maximum among active values; there the constraint relaxes to the second max. So we need per r: max1, max2 (distinct-value second), and count of pairs achieving max1. Gain of a pair = Σ over r ≥ max(p) where it is the unique max of (max2 - max1). Answer = base total + max gain over pairs.

Implementation approach: normalize each pair to (u=min+1, v=max). Group pairs by v. Sweep r from 1..n, inserting all pairs with v == r into a structure maintaining top-two u values and count of max. Since u values only get inserted (no deletions), we can maintain running max1, cnt1, max2 with simple updates: for each inserted u: if u > max1: max2 = max1; max1 = u; cnt1 = 1. elif u == max1: cnt1 += 1. elif u > max2: max2 = u. But careful: gain must be attributed per pair, and a pair is "active and unique max" for all r from its v onward — however max1/max2 change as more pairs insert. So at each r, if cnt1 == 1, the unique max pair gets gain (max2 - max1) at this r; we need to know which pair is the current max. Track the identity (index) of the pair achieving max1. Since insertions only raise max1, the identity changes only when a strictly larger u arrives. That works: keep idx1 alongside.

Pitfalls: (1) pairs may be duplicated — count multiplicity matters for cnt1; (2) max2 should be the largest u strictly less than max1 (a different value), because removing the unique max relaxes to the next distinct value; if another pair shares max1, removal changes nothing (cnt1 > 1 → gain 0 contribution); (3) when cnt1 == 1, gain added to pair idx1 is (max1 - max2)?? Sign: L = max1; after removal L becomes max2 (or 0 meaning L=1 if no pairs). Contribution r-L+1 increases by (max1 - max2) where max2 defaults to 0 (i.e., L=1 → u=0 baseline). So gain = max1 - max2 with max2 ≥ 0 baseline 0. (4) Must remove exactly one pair even if gain is 0 — answer = base + max(gains, default 0). (5) Large answer: n up to 1e5, subarrays ~5e9, fits in 64-bit; Python int fine.

Edge cases: m could be 1 → removing it leaves no constraints, answer = n(n+1)/2; base computed with that pair, gain = base difference works naturally. Also pairs where u = v? Not possible since a ≠ b.

- For a fixed pair set, sweeping r = 1..n: each active pair (u = min+1, v = max) with v ≤ r forces the left endpoint L ≥ u, so L(r) = max u over active pairs (or 1 when none, represented by max1 = 0). Contribution at r is r - L + 1 = r - max1 + 1; `base` accumulates this.
- Deleting pair p only helps at positions r ≥ v(p) where p is the *unique* maximum u; there L relaxes from max1 to max2 (second distinct value, 0 if none), gaining max1 - max2 subarrays. Since insertions only raise max1, tracking (max1, cnt1, idx1, max2) with simple comparisons is exact; when cnt1 == 1 we credit `gain[idx1] += max1 - max2`.
- Duplicates handled via cnt1 (if two pairs share the max u, removing one changes nothing). Exactly-one-removal is satisfied because gains are ≥ 0, so base + max(gain) corresponds to removing the best pair (gain 0 if nothing helps).
- Verified: Example 1 (n=4, [[2,3],[1,4]]) → 9; Example 2 (n=5, [[1,2],[2,5],[3,5]]) → 12. Brute-force cross-check on small random cases (n ≤ 8, random pairs, comparing against enumerating all removals and all subarrays) matched.
- Complexity: O(n + m) time, O(n + m) space.
