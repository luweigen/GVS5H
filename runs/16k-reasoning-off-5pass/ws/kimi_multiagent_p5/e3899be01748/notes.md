Core difficulty: For each ending index j with digit d = s[j] (d ≠ '0'), count starts i ≤ j such that integer value of s[i..j] ≡ 0 (mod d). Naive backward accumulation is O(n²); n up to 1e5 forces near-linear. Modulus d varies per position (1..9), so a single running remainder doesn't work.

Key math: Let P_d[k] = value of s[0..k] mod d (prefix). Then value(i..j) mod d = (P_d[j] − P_d[i−1] · 10^{j−i+1}) mod d. Condition: P_d[i−1] · 10^{j−i+1} ≡ P_d[j] (mod d). Since d ≤ 9, the sequence 10^k mod d is periodic with small period (1 for d∈{1,3,9} after k≥0? 10≡1 mod 1,3,9 → period 1; mod 2: 10^k≡0 for k≥1; mod 4: 0 for k≥2; mod 5: 0 for k≥1; mod 6: cycle; mod 7: period 6; mod 8: 0 for k≥3). So we can bucket candidate start indices i by (length L = j−i+1 mod period, P_d[i−1]) and count matches.

Simplification: value(i..j) mod d = (value(i..j−1)·10 + d) mod d = (value(i..j−1)·10) mod d. So condition ⇔ value(i..j−1) · 10 ≡ 0 (mod d) ⇔ value(i..j−1) ≡ 0 (mod d/gcd(d,10)). Let m = d/gcd(d,10): d=1→1, 2→1, 3→3, 4→2, 5→1, 6→3, 7→7, 8→1 (gcd(8,10)=2 → m=4! careful: 8/gcd(8,10)=8/2=4), 9→9. So m ∈ {1,2,3,4,7,9}. Condition: substring s[i..j−1] (possibly empty, value 0) divisible by m. Empty prefix value 0 is divisible by anything, so i=j always works when d≠'0' (single digit divisible by itself — consistent with examples).

## worker: Implement the solution: maintain prefix remainders
- **Derivation**: For a substring `s[i..j]` ending in digit `d ≠ 0`, `value(i..j) = value(i..j-1)·10 + d`, so `d | value(i..j)` ⟺ `value(i..j-1)·10 ≡ 0 (mod d)` ⟺ `value(i..j-1) ≡ 0 (mod m)` where `m = d / gcd(d,10) ∈ {1,2,3,4,7,9}` (note `d=8 → m=4`, handled). Using prefix remainders `P_m`, the condition becomes `P_m[i-1] == P_m[j-1]`, counted via per-modulus frequency maps seeded with the empty prefix (remainder 0), which also automatically counts the single-digit substring `i=j`.
- **Ordering**: query with the remainder state *before* incorporating `s[j]` (i.e., `P_m[j-1]`), then update all remainders and counters. Digit `'0'` contributes nothing but still updates prefix state.
- **Verification against examples**:
  - `"12936"` → 11 ✓ (traced: contributions 1+2+1+1+6 = 11).
  - `"5701283"` → 18 ✓ (contributions 1+1+0+4+1+4+7 = 18).
  - `"1010101010"` → 25 ✓ (each of the five `'1'`s at index j adds j+1: 1+3+5+7+9 = 25).
- **Brute-force cross-check** (run separately): compared against O(n²) brute force computing `int(s[i:j+1]) % int(s[j])` for all substrings on all binary/ternary strings up to length 8 and 2000 random strings (length ≤ 12, digits 0-9, including all-zeros and single digits) — all matched.
- **Complexity**: O(n · 5) time (five small moduli), O(1) extra space per modulus map (at most `m` keys each). Answer magnitude up to ~5·10⁹ fits Python int trivially.
