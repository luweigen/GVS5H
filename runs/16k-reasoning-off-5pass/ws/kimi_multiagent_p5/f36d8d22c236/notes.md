- Built the constraint mapping `f` from each position: `S[i] -> T[i]`. Conflicting targets for the same letter make it impossible (`-1`).
- Any consistent functional graph (out-degree ≤ 1) is realizable: process each component's cycle first (using a spare letter as a temporary), then tree/chain edges in reverse order (sinks first), so every letter's occurrences land exactly on their image.
- Minimum operations = (number of letters x with f(x) ≠ x) + (number of directed cycles of length ≥ 2), since each cycle of length L needs L+1 ops (one extra to break it via a temp letter).

**Cycle-detection correctness**: The graph is functional (out-degree ≤ 1), so from any start the walk is a path ρ followed by at most one cycle. The walk marks nodes 1 as it goes and stops when it hits (a) an unconstrained/fixed node (chain end — the `f[x] == -1 or f[x] == x` guard), (b) a node marked 2 (previously processed component), or (c) a node marked 1. Case (c) in a functional graph means we re-entered our own path, which can only happen at the cycle entry, and since every node on a cycle of changed letters satisfies `f[x] ≠ x` and `f[x] ≠ -1`, the guard `state[x] == 1` correctly fires exactly once per cycle. The unwind loop then converts all 1s to 2s so each component is visited once. Self-loops (`f[x] == x`) are excluded from `changed` and terminate walks, so they are never counted as cycles. Also note the stop-condition re-checks `f[x] != -1 and f[x] != x` before counting, preventing a false positive when a path ends at a fixed point that was marked 1... (this can't actually happen since the walk loop would have stopped before marking a fixed point, but the guard makes it airtight).
