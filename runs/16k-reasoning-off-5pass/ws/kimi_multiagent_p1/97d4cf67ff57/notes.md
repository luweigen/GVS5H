
## ideation
Core difficulty: the chosen subgraph must be a connected subtree of T where every selected vertex has induced-degree exactly 1 or 4, and at least one vertex has degree 4. Since T is a tree, any connected subgraph is a subtree; dropping edges only reduces degrees, so effectively we choose a connected vertex set S and may delete some induced edges — but deleting edges from a tree disconnects it, so the subgraph must be an induced connected subtree where each vertex's degree within S is 1 or 4 (degree 0 only if single vertex, which isn't valid anyway). So the problem is: find the largest connected vertex subset S such that every vertex has degree (within S) in {1,4}, with at least one degree-4 vertex.

Key structural fact: in such a tree, if k = number of degree-4 vertices, then leaves = 3k+2, total = 4k+2. So valid sizes are 5, 9, 13, ... i.e., answer ≡ 1 (mod 3)? 4k+2 with k≥1: 6? No: k=1 → leaves=5? Check: sum of degrees = 2(V-1). 4k + L = 2(k+L-1) → 4k+L = 2k+2L-2 → 2k+2 = L. So L = 2k+2, V = 3k+2. Sizes: 5, 8, 11, 14... Sample 1 answer 8 = 3·2+2 ✓, sample 3 answer 11 = 3·3+2 ✓. Good — so answer is always ≡ 2 (mod 3), a useful sanity check.

Candidate approach: root the tree, DP per node with state = degree of node within chosen component (0..4), value = max size of a connected chosen subtree in the node's subtree that includes the node and respects constraints for all included descendants (children either excluded entirely, or included via keeping the edge, contributing 1 to node's degree). Transitions: for each child, option "cut" (gain 0) or "keep" (gain best valid child-subtree size where child has degree d_c in {1..4} within its own component, i.e., child component valid given the edge to node is kept). Then node with degree d is "complete/valid" if d ∈ {1,4}; d=0 means isolated node (invalid as alkane but could be a building block? No — a partial component under construction can have node degree 0..3 only if it will later connect upward; when we finalize a component not extending to parent, node degree must be 1 or 4, and the component must contain a degree-4 vertex somewhere).

So we need two values per node per degree: best size of connected subtree containing node, with node's degree = d, where the subtree may or may not yet contain a degree-4 vertex (flag f ∈ {0,1}). Answer = max over nodes of dp[node][d=4][f=1] or dp[node][d=1][f=1] (component closed at node, not using parent edge). Also a component could be "closed" at a node while also... no — if it connects to parent, it's not closed.

Pitfalls: (1) combining children is a knapsack over degree slots (degree ≤ 4, so small — O(deg·5·2) per node, fine). (2) When keeping a child edge, the child's component must be valid with child degree counting that edge; child degree ∈ {1,4} required since child won't connect further up. So child contribution = max over d∈{1,4}, f of child dp with edge-to-parent counted. Define for each node u with parent p: g[u][f] = max size of valid component in subtree(u) that includes u and the edge (u,p), i.e., u's degree includes that edge. Then at node u, for each child v, keeping edge adds g[v][f] (must pick f consistently for the OR flag). (3) Merging: dp_u[d][f] = 1 + sum over kept children of g[child][f_c], with number of kept children = d (each kept child contributes exactly one degree), f = OR of f_c (or u itself... u contributes to f only via its degree being 4 — but that's about final validity, not during construction; actually f should track "some vertex in the component has degree 4", and u's degree is fixed at d in this state, so if d==4 then f=1 automatically). (4) Answer also includes components entirely within a child's subtree not including u — handled by taking max over all nodes' closed values. (5) N up to 2e5: recursion depth — use iterative post-order or sys.setrecursionlimit with care (Python recursion at 2e5 risky; use iterative stack). (6) g[u] needs dp over degrees 1..4 with the parent edge included: g[u][f] = max over d∈{1,4} of dp_u_counting_parent[d][f]. Compute dp_u[d][f] for d = 0..4 = degrees from children only; then closed answer uses d∈{1,4}; g[u][f] = max over d∈{0,3} of dp_u[d][...] with parent edge making total degree d+1 ∈ {1,4}, and f' = f or (d+1==4).

Complexity: sum over edges of 5·2·(5·2) ≈ O(100·N) — fine.

## worker: Implement the full solution in Python: parse input
- Modeled the problem as: choose a connected vertex subset S of the tree such that every vertex's induced degree is 1 or 4, with at least one degree-4 vertex; maximize |S|. (Deleting edges from a subtree would disconnect it, so the subgraph is an induced connected subtree.)
- Handshaking gives leaves L = 2k+2 and V = 3k+2 for k degree-4 vertices, so valid answers are 5, 8, 11, ... (≡ 2 mod 3) — used as a sanity check.
- Root tree at 1 iteratively (avoids recursion limits for N=2e5), process nodes in reverse preorder (post-order).
- DP state `dp[u][d][f]`: best connected chosen subtree within subtree(u) containing u, with exactly d chosen children of u, flag f = "some vertex already has final degree 4".
- When keeping edge (u,v), child v's component is closed (v can't connect elsewhere), so v's total degree must be 1 (0 chosen children) or 4 (3 chosen children, forcing f=1): `best0 = dp[v][0][0]`, `best1 = max(dp[v][0][1], dp[v][3][0], dp[v][3][1])`.
- Knapsack merge over children capped at degree 4: O(deg(u)·5·2·2) per node, total O(N·const).
- Answer: close at any node u with total degree d ∈ {1,4} (no parent edge) and (f=1 or d=4). Since any alkane has a unique highest vertex (closest to root), every candidate is counted.
- Verified mentally: Sample 1 → 8 (two adjacent degree-4 vertices 2,3 with 6 leaves); Sample 2 → -1 (any vertex closing with degree 4 lacks 4 children; no valid combo); Sample 3 → 11. Star K1,4 → center d=4, f auto → 5. Path → -1. N<5 → -1.
