- **Strategy (verified optimal by exhaustive brute-force Dijkstra over all permutations for N=2..7, plus 200 random permutations each for N=2..12, all matching):** process values v = N down to 1. When processing v, all larger values are already in their final positions to the right, so v only needs to bubble right past the smaller values that lie between its current position and slot v. The swaps occur at consecutive current indices cur, cur+1, ..., v−1.
- **Why optimal:** every inversion must be resolved by exactly one adjacent swap. Processing largest-first forces each inversion's resolving swap to occur at the smallest index consistent with the required crossing order; any other order pushes some swaps to larger indices, never reducing cost. Confirmed empirically with zero mismatches against exact Dijkstra on ~5900 exhaustive states and 2200 random states.
- **Computation:** cur = original 1-based position pos[v] minus the number of already-placed (larger) elements originally to its left, maintained with a Fenwick tree (`cur = pos[v] − bit_sum(pos[v])`). The bubble cost is the arithmetic series (cur + v−1)·(v−cur)/2. Then mark pos[v] as placed.
- **Complexity:** O(N log N) time, O(N) memory — handles N = 2×10⁵ easily. Answer fits in Python int (max ~ N²/2 ≈ 2×10¹⁰).
- Samples verified: (3,2,1) → 4, (2,4,1,3,5) → 6, (1,2) → 0.
