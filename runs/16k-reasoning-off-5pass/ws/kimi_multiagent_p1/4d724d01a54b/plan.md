Each element must cross every inversion exactly once, so the problem reduces to choosing the order of adjacent swaps. A swap at position i costs i, and swapping adjacent elements that are already in correct relative order is wasteful. The key insight: process elements in increasing order of value, moving each element left to its final position; the cost equals sum over inversions of the position where the swap occurs. Equivalently, for each element, its contribution is the sum of indices of swaps needed, which can be computed with a Fenwick tree tracking positions of already-placed (smaller) elements. The answer is sum over each element x (placed in increasing order) of (number of elements before its current position already placed) contributing swap costs — compute via BIT over positions with prefix sums of indices.
