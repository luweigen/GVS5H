Model the problem as a shortest-path/DP over positions: a good caption is a concatenation of blocks of identical characters, each block having length at least 3. The cost of turning a segment caption[l..r] into a run of character c is the sum of alphabet distances |caption[i]-c|, and the best c for a segment is its median character (computed fast via 26-letter prefix counts). Run a DP where dp[i] = min cost to fix the first i characters, with transitions dp[j] = dp[i] + cost(i, j-1) for block lengths j-i >= 3, tracking the chosen character per block. To recover the lexicographically smallest answer among all minimum-cost captions, do a forward greedy reconstruction: at each step, pick the smallest next character (and shortest valid block) that still allows an optimal total completion, which requires the DP to be computed as "cost from position i to end" (suffix DP). Overall complexity is O(n * 26) or O(n * 26^2) depending on implementation details, well within limits for n up to 5*10^4.
