Model each block as a node; moving vertically within a building costs the floor difference, while horizontal walkways are free but only usable at floors ≤ min(F_u, F_v). Key insight: the optimal strategy is to choose a "travel height" h, descend from Y to h in the start building, walk freely through the region of buildings with F ≥ h, then ascend from h to Z in the target building — cost = (Y − h) + (Z − h) = Y + Z − 2h, valid only if start and target are connected in the subgraph of cells with F ≥ h. So the answer is Y + Z − 2·(max h such that start and target are connected using only cells with F ≥ h, also requiring h ≤ min(Y, Z, F_start, F_target)). This becomes a maximum-bottleneck connectivity problem: sort cells by F descending, add them to a union-find, and answer queries offline at the threshold h = min(Y, Z, F_start, F_target) — but since we want the max h, process thresholds descending and for each query find the largest h where connectivity holds, which is exactly the max-min bottleneck value capped by min(Y, Z). Compute per-query bottleneck via offline parallel binary search or by processing cells in descending order with union-find and answering queries when their required threshold is reached — actually the max h equals min(bottleneck path value, Y, Z), where bottleneck = max over paths of min F along path. Use Kruskal-style maximum spanning tree / union-find descending: process queries sorted by their cap, but connectivity at level h is monotone, so sort all queries by threshold descending and unite cells with F ≥ threshold; then answer = Y + Z − 2·min(cap, highest level where connected) — highest level where connected is found by binary lifting on the maximum spanning tree, or simpler: answer each query at moment of connection in the descending union process (like Kruskal reconstruction tree). Build the Kruskal reconstruction tree (KRT) of the grid graph with edge weight = min(F_u, F_v); the bottleneck value between two nodes is the weight of their LCA in the KRT. Then answer = Y + Z − 2·min(Y, Z, weight(LCA)). Preprocess LCA with binary lifting in O(N log N), answer queries in O(log N).
