We need the maximum subarray sum after optionally deleting all occurrences of one value x (the array must stay non-empty). The key observation: after deleting x, the array splits into segments separated by occurrences of x, and the best subarray lies entirely within one segment. For each distinct value x, we need the maximum subarray sum over the segments of nums split at positions where nums[i] == x. Doing this naively per distinct x is O(n * distinct), so instead we process positions grouped by value and use a union-find / "activate positions" trick: sort distinct values, and for each value x compute segment max subarray sums by scanning only the gaps between occurrences of x — total work is O(n) per value only if we're careful, so the cleaner approach is: for each distinct value x, iterate over its occurrence indices and run Kadane's on each gap between consecutive occurrences; the sum of gap lengths over all x is O(n * distinct) in the worst case (e.g., alternating values), so we need the union-find approach: add positions in order of value, merging active neighbors, maintaining segment sum and segment max-subarray sum per component (like dynamic connectivity with Kadane data). Each component stores: total sum, best prefix, best suffix, best subarray — mergeable in O(1). Process values in any order: when activating all positions of value x, the segments NOT containing x are exactly the components formed by previously activated positions... actually simpler: activate positions in decreasing order of value; when about to add value x, current active components are exactly segments of elements > x... that gives "delete all values >= threshold" semantics, not "delete exactly x". The correct reduction: deleting x gives segments of the array with x removed — components of positions whose value != x. So for each x, answer candidate = max subarray sum over components of the array minus x-positions. Using offline dynamic connectivity is complex; instead note sum over distinct x of (occurrences of x + gaps) — each gap between consecutive x's must be Kadane-scanned, and a position i belongs to gaps of many x's. Worst case distinct ~ n/2 with each appearing twice → total gap work O(n * distinct). Alternative: for each x, gaps are intervals; total gap length = n - count(x) + (number of gaps), summed over x = distinct*(n+1) - n... too big. So the intended solution: for each x, we only need max subarray sum in gaps, and gaps are bounded by x occurrences — use the fact that Kadane over a gap can reuse precomputed prefix/suffix data: precompute for each position the max subarray sum ending here and starting here; then a gap [l..r] max subarray can't be answered in O(1) from those alone. Practical accepted approach: for each distinct x, scan the array skipping x's — O(n * distinct) worst case but with the constraint that we only scan segments between occurrences, total is O(sum over x of n) — too slow at 1e5 with many distinct values... but if every value is distinct, deleting any x just removes one element; handle that via prefix/suffix Kadane combination in O(n) total. General efficient method: for each x, candidate = max over gaps; compute via iterating occurrences and for each gap use precomputed sparse structure — simplest correct plan: group indices by value; for values with few occurrences, compute gap answers using precomputed prefix-max of "max subarray sum ending at i" and suffix arrays combined with RMQ...
