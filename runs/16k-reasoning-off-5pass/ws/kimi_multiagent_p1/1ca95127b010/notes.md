
## ideation
The operations swap adjacent homogeneous blocks: A turns 0^X 1^Y into 1^Y 0^X, B turns 1^Y 0^X into 0^X 1^Y. Both preserve the number of 1s (necessary condition). The core difficulty is characterizing reachability: operations require exact block lengths X and Y at the moment of application, but runs can be longer (e.g., a 0-run of length ≥ X adjacent to a 1-run of length ≥ Y can partially swap, splitting runs). Effectively, we can pass "X zeros" past "Y ones" repeatedly, which suggests zeros and ones can be reordered with some granularity constraints. Key questions: (1) Can any zero move past any one if run lengths permit? (2) Are there invariants beyond popcount — e.g., positions modulo gcd(X,Y), or parity of some permutation? Consider small cases: X=Y=1 means adjacent swap of 0 and 1 — full sorting possible, so reachability = equal popcount. For general X, Y, moving a single 1 left past zeros requires accumulating Y ones and X zeros adjacently. Likely the answer involves: strings are equivalent iff they have the same count of 1s AND some condition on the "gaps" — perhaps the sequence of 1-positions can shift arbitrarily as long as counts match, when N is large enough, but boundary effects matter (blocks near edges can't be formed). Pitfalls: assuming popcount suffices (Sample 2 shows N=1 < X+Y so no operation possible — but popcounts differ there anyway; need a case with equal popcount but unreachable, e.g., N=3, X=Y=1... that's fully sortable. Try X=2,Y=2, N=5: "00110" vs "01100"? Operation needs length 4 window: 0011 → 1100 reachable. Hmm.) Need to think about whether the operation generates full connectivity within fixed popcount when N ≥ X+Y, or whether there are extra invariants like the count of 1s mod something in prefix regions.

- **Task performed (small-case analysis):**
  - **X=Y=1:** Operations are adjacent swaps `01 ↔ 10`. This generates the full symmetric group action on positions, so any rearrangement preserving popcount is reachable. Invariant: popcount only.
  - **X=1, Y=2:** Rule `0 11 ↔ 11 0`. A block of two 1s can move past a single 0. Single 1s cannot move alone. Testing small strings (e.g., N=4, strings with two 1s): `0110 ↔ 1100` reachable, but `0101` (two isolated 1s) has no valid move and is stuck. So invariant: popcount plus the "clustering" structure — isolated 1s that can never pair up are frozen. Hence popcount alone is NOT sufficient.
  - **X=2, Y=2:** Rule `0011 ↔ 1100`. Blocks of two 1s jump past blocks of two 0s. Odd-length runs create frozen "leftover" bits. E.g., N=5, `01100` vs `00110`: `01100` — window `0110` doesn't match either pattern (needs `0011` or `1100`); positions 2-5 = `1100` matches B → `00011`. So `01100 → 00011`. Meanwhile `00110` → (A at i=1) `11000`. Both popcount 2, but `01100` reduces to `00011` and `00110` reduces to `11000` — different normal forms, unreachable from each other. Confirms extra invariants exist.
- **Algorithm in code:** The rewriting rule `0^X 1^Y → 1^Y 0^X` (Operation A direction, pulling 1s left) is terminating (each application strictly decreases the sum of positions of 1s) and locally confluent (overlapping redexes resolve consistently since the rule is length-preserving and only depends on the suffix pattern), so it yields a unique normal form. Two strings are inter-reachable iff they share this normal form, because Operation B is exactly the inverse rewrite. The stack-based simulation computes the normal form in O(N·L) worst case as written (suffix check is O(L) per step).
- **Complexity concern:** The inner suffix check is O(L) each iteration, giving O(N·L) worst case — too slow for N=5×10^5. Needs optimization (e.g., track run lengths instead of characters, or use a counter-based suffix matcher to make each check O(1) amortized).

## worker: Verify the run-stack normal-form algorithm against
- **Verification against brute force (performed during development):** I cross-checked `canonical` against BFS on the full state graph for all N ≤ 9 and all X, Y ∈ {1,2,3} (plus spot checks at N=10–12, X,Y ≤ 4): for every pair (S,T) of equal popcount, BFS-reachable ⟺ `canonical(S) == canonical(T)`. All matched. Also verified `canonical` is idempotent and that its output contains no redex `0^X 1^Y`.
- **Why the normal form is valid:** the rewrite `0^X 1^Y → 1^Y 0^X` (Operation A) terminates (each application moves Y ones left past X zeros, decreasing the sum of 1-positions by X·Y) and Operation B is its exact inverse, so the reachability classes are precisely the equivalence classes of the rewrite system. Two distinct redex occurrences cannot overlap: the pattern has a single 0→1 transition, and an occurrence shifted by 1..X+Y−1 would force some position to be both 0 and 1. Hence redexes are disjoint, disjoint redexes commute, the system is locally confluent, and by Newman's lemma it has a **unique normal form**. Thus S↔T reachable ⟺ nf(S) = nf(T).
- **Run-stack correctness:** processing left to right, the stack always holds the normal form of the processed prefix. Pushing one char can only create a redex ending at the new last position (any other redex would have existed before). Reducing it moves the trailing 1-run left past the adjacent 0-run in `q = a // X` elementary swaps at once (valid because the swaps are sequential redexes `0^X 1^Y` at the same boundary). If the 0-run is consumed exactly (r = 0), the 1-run merges with the next 1-run left and may cascade past further 0-runs (phase 2, dragging accumulated zeros); if r > 0 the leftover boundary `0^r 1^b` with r < X is inert and nothing further left changed. Cascading merges (e.g., `0^X 1^Y 0^X 1^Y` with X=2,Y=1 style cases) were explicitly confirmed against BFS.
- **Complexity:** each phase-1/phase-2 step with r = 0 permanently destroys one 0-run; r > 0 steps occur at most once per pushed character. Total O(N) stack operations, O(N) memory — fine for N = 5×10⁵.
- Edge cases handled: popcount mismatch → No; N < X+Y → no operation possible, answer is S == T; X or Y ≥ N covered by that check.
