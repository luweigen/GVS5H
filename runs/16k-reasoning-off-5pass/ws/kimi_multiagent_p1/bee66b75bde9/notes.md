
## ideation
The grid conditions mean each row is a prefix of black cells, and each column is a prefix of black cells. This forces the black region to be a "staircase" (Ferrers/Young diagram shape anchored at top-left). Equivalent characterization: black cells form a downset under the product partial order — if (x,y) is black, then all (x',y') with x'≤x, y'≤y are black. Contrapositive: the coloring is infeasible iff there exist a black cell (x_b, y_b) and a white cell (x_w, y_w) with x_w < x_b and y_w < y_b... wait, need care: if (x_b,y_b) is black, then everything weakly northwest is black, so any white (x_w,y_w) with x_w ≤ x_b and y_w ≤ y_b is a contradiction. Since cells are distinct, strict in at least one coordinate. So feasibility ⟺ no white cell is weakly northwest (≤ in both coordinates) of a black cell.

So the problem reduces to a 2D dominance query: does any W point dominate (be ≤ in both coords than) any B point? Approach: sort all points by x ascending; sweep maintaining the minimum y among W points seen so far (with x ≤ current x). For each B point in order of x, if min W-y among W with x_w ≤ x_b satisfies min_y ≤ y_b, infeasible. Careful with equal x: a white cell with same x and y_w ≤ y_b also contradicts (since x_w ≤ x_b). So when processing groups with equal x, we should include W points of the same x before checking B points of that x. Actually check: white (x, y_w) and black (x, y_b) with y_w ≤ y_b: column x has black below white → violates column prefix condition. Yes, infeasible. So process all W at coordinate x first (update min), then answer B queries at x.

Alternative: sort B and W together, sweep. Complexity O(M log M), fine for M ≤ 2e5, N up to 1e9 irrelevant (just coordinates).
