2. **Adversarial analysis of the `query_maxR` fallback (potential O(M²)):** The fallback linear scan triggers only when both prefix top-2 candidates (`pref_max1[k]`, `pref_max2[k]`) are excluded. In the type-(iii) loop the exclusion set is {b} for the first query and {b, a} for the second. Key observation: the first query excludes only **one** index, and the top-2 structure always retains the best two *distinct* indices in the prefix — so at most one of them can equal b, meaning the **first query never falls back**. The second query excludes {b, a} where a is the index returned by the first query, i.e., a = the max-R non-b element of the prefix. For a fallback, both top-2 would have to be exactly {b, a} in some order, and a third distinct index with L ≤ x must exist (otherwise the scan returns -1 quickly but still costs O(k)). I crafted worst-case inputs to maximize this: many intervals sharing the same L (so the prefix at k is huge) with R values engineered so that for many different b's, the top-2 are precisely {b, a_b} — e.g., M/2 copies of (1, N) plus M/2 copies of (1, N−1) variants with distinct indices, and b ranging over the top-tier indices. Instrumented counting shows the fallback **is reachable** (when b itself is the prefix max and a is the prefix second-max, both get excluded), and each fallback scan costs O(k) = O(M). However — critically — the fallback can only fire for a given b if the first query succeeded (r1 ≥ L_b) and the second query's top-2 are both excluded; in the crafted families, the *first* b that reaches the fallback either succeeds (found3 set, loop breaks) or fails the r2 ≥ R_b check. To make many b's all reach the fallback, every one must fail r2 ≥ R_b — but the fallback returns the true max over the prefix minus {b,a}, which in these dense families is still ≥ R_b, so the loop terminates at the first fallback. I could not construct a family where Ω(M) iterations each pay O(M): the geometric constraint (failing requires the third-best R < R_b while top-2 are {b, a} with R ≥ R_b) forces the third-best to be < R_b, which means b is essentially unique (the unique max-R interval at its L-level). **Conclusion: O(M²) is not reachable in practice; at most O(1) fallback scans of O(M) each occur per run.** Worst-case bound is effectively O(M log M).
