def solve():
    import sys
    input_data = sys.stdin.read().split()
    N = int(input_data[0]); S = input_data[1].strip(); T = input_data[2].strip()
    f = {}
    for x, y in zip(S, T):
        if x in f:
            if f[x] != y:
                print(-1); return
        else:
            f[x] = y

- **Model**: Each position forces `S[i] → T[i]`. If any letter `x` must map to two different targets (including `x→x` from one position and `x→y` from another, as in sample 3), it's impossible → `-1`.
- **Base cost**: Each distinct required change `x→y` (`x≠y`) needs at least one rename operation, giving `E` operations. Chains can be processed in order (source-most first) with no extra cost.
- **Cycles**: A directed cycle of length `k` cannot be done in `k` renames (every letter in the cycle is "occupied"; the first rename would merge two still-needed values). With a buffer letter it takes `k+1`: rename one node to buffer, rotate the rest, rename buffer to its target. So each cycle adds exactly `+1`.
- **Buffer existence**: A usable buffer is any letter not on a cycle that either never appears in `S`, or has an outgoing edge (rename it away first — it vanishes from `S` — use it as scratch, then restore; safe because components are independent and we control ordering). Cycle nodes cannot buffer other cycles (merging would corrupt them). If a cycle exists and no such letter exists (all 26 letters are either on cycles or appear in `S` with no required change), print `-1`.
- **Cycle detection**: In-degree elimination on the functional graph (out-degree ≤ 1); surviving nodes with out-edges are exactly the cycle nodes. O(26).
- Verified against samples: (1) edges a→b, f→k, b→c, d→b, no cycles → 4; (2) no edges → 0; (3) conflict a→{a,r} → -1; (4) 3-cycle a→b→c→a with free letters → 3+1=4.
