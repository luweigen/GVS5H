
## ideation
Core difficulty: answering rectangle queries (prefix X × prefix Y) of the pairwise kernel |A_i − B_j| fast. The kernel couples values with a per-pair comparison (a≥b vs a<b), so it does not factorize over the index rectangle naively. Key identities:
- |a−b| = a + b − 2·min(a,b). The "a+b" part factorizes into simple 1D prefix sums (Y·ΣA(X) + X·ΣB(Y)). So the whole problem reduces to M(X,Y) = Σ_{i≤X,j≤Y} min(A_i,B_j).
- min(a,b) = Σ_{t≥1} [a≥t][b≥t], i.e. an integral over thresholds of cA(t)·cB(t) — the product of two prefix counts, which is the nonlinear obstruction.

Candidate approaches and their costs:
1. CDQ on value (split by median): cross pairs (one value low, one high) have min = the low value, and the weight depends only on one side, so the cross term FACTORIZES: (Σ_{i≤X, A_i∈low} A_i)·(cnt_{j≤Y, B_j∈high}) + symmetric. This kills the 4D coupling! But naive "every query visits every value-node" is K·V. Need to reorganize: for each query, M = Σ over value-nodes of factorized products. This equals a simultaneous recursion over two value segment trees (PST over A-prefix and B-prefix): at node pair (u,v) with range [l,r]: cross children are disjoint-range (formula O(1)), recurse only (left,left) and (right,right). Complexity = number of visited node pairs.
2. PST simultaneous traversal (equivalent to above): worst case O(min(nodesA, nodesB)) per query = O(N) → 1e9 total worst case. BUT with a crucial observation: we can prune when one side's subtree is empty, and the recursion only branches where BOTH sides are nonempty. Worst case is bad only if value sets interleave heavily at all levels. With coordinate compression (2e5 distinct values), worst case per query is O(min(N, V) · something). Risky but possibly OK in practice; adversarial tests could break it. Need to estimate honestly: A and B each have 1e5 values over 2e5 slots — trees are dense, traversal could visit ~O(N) pairs per query. Probably too slow worst-case.
3. Sqrt decomposition on index with precomputed coarse-boundary tables: memory N·(N/B) is the blocker (need ~3e7 int64 = 250MB at B≈300). Two-level sqrt gets complicated; per-query remainder costs blow up. Not clean.
4. Offline sweep maintaining BIT over index of active A's and B's while decreasing threshold t: needs per-query Σ_t cA(X,t)·cB(Y,t)·gap — product of two query-dependent prefix counts can't be accumulated with linear structures. Dead end unless combined with value-CDQ factorization (approach 1).
5. Reframe approach 1 iteratively: process value domain as a segment tree; for each query walk down BOTH the A-PST and B-PST simultaneously, accumulating cross terms. This is approach 2 — same thing.

Better idea to bound approach 2: instead of PST per (X,Y) pair, note the recursion for M(X,Y) only depends on the two multisets A[1..X], B[1..Y]. We can implement the two-tree walk iteratively with a stack, pruning empty nodes. Each visited node pair either (a) is a leaf pair, (b) has an empty child on one side (prune), or (c) generates 2 recursive calls + O(1) cross work. Total visited pairs ≤ 2·(number of nodes in the smaller tree restricted to common support)... still O(N) worst case per query.
