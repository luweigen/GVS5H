We need the sum of products over all monotone (down/right) paths from (1,1) to (H,W), updated after each point assignment. Since HW ≤ 2e5, the grid is "thin": either H or W is small (≤ ~447), or more precisely min(H,W) ≤ sqrt(2e5). Use DP where dp over one dimension: answer = sum over paths; maintain forward DP F[h][w] = sum of path-products from (1,1) to (h,w), and backward DP G[h][w] = sum from (h,w) to (H,W). Total answer = F[H][W]. On updating cell (h,w) to value a, only F values in the rectangle [h..H]×[w..W] change, and G in [1..h]×[1..w]. Recomputing naively is O(HW) per query — too slow. Instead, exploit that the smaller dimension is small: WLOG assume W ≤ H (transpose otherwise), so W ≤ 447. Then recomputing F row-by-row from row h to H costs O((H-h+1)*W), worst O(HW) still. Better: process queries offline with a sqrt-decomposition / "rebuild every B queries" scheme: every B queries, recompute full DP in O(HW); between rebuilds, at most B cells are dirty, and the answer can be computed as base answer plus corrections via inclusion of paths through dirty cells using precomputed prefix/suffix DP sums. With B ≈ sqrt(HW) ≈ 447, total cost O((Q/B)*HW + Q*B*min(H,W)) roughly — need care. Alternative cleaner approach: since W small, represent each row's DP as vector of size W; a cell update at (h,w) requires recomputing rows h..H, each row O(W), so O(H*W) worst. Use the classic trick: maintain segment tree over rows where each node stores a W×W linear (actually affine) transition matrix? Transition is linear with diagonal structure: new_row[j] = A[row][j]*(new_row[j-1] + prev_row[j]) — this is a linear map on the vector prev_row plus a boundary term, representable as W×W matrix; composing H such matrices via segment tree gives O(H/W * W^3 log) — too heavy. The sqrt-rebuild approach is standard for this AtCoder problem (typical solution: rebuild every ~450 queries, handle pending updates by computing contribution via DP that treats dirty cells specially). Simplest correct plan: rebuild full DP every B queries; for queries within a block, collect the ≤B modified cells, and compute answer = sum over subsets?
