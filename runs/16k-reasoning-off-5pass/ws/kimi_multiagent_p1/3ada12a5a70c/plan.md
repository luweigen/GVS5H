Map each boundary point to a 1D position along the square's perimeter (arc length from (0,0), going counterclockwise), so Manhattan distance between boundary points equals the shorter arc distance along the perimeter. Then the problem becomes: on a circle of circumference 4*side, choose k of the given positions to maximize the minimum circular gap between consecutive chosen points. Binary search the answer d and use a greedy feasibility check: for each candidate starting point, walk the circle picking the earliest available point at distance >= d each step; if we can complete k picks and wrap back within the perimeter, d is feasible. Since k <= 25 and n <= 15000, an O(n * k) check per start (or smarter) is fine within ~31 binary search iterations.
