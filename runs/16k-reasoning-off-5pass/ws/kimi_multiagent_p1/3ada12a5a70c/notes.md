from typing import List

class Solution:
    def maxDistance(self, side: int, points: List[List[int]], k: int) -> int:
        P = 4 * side
        pos = []
        for x, y in points:
            if y == 0:
                p = x
            elif x == side:
                p = side + y
            elif y == side:
                p = 2 * side + (side - x)
            else:
                p = 3 * side + (side - y)
            pos.append(p)
        pos.sort()
        n = len(pos)
        pos2 = pos + [p + P for p in pos]
        N2 = 2 * n

        def feasible(d: int) -> bool:
            # nxt[i] = smallest j > i with pos2[j] - pos2[i] >= d, else N2
            nxt = [N2] * (N2 + 1)
            j = 0
            for i in range(N2):
                if j < i + 1:
                    j = i + 1
                limit = pos2[i] + d
                while j < N2 and pos2[j] < limit:
                    j += 1
                nxt[i] = j
            # binary lifting for k-1 jumps
            steps = k - 1
            # build levels needed
            up = [nxt]
            bit = 1
            while (1 << bit) <= steps:
                prev = up[-1]
                up.append([prev[prev[i]] for i in range(N2 + 1)])
                bit += 1
            limit_total = P - d
            for i in range(n):
                cur = i
                b = 0
                s = steps
                while s:
                    if s & 1:
                        cur = up[b][cur]
                    s >>= 1
                    b += 1
                if cur < N2 and pos2[cur] - pos2[i] <= limit_total:
                    return True
            return False

        lo, hi = 1, min(side, P // k)
        while lo < hi:
            mid = (lo + hi + 1) // 2
            if feasible(mid):
                lo = mid
            else:
                hi = mid - 1
        return lo

**Key insight / correction to a naive approach:** Manhattan distance between boundary points does NOT equal the shorter perimeter arc in general (e.g., side=10, points (0,5) and (10,5): Manhattan = 10, but both perimeter arcs = 20). However, two facts rescue the perimeter reduction:

1. **The answer never exceeds `side` when k >= 4.** Proof: suppose 4 points are pairwise at distance > side. Two points on the same edge are at distance <= side, so each edge holds at most one of them. If a corner (say (0,0)) is selected, no other selected point can lie on the left or bottom edge (distance <= side to the corner), and at most one can lie on each of the right/top edges — at most 3 points total. Otherwise the 4 points lie strictly one per edge: left (0,y1), right (side,y2), bottom (x3,0), top (x4,side). The adjacent-edge constraints give x3 >= d-y1 and x3 <= side-d+y2, requiring y1+y2 >= 2d-side = side+2s (s=d-side>0); similarly the top point requires y1+y2 <= 3side-2d = side-2s. Contradiction. So d <= side always.

2. **For d <= side, pairwise Manhattan >= d ⟺ consecutive-on-perimeter circular gaps >= d.** Same-edge pairs: arc = Manhattan. Adjacent-edge pairs: Manhattan equals the arc via the shared corner. Opposite-edge pairs: Manhattan = side + |offset| >= side >= d automatically, and both arcs are >= side >= d as well. Both directions of the equivalence follow.
