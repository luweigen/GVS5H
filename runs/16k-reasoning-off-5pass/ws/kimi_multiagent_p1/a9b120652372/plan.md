Model each operation as choosing an attractor i: every piece moves one step toward i (pieces at i stay). Key observations: pieces never cross each other (order is preserved), and pieces at the same square stay together forever, so we can treat the initial distinct occupied positions as an ordered list of "tokens" with multiplicities. The final configuration must have every B=1 square occupied; since tokens keep order, token k must end at the k-th target position, and achievability requires each token to be able to reach its target — which holds iff at each step we can move tokens monotonically; the process is equivalent to: repeatedly pick an index and shift all tokens one step toward it. The minimum number of operations equals the minimum number of "sweeps": each operation can move every token by at most 1, so the answer is at least max over tokens of |start - target|, and one can show this lower bound is achievable by scheduling operations at appropriate attractor points (move all tokens leftward via attractor at/left of all, rightward similarly, splitting into phases). Feasibility condition: the k-th initial piece position must be matchable to the k-th B=1 position (equal counts), and additionally the leftmost/rightmost constraints are automatically satisfiable — but sample 2 shows infeasibility arises when counts differ (1 piece vs 3 targets). So: if popcount(A) != popcount(B) output -1; else answer = max_k |p_k - q_k| where p, q are sorted positions of 1s.
