
## ideation
The core difficulty is computing, for a candidate max run length L, the minimum number of flips needed to ensure no identical-character run exceeds L — and doing so correctly for the edge case L = 1.

Key observations:
- Feasibility is monotone in L: if we can achieve max run ≤ L, we can achieve ≤ L+1. So binary search on L ∈ [1, n] works.
- For L ≥ 2: process each maximal run independently. A run of length `len` needs floor(len / (L+1)) flips (flip positions L+1, 2(L+1), ... within the run). This is optimal because each flipped character can "break" the run into segments of length ≤ L, and one flip can cover at most L+1 consecutive characters. Runs are independent since flips inside one run don't affect another (a flip at a boundary just merges into the neighbor differently, but flipping strictly inside at spacing L+1 is safe and optimal).
- For L = 1: the whole string must alternate (0101... or 1010...). The per-run formula does NOT apply because flipping one character affects two adjacent runs simultaneously (e.g., "0000" with 2 flips → "1010"). So handle L = 1 specially: count mismatches to both alternating patterns, take the min.
- Pitfalls: (1) applying the run formula to L=1 gives wrong answers (e.g., "0000" would give floor(4/2)=2 — actually correct here, but "0101" type interactions and cases like "00100" break it; safer to special-case). Actually floor(len/2) per run for L=1 fails on e.g. s="0110": runs are 0,11,0 → 0+1+0=1 flip, but flipping middle of "11" gives "01010"? No — flipping index 1 or 2 gives "0010" or "0100", still has run of 2. True answer for L=1 on "0110" is 2 (→ "0101" or "1010"). So special-casing L=1 is REQUIRED. (2) Binary search bounds: lo=1, hi=n (answer is at most n, at least 1).

Complexity: O(n) per check, O(n log n) total. n ≤ 1000, trivially fast.

**Edge cases:**
- `numOps = 0`, e.g. `s = "0001100"`: L=1 needs ≥2 flips, L=2 needs 3//3=1, L=3 needs 0 → returns **3** (longest existing run) ✓
- Already alternating, e.g. `s = "01010", numOps = 0` → L=1 feasible with 0 flips → returns **1** ✓
- `n = 1`, e.g. `s = "0", numOps = 0`: binary search lo=hi=1 → returns **1** ✓ (also works with numOps=1)
- All-same with enough flips, e.g. `s = "00000", numOps = 5` (or 2): L=1 needs min(3,2)=2 flips → returns **1** ✓
- All-same with insufficient flips, e.g. `s = "00000", numOps = 1`: L=1 needs 2, L=2 needs 5//3=1 → returns **2** ✓

**Correctness of the run formula:** For L ≥ 2, a run of length `run` with k flips leaves `run - k` original characters in at most k+1 segments; keeping each segment ≤ L requires `run - k ≤ (k+1)·L`, i.e., `k ≥ (run - L)/(L+1)`, so minimum k = ⌈(run-L)/(L+1)⌉ = ⌊run/(L+1)⌋ (identity verified numerically: run=5,L=2 → 1; run=6,L=2 → 2; run=4,L=2 → 1). Runs are independent since flips are placed strictly inside runs at spacing L+1. L=1 is special-cased because one flip can fix two adjacent runs simultaneously, which the per-run formula doesn't capture (e.g., "0110" would wrongly give 1 instead of 2).
