Binary search on the answer value X: count how many triples (i,j,k) give value ≥ X, and find the largest X with count ≥ K. For fixed i, the expression factors as A_i·B_j + B_j·C_k + C_k·A_i = (A_i + C_k)·B_j + C_k·A_i, but a cleaner counting approach: for each pair (i,k) we need B_j ≥ (X − C_k·A_i)/(A_i + C_k), so counting over all N² pairs is too slow. Instead, sort A and C, and for each i count over k using two pointers / binary search on a per-i basis is still O(N² log). Key trick: since K ≤ 5·10⁵, we only need to count up to K and can cap; but the standard intended solution uses the factorization with sorting A_i+C_k sums — precompute nothing quadratic; instead, for each i, sort C values and for each threshold do binary search over k, giving O(N² log N) per check which is too slow. The workable approach: binary search on X (≈60 iterations over 64-bit range), and for counting, fix i and note that as C_k grows the required B_j threshold decreases monotonically, so with sorted B and sorted C we can two-pointer over k per i in O(N log N) total per check — O(N log N log MAX) overall ≈ 2·10⁵·17·60, feasible in PyPy with care (or reduce iterations by searching over candidate values). Workers should validate the counting monotonicity carefully and optimize constants.
