For a fixed k, B_i = (A_i + k) mod M. An inversion (i<j) occurs when A_i > A_j but the shift wraps A_j past M while A_i doesn't wrap, i.e., A_i + k < M ≤ A_j + k, equivalently A_i < M-k ≤ A_j. So for each k, the answer is the number of pairs (i<j) with A_i < t ≤ A_j where t = M-k. We need, for every threshold t in 1..M, the count of pairs (i<j) with A_i < t ≤ A_j. This can be computed by sweeping t from M down to 1 while inserting elements equal to t into a Fenwick tree over positions, accumulating how many earlier elements are below the threshold. Alternatively, count for each pair the set of t values where it contributes (t in (A_i, A_j] when A_i < A_j) and difference-array over t. The pair-based difference array approach: for each i<j with A_i < A_j, add +1 to all t in (A_i, A_j]; this is O(N^2) naively, so instead process with a Fenwick over values: sweep t downward, maintain a BIT over positions of elements with A ≥ t; for each element with value exactly t-1... Actually cleaner: for each t, answer(t) = sum over j with A_j ≥ t of (number of i<j with A_i < t). Compute by iterating t from M down to 1, adding positions where A_i = t to a position-BIT, and for positions with A_i = t-1... hmm, simpler: answer(t) = total pairs i<j with A_i < t minus pairs with A_i < t and A_j < t. Both terms computable via offline sweeps in O((N+M) log N).
