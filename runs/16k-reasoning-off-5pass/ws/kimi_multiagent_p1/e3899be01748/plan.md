For each ending position j, count how many starting positions i make the substring s[i..j] divisible by its last digit d = s[j]. Substrings ending in '0' never qualify; single non-zero digits always qualify. For d in {1,2,5}, divisibility depends only on the last digit, so all substrings ending there count. For d in {4,8}, divisibility depends on the last 2 or 3 digits, so we can check the number formed by the last up-to-3 digits directly. For d in {3,6,7,9}, maintain the suffix value modulo d incrementally: as i shrinks, value = digit*10^len + prev, so we can iterate i from j downward while the count of valid i's is tracked, but an O(n^2) scan is too slow — instead note that for d in {3,9} only the digit sum matters (track prefix sums mod d), and for d in {6,7} we need a different trick. Actually the cleanest unified approach: for each j, the substring value mod d as i varies is determined by prefix values P[i] = value of s[0..i-1] mod d, since substring(i,j) = P[j+1] - P[i]*10^(j-i+1) (mod d). Because 10 is invertible mod d for d in {3,7,9} (and 6 needs care), we can rewrite the condition as P[i] ≡ P[j+1] * inv(10^(j-i+1))... which still depends on i. Simpler: for d in {3,7,9}, substring(i,j) mod d = (P[j+1] - P[i] * 10^(j+1-i)) mod d; multiplying both sides by inv(10^(j+1)) gives condition P[i] * inv(10^i) ≡ P[j+1] * inv(10^(j+1)) (mod d). So maintain a counter of keys P[i] * inv(10^i) mod d per modulus d, and for each j with that last digit, look up the matching key. Handle d=6 by requiring divisibility by 2 and 3 (last digit even — always true since d=6 — and digit-sum divisible by 3, reuse the mod-3 counter). Combine: per j, answer contribution = count based on last digit category, using hash maps for mod 3, 7, 9 keys.
