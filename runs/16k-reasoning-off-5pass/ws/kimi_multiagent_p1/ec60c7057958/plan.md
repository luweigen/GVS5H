We need the k-th lexicographic permutation of [1..n] where adjacent elements differ in parity. Since n ≤ 100, we cannot enumerate; instead we build the permutation digit-by-digit (like the standard "k-th permutation" factorial-number-system approach), but at each position we count how many valid completions exist for each candidate next value. The count of completions depends only on how many odd and even numbers remain and the parity of the last placed element. This count is a product of factorials: if the remaining slots force a fixed parity pattern (determined by the last parity and remaining counts), the number of completions is (odds_left)! × (evens_left)! when the pattern is feasible, else 0. We use exact big integers (Python handles k up to 10^15 and factorials up to 100! natively). If total count < k, return [].
