Model each person as an interval on the line of towns: traveling from S to T, the prefix sums of road strengths along the path must be 0 at both endpoints and strictly positive at every interior town. Since direction matters, normalize each person to a left-to-right traversal: a person from S to T with S<T requires prefix sums over edges [S, T-1] to be 0 at S and T and positive inside; a person with S>T traversing right-to-left requires the same on edges [T, S-1] but with negated weights, i.e., the partial sums of w over that interval must be 0 at endpoints and negative inside. So each person is a constraint on the prefix-sum array P[0..N-1] (P[j] = sum of w_1..w_j): for interval [a,b] (a<b, b-a>=2), "up" type requires P[a]=P[b] and P[x]>P[a] for a<x<b; "down" type requires P[a]=P[b] and P[x]<P[a] inside. The feasibility question for a set of people becomes: does there exist an integer sequence P with these equality/inequality constraints? Key observation: equal endpoints create "levels"; constraints decompose into a graph where P[a]=P[b] merges nodes, and interior strict inequalities impose order constraints between merged components — feasibility reduces to checking that no contradiction (a cycle of strict inequalities, or an interior point forced equal to endpoint level) arises. Because queries are ranges over people, we need an offline structure: likely the condition is that the set of intervals must be "non-nested conflicting" — two intervals with equal endpoints relation must not interleave improperly. Concretely, build a graph whose vertices are towns; each person adds an equality edge (a,b) plus the requirement that all towns strictly inside (a,b) are strictly above (or below) the component of a. A set is feasible iff no town inside an interval belongs to the same equality-component as that interval's endpoints with wrong ordering — this becomes checking that the equality graph restricted appropriately has no "forbidden" containment, which can be reframed as: intervals whose endpoints are connected by equality edges must be nested consistently. This is equivalent to checking, over the query subset, that the union of equality edges forms components such that every interval's interior contains no vertex of its endpoints' component at an inconsistent relative position — practically, we can process queries offline with a data structure (e.g., Mo's algorithm with rollback DSU plus auxiliary checks, or segment-tree divide-and-conquer over queries with rollback DSU) maintaining components and for each interval checking min/max constraints via range queries.
