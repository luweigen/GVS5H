For a fixed subarray, the minimum operations to make it non-decreasing equals the sum of "deficits" when scanning left to right while raising elements to match the running maximum. We need to count subarrays whose total deficit ≤ k. Since extending a subarray to the right never decreases its cost, for each left endpoint the valid right endpoints form a prefix — enabling a sliding window / two-pointer approach. The key challenge is maintaining the cost incrementally as the window expands and shrinks; this can be done with a monotonic stack that tracks "segments" where the running maximum stays constant, storing each segment's length and height so cost deltas can be computed in O(1) amortized. Each push/pop on the stack is O(1) amortized, giving O(n) total time.
