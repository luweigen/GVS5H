The core difficulty is that for a fixed target sum H, the problem decomposes into choosing u_i in [max(0, H-D_i), min(U_i, H)] minimizing sum |u_i - U_i| subject to |u_i - u_{i+1}| <= X. This is a convex separable problem on a path, solvable via isotonic regression / taut-string methods or min-cost flow, but N up to 2e5 demands an O(N) or O(N log N) per-H approach. The total cost as a function of H is convex (piecewise linear), so we can search over H. Candidate H values are bounded by sums U_i + D_i (up to 2e9), so ternary search over integers may work but needs care with convexity and integer domain; alternatively, the optimal H is near a "median-like" point computable from the structure. Pitfalls: (1) H can be as large as 2e9 and as small as 0; (2) the per-H subproblem must handle the Lipschitz constraint correctly — a greedy two-pass (forward then backward clamping) works for minimizing sum of absolute deviations with Lipschitz constraints? Actually the standard approach: unconstrained optimum is u_i = clamp(U_i, L_i, R_i); then enforce Lipschitz via a "pool adjacent violators"-like algorithm for total variation denoising, which is exactly the taut-string problem solvable in O(N). (3) Cost must be computed in 64-bit. (4) Ternary search over convex integer function needs the function to be unimodal — convex piecewise-linear is unimodal, fine, but range up to 2e9 means ~32 iterations, each O(N) gives 6.4e6 * constant — acceptable if per-H solve is O(N). But implementing O(N) taut-string correctly is tricky; alternative: min-cost flow too slow. Another approach: parametric search on H directly using the structure of the dual.

**Derivation of the formula:**

We choose final lengths $u_i \le U_i$, $d_i \le D_i$ with $u_i + d_i = H$ (common sum) and $|u_i - u_{i+1}| \le X$. Cost $= \sum (U_i - u_i) + (D_i - d_i) = \sum (U_i + D_i) - N \cdot H$. So for fixed $H$, feasibility is all that matters; we want the **maximum feasible $H$**, then answer $= \text{total} - N \cdot H$.

Feasibility for given $H$: need $u_i \in [\max(0, H - D_i), \min(U_i, H)]$ with Lipschitz constraint. Since $d_i = H - u_i \le D_i \iff u_i \ge H - D_i$ and $u_i \le U_i$.

**Claim:** feasible iff $H \le U_k + B_k$ for all $k$, where $B_k = \min_j (D_j + X|j-k|)$.

*Proof sketch:* The Lipschitz constraint propagates: $u_k \ge u_j - X|j-k| \ge (H - D_j) - X|j-k|$ for all $j$, i.e., $u_k \ge H - B_k$. Combined with $u_k \le U_k$: need $H - B_k \le U_k$, i.e., $H \le U_k + B_k$. Conversely, if $H \le U_k + B_k$ for all $k$, set $u_k = \max(0, H - B_k)$... more precisely, define $u_k = \max_j (H - D_j - X|j-k|) = H - B_k$ (clamped at 0). This is the pointwise maximal lower-envelope cone function; it satisfies the Lipschitz constraint because each cone $H - D_j - X|j-k|$ is $X$-Lipschitz and the max of $X$-Lipschitz functions is $X$-Lipschitz. Also $u_k = H - B_k \le U_k$ by assumption, and $u_k \ge H - D_k$ (take $j = k$), so $d_k = H - u_k \le D_k$. Also need $u_k \ge 0$ and $d_k \ge 0$: if $H - B_k < 0$ for some $k$... note $B_k \le D_k$, so $H - B_k \ge H - D_k$; if $H \le D_k$ then $d_k = H - u_k \le H \le D_k$ fine and $u_k \ge 0$ requires care: take $u_k = \max(0, H - B_k)$; this remains $X$-Lipschitz (max with constant 0 preserves Lipschitz) and $u_k \le U_k$ still holds, and $d_k = H - u_k \le H$; we need $d_k \le D_k$: if $u_k = 0$ then $d_k = H \le D_k$ needed. Hmm — but if $H - B_k < 0$ then $B_k > H$, and $B_k \le D_k$ doesn't directly give $H \le D_k$. However, we can also lower $H$... Actually the standard result (this is AtCoder ABC problem "Teeth") confirms the answer is $\sum(U_i + D_i) - N \cdot H$ with $H = \min_k (U_k + B_k)$, and the construction works because we can also symmetrically cap: the tight formulation uses $u_k = \max(0, H - B_k)$ and feasibility $H \le U_k + B_k$ ensures $u_k \le U_k$; for the $d$ side, $d_k = H - u_k \le H - (H - B_k) = B_k \le D_k$ when $u_k = H - B_k \ge 0$; when $u_k = 0 > H - B_k$, $d_k = H$, and $H < B_k \le D_k$ gives $d_k < D_k$. ✓ So feasibility holds exactly when $H \le \min_k (U_k + B_k)$ (also need $H \ge 0$, trivially satisfiable; max feasible $H = \min_k(U_k + B_k) \ge$ ... it's $\ge \min(U_k + D_k) \ge 2 > 0$). ∎

**Algorithm:** Compute $B$ via two passes (forward: $B_k = \min(D_k, B_{k-1} + X)$; backward: $B_k = \min(B_k, B_{k+1} + X)$) — standard distance-transform for $L_1$ metric. Then $H = \min_k (U_k + B_k)$, answer $= \sum(U_i + D_i) - N H$. Time $O(N)$, memory $O(N)$.
