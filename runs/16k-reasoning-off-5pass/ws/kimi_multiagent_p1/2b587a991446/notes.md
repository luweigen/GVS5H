## worker: finalize
- **Approach:** The answer is the minimum over three exchange strategies, all computed in O(N+M):
  1. **A1 (cycle through both S and T):** the two tokens take the two vertex-disjoint arcs of a cycle containing both endpoints; cost = cycle length. Computed as min over edges (u,v) of `dS[u]+1+dT[v]`, keeping only candidates whose reconstructed shortest paths are internally vertex-disjoint (otherwise the formula underestimates).
  2. **A3 (cycle through exactly one endpoint):** cost = `|C| + 2·dist(other endpoint, C)`; the near-endpoint token routes around the cycle arc while the other walks in and parks. Shortest cycle through a vertex is found via BFS tree + best non-tree edge joining different top-level subtrees.
  3. **A2 (pocket pass):** one token steps one vertex off the route (2 extra moves) at a junction w; cost = `2·(dS[w]+dT[w]) + 2`, with a +2 penalty when w ∈ {S,T} because the token parking at the endpoint blocks the junction and forces a second dodge (star-center case = 6 = 2d+4).
- **Feasibility:** impossible iff the graph is a path (connected, M = N−1, max degree ≤ 2) — token order on a path is invariant.
- **Complexity:** O(N + M) overall (a few BFS passes and edge scans).
- **Caveat:** The A1 disjointness check via greedy path reconstruction may reject valid candidates if the greedy choice picks a non-disjoint pair when a disjoint pair of the same length exists; the fallback loop over all edges mitigates this. The pocket condition in A2 uses a distance-level heuristic for "x not forced onto the routes." These are the two spots most likely to need refinement against the brute-force oracle battery (which I could not execute in this environment); the overall min(A1, A2, A3) framework is derived from and consistent with all hand-verified cases: samples (3, −1, 4), C_n → n, star center-leaf and leaf-leaf → 6, triangle+tail S=1,T=4 → 5, lollipop cases.
