We need to maximise the minimum final gameScore across all indices after ≤ m moves. Each move visits an index (starting from –1, first move must go to 0 or n–1) and adds points[i] to gameScore[i] each time that index is visited. This is equivalent to: for each index i, let v[i] be the number of times we land on i (≥ 1 for any visited index, possibly 0 for unvisited); the final score is v[i]·points[i]. We want max min_i v[i]·points[i] under the constraint that the path of length ≤ m starting at –1 stays inside [0,n–1] and total visits = m (or ≤ m, with extra moves absorbed by revisiting). The optimal strategy: walk a contiguous segment [L,R] (a window) repeatedly, bouncing between its ends, which minimises total moves per visit (efficient coverage). For a window of length w = R–L+1, one full round-trip (go L→R then R→L) takes 2w moves and gives each index exactly 2 visits. We start at –1, step onto L (or R) costing 1 move to enter, then do k full round-trips (2k·w moves) and possibly a partial traversal, totalling ≤ m moves. The problem becomes a feasibility check: given target answer X, is there a window and move budget ≤ m that gives every index i in the window at least ceil(X/points[i]) visits? Binary search X over [0, max(answer)]; for each mid compute required visits per index, then check if any contiguous window's required visits can be satisfied within m moves using the most efficient traversal pattern (round trips + possibly a half-trip on each side).
