
## ideation
The problem asks for the maximum total score obtainable by repeatedly removing adjacent pairs from a sequence of length N, scoring the absolute difference of the removed pair each time. The process stops when at most one element remains, so exactly floor(N/2) operations are performed.

This is equivalent to selecting a non-crossing matching of size floor(N/2) on a line of N vertices, where the weight of edge (i, j) is |A_i - A_j|, and the total score is the sum of weights of the chosen edges. The matching is non-crossing (no two edges cross) and can be nested (one edge inside another). This is exactly the maximum weight non-crossing matching problem.

A key observation is that the total score can be rewritten using the identity |a - b| = a + b - 2·min(a, b). Since each element appears in exactly one pair (except possibly one left over when N is odd), the sum of a + b over all pairs is fixed: it equals the total sum of all elements minus the unpaired element (if any). Therefore, maximizing the total score is equivalent to minimizing the sum of the minimums of each pair.

Let k = floor(N/2). To minimize the sum of the k minimums, we would like the minimums to be the k smallest elements of the whole array. However, the non-crossing constraint may prevent us from pairing the k smallest elements arbitrarily with larger elements. Surprisingly, the optimal total score is achieved by a simple formula based only on the sorted values, without needing to consider the original positions or the non-crossing geometry. Specifically, after sorting the array B[1..N] in non-decreasing order, the maximum total score is:

- If N is even: total = sum_{i=1}^N B[i] - 2 * sum_{i=1}^{N/2} B[i].
- If N is odd: total = sum_{i=1}^N B[i] - B[(N+1)/2] - 2 * sum_{i=1}^{(N-1)/2} B[i].

This works because we can always realize the required pairs by a non-crossing matching: pair the smallest remaining with the largest remaining, recursively. This pairing is non-crossing in the original order (it corresponds to a "balanced" nesting) and yields exactly the formula above. The derivation shows that leaving the median element unpaired (when N is odd) is optimal.

Pitfalls:
- One might think greedy removal of the maximum adjacent difference works, but counterexamples show it fails.
- The problem is not just about adjacent differences; pairs can be formed between elements that become adjacent after inner removals.
- The formula above reduces the problem to sorting and computing prefix sums, which is O(N log N) due to sorting (N up to 3e5 is fine).
