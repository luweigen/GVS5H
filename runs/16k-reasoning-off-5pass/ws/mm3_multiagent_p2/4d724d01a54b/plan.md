We need the minimum total cost to sort permutation P using adjacent swaps where swapping positions i and i+1 costs i. The optimal strategy is greedy: repeatedly fix the leftmost misplaced element by moving it directly to its target position using the cheapest possible cost path.

Concretely, for each value v from 1 to N, let cur = current index of v. It needs to go to position v. While cur > v, we swap v leftwards: each step swaps at position cur-1 (cost cur-1) and decreases cur by 1. Accumulate the sum of costs (cur-1) for each leftward step. Since v only moves left in this process, later elements are not disturbed in a way that increases cost (and moving right would only increase cost because positions are positive). This greedy yields the minimum total cost.

We simulate this efficiently with a Fenwick tree (BIT) over N. Initially BIT[pos] = 1 for all positions, representing "free slots". To move v from current position cur to v, we query how many free slots exist in range [v, cur], which equals the number of leftward moves needed: steps = sum(v..cur) - 1. The cost contributed is sum_{k=v}^{cur-1} k = (steps)*(v + cur-1)/2. We then update BIT at position cur to 0 (remove the free slot), and add a free slot at position v (update BIT at v to 1). Actually we just need to mark the original position as used and add one at destination. We process v=1..N, tracking the current position of v via the BIT (find k-th free slot) for efficiency O(log N) each.
