We can solve this with dynamic programming using Convex Hull Trick (CHT) optimization. The state is `dp[i]` = minimum cost to partition the prefix `nums[0..i-1]`. Transition: for a partition ending at `i` (previous cut at `j`), the sum of `nums` up to `i-1` is `S[i] = S[i-1] + nums[i-1]`, and sum of `cost` is `C[i]`. The subarray `[j, i)` becomes the `t`-th group where `t = groups_so_far + 1`. The `t` depends on how many groups before `j`, which makes the formula quadratic in naive form. We reformulate: let `dp[i]` = min cost; when we make a cut before `i`, the contribution of group number can be expressed using prefix sums. The standard reformulation gives a linear function in `C[j]` times `S[i] + k * something`, enabling CHT. Use Li Chao segment tree or deque-based CHT since queries are monotonic in slopes. With n ≤ 1000, even O(n²) suffices, but implementing O(n log n) with CHT is clean. We'll implement a CHT with lines `y = m*x + b` where `m = C[j]`, `b = dp[j] - (S[j] + k) * C[j] - k * (something involving group count)`. Since group count equals the number of partitions, we can precompute `dp` iteratively; each `dp[i]` is the i-th position's minimum. Simpler O(n²) with n=1000 is acceptable. We'll use O(n²) DP for correctness and clarity: for each i, try all j<i, compute the subarray cost, take min. This is fast enough (10⁶ ops) and avoids CHT complexity.
