
## ideation
The problem requires finding the minimum number of vertex deletions so that the remaining induced subgraph is a "Snowflake Tree": a central vertex connected to exactly `x` internal vertices (blue), each of which has exactly `y` leaf neighbors (green). The key insight is that for a fixed center `c`, we can choose any subset of its neighbors to be blue vertices, and for each blue neighbor `v`, we can choose any number of leaves from 1 to `deg(v)-1`. All blue vertices must have the same number of leaves `y`. Thus, for a given center `c`, we need to find the maximum value of `1 + x*(1+y)` over all possible choices of `x` (number of blue neighbors) and `y` (common number of leaves), subject to the constraint that for each of the `x` chosen neighbors `v`, `deg(v)-1 ≥ y`. To maximize, we should choose the `x` neighbors with the largest degrees, so that the minimum degree among them is as large as possible. Therefore, for each center, we can sort the degrees of its neighbors (ignoring those with degree 1) in descending order, and for each `x` from 1 to the number of eligible neighbors, compute `y = min_degree - 1` (where `min_degree` is the degree of the `x`-th largest neighbor), then compute `kept = 1 + x*(1+y)`. The maximum over all centers gives the maximum number of vertices we can keep, and the answer is `N - max_kept`.

The algorithm works by iterating over each possible center vertex. For each center, we consider only neighbors with degree at least 2 (since a blue vertex must have at least one leaf). We sort these neighbor degrees in descending order so that for any number `x` of blue vertices, we can achieve the maximum possible `y` (the common number of leaves) by picking the `x` neighbors with the largest degrees; then `y` is the minimum degree among those minus 1. We compute the total kept vertices as `1 + x*(1+y)` and track the maximum over all centers. The answer is `N - max_kept`. The complexity is `O(N log N)` due to sorting neighbor lists, which is efficient for `N ≤ 3e5`.
