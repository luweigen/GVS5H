We need to support N insertions where each new number `i` (1..N) is inserted at position P_i (1-indexed) of the current array, pushing later elements to the right. N can be up to 5e5, so an O(N²) approach (like Python list insert) is too slow. The classic trick is to process insertions in reverse order using a balanced binary indexed tree (Fenwick) or a segment tree to find the k-th empty slot. Process i from N down to 1: the final position of i is the P_i-th empty slot in the current "free positions" list. Use a Fenwick tree storing 1 for each free position; to find the P_i-th free slot, binary search on the prefix sum. Then mark that slot as occupied (set to 0) and place i there. After processing all i, we have the final array of length N.
