We need the minimum total increments (each increment is +1 to a single `nums[i]`) so that every `t` in `target` has at least one `nums[i]` that is a multiple of `t`. Since `target` length ≤ 4, we can enumerate all assignments of each target to a distinct `nums` element (permutations, at most `4! = 24`). For each assignment, compute for every chosen `nums[i]` the minimum increment to reach the smallest multiple of its assigned target that is ≥ `nums[i]`; the cost is the sum of those increments. The answer is the minimum over all assignments.

We also need to consider the case where a single `nums[i]` can satisfy multiple targets (as in example 2: one element becomes a multiple of both 5 and 10). This is naturally handled because we may assign multiple targets to the same `nums` index — but we must ensure we don't reuse the same index for the same target twice. Since `target[i] ≤ 10^4` and there are ≤ 4 targets, the assignment space is `n * (n-1) * ...` permutations of length `len(target)`, which is at most `n^4` ≈ 6.25e18 worst case — too large. However, we can optimize by DP: `dp[mask][i]` = minimum cost to satisfy the targets in `mask` using the first `i+1` elements, with the last target assigned to element `i`. This gives `O(2^T * T * N)` = `O(16 * 4 * 5e4) = 3.2e6`, which is efficient.

For each transition: given current `dp[mask][i]`, we try to assign target `j` (not yet in mask) to element `i`, computing cost to raise `nums[i]` to the next multiple of `target[j]`. Also we can consider not using element `i` at all (carry over `dp[mask][i-1]`).
