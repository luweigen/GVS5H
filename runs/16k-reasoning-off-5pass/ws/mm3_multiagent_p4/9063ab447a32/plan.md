We have N products each with per‑unit cost P_i, and buying k units of product i costs k^2 * P_i. We need to maximize total units ∑k_i with ∑k_i^2 P_i ≤ M. Since the cost grows quadratically, it's optimal to greedily buy from the cheapest P_i first. For a sorted P_i, we buy a block of units x from the current cheapest product (compute max x with x^2 * P_i ≤ remaining M), then move to the next product. This greedy works because any cost spent on a more expensive P_j could have bought at least as many units at a cheaper P_i. The complexity is O(N log N) for sorting plus O(N) scanning. To avoid huge loops when P_i is tiny (worst case M/P_i up to 10^9), we cap the per‑product buy at sqrt(M / min P_i) ≈ 3·10^8, which fits in int64. The remaining M is tracked in Python int (unbounded), and total answer can be up to ~3·10^13, so we use Python integers throughout.
