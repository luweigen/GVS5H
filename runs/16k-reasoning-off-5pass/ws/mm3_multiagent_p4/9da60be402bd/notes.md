
## ideation
The task: for every ordered pair \((i,j)\) in a directed graph with at most one edge per ordered pair (possibly labeled by a lowercase letter, otherwise absent), find the length of the shortest walk (repetition of vertices/edges allowed) whose concatenated edge labels form a palindrome (the empty string counts as a palindrome). If none exists, output -1.

Constraints: \(N\le 100\), alphabet 26 letters. Graph can be dense (up to \(N^2\) edges). We must answer \(N^2\) queries.

Key observations:
1. A walk of length \(L\) with palindrome string can be thought of as building the string from both ends: we choose a middle point (a vertex) and expand simultaneously left and right. Each expansion uses an edge (forward direction) on the left side and an edge (backward direction) on the right side; the two edges must have the same label.
2. A walk may have an odd number of characters: then one side (the middle edge) is unpaired. In the palindrome, the middle character can be anything; it corresponds to taking a single edge without requiring a matching opposite edge.
3. Therefore any palindrome walk can be described as a sequence of “paired steps” (two edges with same label taken symmetrically) and possibly one “middle edge” (if length is odd). The order of traversal is: we start at vertex \(i\); we repeatedly take a step forward (using an original edge) to build the left half, then eventually take a middle edge (if odd), then take steps backward (using reverse edges) to rebuild the right half, ending at \(j\).

A convenient formalism: state = (vertex \(v\), side \(s\), balance \(b\)):
- side \(0\): we are currently building the forward half (still to the left of the middle).
- side \(1\): we are currently building the reverse half (already passed the middle, moving backward).
- balance \(b\): net number of forward steps taken minus reverse steps already taken (i.e., how many characters have been added to the left side but not yet matched on the right). When \(b=0\) the string built so far is a palindrome prefix (and if we are at side \(0\) we are still before the middle; if side \(1\) we are after the middle, but palindrome property already ensured).

The solution uses the standard product-graph BFS technique for shortest palindrome walks.  
- States are pairs `(u, v)` representing that we have built a forward path from `i` to `u` and a reverse path from `j` to `v` with matching labels.  
- A product-graph step corresponds to traversing one edge forward and one edge backward simultaneously with the same label; the original walk length increases by 2.  
- Even-length palindromes end when the two paths meet at the same vertex: state `(v, v)`.  
- Odd-length palindromes end with a middle edge: state `(v, w)` where `v→w` exists; the walk length is `2·dist + 1`.  
- For each target `j`, we run a BFS on the **reverse** product graph starting from the set `S_j = {(j, j)} ∪ {(v, j) | ∃ edge v→j}`. This efficiently computes distances from every source `(i, j)` to `S_j` in `O(N)` BFS runs instead of `O(N²)`.  
- Distances are stored per source during the BFS when the current state's second coordinate equals `j`.  
- Complexity: Each BFS processes up to `N²` states; neighbor generation takes `∑_c outdeg_c(u)·indeg_c(v)`. In the worst case this is `O(N⁴)` per BFS, but with `N=100` the total work remains within limits (≈10⁸ operations per BFS, optimized via label-specific adjacency lists and early termination).
