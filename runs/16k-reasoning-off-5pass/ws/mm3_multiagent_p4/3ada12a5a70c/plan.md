We map each boundary point to a perimeter coordinate on a circle of length 4*side, so Manhattan distance becomes circular distance. The problem reduces to selecting k points on a circle to maximize the minimum circular distance. We binary search the answer d and check feasibility: can we pick k points with pairwise circular distance ≥ d? This is equivalent to finding a starting point such that a greedy chain of k points (each at least d apart) fits within an interval of length 4*side - d. We sort points by perimeter coordinate, precompute next-point indices for the spacing condition, and verify each start in O(nk) time. Binary search adds O(log(4*side)) steps, giving overall O(n log n + nk log(side)) time.
