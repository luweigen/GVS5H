We need to count subarrays that can be made non-decreasing by incrementing elements with total operations ≤ k. For a subarray to be fixable, we need to raise smaller elements to be at least the running maximum. If we traverse left→right, the cost to fix a subarray `nums[l..r]` is the sum over positions of `max(0, max_so_far - nums[i])` where `max_so_far` is the max seen so far in the subarray. This is a classic sliding-window problem where we maintain the right endpoint and try to expand while the total cost ≤ k. When adding a new element increases cost beyond k, we shrink from the left. Since the maximum of the window can change, we need a data structure (like a decreasing stack of `nums` values with their positions) to efficiently compute the cost of raising elements to the current maximum as the window slides. We maintain a sorted (by value) structure to support queries of the form: given a current max `M`, compute the sum of deficits `max(0, M - nums[i])` over the window. Using a monotonic stack and Fenwick tree / sorted containers by value, we can update and query in O(log n) amortized per step. After this, for each `r`, the number of valid left endpoints equals the minimal `l-1` such that cost ≤ k — we count the size of the window.
