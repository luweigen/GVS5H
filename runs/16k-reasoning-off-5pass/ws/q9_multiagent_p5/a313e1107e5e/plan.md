The problem asks for the length of the longest strictly increasing subsequence (LIS) within the prefix $A[1 \dots R_i]$ where all elements are $\le X_i$. Since $N, Q \le 2 \times 10^5$, an $O(N^2)$ or $O(N \cdot Q)$ solution is too slow. We can process queries offline by sorting them based on $R_i$. As we iterate through the array $A$ and increase the current index $R$, we maintain a data structure that stores the LIS lengths for various values. Specifically, for a fixed $R$, let $dp[v]$ be the length of the longest strictly increasing subsequence ending with a value $v$ using only elements from $A[1 \dots R]$. When moving from $R$ to $R+1$, if $A_{R+1} \le X_{max}$ (conceptually), we update the DP state: $new\_len = 1 + \max(\{dp[v] \mid v < A_{R+1}\} \cup \{0\})$. This update can be efficiently handled using a Fenwick tree (Binary Indexed Tree) or Segment Tree over the coordinate-compressed values of $A$. After processing all elements up to $R_i$, the answer for a query $(R_i, X_i)$ is the maximum value in the data structure for all indices corresponding to values $\le X_i$.
