The problem requires maximizing the sum of distinct elements in three contiguous subarrays. Since $N$ is up to $3 \times 10^5$, an $O(N^2)$ solution is too slow. We can fix the middle split point $j$ and optimize the first and second split points. However, a more efficient approach is to iterate over the split point between the first and second subarray ($i$) and the split point between the second and third ($j$). Actually, a standard technique for this "three parts" problem is to iterate over the split point between the first and second part ($i$), and then find the optimal $j > i$. To do this efficiently, we can precompute suffix information. Specifically, for each possible $i$, we want to maximize `distinct(A[i+1...j]) + distinct(A[j+1...N])`. We can precompute the maximum value of `distinct(A[j+1...N])` for all $j$, and then for a fixed $i$, we need to maximize `distinct(A[i+1...j]) + suffix_max[j]`. We can use a Segment Tree or a similar data structure to maintain the values of `distinct(A[i+1...j])` as we iterate $i$ from left to right, updating the structure as the window expands. Alternatively, since the constraints on values are $A_i \le N$, we can use a Segment Tree where the leaves represent the contribution of each value to the distinct count. A simpler $O(N \log N)$ approach: Iterate $i$ from $1$ to $N-2$. As $i$ increases, the first part shrinks. As we move $i$ to $i+1$, the range $(i+1..j)$ changes. This suggests we can iterate $j$ from $2$ to $N-1$ and maintain the best $i < j$. Let's reverse: Iterate $j$ from $2$ to $N-1$. Correct approach: Iterate $i$ (split between 1st and 2nd) from $1$ to $N-2$. We need $\max_{j=i+1}^{N-1} (\text{distinct}(i+1..j) + \text{distinct}(j+1..N))$. Let $f(j) = \text{distinct}(j+1..N)$. We need $\max_{j} (\text{distinct}(i+1..j) + f(j))$. As $i$ increases, the range $(i+1..j)$ shrinks from the left. We can maintain a data structure that stores $\text{distinct}(i+1..j) + f(j)$ for all valid $j$. When moving from $i$ to $i+1$, the element $A_{i+1}$ is removed from the start of the middle segment. We can update the distinct counts for all $j \ge i+1$. This can be done efficiently. Specifically, we can use a Segment Tree over the indices $j \in [2, N-1]$. The leaf at $j$ stores $\text{distinct}(i+1..j) + f(j)$. When moving $i \to i+1$, we remove $A_{i+1}$ from the prefix. For all $j \ge i+1$, if $A_{i+1}$ was the first occurrence in $(i+1..j)$, the distinct count decreases by 1. We can find the range of $j$ where $A_{i+1}$ is the first occurrence in $(i+1..j)$. When we move the left boundary of the middle segment from $i+1$ to $i+2$, we are effectively removing $A_{i+1}$ from the consideration. For any $j$, if $A_{i+1}$ appears in $(i+1..j)$, its contribution to the distinct count of $(i+1..j)$ might disappear if it was the only occurrence. But since we are increasing the left bound, we are removing elements from the left. $A_{i+1}$ is removed. If $A_{i+1}$ does not appear again in $(i+2..j)$, then the distinct count of $(i+1..j)$ decreases by 1. The condition "does not appear again in $(i+2..j)$" means the next occurrence of $A_{i+1}$ is at index $> j$. So for all $j$ such that $next\_occurrence(A_{i+1}) > j$, the distinct count decreases by 1. We can identify this range $[i+2, next\_occurrence(A_{i+1}) - 1]$ and subtract 1 from the stored values in our Segment Tree for these indices. Then we update the max. This is $O(N \log N)$.
