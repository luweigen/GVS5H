1. Sort the input array S to easily access elements in increasing order.
2. Use a boolean array (or set) for O(1) existence checks since values are up to 10^6.
3. Iterate over all possible middle elements B in S. For each B, iterate over all possible A in S such that A < B.
4. Calculate C = 2*B - A. If C > B and C exists in S, increment the count.
5. To optimize, note that for a fixed B, A must be less than B and C = 2B - A must be at most max(S). This limits the range of A.
6. The total complexity will be O(N * max_val) in the worst case if not careful, but since we iterate A over existing elements, it's O(N^2) which is too slow for N=10^6. We need a better approach.
7. Better approach: Iterate over the difference d. For each d, count pairs (A, C) such that C - A = 2d and B = A + d is in S. This can be done by iterating over A and d, but still potentially O(N * max_val).
8. Actually, since max(S) is 10^6, we can use a frequency array. For each B in S, and for each possible difference d >= 1, check if B-d and B+d are in S. The number of d values for each B is at most max(S)/2. Total operations ~ sum over B of (max(S)/2) which is O(N * max_val) = 10^12, too slow.
9. Optimized approach: Use FFT or simply iterate over all pairs (A, C) with A < C, compute B = (A+C)/2, and check if B is integer and in S. This is O(N^2) which is too slow for N=10^6.
10. Key insight: Since values are bounded by M=10^6, we can use a bitset or boolean array. For each B in S, the number of valid A's is limited by the fact that A = B - d and C = B + d must both be in S. We can iterate d from 1 to min(B-1, M-B). For each d, check if B-d and B+d are in S. The total work is sum_{B in S} min(B-1, M-B). In the worst case, this is O(N * M) which is 10^12.
11. Wait, let's reconsider. N is up to 10^6, but M is also 10^6. The worst case is when S contains all numbers from 1 to 10^6. Then for each B, we check d from 1 to min(B-1, M-B). The total number of checks is sum_{B=1}^{M} min(B-1, M-B) which is O(M^2) = 10^12, too slow.
12. Better: Use the fact that we can iterate over all possible differences d. For a fixed d, we want to count B such that B-d in S, B in S, and B+d in S. This is equivalent to counting B in S such that B-d in S and B+d in S. We can do this by iterating d from 1 to M/2, and for each d, iterate over B in S such that B-d >= 1 and B+d <= M. But this is still O(M^2) in worst case.
13. Actually, the constraint N <= 10^6 and S_i <= 10^6 suggests an O(M log M) or O(M) solution. Let's use a boolean array `exists` for O(1) lookups. Then for each B in S, we iterate d from 1 to min(B-1, M-B). If exists[B-d] and exists[B+d], count++. The total number of iterations is sum_{B in S} min(B-1, M-B). In the worst case (S = {1,2,...,M}), this sum is approximately M^2/4 = 2.5 * 10^11, which is too slow for Python.
14. We need a faster method. Let's use FFT. Create a polynomial P(x) where the coefficient of x^i is 1 if i in S, 0 otherwise. Then the number of triplets is the sum over B in S of (number of A in S such that 2B-A in S). This is equivalent to convolving the indicator array with itself and then summing appropriate terms. Specifically, let Q(x) = P(x) * P(x^{-1}) but we need to be careful with indices.
15. Alternatively, note that for each pair (A, C) with A < C and A+C even, B = (A+C)/2 must be in S. So we can iterate over all pairs (A, C) with A < C, check if A+C is even, and if (A+C)/2 is in S. This is O(N^2) which is too slow.
16. Let's go back to the d-iteration approach but optimize. The total number of pairs (A, C) with A < C and C-A even is what we need. We can group elements by parity. Let S_even and S_odd be the subsets of S with even and odd values. For each parity group, we want to count pairs (A, C) with A < C, C-A even (always true within same parity), and (A+C)/2 in S.
17. For a fixed parity, let T be the sorted list of elements in that parity group. For each B in T, we want to count A in T with A < B such that 2B-A is in S. This is still O(N^2) in worst case.
18. Given the constraints and time limits, the intended solution in C++ might use the O(M^2) approach with optimizations, but in Python, we need something faster. However, note that in practice, the number of valid d for each B is small if S is sparse. But worst case is dense.
