1. Model the problem as a system of XOR equations over a graph where nodes are indices $1 \dots N$ and edges $(X_i, Y_i)$ have weight $Z_i$, meaning $A_{X_i} \oplus A_{Y_i} = Z_i$.
2. Decompose the graph into connected components. For each component, pick an arbitrary root node and assign it a temporary value (initially 0) to determine the relative values of all other nodes in the component via BFS/DFS.
3. During traversal, check for consistency: if we encounter an already visited node, verify that the implied XOR difference matches the edge weight. If any contradiction is found, output -1.
4. For each connected component, the absolute values of the nodes are determined up to a global XOR constant $C$ for that component. That is, $A_i = V_i \oplus C$, where $V_i$ is the relative value computed in step 3.
5. To minimize the sum $\sum A_i$, we need to choose $C$ such that $\sum (V_i \oplus C)$ is minimized. Since $Z_i \le 10^9 < 2^{30}$, we can determine the optimal $C$ bit by bit from most significant to least significant (or independently per bit because XOR operations on different bits don't interfere). For each bit position $k$, count how many $V_i$ in the component have the $k$-th bit set. If more than half have it set, setting the $k$-th bit of $C$ to 1 will flip those to 0 and the others to 1, potentially reducing the sum. Specifically, for each bit $k$, if the number of elements with bit $k$ set in $V$ is greater than half the component size, we should set bit $k$ of $C$ to 1; otherwise 0. This minimizes the sum of the $k$-th bits across all elements.
6. Construct the final sequence using the optimal $C$ for each component and print it.
