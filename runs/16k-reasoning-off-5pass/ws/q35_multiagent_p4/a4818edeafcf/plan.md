1. The problem asks to split array A into three non-empty contiguous subarrays by choosing two split points i and j (1 <= i < j <= N-1), maximizing the sum of distinct counts in each subarray.
2. A naive O(N^2) approach is too slow for N up to 3*10^5. We need an O(N) or O(N log N) approach.
3. Key insight: For a fixed middle subarray A[i+1..j], the total distinct count is distinct(A[1..i]) + distinct(A[i+1..j]) + distinct(A[j+1..N]). We can precompute prefix distinct counts and suffix distinct counts.
4. However, iterating over all i,j is still O(N^2). We need to optimize. Notice that for a fixed j, we want to maximize distinct(A[1..i]) + distinct(A[i+1..j]) for 1 <= i < j. But distinct(A[i+1..j]) depends on i as well, making it tricky.
5. Alternative approach: Iterate over the middle subarray's right endpoint j from 2 to N-1. For each j, the middle subarray ends at j. The left part is A[1..i] and middle is A[i+1..j]. We need max over i of (prefix_distinct[i] + distinct(A[i+1..j])). This still seems hard because distinct(A[i+1..j]) changes with i.
6. Better approach: Use the fact that we can iterate j from 2 to N-1, and maintain information about the best left split. Actually, a known technique for this problem is to iterate the middle cut point and use a sweep-line with a data structure. Let's precompute L[i] = distinct(A[1..i]) and R[j] = distinct(A[j..N]). Then for a fixed middle subarray A[i+1..j], the answer is L[i] + distinct(A[i+1..j]) + R[j+1]. We can iterate j from 2 to N-1, and for each j, we need max_{1<=i<j} (L[i] + distinct(A[i+1..j])). As j increases, distinct(A[i+1..j]) increases by 1 if A[j] is new in A[i+1..j], else stays same. This suggests we can maintain for each i the value L[i] + distinct(A[i+1..j]) as j increases. We can use a segment tree or similar structure to query the maximum efficiently.
