1. Since we need to maximize the minimum Manhattan distance, this is a classic "maximize the minimum" problem which can be solved using binary search on the answer (the distance).
2. The possible range for the answer is from 0 to 2*side (the maximum possible Manhattan distance on the boundary).
3. For a given candidate distance `mid`, we need to check if it's possible to select at least `k` points such that every pair of selected points has a Manhattan distance >= `mid`.
4. Because k is very small (<= 25), we can use a greedy approach with backtracking or simply try to build a subset greedily: sort points by their perimeter position, then iteratively pick the next point that is at least `mid` away from the last picked point. However, a simple greedy might not be optimal. Instead, since k is small, we can use a recursive backtracking with pruning: try to pick points one by one, ensuring the distance constraint.
5. Actually, a more efficient check for small k: sort the points along the perimeter of the square. Then use a recursive function that tries to pick k points. To optimize, we can use memoization or simply rely on the fact that k is small (<=25) and the number of points is up to 15000. But worst-case backtracking is O(n^k) which is too slow.
6. Better approach for the check: Since k is small, we can use a greedy strategy that works for 1D arrays: sort points by perimeter coordinate, then iterate and pick the first point, then the next point that is at least `mid` away, etc. This greedy works for the "maximize minimum distance" problem when points are on a line (or perimeter mapped to 1D). We map each point to its perimeter coordinate, sort, and then greedily select.
