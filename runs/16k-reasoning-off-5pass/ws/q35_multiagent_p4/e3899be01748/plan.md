1. Iterate through each digit in the string, treating it as the last digit of potential substrings.
2. For each position `j` (last digit index), iterate backwards to find all starting positions `i`.
3. Maintain the numeric value of the substring `s[i..j]` modulo `d` (where `d` is the last digit `s[j]`). If `d` is 0, skip as per problem constraints (non-zero last digit).
4. If the current substring value modulo `d` is 0, increment the count.
5. To optimize, note that for a fixed last digit `d`, we can compute the remainder incrementally. However, since `N` is up to $10^5$, an $O(N^2)$ solution might be too slow if the constant factor is high. But notice that for each `j`, we only need to check substrings ending at `j`. The number of substrings is $O(N^2)$ in worst case. We need a more efficient approach.
6. Actually, for each last digit `d` (1-9), we can process indices where `s[j] == d`. For each such `j`, we want to count `i <= j` such that `int(s[i..j]) % d == 0`. We can compute the value of `s[i..j]` mod `d` efficiently. Let `val(i, j)` be the integer value. `val(i, j) = val(i, j-1)*10 + s[j]`. This suggests we can maintain remainders. But since `d` changes, we can group by `d`. For a fixed `d`, iterate `j` from 0 to n-1. If `s[j] == d`, we want to count `i` such that the number formed by `s[i..j]` is divisible by `d`. We can compute the remainder of `s[i..j]` mod `d` by keeping track of powers of 10 mod `d`. Specifically, `s[i..j] = sum_{k=i}^j s[k] * 10^{j-k}`. This can be rewritten as `10^j * sum_{k=i}^j s[k] * 10^{-k}` mod `d`. We can precompute prefix sums of `s[k] * 10^{-k}` mod `d` for each `d`. Then for each `j` with `s[j]==d`, the count is the number of `i` such that `prefix_sum[j+1] - prefix_sum[i] == 0 mod d` (adjusted for the `10^j` factor). This gives an $O(N \cdot 9)$ or $O(N)$ solution.
