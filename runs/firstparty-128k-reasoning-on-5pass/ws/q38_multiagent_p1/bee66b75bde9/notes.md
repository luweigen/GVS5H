- **Valid shape:** A grid satisfying both prefix conditions is exactly a Ferrers diagram anchored at the top-left. If `r_x` is the number of black cells in row `x`, then `r_1 >= r_2 >= ... >= r_N`. Equivalently, black cells form an order ideal: if `(x, y)` is black, then every `(x' <= x, y' <= y)` is black.
- **Chosen check:** Use only fixed black cells to compute the minimal forced black region, the closure of all fixed black cells. A fixed white is impossible exactly when it lies in this closure.
- **Dominance condition:** A white cell `(x, y)` lies in the closure iff there is a fixed black cell `(xb, yb)` with `xb >= x` and `yb >= y`. Thus we need to detect such a pair.
- **Sweep:** Sort all given cells by row descending. For cells in the same row, process black before white. Maintain `max_y_black`, the maximum column among black cells already processed. When a white cell `(x, y)` is seen, all processed black cells have row `>= x` (and same-row blacks are included), so `y <= max_y_black` means a dominating black exists; print `No`. For a black cell, update `max_y_black = max(max_y_black, y)`. If no conflict, print `Yes`.
- **Sufficiency:** If no conflict, color exactly the closure of the fixed black cells black and all other cells white. This region is an order ideal, so it satisfies both row and column prefix conditions. It contains every fixed black cell. The sweep proves it contains no fixed white cell; consequently it also contains no cell forced white by a fixed white, because any such cell would dominate that white and make the white itself lie in the closure.
- **Necessity:** If a white cell is dominated by a fixed black cell, every valid completion containing that black cell must also contain the white cell, contradiction.
- **Complexity:** `O(M log M)` time for sorting, `O(M)` memory. `N` can be up to `1e9` and is not used; no array of size `N` is allocated.
- **Pitfalls:** Use `<=` for white cells, not `<`, because a black cell in the same column below forces the white cell black. Process larger row numbers first. In the same row, black events must precede white events; otherwise a same-row black to the right would be missed. Use bytes comparison `c == b'B'` when reading with `sys.stdin.buffer`.
- **Relation to row bounds:** This dominance check is equivalent to checking feasibility of nonincreasing row-length bounds, but it avoids explicitly propagating bounds and is simpler to implement.
