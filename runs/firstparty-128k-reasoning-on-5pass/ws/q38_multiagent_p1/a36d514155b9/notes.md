- **Core reduction:** A valid arrangement is a k-subset of N = m*n cells. For any fixed unordered pair of cells, exactly C(N - 2, k - 2) arrangements contain that pair, so the answer is that binomial factor times the sum of Manhattan distances over all unordered cell pairs.
- **Manhattan split:** Manhattan distance separates into row difference plus column difference. The row contribution is the sum over unordered row pairs of their distance, multiplied by n^2 possible column choices. The column contribution is symmetric, multiplied by m^2.
- **1D closed form:** For L positions, sum_{i<j} (j - i) = sum_{d=1}^{L-1} d(L - d) = L(L^2 - 1) / 6. Therefore the full grid pair-distance sum is n^2 * m(m^2 - 1) / 6 + m^2 * n(n^2 - 1) / 6.
- **Modulo arithmetic:** Use MOD = 10^9 + 7 and INV6 = pow(6, MOD - 2, MOD). All divisions by 6 are done by multiplying with INV6. Reduce m and n modulo MOD before squaring.
- **Binomial computation:** Factorials and inverse factorials are cached in class attributes. The first call precomputes up to at least 100000, matching the constraint m*n <= 100000; larger limits extend the arrays if ever needed. C(N, R) = fact[N] * invfact[R] * invfact[N - R] mod MOD, with correct handling of R = 0 and R = N.
- **Verification:** m = 2, n = 2, k = 2 gives C(2, 0) * (4*1 + 4*1) = 8. m = 1, n = 4, k = 3 gives C(2, 1) * (1*0 + 1*10) = 20. Brute force over all k-subsets for small grids, such as m, n up to 3 and all valid k, matches the formula.
- **Complexity:** O(100000) precomputation once, then O(1) per query within constraints. Memory is O(100000) for the factorial and inverse-factorial arrays.
