Model the final string as runs of length at least 3 and use a suffix DP over position and current run character. Let `G[i][c]` be the minimum cost to complete from position `i` when the previous run is `c` and already has length at least 3; from there we either continue `c` or start a new run `x != c`, which forces `x` at positions `i`, `i+1`, and `i+2`. Compute `G` backwards in `O(26n)` by keeping the smallest and second smallest switch costs for each `i`. The total optimum is the minimum cost to make the first three positions a run plus `G[3][x]`. To get the lexicographically smallest optimum, greedily append the smallest next character that can still achieve the stored remaining optimal cost, forcing the current character until its run reaches length 3. Return an empty string when `n < 3` or the optimum is infinite.
