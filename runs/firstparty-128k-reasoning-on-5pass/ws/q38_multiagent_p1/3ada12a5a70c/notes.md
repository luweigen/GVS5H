- **Reduction:** For k >= 4 the optimum is at most side. For any D <= side, Manhattan distance >= D is equivalent to shorter perimeter distance >= D. Same-side and adjacent-side pairs have equal Manhattan and perimeter distances; opposite-side pairs both have distance at least side, so they are automatically safe for D <= side.
- **Perimeter mapping:** Use a clockwise coordinate in [0, 4*side). Bottom y=0 maps to x; right x=side maps to side+y; top y=side maps to 2*side+side-x; left x=0 maps to 3*side+side-y. The condition order gives unique corner coordinates: (0,0)=0, (side,0)=side, (side,side)=2*side, (0,side)=3*side.
- **Feasibility check:** Sort perimeter coordinates, duplicate the array by adding C. For D=0 return true. Build nxt[i] with two pointers as the first index j where arr[j]-arr[i] >= D. For each start i < n, jump k-1 times. If idx reaches start+n, the selection would reuse the start point or leave one full circumference, so fail. If k points are reached, check the wrap gap arr[start]+C-arr[idx] >= D.
- **Greedy optimality:** For a fixed start, taking the earliest possible next point is dominant. By induction, the greedy r-th selected point is no later than the r-th point of any feasible selection from that start. Therefore, if any feasible k-point chain exists from that start, the greedy chain also stays within one circumference and has at least as large a final wrap gap.
- **Complexity:** Sorting is O(n log n). Each feasibility check is O(n + n*k) because nxt is built in O(n) and each start performs at most k-1 jumps. Binary search adds O(log side). With n <= 15000 and k <= 25, this is comfortably fast.
- **Edge cases:** D=0 is handled directly. The limit start+n is exclusive, preventing selection of the duplicate of the start point. The final wrap gap is explicitly checked. The upper bound C//k follows from the sum of k cyclic gaps being C. All points on one side still work because the wrap gap around the rest of the square is large. Integer coordinates make D=1 feasible whenever n >= k.
- **Verification:** The three examples return 2, 1, and 1. Edge cases checked include side=1 with four corners and k=4 returning 1, all points on one side reducing to ordinary 1D spacing, n=k requiring all cyclic gaps to be valid, and infeasible D values failing either by exceeding the one-circumference limit or by a too-small wrap gap.
- **Pitfalls:** Do not use strict > for allowed distance; distance at least D is valid. Do not allow idx = start+n. Do not map corners inconsistently. Do not binary search above side for k >= 4, because the Manhattan/perimeter equivalence can fail for D > side on opposite-side pairs.
- **Rejected alternatives:** Chain DP, circular-arc independent set, side-wise DP, and u/v Chebyshev transforms are more complex. The perimeter greedy check is exact for the needed range and simpler.
