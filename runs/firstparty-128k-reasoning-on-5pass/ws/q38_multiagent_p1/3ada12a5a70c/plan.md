We first prove the answer is at most `side`: for k≥4, either two chosen points share a side (distance ≤ side) or, in the one-per-side case, the four adjacent-side distances cannot all exceed side. Hence binary search only over D in [0, side]. For any D ≤ side, Manhattan distance < D is equivalent to shorter perimeter (circular) distance < D, so the problem becomes selecting k points on a circle of circumference 4*side with minimum circular distance at least D. Sort points by perimeter coordinate, duplicate the array, and for a candidate D compute `next[i]` as the first point at least D clockwise using two pointers. For each start, greedily follow `next` up to k points within one circumference; if k points are reached and the final clockwise gap back to the start is at least D, D is feasible. Greedy is optimal for a fixed start because the earliest feasible next point leaves the largest remaining arc, so binary search yields the answer.
