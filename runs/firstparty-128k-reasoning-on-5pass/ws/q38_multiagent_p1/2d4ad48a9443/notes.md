- **Cost model:** For a subarray, minimal increments equal sum over positions of (running maximum from the left - current value). Raising later elements to the running max is optimal; raising earlier elements cannot help.
- **Next greater chain:** `ng[i]` is first index to the right with strictly greater value, sentinel `n`. Equal values are not new maxima, so the running-max records for a start `l` are `l, ng[l], ng[ng[l]], ...`.
- **Segment aggregation:** A record `p` owns `[p, ng[p])`. Its full segment cost is `nums[p]*(ng[p]-p) - (pref[ng[p]]-pref[p])`. `root_cost[i]` is that segment cost plus `root_cost[ng[i]]`, computed right-to-left.
- **Binary lifting query:** `up[j][i]` is the 2^j-th next-greater ancestor. For `[l,r]` with `R=r+1`, jump to the farthest ancestor `p` with `p <= R`. `root_cost[l]-root_cost[p]` pays all complete segments before `p`; if `p <= r`, add the partial segment `[p,R)` using `nums[p]`. This gives O(log n) cost.
- **Two-pointer counting:** For fixed `r`, cost is nonincreasing as `l` increases, so valid starts form a suffix. Sweep `r`, advance `left` while `cost(left,r)>k`, add `r-left+1`. Total cost calls are O(n).
- **Complexity:** O(n log n) time and O(n log n) memory per call due to the jump table. For n=100000, LOG=17, so about 1.7M table entries; Python integers handle large costs and answers.
- **Pitfalls handled:** strict greater vs equal, sentinel `n`, inclusive `r` vs exclusive `R`, partial segment only when `p<=r`, enough jump levels via `(n+1).bit_length()`, and k=0 edge cases.
- **Small correctness:** The harness checks the two provided examples, fixed edge cases, and 200 small random arrays against a brute-force O(n^2) counter before the large sanity run.
- **Large sanity harness:** Runs n=100000 cases: random values in [1,1e9] with k=1e9 (bounds check), the same random array with k=1e18 (expected all subarrays), strictly increasing large values (expected all subarrays), strictly decreasing large values (expected formula), and all-equal large values (expected all subarrays).
- **Decreasing formula:** For consecutive strictly decreasing values, a length-L subarray costs L(L-1)/2. The maximum valid length is the largest L with L(L-1)/2 <= k, computed with `math.isqrt` and corrected by one-step loops. Count is `m*(n+1)-m*(m+1)//2`, capped at n.
- **Runtime/memory report:** Each large case prints wall time from `time.perf_counter` and peak RSS in MiB. On Linux/macOS it uses `resource.getrusage`; if unavailable, it falls back to `tracemalloc` for the solution call. The final line prints overall PASS/FAIL and total large time.
- **Expected performance:** Five 100k cases should finish in a few seconds; peak RSS is expected to stay in the tens of MiB to about 100 MiB depending on Python build and allocator.
