- **Marginal costs:** The k-th unit of product i costs P_i(2k-1), and the first c units cost P_i c^2. Because marginal costs increase within each product, an optimal purchase is a prefix of the globally sorted marginal-cost multiset.
- **Threshold function:** For integer T, product i contributes c_i(T)=(T//P_i+1)//2 units and cost P_i c_i(T)^2. S(T)=sum P_i c_i(T)^2 is monotone, so binary search the largest T with S(T)<=M.
- **Bounds:** If min(P)>M, answer is 0. Otherwise pmin=min(P). Let q=isqrt(M//pmin)+1 and hi=pmin*(2*q-1). The pmin product alone costs pmin*q^2>M at T=hi, so hi is infeasible. lo=pmin-1 is feasible because no marginal cost is <=pmin-1.
- **Final correction:** At maximal T, S(T+1)>M, hence at least one next marginal cost equals T+1. If R=M-S(T), then R < count_{T+1}*(T+1), so floor(R/(T+1)) such units are affordable and enough exist. Answer is C(T)+R//(T+1), where C(T)=sum c_i(T).
- **Safe truncation:** Sort P and keep only p<hi using bisect_left. For T<hi, products with p>=hi have c_i=0, so they do not affect the search. Do not drop p>M: a product with p>M and p<hi can make some T infeasible, and removing it can raise T incorrectly (e.g. P=[2,3], M=2).
- **Performance:** ok(T) loops over sorted kept P, breaks at p>T, and returns False as soon as the accumulated sum exceeds M. hi is at most about 9e13 under the constraints, so at most 47 iterations. Equal P values are compressed adaptively: if unique_count*2 <= len(P), loop over (p, weight=cnt*p, cnt); otherwise use the original list to avoid overhead.
- **Edge cases checked:** M<min(P) gives 0; multiple cheapest products with S(pmin)>M give T=pmin-1, C=0, and the final division buys floor(M/pmin) units; P=[1], M=10^18 gives T=1999999999 and answer 10^9; P=[2,2], M=2 gives 1, M=4 gives 2.
- **Samples:** Sample 1 reaches T=4, C=3, S=8, answer 3. Sample 2 reaches T=37, C=53, S=998, answer 53.
- **Implementation notes:** Use integer arithmetic only, isqrt for the bound, shift for division by 2, and default arguments in ok to keep loop variables local. Python big integers handle all intermediate values.
