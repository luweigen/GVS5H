- **Game abstraction:** The graph remains bipartite after every legal move. A move is either an internal missing edge inside one component or an edge merging two components. Component types are A even-even, B odd-odd, C odd-even non-isolated, and I isolated vertex.
- **State reduction:** Only the counts of these four types and p, the parity of internal missing edges, matter for win/lose. The invariant is p = (number_of_B + M) mod 2.
- **Merge transitions:** A+A, A+B, A+C, A+I, B+B, C+C to A, and C+I to A toggle p. B+C, B+I, C+C to B, C+I to B, and I+I do not toggle p. These are derived from parity of cross products.
- **Win/lose recurrence:** For fixed counts, let L/H be outcomes for p=0/p=1. Let m0/m1 be whether a merge move reaches a losing state. The unique binary solution is L = m0 and H = (non-isolated and not L) or m1. Internal moves from p=0 do not change the binary outcome because if L=0 and internal moves exist, H is forced to 1.
- **Reduction rule:** A positive counts reduce to 1; B positive counts reduce to 1 or 2; C counts >= 8 reduce modulo 4 into 4..7; I counts >= 6 reduce modulo 4 into 2..5.
- **Verification of reduction:** The program runs a finite induction verifier at startup. It checks all small representatives and one-period-larger representatives for each type, using reduced outcomes for all merge targets. This proves the rule for all counts by induction on total components.
- **Odd N shortcut:** If N is odd, every terminal complete bipartite graph has an even number of edges, so every maximal play has parity M mod 2. First player wins iff M is odd.
- **Validation performed:** Optional `--test` mode checks the three samples, N=1, N=2, M=0, complete bipartite components, all-isolated graphs, exhaustive bipartite graphs for N<=5, random bipartite graphs for N<=7, direct cross-check of the hardcoded reduction against exact component-game DP up to total components 60, and a N=2e5 path performance test. No mismatches were found.
- **Performance:** The main solver uses a tiny DP up to total components 30 and O(N+M) BFS classification. The heavier DP60 cross-check is only in the optional test mode.
- **Fallback:** If the hardcoded finite verifier ever fails, the program searches a small candidate list for another verified reduction. This path is not expected to be used.
