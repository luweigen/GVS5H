Exploit the sorted order: if K kagamimochi can be made in [L,R], the K smallest mochi in that interval can serve as tops and the K largest as bottoms. For each index i, precompute f[i], the first index j with A[j] >= 2A[i], and define g[i]=f[i]-i. For a query of length M, K is feasible iff max_{i=L}^{L+K-1} g[i] <= M-K, because the i-th of the K smallest tops must be paired with a bottom at least M-K positions to its right. This predicate is monotone in K, so the answer can be found by binary search. Preprocess g with a sparse table for O(1) range maximum queries. The total complexity is O(N log N + Q log N), which fits the constraints.
