- **Core reduction:** For a subarray, only the set D of distinct values matters. An operation can erase a value interval only if every value in that interval is present, so it cannot cross a missing value. Missing values never appear later, so each initial connected component of D on the integer line needs at least one operation, and one operation per component suffices by erasing its whole min-to-max interval. Thus f(L,R) is the number of connected components of D.
- **Component formula:** For a set D, components = |D| minus the number of adjacent value pairs (x, x+1) both in D. Equivalently, components = sum over x of [x in D and x-1 not in D]. This left-boundary view is used in the sweep.
- **Fixed right endpoint:** Let last[x] be the last position <= R where value x occurs, with last[0]=0. For fixed R, value x is present in A[L..R] iff L <= last[x], and x-1 is absent iff L > last[x-1]. Therefore the number of left endpoints L for which x is a component left boundary is max(0, last[x] - last[x-1]). Define S_R = sum_{x=1}^N max(0, last[x]-last[x-1]); then S_R = sum_{L=1}^R f(L,R). The answer is sum_R S_R.
- **Update:** When R advances to value v, only last[v] changes. The only terms depending on last[v] are T_v = max(0, last[v]-last[v-1]) and T_{v+1} = max(0, last[v+1]-last[v]) if v+1 <= N. Subtract their old values, set last[v]=R, add their new values, then add S_R to the answer. T_{N+1} is not part of the sum, so skip it when v=N. After setting last[v]=R, T_{v+1} is actually always 0 because last[v+1] < R, but computing it uniformly is harmless.
- **Edge cases:** last[0]=0 handles x=1. Values are in 1..N, so last size N+2 is enough. If v=N, do not update T_{N+1}. S can decrease when a new occurrence bridges two already present neighboring values; the subtract-then-add update handles negative net changes. Python integers avoid overflow; the maximum answer is around N^3/6, well within Python arbitrary precision.
- **Complexity:** One pass over N, O(N) time and O(N) memory. The loop does a constant number of list accesses and integer operations, easily within limits for N=3e5.
- **Sample verification:** Manual traces: sample 1 gives S_R = 1, 3, 5, 7 and total 16; sample 2 gives S_R = 1, 3, 5, 6, 8 and total 23; sample 3 gives S_R = 1, 3, 6, 7, 10, 15, 16, 20, 24, 27 and total 129. These match the expected outputs.
- **Brute-force cross-check:** For small random arrays, a direct checker can compute for every subarray the set of values and sum 1 for x in set if x-1 not in set, then compare with the sweep. The sweep was checked against this logic on small cases, including repeated values, non-adjacent values, and bridging cases such as [2,1,3,2] and [2,4,1,3].
- **Superseded approaches:** The offline gap/inclusion-exclusion plan is correct but more complex; the streaming left-boundary sweep is simpler and less error-prone. Divide-and-conquer or Fenwick approaches are unnecessary.
