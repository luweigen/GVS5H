- **Block model:** Use `S = min(50, int(sqrt(K*log2(N)/4)) + 1)` as the number of index blocks. Block length is `L = ceil(N/S)`, so `nb <= 50`. A prefix is split into complete `L`-length blocks (`fa`, `fb`) and a remainder (`ra`, `rb`). If the last block is shorter and the prefix ends at `N`, it is treated as a remainder, which keeps `fa = X // L` valid.
- **Answer decomposition:** For each query, the answer is `F_A x F_B + F_A x R_B + R_A x F_B + R_A x R_B`. The four parts are added independently, so processing order does not affect correctness.
- **Block costs C:** While processing each complete B block `b`, compute the cost of every A element against that B block by a global two-pointer over A sorted by value and the B block sorted by value. This gives `cost_arr[i] = sum_{j in B block b} |A_i - B_j|`. A prefix over A indices gives both the A-remainder contribution for queries with `fb > b` and the column `C[a][b]`.
- **Full-full part:** Build a 2D prefix `P` over `C` and add `P[fa][fb]` to each query.
- **B-remainder vs A-full:** Symmetric on-the-fly processing over complete A blocks. For each A block, compute costs of all B elements against it, prefix over B, and add to queries with `fa > a`.
- **Partial-partial grouping:** Group queries by `(fa, fb)`. For a group, let `max_x`, `max_y` be maximum remainders. If `max_x * max_y` is no larger than an estimated per-query cost, use row-by-row cumulative columns: process A rows up to each query’s `x`, maintaining `col[y] = sum over processed rows of cost against B prefix y`. This uses `O(max_y)` memory and `O(max_x*max_y)` time.
- **Per-query partial fallback:** If row-by-row is not chosen, answer each query individually. Use direct double loop for very small `x*y`; sorted-slice two-pointer when `x + y <= L`; otherwise scan the full sorted block lists and filter by index `< x` or `< y`. Duplicate `(x, y)` pairs in a group are cached.
- **Complexity:** Full-block on-the-fly work is `O(N*S)` with `S <= 50`, about `1e7` element-cost operations plus prefix passes. Partial work is bounded by roughly `O(K*L)` plus row-group costs, with `L = N/S`; worst case is around a few tens of millions of simple Python operations. Memory is `O(N + S^2)`.
- **Edge cases:** Equality is handled by using strict `<` in two-pointer comparisons; zero-cost equal pairs are naturally included in the `>=` side. Last shorter blocks are valid remainder blocks. Answers can reach about `2e18`, so Python integers are used throughout.
- **Implementation notes:** Global sorted arrays are used only for full-block processing and can be discarded after that phase. Query lists for remainder-vs-full contributions are grouped by `fb` and `fa` to avoid unnecessary zero additions.
