- **Expression symmetry:** The value is xy+yz+zx, symmetric in the three chosen values, so after sorting and truncating we may assign the three arrays to X,Y,Z in any order. We sort the three truncated arrays by decreasing spread and use that order as X,Y,Z; this is a performance heuristic only.
- **Truncation:** Let M=min(N,K). Any element outside the top M of one array cannot be strictly above the K-th largest: for fixed other two values, the M kept elements of that array give M triples with values at least as large. If it ties, the tied value is also represented by kept elements. Thus the K-th value is unchanged.
- **Monotonicity:** With positive arrays sorted descending, f(i,j,k)=X_iY_j+Y_jZ_k+Z_kX_i is nonincreasing in each coordinate. Coordinate differences are (X_{i+1}-X_i)(Y_j+Z_k), (Y_{j+1}-Y_j)(X_i+Z_k), (Z_{k+1}-Z_k)(X_i+Y_j), all nonpositive.
- **Tree:** Parent of (i,j,k) is (i,j,k-1) if k>0, else (i,j-1,0) if j>0, else (i-1,0,0). Children are (i+1,0,0) only when j=k=0, (i,j+1,0) when k=0, and (i,j,k+1) always. This gives a unique parent for every triple and child value <= parent value, so a best-first max-heap pops values in nonincreasing order.
- **Packed keys:** bits=max(1,(M-1).bit_length()), shift=3bits, idx=(i<<2bits)|(j<<bits)|k. key=(-value<<shift)+idx. Since idx<2^shift, larger values produce strictly smaller keys, so Python min-heap acts as max-heap. value=-(key>>shift) and idx=key&((1<<shift)-1) work for negative keys.
- **Heap optimization:** The loop processes K-1 nodes and then reads heap[0] as the answer. For each node, up to three child keys are computed; the smallest child key is inserted with heapreplace instead of heappop+heappush, and the remaining children are heappushed. This saves one sift per non-leaf and is safe because every child key is >= the old root key.
- **Value updates:** Precompute dX,dY,dZ and XplusZ0. A child value is parent value plus diff times the sum of the two unchanged coordinates, avoiding repeated products.
- **Complexity:** Sorting O(N log N). The heap holds O(K) entries (at most about 2K+1), and each of K-1 steps does O(log K) heap work plus O(1) arithmetic, so O(N log N + K log K) time and O(N+K) memory.
- **Samples:** Sample 1 pops 44,38,36,34,31; sample 2 all values are 30000; sample 3 yields 689589940713840351.
- **Pitfalls:** M^3>=K guarantees the heap is nonempty; the K-th node is not expanded; negative right shift is floor but recovers value because idx<2^shift; heapreplace requires the new item not to be smaller than the old root, which holds by monotonicity.
