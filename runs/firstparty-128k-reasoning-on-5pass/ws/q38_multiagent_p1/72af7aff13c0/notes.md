- **Audit:** Checked `compute_B` for `b_case[t] == 0`. The previous version set `new[0] = pp`, then looped `new[j-1] = pp + p`, and finally set `new[n-1] = pp`. For `n >= 2`, the initial `new[0]` is overwritten by `p0 + p1`, so it was already equivalent to the required adjacent-sum recurrence. The redundant assignment was removed so the code literally computes `new[j] = p[j] + p[j+1]` for `j = 0..n-2` and `new[n-1] = p[n-1]`.
- **Recurrences:** Forward `G` plateau uses `p[j-1] + p[j]`; backward `B` plateau uses `p[j] + p[j+1]`. This asymmetry comes from the left boundary `L[s]` staying constant on the plateau. All case `1`, `0`, and `-1` mappings were rechecked for increasing, plateau, and decreasing diagonals, including transposed grids.
- **Verification:** Re-ran sample 1 and got `456`, `666`, `822`. Re-ran sample 2 and got the six listed outputs. A separate brute-force checker was run on small grids `2x3`, `3x3`, and `4x4`, with all-zero and random values, both `H > W` and `H < W`, random walks, and random assignments; all outputs matched.
- **State invariant:** After each query, `G[0..s]` and `B[s..S]` are valid. Optional vectors `G[s+1]`, `G[s+2]`, `B[s-1]`, and `B[s-2]` are tracked by flags. Moving right makes `B[s]` the new `b1` and `B[s-1]` the new `b2`; moving left makes `G[s]` the new `g1` and `G[s+1]` the new `g2`. Conservative invalidation preserves correctness.
- **Update propagation:** A point delta at diagonal `t`, index `i` changes the answer by `delta * G[t][i] * B[t][i]`. It changes `G[t+1]` and `B[t-1]` by `delta * G[t][i]` and `delta * B[t][i]`, respectively. Distance-two vectors are updated by multiplying the adjacent `A` values. The helpers use the same case mappings as the full recomputes.
- **Edge cases:** Boundary moves never call `apply_G1` at `t = S` or `apply_B1` at `t = 0` because the corresponding flags are false. Zero `g_val` or `b_val` safely skips propagation. Same-value queries only shift flags and do not change the answer.
- **Performance:** Initial precomputation is `O(HW)`. Each query is `O(1)` plus occasional full recomputation of one diagonal of length at most `min(H, W) <= 447`. Oscillating walks avoid most recomputes; long straight runs are bounded by grid length, and rectangular cases have small vector width.
