- **Chosen algorithm:** Count the total number of ones `k`, then scan the string left to right while maintaining `ones_seen`. For every zero strictly between the first and last one, add `min(ones_seen, k - ones_seen)` to the answer.
- **Why it works:** Adjacent swaps only matter when a zero and a one cross. In the final string, every internal zero must end either before the whole block of ones or after it. If a zero has `a` ones to its left and `b = k - a` ones to its right, moving it before the block requires crossing `a` ones, while moving it after the block requires crossing `b` ones. Thus its unavoidable contribution is `min(a, b)`.
- **Global feasibility:** The values `a` for internal zeros are nondecreasing as we scan left to right. Choosing the cheaper side for each zero therefore selects a prefix of internal zeros to place before the final block and the remaining suffix after it. Any such split is realizable by choosing the final block start accordingly, so the independent lower bounds are simultaneously achievable.
- **Indexing rule:** A zero is internal exactly when `0 < ones_seen < k`. Leading zeros have `ones_seen = 0`, trailing zeros have `ones_seen = k`, and both contribute zero because they are already on the correct side of all ones.
- **Edge cases:** If `k = 1`, there are no internal zeros and the answer is `0`. If all characters are ones, there are no zeros and the answer is `0`. Python integers are arbitrary precision, so large answers are safe.
- **Sample verification:** `0101001` gives `1 + 1 + 1 = 3`. `100` has `k = 1` and gives `0`. `0101001001` gives `1 + 2 + 2 + 1 + 1 = 7`.
- **Complexity:** The scan is linear in `N`, and `S.count('1')` is also linear, so total time is `O(N)`. Memory usage is `O(1)` besides storing the input string.
