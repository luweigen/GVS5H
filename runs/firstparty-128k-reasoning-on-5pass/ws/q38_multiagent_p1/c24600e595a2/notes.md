- **Problem model:** Split positions into D (1 to 0), U (0 to 1), S (1 to 1), and Z (0 to 0). Since all C are positive, D and U bits are flipped exactly once, Z bits never, and S bits either stay unchanged or are flipped twice: once off in the first phase and once on in the second phase.
- **Ordering structure:** Every off flip must precede every on flip. Among off flips, larger C should be earlier; among on flips, smaller C should be earlier. Adjacent swap arguments prove this locally and globally.
- **Cost representation:** Let W0 be the initial weighted sum. For x selected S bits, total operations are M = |D| + |U| + 2x. Total cost equals M*W0 minus the savings from off flips plus the additions from on flips. An off flip at negative rank r saves C*(M-r+1); an on flip at positive rank r adds C*(|U|+x-r+1).
- **Initial cost:** With x=0, sort D ascending and U ascending. Let F = sum(D_asc[j]*(j+1)) and G = sum(U_asc[k]*(p-k)), where p=|U|. Then cost0 = (|D|+p)*W0 - p*sumD - F + G.
- **Prefix property:** For a fixed number x of selected S bits, the optimal selected bits are the x largest C values. An exchange argument shows replacing a selected smaller y by an unselected larger x cannot increase cost. The individual advantage is at least t*(x-y), while the worst pairwise disadvantage is at most (t-1)*(x-y), where t is the fixed selected count.
- **Marginal update:** Scan S in descending order. Before adding current c, maintain n0 = |D| + i, sumNeg = sumD + sum(previous selected S), idxD = count of D values <= c, idxU = count of U values < c, and start = count of previous S values strictly greater than c.
- **Delta formula:** cntN_gt = (|D|-idxD)+start, sumN_gt = (sumD-prefD[idxD])+prefS[start], cntP_lt = idxU, sumP_lt = prefU[idxU]. Then delta = 2*W0 - sumNeg + c*(-n0 - 1 + cntN_gt - cntP_lt) + sumP_lt - sumN_gt. Add delta to the current cost and update the answer.
- **Tie handling:** D values equal to c are not greater, so idxD includes them. U values equal to c are not less, so idxU excludes them. Previous S values equal to c are included in sumNeg but not in start or prefS[start]. This convention is consistent and gives the same cost for any tie order.
- **Complexity:** Sorting dominates with O(N log N) time. The scan uses monotone pointers and prefix sums, so it is O(N). Memory is O(N). Python integers safely handle the maximum cost.
- **Pitfalls:** The total operation count increases by 2 for each selected S bit. The positive-phase coefficient uses |U|+x-r+1, not M-r+1. Pointers must be updated before computing the delta. For equal S values, start must remain the first index of the equal group, not the current index.
