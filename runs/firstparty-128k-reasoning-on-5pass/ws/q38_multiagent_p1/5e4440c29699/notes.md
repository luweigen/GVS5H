- **Model:** Allowed points are the full rectangle `[0,W] x [0,H]` minus the closed forbidden rectangle `[L,R] x [D,U]`. Count all monotone right/up paths of any length, including length-zero paths.
- **Basic counts:** For a fixed point `(x,y)`, the number of full-rectangle paths ending there from any start is `E(x,y)=C(x+y+2,x+1)-1`. The number starting there to any end is `S(x,y)=C(W-x+H-y+2,W-x+1)-1`. These follow from double hockey-stick identities.
- **Full total:** Summing `S(x,y)` over all points gives `C(W+H+4,H+2)-W-H-4-(W+1)(H+1)`.
- **Invalid partition:** Any invalid path either starts inside the forbidden rectangle, or starts outside and has a unique first entry into it. A first entry can only be a move from `(L-1,y)` to `(L,y)` with `L>0, D<=y<=U`, or from `(x,D-1)` to `(x,D)` with `D>0, L<=x<=R`. These three categories are disjoint.
- **Start inside:** Sum `S(x,y)` over the forbidden rectangle. With `a=W-x`, `b=H-y`, use the prefix `T(A,B)=sum_{a<=A,b<=B} C(a+b+2,b+1)=C(A+B+4,B+2)-A-B-4`. Apply inclusion-exclusion over `a0=W-R..a1=W-L`, `b0=H-U..b1=H-D`, then subtract the rectangle area.
- **Left entry:** For each `y`, count prefixes to `(L-1,y)` times suffixes from `(L,y)`: `(C(L+y+1,L)-1)*(C(W-L+H-y+2,W-L+1)-1)`. The prefix is automatically outside the hole because its x-coordinate is `< L`.
- **Bottom entry:** For each `x`, count prefixes to `(x,D-1)` times suffixes from `(x,D)`: `(C(x+D+1,x+1)-1)*(C(W-x+H-D+2,W-x+1)-1)`. The prefix is automatically outside because its y-coordinate is `< D`.
- **Implementation:** Precompute factorials and inverse factorials up to `W+H+5` modulo `998244353`. All binomial arguments are below the modulus, so ordinary factorial inverses are valid. Edge sums use `O(W+H)` total iterations. Raw congruent sums are accumulated and one final modulo is applied to reduce modulo operations.
- **Boundary handling:** If `L=0`, skip left entry. If `D=0`, skip bottom entry. `T` returns `0` for negative arguments. Corners are counted correctly because the previous vertex of the first entry is unique; left and bottom entries to the same corner are different paths.
- **Verification:** Sample 1 gives `431 - 30 - 58 - 151 = 192`. Small brute-force checks on `2x2` and `3x3` grids, including single-point holes, line holes, and holes touching left/bottom/right/top boundaries, match. When `L=D=0`, as in sample 3, allowed starts cannot move into the hole, so the answer correctly reduces to `full_total - start_inside`.
