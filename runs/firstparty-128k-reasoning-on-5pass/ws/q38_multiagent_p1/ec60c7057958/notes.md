- **Parity patterns:** A valid permutation must alternate parity. For odd n, only the odd-start pattern is possible because there is one more odd number than even number. For even n, both odd-start and even-start patterns are possible.
- **State abstraction:** After fixing a prefix, the number of valid completions depends only on how many odd and even numbers remain and which parity is required next. The exact remaining values do not affect the count, only their parity.
- **Counting helper:** For remaining counts rem_odd and rem_even and next parity next_odd, let m = rem_odd + rem_even. If m is zero, there is exactly one completion. Otherwise, the alternating suffix requires need_odd = (m + 1) // 2 and need_even = m // 2 when next_odd is true, with the counts swapped when next_odd is false. If the remaining counts do not match these required slot counts, the state is infeasible and returns 0. Otherwise, the number of completions is fact[rem_odd] * fact[rem_even], capped.
- **Factorial capping:** Precompute factorials up to n with cap = 10**15 + 1. Since k is at most 10**15, any true count above the cap can safely be represented by the cap. If a capped block is encountered, it is larger than any possible k, so the current candidate must be selected.
- **Unranking procedure:** At each position, scan unused numbers in ascending order. Skip used numbers and numbers with the wrong required parity when the required parity is fixed. For each allowed candidate, compute the size of the lexicographic block that would result from choosing it. If k is larger than that block, subtract the block and continue; otherwise choose that candidate.
- **Lexicographic correctness:** Scanning candidates in ascending order at every position partitions the valid permutations into contiguous lexicographic blocks. Subtracting whole blocks until k falls inside one block is the standard unranking method.
- **Out of range handling:** If a full scan finds no candidate whose block can contain k, return an empty list. This happens exactly when k exceeds the total number of valid alternating permutations.
- **Edge cases:** n = 1 has only [1]. n = 2 has [1, 2] and [2, 1]. For odd n, the first element must be odd. For even n, first-element blocks are interleaved by numeric value, not grouped by starting parity.
- **Complexity:** The algorithm uses O(n^2) time and O(n) space, which is easily sufficient for n <= 100.
