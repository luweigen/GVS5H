- **Chosen solution:** Use the static smaller-before formula. For each value x, let L_x be the number of values smaller than x that appear before x in the original permutation. The answer is sum over x of T(x-1) - T(L_x), where T(k) = k(k+1)//2.
- **Why formula holds:** Process values from largest to smallest. When x is handled, all larger values are already fixed in the suffix. Among the remaining values 1..x, x's rank is L_x + 1 because exactly L_x smaller values were originally before it. To finish, x must move right to position x, crossing the smaller values currently to its right. Those swaps occur at edges L_x + 1, ..., x - 1, so the contribution is the sum of those edge costs.
- **Optimality intuition:** A larger value never benefits from moving left; its required rightward swaps are forced and are cheapest when done before smaller values are rearranged. After fixing the largest value, the remaining problem is the same problem on the original relative order of the smaller values.
- **Fenwick computation:** Scan P left to right. Maintain a 1-indexed Fenwick tree over values, with 1 for values already seen. For current x, L = query(x-1) counts smaller seen values. Add T(x-1) - T(L), then update(x, 1). Query must happen before update.
- **Indexing:** Values are 1..N, so Fenwick indices are natural. query(0) returns 0. The range L+1..x-1 is empty when L = x-1, giving zero contribution.
- **Complexity:** O(N log N) time and O(N) memory. For N = 2e5 this is easily fast in Python; inline Fenwick loops avoid method-call overhead.
- **Integer size:** The answer can be as large as sum_{k=1}^{N-1} T(k) = N(N-1)(N+1)/6 for the reverse permutation, about 1.33e15 for N = 2e5. Python integers are arbitrary precision, so no overflow concern.
- **Edge cases:** Sorted permutation gives L_x = x-1 for every x and answer 0. N=2 works: [2,1] gives 1, [1,2] gives 0. Input is read from stdin; no sample-specific behavior.
- **Pitfalls avoided:** Do not count smaller values after x directly unless converting to L_x = x-1-R_x. Do not update before querying. Do not confuse value x with its original position; L_x is a count of smaller-before values, not a position in the full array. The formula uses triangular numbers, so endpoints are inclusive from L_x+1 to x-1.
- **Verification:** Samples: [3,2,1] -> contributions 3+1+0=4; [2,4,1,3,5] -> 1+5+0+0+0=6; [1,2] -> 0.
