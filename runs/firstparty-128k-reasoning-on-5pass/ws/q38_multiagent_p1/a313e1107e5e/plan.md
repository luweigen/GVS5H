Process the queries offline in increasing order of R_i. Maintain a Fenwick tree over the compressed values of A, where each position stores the maximum length of a strictly increasing subsequence in the current prefix that ends with that value. When adding A_i, compute its candidate length as 1 plus the prefix maximum over all smaller values, then update its value position with that candidate. For a query (R_i, X_i), after the prefix R_i has been processed, answer with the prefix maximum over all compressed values <= X_i, using upper_bound to map X_i to a rank. This gives O((N+Q) log N) time and O(N+Q) memory.
