- **Graph structure:** The map i -> A_i is a functional graph. Each weak component has exactly one directed cycle, and all other nodes form rooted trees directed toward that cycle. The inequalities x_i <= x_{A_i} force all nodes on a directed cycle to have the same value.
- **Non-cycle DP:** For a non-cycle node u, let G_u(v) be the number of valid assignments to the non-cycle subtree rooted at u when x_u <= v. If u has non-cycle children c, then with x_u = t the children are independent and contribute prod_c G_c(t). Hence G_u(v) = G_u(v-1) + prod_c G_c(v). A leaf has G_u(v) = v.
- **Rolling sweep:** Maintain g[u] = G_u(v) for the current v. Start at v = 0 with all g[u] = 0. For v = 1..M, process non-cycle nodes in leaf-to-root order and do g[u] += prod_{c} g[c] modulo MOD. Children are processed before parents, so g[c] already equals G_c(v).
- **Order construction:** Build children lists containing only non-cycle children. Use Kahn's algorithm on child_count = number of non-cycle children: start from leaves, append the node, then decrement its non-cycle parent's count. This gives a valid leaf-to-root order.
- **Cycle detection:** Peel nodes with indegree zero. Nodes left with in_cycle True are exactly cycle nodes. This handles self-loops and multiple cycles.
- **Cycle contribution:** For each directed cycle, collect all non-cycle children whose parent is in that cycle. If the common cycle value is v, the attached subtrees contribute prod g[c]. Add this product to the cycle's total for each v. The final answer is the product of all cycle totals modulo MOD, because different components choose independent cycle values.
- **Complexity:** Cycle detection and order construction are O(N). The sweep does O(N) work per value, so total time is O(NM) and memory is O(N). With N, M <= 2025 this is easily fast enough.
- **Edge cases:** Self-loop cycles, cycles with no attached trees, multiple independent cycles, and deep chains. Modulo is applied after each multiplication and addition; one subtraction is enough for additions because both operands are already reduced.
