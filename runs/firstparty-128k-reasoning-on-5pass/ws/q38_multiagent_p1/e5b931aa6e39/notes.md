- **Core reduction:** Set d=x-y>0. Then N=d(3y^2+3dy+d^2). Because y>=1, the second factor is strictly larger than d^2, so d^3<N. Hence d is at most floor(cuberoot(N)), which is <=1e6 for N<=1e18. This is the main reason enumeration is feasible.
- **Quadratic completion:** For a candidate d dividing N, let q=N//d. The equation is 3y^2+3dy+d^2=q. Completing the square gives (6y+3d)^2=12q-3d^2. Define D=12q-3d^2. A solution exists for this d iff D is a perfect square s^2 and t=s-3d is a positive multiple of 6. Then y=t//6 and x=y+d.
- **Why conditions are sufficient:** If s=6y+3d, then s^2=12q-3d^2 and t=6y. Conversely, if s^2=D and t=6y, substituting back yields 3y^2+3dy+d^2=q, so d*q=N.
- **Integer cube root:** Use binary search with integer arithmetic only. A dynamic hi (double until hi^3>N) plus binary search avoids floating point rounding and is robust. If L were accidentally too large, D could become negative; the code guards D<0, but correct L makes this unnecessary.
- **Edge cases:** N=1: d=1 gives D=9, s=3, t=0, rejected because y must be positive. Perfect cubes can make d=cuberoot(N) a divisor, but then t=0 and it is rejected. D can be as large as about 1.2e19, exceeding signed 64-bit, but Python integers and math.isqrt handle it exactly.
- **Performance:** The loop runs at most 1e6 times. Non-divisors are skipped with a single modulo. math.isqrt is called only for divisors of N, so the total work is small. This is simpler and safer than factorizing N or generating divisors.
- **Rejected approaches:** Enumerating x or y directly is unsafe because y can be around sqrt(N/3) when d=1. Binary searching y for each d is correct but slower. Full factorization or Eisenstein norm methods are overkill and introduce extra edge cases.
- **Implementation details:** Read stdin as bytes, parse one integer. Use math.isqrt for exact square root. Check s*s==D before using s. Print the first valid pair and return; otherwise print -1.
