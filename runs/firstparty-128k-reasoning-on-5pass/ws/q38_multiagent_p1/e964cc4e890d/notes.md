- **Strong connectivity criterion:** With the base path 1 -> 2 -> ... -> 2N, strong connectivity is equivalent to every prefix cut i having at least one added edge from the suffix to the prefix. An added edge white u to black v covers cuts v <= i < u.
- **Validated recurrence:** Let c[w] be the number of B's before the w-th W. The answer is R[N] if S[0]=='B' and S[-1]=='W', otherwise 0. For w=1..N:
  - if c[w] > w, R[w] = 0;
  - otherwise R[w] = fact[w] - sum_{v<w} R[v] * fact[w - c[v]] modulo 998244353.
- **CDQ structure:** Maintain add[i] as the accumulated sum of contributions from already solved j < i. solve(l,r) solves left, applies left-to-right contributions, then solves right. Leaves of size BLOCK=32 are computed sequentially with direct updates inside the leaf only.
- **Contribution application:** For a node [l,r] with mid, contributions from j in [l,mid] to i in [mid+1,r] are sum_j A[j] * fact[i-c[j]]. Grouping by d=c[j] gives T[d] = sum A[j], and the needed values are a convolution of T (shifted by d0=c[l]) with a segment of fact.
- **NTT convolution shift:** Let d0=c[l], L=min(c[mid],r)-d0+1. Use T'[t]=T[d0+t]. Let k_min=max(0, mid+1-d0-(L-1)), k_max=r-d0, K=k_max-k_min+1. Convolve T' with fact[k_min:k_min+K]. For i in the right half, the contribution is conv[i-d0-k_min], starting i at max(mid+1, d0+k_min).
- **Grouped direct optimization:** If c has few distinct values in the left half, direct grouped updates are much faster than NTT. For each distinct d, sum A[j] over that group and add coeff * fact[i-d] to the relevant i range. This makes flat/near-flat c cases O(N log N) instead of NTT-heavy.
- **Cost model:** For each internal node, compute rough=left_len*right_len. If rough is tiny, use grouped direct. Otherwise compute the NTT length n and limit = 2 * n * log2(n). Scan grouped cost up to limit; if grouped_cost <= limit or n < 128, use grouped direct; otherwise use NTT. This avoids NTT when the grouped direct work is small or when the convolution length is large due to sparse c-range.
- **NTT implementation:** Use modulus 998244353, primitive root 3. Forward transform is DIF and inverse is DIT, so no explicit bit-reversal is needed. Twiddle tables are built lazily per stage for both forward and inverse transforms; this removes one modular multiplication per butterfly compared with updating w inside the inner loop.
- **Memory/performance tuning:** Largest NTT length is around 2^19 for N=2e5. Lazy twiddle tables add memory but significantly reduce modular multiplications. GC is disabled because large lists are acyclic and reference counting is sufficient.
- **Edge cases:** S[0] must be B and S[-1] must be W, otherwise answer 0. If c[w] > w, R[w] is forced to 0. Terms with i < c[j] are omitted because fact of a negative index is zero.
- **Sample consistency:** Sample 1 gives 1, sample 2 gives 0 due to ending in B, sample 3 matches the validated recurrence output 240792.
