- **Game abstraction:** A move either opens an unmarked index or spends one unit from the already opened pool. Opening index i consumes the move and adds A_i - 1 future spend moves to the pool. The game ends immediately when the last unopened index is opened, so the winner is the player who makes the final opening move.
- **Parity suffices:** Only the parity of the pool and the parity of each unopened A_i matter. Opening an odd A_i adds an even number of pool tokens, preserving pool parity; opening an even A_i adds an odd number, toggling pool parity. Spending one token toggles pool parity. Exact values do not affect the outcome.
- **Small unopened counts:** Let k be the number of unopened indices and p be pool parity. For k=1, the player to move wins by opening the last index. For k=2, the player to move loses exactly when p is even: if p is odd, spend to make p even and hand a losing position; if p is even, any opening leaves k=1 to the opponent, who wins. For k=3, losing positions are all three unopened even with p even, or all three unopened odd with p odd.
- **Induction for k>=4:** A position with k>=4 unopened indices is losing iff p equals the parity o of the number of odd unopened A_i. If p != o, a winning move exists: if an odd index is available, open it, which toggles o but leaves p unchanged; otherwise all are even, so o=0 and p=1, and opening an even index toggles p to 0. If p = o, every opening or spend makes p' != o'; for k-1>=4 this is winning for the opponent by induction, and the k=4 to k=3 transition is checked directly against the k=3 rule.
- **Initial state:** Initially pool parity p=0. Therefore for N>=4, Fennec wins iff the initial odd_count parity is 1, i.e. odd_count is odd. The small cases are N=1 Fennec, N=2 Snuke, and N=3 Fennec iff odd_count > 0.
- **Implementation:** Read all tokens, parse N, count odd A_i among the next N tokens, apply the case table, and print the winner. Complexity is O(N) time and O(N) token storage, well within limits.
- **Verification:** Sample 1 has N=3 and odd_count=2, so Fennec. Sample 2 has N=2, so Snuke. Sample 3 has N=6 and odd_count=4, so Snuke. Edge cases: N=1 gives Fennec; N=2 gives Snuke; N=3 all even gives Snuke; N=4 all even gives Snuke; N=4 one odd gives Fennec.
