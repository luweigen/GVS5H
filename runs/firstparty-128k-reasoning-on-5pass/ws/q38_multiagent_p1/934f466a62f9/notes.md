- **Equivalence:** A pair’s price is the maximum coordinate sum. Choosing a maximizing coordinate for each pair is equivalent to selecting 2K cakes, assigning each selected cake one of X/Y/Z, and requiring each color count to be even. Pairing cakes of the same assigned color arbitrarily gives a valid matching with price at least the assigned sum, and every matching gives such a colored selection, so the optima coincide.
- **WQS scaling:** Let H(k) be the best original doubled value using exactly k selected cakes with even color counts. We need H(2K). For penalty mu per selected cake on the doubled scale, define F(mu)=max_k(H(k)-mu*k). Doubling coordinates makes relevant slopes integral. Binary search the largest integer mu with maximum count among optimal relaxed solutions at least 2K; then answer is (F(mu)+mu*2K)/2.
- **Fixed-mu evaluation:** Instead of literally maintaining 8 DP states, evaluate the same Lagrangian by a baseline-plus-changes method. For each cake, choose the best option among skip and the three colors, where option code is (adjusted_doubled_value<<SHIFT)+count. Let base be the sum of best codes and parity be the xor of best color masks.
- **Change keys:** Changing a cake from its best option to another option has key = best_code - option_code, which is nonnegative and encodes lost value first, then lost count. The final code is base - sum(keys). We need xor of change masks equal to parity.
- **At most three changes:** Change masks live in GF(2)^3. Any optimal set of changes can remove a nonempty zero-xor subset without increasing total key, so an optimal set has size at most 3. For each toggle mask, only the best 3 candidates by key are needed: in a 3-change solution, at most two other cakes can conflict, so one of the top 3 is always usable.
- **Top-3 combination:** Keep top 3 (key, cake_id) for each of masks 1..7. Brute force subsets of size 1, 2, 3 from these at most 21 candidates, enforcing distinct cake ids and xor parity. This gives the minimum key to fix parity, hence the maximum final code.
- **Encoding:** SHIFT=max(N.bit_length(),4), so count fits in low bits and small key sums do not cause lexicographic carry issues. Code ordering maximizes adjusted value, then selected count. Final count is code & MASK.
- **Binary search range:** mu is in [0, max_doubled_coordinate+1). At mu=0 the maximum count is at least 2K; at max+1 all selections are negative and count is 0.
- **Edge cases:** All-zero values, odd N, ties among colors, negative adjusted values, and exact-count tie-breaking are handled by the code encoding and top-3 conflict checks.
- **Complexity:** Each test case does O(N log C) work, where C<=2e9 is the doubled coordinate bound. The per-mu scan is O(N) with small constants, and the candidate combination is O(1). Total N over tests is 1e5.
