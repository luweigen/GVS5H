- **Fixed-center characterization:** If vertex `c` is the snowflake center, any neighbor `v` can be an intermediate vertex with capacity `deg(v)-1`, because one incident edge is used for `v-c`. It can retain any number of leaves from `1` through this capacity.
- **Optimization for a center:** For a chosen positive leaf count `y`, all neighbors with capacity at least `y` can be intermediates. Using all of them is optimal, giving retained size `1 + x * (y + 1)`, where `x` is their count.
- **Relevant values:** As `y` changes, the eligible-neighbor count changes only when `y` reaches a neighbor capacity. Therefore, after sorting capacities descending, process each equal positive capacity group. At capacity `cap`, all processed neighbors have capacity at least `cap`, so candidate size is `1 + count * (cap + 1)`.
- **Correctness:** Every candidate counted by the algorithm is feasible by retaining the center, the selected neighboring intermediates, and exactly `cap` arbitrary other neighbors of each intermediate as leaves; all other vertices are deleted. Conversely, every feasible snowflake has some center and leaf count `y`; all its intermediates must be neighbors of that center with capacity at least `y`, so its size is at most the candidate evaluated for that center and threshold.
- **Complexity:** Sorting neighbor capacities for a vertex of degree `d` costs `O(d log d)`. Total complexity is `O(sum(deg(v) log deg(v)))`, bounded by `O(N log N)` for a tree. Memory usage is `O(N)`.
