- **Prefix formulation:** Let `P[v]` be the sum of strengths before town `v`. A forward person on normalized interval `[l,r]` requires `P[l]=P[r]` and every interior value greater than this common value. A backward person requires every interior value smaller.
- **Feasibility criterion:** Contract all endpoint-equality pairs. Add directed strict-order edges from lower prefix value to higher prefix value. A chosen set is feasible exactly when no strict edge is internal to a contracted component and the resulting strict graph is acyclic.
- **Conflict characterization:** A set is infeasible exactly when it contains a conflicting pair: equal normalized left endpoint, equal normalized right endpoint, or a proper crossing of equal orientations. Proper crossing means either `l1 < l2 < r1 < r2` or its symmetric form. Opposite-orientation crossings are feasible.
- **Why pair detection suffices:** Same-orientation crossings create opposite strict orders between the two equality components. Equal-side endpoints make an endpoint of one interval strictly interior to another while being forced equal. With these forbidden cases absent, same-orientation interval families are noncrossing and the remaining strict relations are acyclic.
- **Conflict index:** `bad[i]` stores the greatest earlier person index conflicting with person `i`. A query interval `[L,R]` is feasible iff `max(bad[L-1:R]) < L`.
- **First crossing search:** For earlier `[l',r']` satisfying `l' < l < r' < r`, query points `(r',l')` with `r'` in `(l,r)` and `l' < l`.
- **Second crossing search:** For earlier `[l',r']` satisfying `l < l' < r < r'`, query points `(l',r')` with `l'` in `(l,r)` and `r' > r`.
- **Data structure validation:** `RangeTreeMax` stores a Fenwick maximum structure at every outer segment-tree node. Normal mode correctly implements inner `< threshold`; suffix mode reverses coordinate ranks so it correctly implements inner `> threshold`, including duplicate coordinates and strict boundaries via `bisect_left`/`bisect_right`.
- **Resource detail:** Trees are explicitly deleted after each orientation pass so the prior large static 2D structure is released before constructing the next one.
- **Complexity:** Building conflict indices is `O(M log^2 N)`. Each query is `O(log M)`. Memory is `O(M log N)` for one active static range tree plus `O(M)` arrays.
