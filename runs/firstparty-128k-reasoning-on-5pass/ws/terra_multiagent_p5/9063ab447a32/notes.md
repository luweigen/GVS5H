- **Marginal-cost model:** Buying the \(k\)-th unit of product \(i\) increases its total cost from \((k-1)^2P_i\) to \(k^2P_i\), so its marginal cost is \((2k-1)P_i\). These marginal costs are increasing for every product, so selecting globally cheapest marginal units automatically respects the required prefix of units for each product.
- **Threshold count formula:** For a marginal-cost threshold \(x\), product with price \(P\) contributes all positive odd multiples of \(P\) not exceeding \(x\). If \(q=\lfloor x/P\rfloor\), the count of positive odd integers at most \(q\) is \((q+1)//2\). Thus `k = (x // P + 1) // 2`.
- **Threshold cost formula:** Taking those `k` units costs \(P k^2\), equivalently the sum of the first `k` marginal costs. Therefore total threshold cost is `sum(P_i * k_i * k_i)`.
- **Binary search:** Predicate `cost(x) <= M` is monotone. Search for the largest integer threshold `x` satisfying it, with inclusive feasible lower bound `0` and exclusive upper bound `M+1`. Any marginal cost greater than `M` cannot be purchased in a solution of total cost at most `M`, so this upper bound is sufficient.
- **Leftover handling:** After the maximal feasible threshold `x`, let `k_i` be selected counts and let each product’s next marginal cost be `(2*k_i+1)*P_i`. Let `y` be their minimum. Every unselected unit costs at least `y`; units costing exactly `y` are the next units for tied products. If `remaining = M - spent`, then exactly `remaining // y` more units can be bought.
- **Why no tie cap is needed:** By maximality of the threshold, including all units with marginal cost `y` is infeasible. Hence `spent + (#ties)*y > M`, so `remaining // y < #ties`. There are always enough tied next units to buy that many.
- **Complexity:** Each feasibility check is \(O(N)\); binary search uses at most about 60 iterations because \(M \le 10^{18}\). Total complexity is \(O(N\log M)\), memory \(O(N)\).
- **Integer safety:** Python integers handle all intermediate products and squares exactly. In fixed-width languages, `P*k*k` may exceed 64-bit even though the budget is at most \(10^{18}\), so saturation or wider arithmetic is required.
- **Stock bound:** The stated \(10^{100}\) stock is never relevant under budget \(10^{18}\).
