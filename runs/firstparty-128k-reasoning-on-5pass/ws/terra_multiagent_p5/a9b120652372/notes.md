- **Support model:** Multiplicities never affect future occupied-square supports. It is enough to track the increasing lists of occupied positions in `A` and `B`.
- **Order property:** Pieces never pass each other. Each initial occupied position is assigned to a final occupied position, assignments are nondecreasing, and every target position must receive at least one initial position.
- **Displacement property:** If consecutive initial positions `x_i < x_{i+1}` are assigned to `y_j <= y_k`, then `y_k - y_j <= x_{i+1} - x_i`. Equivalently, the displacements `assigned_y - x_i` are nonincreasing. This is the finite restriction of the fact that every operation is a nondecreasing 1-Lipschitz map.
- **Minimum operations characterization:** For a valid assignment, its required operation count is the maximum absolute displacement of an initial occupied position. The minimum answer is therefore the smallest `M` for which there is a surjective ordered assignment satisfying both the displacement bound `|x_i-y_j| <= M` and the adjacent gap condition.
- **Feasibility for fixed `M`:** Process initial positions left to right. Since every target must be used, an assignment may stay at its current target or advance by exactly one target; it may not skip a target. The possible target indices for the current source form one interval `[L,R]`.
- **Interval transition:** A source position can only be assigned to target positions in the contiguous index interval whose coordinates lie in `[x_i-M, x_i+M]`. From old right endpoint `R`, the new interval can extend to `R+1` exactly when `y[R+1]-y[R] <= x_i-x_{i-1}`. Intersect this with the displacement-valid interval. The first source must map to the first target, and feasibility requires the last source interval to contain the last target.
- **Complexity:** Binary search `M` in `[0,N]`; each feasibility check is `O(number_of_ones_in_A * log(number_of_ones_in_B))` due to coordinate interval searches. Total complexity is `O(N log^2 N)` in the loose bound, acceptable for total input size `10^6`; actual binary search has at most 20 iterations.
- **Impossibility:** If `A` has fewer occupied positions than `B`, reaching `B` is impossible because operations can merge occupied positions but cannot split one occupied support position into multiple positions.
