- **Transfer representation:** Processing columns left-to-right gives a lower-triangular transfer matrix. For one column with values `v[0..K-1]`, entry `(i,j)` is `prod(v[j..i])` for `j <= i`. The answer is the bottom-left entry of the ordered product. Transposing allows `K=min(H,W)`.
- **Rank-one update:** Changing entry `v[r]` by `delta` changes its transfer matrix by `delta * u * v^T`, where `u[i]=prod(v[r+1..i])` for `i>=r` and `v[j]=prod(v[j..r-1])` for `j<=r`. This does not use division and correctly handles zero weights.
- **Segment tree propagation:** If a leaf product changes by rank one, every ancestor product changes by rank one. For product `P=R*L`, a change `delta*u*v^T` in `L` becomes `delta*(R*u)*(v^T)`, while a change in `R` becomes `delta*u*(v^T*L)`. Stored matrices can thus be updated in `O(K^2 log C)` per point change after constructing the rank vectors.
- **Implemented range:** The program uses the rank-one transfer segment tree when `min(H,W)<=8`; this is exact and substantially better than recomputing the grid for narrow cases.
- **Unresolved full constraint issue:** The general case still uses `O(HW)` DP per query and is not sufficient for the intended full limits. A definitive full solution needs a data structure exploiting the adjacent-walk condition beyond narrow transfer matrices.
- **Rejected contraction claim:** Contracting all cells outside a connected set of updated cells can yield a dense `Theta(|S|^2)` marked-vertex DAG, e.g. a staircase of marked cells. Therefore connectedness alone does not provide a linear-size contracted path network.
