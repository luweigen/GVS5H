- **Algorithm:** Use two pointers. Potential top mochi are scanned from indices `0` through `N//2 - 1`; potential bottoms are scanned from index `N//2` onward. If `2 * A[top] <= A[bottom]`, pair them and advance the top pointer. Always advance the bottom pointer after considering it.
- **Why only the first half can be tops:** A solution with `K` pairs has `K <= floor(N/2)`. Replacing any selected top by a smaller unselected mochi cannot invalidate its pair, so an optimal matching can use only mochi from the first half as tops.
- **Greedy correctness:** For the current smallest unpaired top, any bottom that is too small cannot pair with this top or any later top, since later tops are no smaller. Thus it can safely be discarded. When the first compatible bottom is found, using it is safe: it is the smallest feasible bottom, preserving all larger bottoms for later, potentially larger tops. Therefore every greedy pair is compatible with a maximum matching, and the final count is optimal.
- **Complexity:** Each pointer moves at most `N` times, giving `O(N)` time and `O(N)` memory for parsed input.
- **Arithmetic:** Compare `2 * A[top] <= A[bottom]` directly; no floating-point operations are used.
