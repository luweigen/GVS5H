- **Feasibility characterization:** For an interval \([L,R]\) of length \(M\), \(K\) pairs are possible iff the \(K\) smallest mochi can be used as top cakes and the \(K\) largest mochi as bottom cakes, paired in ascending order. Thus feasibility is equivalent to \(2A_{L+i} \le A_{R-K+1+i}\) for all \(0 \le i<K\).
- **Transition values:** Let \(F[x]\) be the first index with \(A_{F[x]} \ge 2A_x\), or \(N\) if it does not exist. Define \(D[x]=F[x]-x\). Since the array is sorted, the condition for all pairs becomes \(\max_{x\in[L,L+K-1]}D[x]\le M-K\).
- **Monotonicity:** As \(K\) increases, the queried range of \(D\) only expands, so its maximum cannot decrease; meanwhile \(M-K\) decreases. Therefore, if a given \(K\) is infeasible, all larger values are infeasible, allowing binary search.
- **Data structure:** Compute each \(F[x]\) with `bisect_left(A, 2*A[x])`. Build a sparse table over \(D\) for static range maximum queries. A maximum query is answered in \(O(1)\) using two overlapping power-of-two blocks.
- **Correctness sketch:** If the range maximum condition holds, every one of the first \(K\) elements has a feasible partner no later than its corresponding element among the last \(K\), so the stated ordered pairing is valid. Conversely, any matching of \(K\) pairs implies that replacing top cakes by the \(K\) smallest interval elements and bottom cakes by the \(K\) largest interval elements cannot make any ordered pair harder to satisfy, yielding the same inequalities and hence the maximum condition.
- **Complexity:** Computing transitions costs \(O(N\log N)\). Sparse table construction costs \(O(N\log N)\) time and space. Each query performs \(O(\log N)\) binary-search steps, each with \(O(1)\) RMQ, for total \(O(Q\log N)\).
