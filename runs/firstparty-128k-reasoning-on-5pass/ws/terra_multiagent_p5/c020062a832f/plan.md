Compute the inversion count for `k=0` using a Fenwick tree over values `0..M-1`. When increasing `k` by one, exactly the elements whose current value is `M-1` wrap to `0`; equivalently, these are the original elements with value `M-1-k`. Their inversion contribution changes based only on how many greater/smaller-position elements occur before and after them. Precompute, for every value `x`, the total change caused when all occurrences of `x` wrap, then update the answer in O(1) per shift. This yields O(N log M + N + M) time and O(N + M) memory.
