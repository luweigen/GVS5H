- **Characterization:** For a fixed starting slime, absorbed slimes always form a contiguous interval. Since all sizes are positive, whenever a boundary slime is absorbable, absorbing it cannot reduce future possibilities.
- **Component decomposition:** For any interval component, let `M` be its maximum value and remove every position whose value is `M`. The remaining non-empty gaps are child components. The resulting hierarchy has at most `N` components because every original position is a maximum position of exactly one component.
- **Maximum-group behavior:** Consider a slime with value `M` in a component whose maximum is `M`.
  - If it has an adjacent smaller value inside the component, it absorbs that value, becomes larger than `M`, and can then absorb every slime in the component.
  - Otherwise all existing adjacent slimes inside the component have value `M`, so it cannot make any move.
- **Crossing to a parent:** A child component is separated from the rest of its parent by parent-maximum slimes. After consuming the whole child, its size is `sum(child)`. It can cross into the parent iff `sum(child) > max(parent)`. Once it absorbs one parent maximum, it becomes larger than every value in the parent and consumes the whole parent.
- **Binary lifting:** For each component `v`, precompute whether a fully consumed `v` can consume its parent. Doubling combines these predicates: a jump of length `2^k` is possible iff both consecutive half-jumps are possible. Each starting slime that can consume its own maximum component climbs the component tree in `O(log N)`.
- **Construction:** A range-maximum segment tree finds the maximum of each component interval. A dictionary from value to sorted occurrence positions identifies all maximum positions in that interval with binary searches. Total component construction is `O(N log N)`.
- **Complexity:** There are `O(N)` components. Segment-tree decomposition costs `O(N log N)`, binary lifting costs `O(N log N)`, and answers cost `O(N log N)`. Memory usage is `O(N log N)` for lifting tables.
- **Strict inequality:** Every transition uses `current_size > barrier_value`; equality does not permit absorption.
