- **Square-root decomposition on X:** Partition possible prefix lengths X into contiguous blocks of size S. For a block with fixed left boundary L, write `F(X,Y) = F(L,Y) + sum_{i=L+1..X} sum_{j=1..Y} |A_i-B_j|`. The residual has at most S A-elements.
- **Processing one X-block:** Sort that block’s queries by Y. Sweep B prefixes from 0 upward. Maintain `base = F(L,currentY)`. When adding `B_j`, add its total absolute-distance contribution against the fixed A prefix `A[1..L]`.
- **Fixed-prefix contribution:** Maintain the A values of the current fixed prefix in two Fenwick trees over compressed values: one tree for counts and one for sums. For a value v, if `(c_left,s_left)` denotes the count/sum of active A values at most v, then `sum |a-v| = v*c_left-s_left + (total_sum-s_left)-v*(total_count-c_left)`.
- **Residual contribution:** Build persistent segment-tree roots for every B prefix. Each root stores counts and sums by compressed B value. For any `A_i` and B-prefix length Y, get count/sum of B values at most `A_i`; apply the same absolute-distance formula. Sum this for `i=L+1..X`.
- **Persistent B tree:** It uses coordinate compression only on B values. Each insertion copies one root-to-leaf path, requiring `O(log N)` nodes. Python `array` storage keeps memory lower than Python object lists.
- **Complexity:** With block size S, processing each used block sweeps at most N B-elements, costing `O(N log N)` per block. Residual work costs `O(K*S*log N)`. Total is `O((N^2/S + K*S) log N)` in the worst case, plus `O(N log N)` preprocessing. Choosing `S ≈ N/sqrt(K)` balances the terms. Memory is `O(N log N + N)`.
- **Integer safety:** Python integers safely handle values up to approximately `2e18`; in fixed-width languages, signed 64-bit integers are required.
