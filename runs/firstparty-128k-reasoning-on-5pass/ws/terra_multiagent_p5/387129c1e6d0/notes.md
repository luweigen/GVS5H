- **Approach:** Store houses indexed both by horizontal row (`y -> houses sorted by x`) and vertical column (`x -> houses sorted by y`). A movement only queries the map for its current row or column.
- **Distinct counting:** Every house is removed immediately after being found. It is deleted from both its row and column successor structures, so revisiting it later never counts it again.
- **Successor DSU:** Each house ID is a node in two disjoint-set successor structures: one for row order and one for column order. For a row, `row_next[id]` points to the next house ID in that same sorted row; similarly for columns. Deleting a house sets its parent to the next currently active house. A sentinel ID `N` represents no remaining house.
- **Query:** For a segment interval, binary search finds the first coordinate at least the inclusive lower endpoint. Applying `find` to that house ID skips any deleted houses. Repeatedly process successors while their coordinate is at most the inclusive upper endpoint.
- **Correctness details:** Segment endpoints are included through `bisect_left(lower)` and `coordinate <= upper`. The departure position cannot initially contain a house, but may contain a previously visited house; deletion handles this correctly.
- **Complexity:** Sorting all row and column lists costs `O(N log N)`. Each movement has one binary search, and every house is enumerated/deleted at most once. DSU operations are amortized inverse-Ackermann, giving `O((N + M) log N)` overall in the worst case for searches, with `O(N)` storage besides coordinate maps/lists.
- **Integer safety:** Python integers naturally support cumulative positions beyond 32-bit and 64-bit bounds used in examples.
