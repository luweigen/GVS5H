- **State representation:** After processing a coordinate `x`, bit `d` of the `B`-bit state stores whether square `x-d` is reachable, for `0 <= d < B`. Bit 0 is therefore the current square.
- **Good-square transition:** For the next good square, it is reachable iff one of the current bits with distances `A-1` through `B-1` is set. Shift the state left by one, discard bits beyond `B`, and insert this result into bit 0.
- **Bad-square transition:** A bad square is never reachable, so its transition is just a left shift with a zero inserted. A bad run of length at least `B` makes the state zero, since all previously reachable squares become too far behind to be used.
- **Compressed runs:** Process each good gap before an obstacle, then its bad interval, then the final good suffix ending at `N`. There are only `O(M)` runs.
- **Fast-forwarding good runs:** `advance_good` detects repeated bitmask states. Once a state repeats, the deterministic automaton is cyclic, so only the remainder modulo the cycle length needs simulation. The number of relevant state transitions before a cycle is small here: for `A < B`, any nonzero state in an uninterrupted good region eventually reaches the all-one fixed state; for `A = B`, the recurrence is periodic.
- **Correct initialization:** Square 1 is initially reachable, represented by state `1`. Obstacles are guaranteed not to include square 1 or square `N`.
- **Complexity:** Each obstacle is processed once. Good-run cycle detection uses only a small finite-state trajectory; with `B <= 20`, practical time is `O(M * small_constant)` and memory is `O(B)` per run aside from the temporary seen-state dictionary.
