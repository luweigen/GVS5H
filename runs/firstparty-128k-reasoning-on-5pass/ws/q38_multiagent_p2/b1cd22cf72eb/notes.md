- **Core formula:** The minimum cost is `total_initial_length - N * H_max`, because every final tooth pair has sum `H`, so the final total length is `N * H`.
- **Upper bound on H:** For any feasible final upper sequence `a`, the Lipschitz condition and `a[j] <= U[j]` imply `a[i] <= U[j] + X * |i - j|` for all `j`. Hence `a[i] <= f[i]`, where `f[i] = min_j(U[j] + X * |i - j|)`. Also `H = a[i] + final_lower[i] <= a[i] + D[i] <= f[i] + D[i]`. Therefore `H <= min_i(f[i] + D[i])`.
- **Achievability:** Let `H = min_i(f[i] + D[i])`. The transformed sequence `f` is `X`-Lipschitz and satisfies `f[i] <= U[i]`. Choosing `a[i] = min(f[i], H)` keeps the sequence `X`-Lipschitz, keeps `a[i] <= U[i]`, and keeps `a[i] <= H`. Since `H <= f[i] + D[i]`, we have `H - D[i] <= f[i]` and `H - D[i] <= H`, so `a[i] >= H - D[i]`. Thus `final_lower[i] = H - a[i]` is between `0` and `D[i]`. This proves `H` is feasible and maximal.
- **Distance transform:** Initialize `f` with `U`. A left-to-right pass computes the minimum over `j <= i`, and a right-to-left pass adds the minimum over `j >= i`. In-place updates are safe because each pass only depends on the already-processed neighbor.
- **Implementation details:** Store `f` and `D`, accumulate `total` while reading. Python integers are arbitrary precision, so values around `10^14` are safe. Time complexity is `O(N)`, memory is `O(N)`.
- **Sample checks:** Sample 1 gives `H = 4`, total `31`, answer `15`. Sample 2 gives `H = 6`, total `24`, answer `0`. Sample 3 gives `f = [4, 3, 2, 1]`, `H = 2`, total `6000000002`, answer `5999999994`. Sample 4 gives `H = 380`, total `15160`, answer `9460`.
- **Superseded approach:** Binary searching `H` with interval propagation is valid but unnecessary; the direct two-pass formula is simpler and faster.
- **Pitfalls:** Do not forget the right-to-left pass, do not choose a single greedy upper value, and do not use 32-bit arithmetic for the final answer.
