- **Structure:** An edge exists exactly when two closed intervals are disjoint, i.e. when one interval is completely to the left or right of the other. This is the comparability graph of the interval order defined by i < j iff R_i < L_j.
- **Path bound:** All vertex weights are positive, so an optimal path can be assumed chordless: any chord lets us shortcut and remove positive-weight vertices. A direct case analysis on five intervals shows this graph has no induced P5. Assuming a chordless path v1-v2-v3-v4-v5, orient v1 left of v2. Nonedge v1v3 forces v3 left of v2. Nonedge v2v4 forces v4 right of v3 and overlapping v2. Nonedge v1v4 then forces L4 < L2. To avoid edge v3v5, v5 must be left of v4, but then it cannot overlap v2, contradiction. Hence every chordless path has at most four vertices, so only paths with 0, 1, or 2 intermediate vertices need to be considered.
- **Direct edge:** If the query intervals are disjoint, the direct edge is optimal because any longer path adds positive-weight vertices.
- **Two-edge paths:** For overlapping query intervals s and t, an intermediate vertex disjoint from both must be completely left of both or completely right of both. Left means R_x < min(L_s, L_t); right means L_x > max(R_s, R_t).
- **Three-edge paths:** Let u be the endpoint with smaller left endpoint, and v the other endpoint. Any 3-edge path not dominated by a 2-edge path has first intermediate x with L_x > R_u and second intermediate y with R_y < L_v. Then R_y < L_v <= R_u < L_x, so x and y are automatically disjoint. Other 3-edge shapes contain an intermediate disjoint from both endpoints, giving a cheaper 2-edge path, so considering the 2-edge candidate plus this broad 3-edge candidate is sufficient.
- **Precomputation:** Store the minimum weight for each left endpoint and each right endpoint. Build suffix minima over L for queries L > y, and prefix minima over R for queries R < x. Coordinates are in [1, 2N], so arrays of size about 2N + 5 are enough.
- **Strict inequalities:** Closed intervals touch when R_i == L_j, so all disjointness checks are strict. Query R < x using prefR[x - 1], and L > y using suffL[y + 1].
- **Endpoint exclusion:** The strict overlap conditions automatically exclude the query endpoints from all intermediate ranges, so no special exclusion is needed.
- **Numerics:** Python integers are used. INF = 10**30 is far above the maximum possible real answer, which is at most 4 * 10^9.
- **Validation:** The program includes an optional `--selftest` mode that compares the fast answer routine against a Dijkstra brute force on random small instances with all ordered pairs. Normal execution reads stdin and writes only the answers.
