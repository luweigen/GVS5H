- **Prefix reduction:** The interval answer is `F(r) - F(l - 1)`, with `F(0) = 0`. `F(n)` counts beautiful numbers from 1 to n.
- **Zero digits:** Any positive integer containing a zero digit has digit product 0, and 0 is divisible by its positive digit sum. Therefore `F(n) = n - count_no_zero(n) + count_no_zero_beautiful(n)`.
- **No-zero count:** Count positive integers <= n with no zero digit by lengths: sum `9^L` for shorter lengths, then scan n's digits. At a digit `d > 0`, add `(d - 1) * 9^rem` for choosing a smaller nonzero digit; break at the first zero; add 1 if n itself has no zero.
- **Memoized digit DP:** `count_no_zero_beautiful(n)` uses `dp(pos, tight, started, sum, e2, e3, e5, e7)`. Before started, digit 0 is allowed as a leading zero; after started, only digits 1..9 are allowed. This counts all positive no-zero numbers <= n without double counting.
- **Exponent caps:** The digit product only has prime factors 2, 3, 5, and 7. For a number of length m, digit sum is at most `9 * m`, so caps `floor(log_p(9 * m))` for p in 2, 3, 5, 7 are sufficient. Capped exponents preserve divisibility by the digit sum.
- **Product table:** A small table maps capped exponent tuples to the corresponding capped product. At a terminal state, the number is beautiful iff `product_table[exponents] % sum == 0`. Sums containing primes other than 2, 3, 5, or 7 automatically fail.
- **Tight handling:** `limit` is the current bound digit when tight, else 9. Choosing the same digit keeps tight; choosing a smaller digit clears it. A leading zero keeps tight only if the bound digit is 0.
- **Verification:** Examples 10..20 gives 2 and 1..15 gives 10. Manual brute-force checks for small ranges match: 1..99 gives 24, two-digit no-zero beautiful numbers are 22, 36, 44, 63, 66, 88, and 1..123 gives 37. Powers of ten and zero-containing boundaries such as 100, 101, 110, and 120 are handled by the zero break and leading-zero DP paths.
- **Complexity:** Under constraints, m <= 9. The DP state space is bounded by position, sum up to 81, and capped exponent combinations, so two prefix calls are fast.
