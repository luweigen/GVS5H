- **Core reduction:** For a fixed common frequency k, a good final string chooses a subset of letters, each appearing exactly k times. Start from the baseline of deleting all n original characters and inserting k*m target characters, where m is the number of chosen letters. Keeping an original character unchanged saves 2 operations; changing it one step forward saves 1; changing it two or more steps costs at least 2, the same as delete plus insert, so such moves can be ignored for the minimum cost.
- **DP state:** For each k, scan the 26 letters. dp0 and dp1 store the best adjusted saving, meaning total positive savings minus k times the number of selected letters, up to the previous letter, with the previous letter not selected or selected. The best cost for a prefix is n - max(0, dp0, dp1).
- **Transition:** For letter i, keep = min(cnt[i], k), rem = k - keep. If i is selected, its base weight is 2*keep - k, plus one extra saving for each character incremented from i-1, up to rem. If i-1 was not selected, all cnt[i-1] characters are available to increment into i. If i-1 was selected, only max(0, cnt[i-1] - k) surplus original i-1 characters are available. This gives w0 and w1, then ndp0 = max(dp0, dp1) and ndp1 = max(dp0 + w0, dp1 + w1).
- **Why state is sufficient:** The only future effect of letter i is how many original i characters remain available to increment into i+1. In an optimal positive-saving solution, a selected letter keeps min(cnt[i], k) exact characters, so the available surplus depends only on cnt[i] and whether i was selected. Zero-saving two-step moves can be replaced by delete plus insert without affecting other choices, so they do not need to be tracked.
- **k bound:** It is enough to try k from 1 to n. For one chosen letter, cost is minimized at k equal to that letter's count or at k=1, both within n. For at least two chosen letters and k > n, the target length exceeds 2n, forcing at least n+2 net inserts, which is worse than the always-available fallback of keeping one character and deleting the rest, cost n-1.
- **Empty target:** Choosing no letters gives adjusted saving 0 and cost n. Since n >= 3, keeping one character and deleting the rest gives cost n-1, so the empty target is never the unique optimum; max with 0 is safe.
- **Complexity:** Counting is O(n). The DP is 26 states per k, so O(26*n) time and O(1) extra space. For n = 20000 this is about 520k inner iterations.
- **Verification:** The examples acab, wddw, aaabc give 1, 0, 2. A reverse BFS brute force over small alphabets and lengths up to 5 found no mismatches. Edge cases include all same, all distinct, large gaps, adjacent surplus, and multi-count cases; all pass.
