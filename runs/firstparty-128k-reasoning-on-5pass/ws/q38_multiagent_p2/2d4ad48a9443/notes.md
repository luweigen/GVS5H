- **Minimum cost:** For a fixed subarray, the optimal final values are the running maxima from the left. Cost is `sum(running maxima) - sum(original)`. Incrementing an element above the running maximum can only increase later requirements.
- **Record chain:** For start `l`, running maxima change only at `l` and iterated next strictly greater indices. `nxt[i]` is the first `j > i` with `nums[j] > nums[i]`, or `n`. The monotonic stack pops `<=` so equal values are skipped, keeping the chain correct and short.
- **Path refactor:** `path[n] = 0` and `path[i] = nums[i] * (nxt[i] - i) + path[nxt[i]]`, computed right-to-left. For query `(l, r)`, after finding `p`, the farthest record index on the chain from `l` that is `<= r`, the running-maximum sum is `path[l] - path[p] + nums[p] * (r - p + 1)`. This removes the old `seg` table.
- **Binary lifting:** `up[0] = nxt`, and `up[b][i] = up[b-1][up[b-1][i]]`. `B = n.bit_length()` levels are enough. In `bad(l, r)`, iterate levels descending and jump while `upb[p] <= r`. Since `r < n`, `p` never becomes the sentinel `n`.
- **Two-pointer:** Cost is nonincreasing when `left` moves right and nondecreasing when `right` moves right. Therefore valid starts for each `right` form a suffix. Advance `left` while cost exceeds `k`, then add `right - left + 1`. Cost exactly equal to `k` is valid because `bad` uses `>`.
- **Complexity:** `O(n log n)` time and `O(n log n)` memory for the `up` table, plus `O(n)` for prefix sums and `path`. The `up` levels mostly store references to existing index integers, so memory is modest for `n = 10^5`.
- **Edge cases:** `n = 1`, all equal, strictly increasing, strictly decreasing, `k = 0`, and exact-cost boundaries are handled. Equal values are skipped by `nxt`, which is correct because they do not change the running maximum.
- **Self-tests:** The `__main__` block checks the two examples, targeted edge cases, and 2000 seeded random small arrays against an `O(n^2)` brute force. It is silent and can be removed for submission.
- **Result:** No failure, TLE, or memory issue was found with the refactored approach, so no alternative approach was needed.
