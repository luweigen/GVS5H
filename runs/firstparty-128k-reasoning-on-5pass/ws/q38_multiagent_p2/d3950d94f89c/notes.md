- **Problem reduction:** Every special path is a suffix of a root-to-node path. For a fixed endpoint, valid starts are ancestors such that the suffix has unique values. Because all edge lengths are positive, the shallowest valid start gives the longest path ending at that endpoint.
- **Left boundary invariant:** For the current root-to-node path, `left_at_depth[d]` is the smallest index `L` such that values in `path[L..d]` are unique. The root has `L = 0`. When entering a node at depth `d` with value `x`, let `prev` be the deepest previous index of `x` on the current path, or `-1`. Any valid suffix ending here must start at least at the parent's left boundary and at least at `prev + 1`, so `L = max(parent_left, prev + 1)`. This is minimal and sufficient.
- **Iterative DFS state:** Use enter/exit events from node 0 to avoid recursion. `path_dist` stores root distances for the active path. `left_at_depth` stores the left boundary for each active depth. `last[value]` stores the deepest active stack index for that value. On entry, compute `prev`, compute `left`, push the node's distance and left boundary, update `last`, update the answer, push an exit event carrying `prev`, then push child enter events. On exit, restore `last[value] = prev` and pop both stacks.
- **Event ordering and rollback:** Pushing the exit event before child enter events ensures a node exits after all descendants. Sibling enter events remain above the parent's exit, so the parent path stays active while siblings are explored. Restoring `last` to the previous occurrence, or `-1`, removes stale branch state.
- **Answer update and tie-breaking:** For a node at depth `d` with left boundary `L`, candidate length is `dist - path_dist[L]` and candidate node count is `d - L + 1`. Initialize `best_len = 0` and `best_nodes = 1` for single-node paths. Update when length is larger, or equal with fewer nodes. Positive edge lengths make the longest path ending at a node have a unique shallowest start, so checking only `L` per endpoint is enough for both maximum length and minimum node count among ties.
- **Complexity:** Building adjacency is `O(n)`. Each node is entered and exited once, and each edge is scanned twice. `last` is an array of size `max(nums) + 1`, bounded by `50001` under constraints, giving `O(1)` value updates. Total time is `O(n)`, and memory is `O(n + max(nums))`.
- **Edge cases and pitfalls:** If all adjacent values duplicate, every candidate length is `0`, and the answer remains `[0, 1]`. Deep chains are safe because the DFS is iterative. The parent check is sufficient because the input is a valid tree. The supplied threshold/binary-search plan is superseded by this simpler left-boundary propagation.
