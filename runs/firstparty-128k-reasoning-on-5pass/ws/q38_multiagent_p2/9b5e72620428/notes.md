- **Reduction:** Fix a common sum S. Unknown B slots can take any fixed A not exceeding S; fixed B slots require the placed A to be S-B. Let f be fixed A count and ub unknown B count. If f<=ub (K=f-ub<=0), choose S=max fixed value. If K=1, choose S=maxA+maxB. Thus K<=1 is always Yes.
- **Matching condition:** For K>1, at least K fixed A values must be paired with fixed B values with a+b=S. For a given S, the maximum number of such pairs is M(S)=sum_x min(cntA[x], cntB[S-x]). Also S must be at least L=max(max fixed A, max fixed B, 0).
- **Layer identity:** Define A_t={x:cntA[x]>=t}, B_t={y:cntB[y]>=t}. Then M(S)=sum_t #{x in A_t : S-x in B_t}. Therefore each triple (t,x,y) with x in A_t, y in B_t contributes one weighted sum x+y; a feasible S is exactly a value appearing at least K times among these sums, after discarding sums below L.
- **Layer cap:** P_t(S) is nonincreasing in t, so layers t>K can never be needed to reach K. Use max_t=min(max count A, max count B, K).
- **Implementation:** Build Counters, then sorted layers by appending each value to layers 1..min(count,max_t). For each t, use the smaller layer as outer and the larger as inner. Since layers are sorted, a moving pointer st gives the first inner value with x+y>=L (same as the min/bisect threshold filter); extend the sum list with x+y for the valid suffix.
- **Decision:** If the total number of generated weighted sums is below K, answer No. Otherwise sort the list and scan for a run of length at least K.
- **Complexity:** Total layer sizes are O(N). The number of generated sums is sum_t |A_t||B_t| = sum_{x,y} min(cntA[x],cntB[y]) <= f*fb <= 4e6. Sorting dominates, O(P log P) with P<=4e6, memory O(P), acceptable for N=2000.
- **Edge cases:** No fixed A or B is covered by K<=1. L can be 0. Duplicates are handled by layers, not by raw pair counts. K=1 is always Yes because maxA+maxB gives one valid fixed-fixed pair.
- **Pitfalls:** Do not forget S must dominate every fixed value, not only matched ones. Do not count all raw pairs; use multiplicity layers. Storing all candidate sums separately is unnecessary; the weighted sum list directly encodes M(S).
