- **Core invariant:** For x=1..M (M=max query), F(x) is the current rating after processed contests. Each contest applies a nondecreasing function to the rating, so F remains nondecreasing.
- **Difference array:** d[x]=F(x)-F(x-1), F(0)=0. Initially d[x]=1. Since F is nondecreasing, d[x]>=0. A contest increments exactly indices a..c-1, where a=first x with F(x)>=L and c=first x with F(x)>=R+1. This is a range add +1 to F, i.e. d[a]+=1 and d[c]-=1 when c<=M; if c=M+1, only d[a]+=1 and F(M) increases by 1.
- **Fenwick tree:** Store d in a Fenwick tree; prefix sum gives F(x). Initialize bit[i]=lowbit(i) for the all-ones array. Maintain total=F(M), initially M.
- **Lower bound:** Fenwick lower_bound finds the first index with prefix sum >= t using nonnegative d. Use highest power of two <=M and a `nxt <= M` guard. It returns M+1 when t exceeds total. In the main loop we skip L>total and handle R+1>total directly, so lb is called only for feasible targets.
- **Update rule:** If R+1>total, the affected range is [a,M]; add +1 at a and total +=1. Otherwise c=lb(R+1); if c>a, add +1 at a and -1 at c. This avoids explicit b and no-op updates.
- **Finalization:** Convert the Fenwick tree to prefix sums in place: for i=1..M, bit[i] += bit[i - lowbit(i)]. Then bit[x] is the final rating for initial x. Answer queries in original order.
- **Complexity:** O((N+Q) log M + M) time and O(M + input) memory. M<=5e5, so the Fenwick work is about 12M loop iterations in the worst case.
- **Pitfalls:** Use R+1 and treat c as b+1; total increments only when the range reaches M; d must stay nonnegative for lower_bound; simulating only up to max query is safe because F(x) for x<=M is independent and F(M) is the maximum; in-place prefix transform must read bit[i] before overwriting it.
