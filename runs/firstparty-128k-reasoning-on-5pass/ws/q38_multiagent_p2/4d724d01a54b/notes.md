- **Core idea:** Swap costs increase with edge index, so an optimal sorting sequence should perform swaps as far left as possible. The key is a potential whose required increase gives a lower bound, and a greedy sequence that attains it.
- **Potential definition:** For a sequence A, let L_i be the number of earlier elements smaller than A_i, and T(k)=k(k+1)/2. Define F(A)=sum_i T(L_i). In the sorted sequence, L_i=i-1, so F(sorted)=sum_i T(i-1).
- **Lower bound:** Consider swapping adjacent values x,y at edge i. Let a be the number of earlier elements smaller than x, and b the number of earlier elements smaller than y. If x>y, F increases by a+1, and a<=i-1, so the increase is at most i. If x<y, F decreases by a+1, so the change is also at most i. Therefore every swap has delta F <= cost, and any sorting sequence has total cost at least F(sorted)-F(initial).
- **Optimal sequence:** Repeatedly swap the leftmost adjacent descent. At that edge i, the prefix up to i is strictly increasing, so the left value is larger than all i-1 previous elements. The swap increases F by exactly i. It also reduces the inversion count by one, so the process terminates. Its total cost equals the lower bound, hence it is optimal.
- **Equivalent insertion view:** This greedy process is equivalent to scanning the original permutation left to right and inserting each element into the already sorted prefix. For original position i, if L_i previous elements are smaller than P_i, the new element crosses exactly the larger previous elements, using edges L_i+1 through i-1.
- **Formula:** The answer is sum over i=1..N of [T(i-1)-T(L_i)] = sum [i(i-1)/2 - L_i(L_i+1)/2], where L_i is the count of previous values smaller than P_i in the original permutation.
- **Computation:** Use a Fenwick tree over values 1..N. Scan positions left to right, query prefix sum x-1 to obtain L_i, add the closed-form contribution, then update value x. This is O(N log N) time and O(N) memory.
- **Off-by-one checks:** Query x-1, not x, because only strictly smaller values count. If L_i=i-1, the contribution is zero. If L_i=0, the contribution is T(i-1). Triangular T(0)=0.
- **Samples:** 3 2 1 gives contributions 0, 1, 3, total 4. 2 4 1 3 5 gives 0, 0, 3, 3, 0, total 6. 1 2 gives 0.
- **Brute force verification:** A Dijkstra search over all permutations with adjacent-swap costs i, compared against the formula, matches for every permutation up to N=7, including all 5040 cases for N=7.
- **Complexity:** O(N log N) time, O(N) memory. Python integers safely handle the maximum answer, which is on the order of N^3/6 for N=2e5.
