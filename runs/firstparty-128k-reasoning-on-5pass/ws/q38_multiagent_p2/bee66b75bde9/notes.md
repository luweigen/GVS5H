- **Model:** A coloring satisfying both prefix conditions is exactly a down-left closed set of black cells: if (r,c) is black, then every (r'<=r,c'<=c) is black. Conversely, any down-left closed set gives black prefixes in every row and column.
- **Forced regions:** A fixed black cell (xb,yb) forces the rectangle rows 1..xb and columns 1..yb to be black. A fixed white cell (xw,yw) is incompatible exactly when it lies in the forced rectangle of some fixed black cell, i.e. xw<=xb and yw<=yb.
- **Sufficiency:** If no white cell lies in the down-left closure of the fixed black cells, color exactly that closure black and everything else white. This closure is down-left closed, contains all fixed black cells, and avoids all fixed white cells.
- **Sweep:** Sort cells by row descending, and within the same row put black before white. Maintain max_y as the maximum column among black cells already seen. When a white cell (xw,yw) is processed, all black cells with xb>=xw have already been seen, so an incompatible black cell exists iff max_y >= yw. If so, print No; otherwise continue.
- **Same-row handling:** Processing black before white in the same row is essential, because a black cell to the right in the same row forces all cells to its left in that row to be black.
- **Complexity:** Sorting M cells costs O(M log M), the scan costs O(M), and memory is O(M). N up to 1e9 is irrelevant to the algorithm beyond coordinate bounds.
- **Edge cases:** No black cells or no white cells is fine; max_y starts at 0. Coordinates are 1-indexed, so y<=max_y is the correct comparison. Duplicate coordinates are absent by constraints.
- **Pitfall:** Checking only same-row or same-column conflicts is insufficient; a white cell strictly above and to the left of a black cell is also impossible, and the sweep catches it.
