- **Model:** Let T be the total weight of current 1s. A flip changes T by +/- C_i, and the operation cost is the new T. This is a shortest path on the hypercube where the cost of entering a state is its total weight.
- **State reduction:** If a bit is 1 during an interval but is 0 at both ends, setting it to 0 throughout that interval keeps the path valid and never increases cost. Hence A=B=0 bits are never flipped; A=1,B=0 bits flip once off; A=0,B=1 bits flip once on; A=B=1 bits are either untouched or flipped off once and on once.
- **Ordering:** For a fixed selected set S of A=B=1 bits, all off flips precede all on flips because swapping an on before an off saves a+b. Among off flips, larger C first; among on flips, smaller C first. Thus the canonical order is X∪S decreasing, then Y∪S increasing.
- **Choice of S:** For fixed k, if a<b, a in S and b not, replace a by b. In a valid sequence, flip b off at a's old off position and b on at a's old on position. Until b is turned on, the new total weight is lower by b-a; afterwards it is equal. So cost does not increase. Therefore the optimal S of size k is the k largest Z values.
- **Cost variables:** For current k, m=x+k, n=y+k, T_mid=sumZ-selected_sum. Define cost_rem = removal_sum - m*T_mid and cost_add = addition_sum - n*T_mid. Then total = (m+n)*T_mid + cost_rem + cost_add.
- **Initial values:** With X and Y ascending, cost_rem = sum_{i=0}^{x-1} (x-1-i)X[i] = x*sumX - weighted_desc(X), and cost_add = sum_{i=0}^{y-1} (y-i)Y[i] = weighted_asc(Y). best starts as cost_rem+cost_add+sumZ*(x+y).
- **Incremental update:** Process Z in descending order. Inserting z into the removal set changes cost_rem by sum_{X<z} + z*(#X>=z + k-1), computed with ix=bisect_left(X,z) and prefX[ix]. Inserting z into the addition set changes cost_add by sum_{Y<z} + z*(#Y>=z + k), computed with iy=bisect_left(Y,z) and prefY[iy]. Then total uses (sumZ-selected_sum)*(x+y+2k).
- **Ties:** bisect_left is consistent with processing equal Z values nonincreasing; equal order does not affect true cost, and the rank formulas remain valid.
- **Complexity:** Sorting and bisect give O(N log N) time and O(N) memory. Python integers handle the large answer safely.
- **Validation:** Samples 1, 2, and 3 give 16, 0, and 2867. A brute-force Dijkstra over masks for N<=8 (precompute weight[mask], relax flips with cost weight[new_mask]) matches the formula on random tiny tests. The submitted program contains only the fast solution.
