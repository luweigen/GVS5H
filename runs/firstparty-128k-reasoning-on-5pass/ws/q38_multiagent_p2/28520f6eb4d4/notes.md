- **Visibility reduction:** For observer (0,h), a building i is visible iff the segment to its top (X_i,H_i) passes strictly above every earlier building top. A lower point on building i gives a lower line at all earlier X_j, and since h and building heights are nonnegative the line stays nonnegative, so it cannot avoid a building by going under it. Thus all buildings are visible exactly when A_i(h)=(H_i-h)/X_i is strictly increasing with i.
- **Pair condition:** For i<j, the ordering A_i<A_j fails exactly when A_i(h)>=A_j(h). The critical height is h_{ij}=(H_i X_j-H_j X_i)/(X_j-X_i). Failing heights for that pair are h<=h_{ij}; the answer is the maximum nonnegative critical height, with -1 if all critical heights are negative and 0 if the maximum is exactly 0.
- **Adjacent suffices:** Write A_i(h)=a_i+m_i h with a_i=H_i/X_i and m_i=-1/X_i. Then m_i strictly increases with i. For i<j, h_{ij}=(a_i-a_j)/(m_j-m_i). For consecutive k, h_{k,k+1}=(a_k-a_{k+1})/(m_{k+1}-m_k). Since a_i-a_j and m_j-m_i are sums of the consecutive differences, h_{ij} is a positive weighted average of the adjacent intersections between i and j, so it cannot exceed the maximum adjacent intersection in that range. Scanning adjacent pairs gives the global maximum.
- **Exact arithmetic:** For adjacent pair (X_i,H_i),(X_{i+1},H_{i+1}), numerator a=H_i X_{i+1}-H_{i+1} X_i, denominator b=X_{i+1}-X_i>0. Keep the best fraction using cross multiplication a*best_den > best_num*b. Python integers are arbitrary precision; products are around 1e18 and cross products around 1e27, easily safe.
- **Sign conventions:** a>0 means H_i/X_i>H_{i+1}/X_{i+1}, so the later building is hidden at height 0 and the critical height is positive. a<0 means the pair is already ordered at height 0. If the maximum numerator is negative, all pairs are ordered at height 0, print -1. If the maximum is zero, height 0 has an exact tie and is not fully visible, but any positive height fixes it, print 0.000000000000000000.
- **Output formatting:** The exact integer fraction is used only to decide -1, 0, and the positive case. For best_num>0, print the floating-point quotient with exactly 18 digits after the decimal point using f"{best_num / best_den:.18f}". Double precision is sufficient: the answer is at most about 1e18, so the relative error from float division is around 1e-16, far below the 1e-9 relative tolerance; the minimum positive answer is at least 1e-9, so it will not be printed as zero.
- **Sample check:** Sample 1 gives 3/2 and prints 1.500000000000000000. Sample 2 has best numerator negative and prints -1. Sample 3 has maximum numerator zero and prints 0.000000000000000000. Sample 4 gives 120/7 and prints 17.142857142857142350.
- **Edge cases:** N=1 has no blocking pair, print -1. N=2 works with one pair. Equality must be treated as blocking, hence zero answer is possible. X_i strictly increasing so denominators are positive. All input values are integers, so no floating point is needed for the comparison.
- **Complexity:** O(N) time and O(N) memory when reading all integers; 2e5 iterations is easily fast enough.
