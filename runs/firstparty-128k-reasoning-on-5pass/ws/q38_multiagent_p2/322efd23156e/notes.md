- **Approach:** For each vitamin type v, compute f_v(c), the maximum vitamin v obtainable using at most c calories from foods of that type only. For a candidate threshold T, define need_v(T) as the smallest c with f_v(c) >= T. The threshold is globally feasible iff need_1(T) + need_2(T) + need_3(T) <= X. Feasibility is monotone, so binary search the largest T.
- **DP invariant:** dp[c] is maintained as an at-most capacity knapsack value. The loop is limited by cur, the capped sum of costs of processed items. Before adding an item, newly reachable capacities cur+1 through min(X, cur+c) are filled with dp[cur], so "not taking the item" is correct for capacities above the old reachable range. Descending updates preserve 0/1 semantics. A final prefix maximum guarantees a nondecreasing array.
- **Pruning:** For each vitamin and calorie cost c, no feasible subset can use more than X // c foods of that cost. Keeping only the largest X // c amounts for each cost is safe because same-cost foods differ only in amount. This can greatly reduce the number of knapsack items.
- **Ordering:** Items are sorted by cost ascending. This is not required for correctness, but it tends to reduce total inner-loop work: small-cost items are processed while cur is still small, while large-cost items have short update ranges once cur is large.
- **Feasibility check:** Use bisect_left on each nondecreasing dp array to find the minimum calorie capacity needed for T. If any vitamin cannot reach T, or the sum of the three minimum capacities exceeds X, T is infeasible.
- **Bounds and edge cases:** If any vitamin group is empty, answer is 0 immediately. The upper bound is min_v f_v(X), since no vitamin can exceed what it can get with the whole calorie budget. T = 0 is always feasible.
- **Complexity:** The knapsack work is O(NX) in the worst case, but pruning and the cur-limited updates keep the practical worst case around a few tens of millions of simple operations for N = X = 5000. Binary search adds only O(log(maxA) * 3 log X).
- **Checks:** Sample 1 evaluates to 3. Sample 2 exits early with 0 because vitamin 3 is absent. Basic edge cases such as all three required foods costing X give 0, while three cost-1 foods with X = 3 give the minimum of their amounts.
