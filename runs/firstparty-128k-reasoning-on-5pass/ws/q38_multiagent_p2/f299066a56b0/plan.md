Use the sorted order and a greedy matching strategy. Treat the earlier mochi as candidates for the top and the later mochi as candidates for the bottom, starting the bottom pointer at the middle to leave enough possible tops. Pair the smallest unpaired top with the smallest bottom that can support it, i.e. when `2 * top <= bottom`. If the current bottom is too small, discard it; otherwise count a pair and advance both pointers. This greedy choice is safe by an exchange argument and runs in linear time.
