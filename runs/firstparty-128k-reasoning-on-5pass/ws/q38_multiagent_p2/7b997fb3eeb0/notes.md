- **Pairing reduction:** For a query interval of length M, if K pairs are possible, replacing tops by smaller unused mochi and bottoms by larger unused mochi preserves feasibility. Thus the K smallest elements can be tops and the K largest can be bottoms. With 0-based [l, r], K is feasible iff for all i in [l, l+K-1], A[l+i] * 2 <= A[r-K+1+i].
- **p_i:** p_i is the first index with A[p_i] >= 2*A_i, using sentinel N when none exists. It is computed by a two-pointer because thresholds 2*A_i are nondecreasing. p_i is nondecreasing and p_i > i for positive sizes.
- **Per-top constraint:** For top i among the first K, the assigned bottom index is r-K+1+i-l. Feasibility is p_i <= that index, equivalent to K <= M + i - p_i when p_i <= r. If p_i > r, no bottom in the whole query can serve i, so K must stop before the first such index.
- **y array:** y[r] is the last index i with p_i <= r. Since p_i is nondecreasing, y_arr is filled in O(N) with a moving pointer. For query [l, r], indices greater than y[r] have no bottom inside [l, r].
- **Direct formula:** Let F = M//2, Smax = l+F-1, y = y[r]. The answer is min of F, y+1-l, and M + min_{i in [l, min(Smax, y)]} (i - p_i). If y < l, the term y+1-l is non-positive and the answer clamps to 0.
- **Why full F prefix RMQ is safe:** For i <= y, M + i - p_i >= i-l+1. If the minimum over [l, min(Smax, y)] were below a candidate K, the index attaining it would have offset d with d+1 <= minimum < K, so it would already be inside the first K tops and would violate feasibility.
- **Implementation details:** Convert queries to 0-based. Store w_i = i - p_i and build an iterative segment tree for range minimum queries. Query [l, m] inclusive as half-open [l, m+1). Use the original Smax for the RMQ range, not a reduced answer. Clamp the final answer to at least 0.
- **Edge cases:** p_i = N is never <= r, so y excludes tops with no possible bottom. M=2 queries reduce to checking p_l <= r. If y < l, even the smallest top cannot be paired, so the answer is 0. The y+1-l term cuts the answer below F when some of the first F tops have p_i > r.
- **Complexity:** O(N log N + Q log N) time and O(N) memory.
