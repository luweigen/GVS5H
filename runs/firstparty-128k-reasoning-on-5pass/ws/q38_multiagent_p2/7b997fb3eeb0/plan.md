For each index i, compute need[i] = p_i - i, where p_i is the first index with A[p_i] >= 2A_i (or N if none), the minimum offset to the right that can serve as a bottom for i. For a query [L,R] of length M, K pairs are possible exactly when the K smallest elements in the range are tops and the K largest are bottoms, which is equivalent to max_{i=L}^{L+K-1} need[i] <= M-K. This condition is monotone in K, so the answer is found by binary searching K in [0, floor(M/2)]. Use a sparse table for O(1) range maximum queries over need, giving O(N log N + Q log N) total time.
