- **Core update:** Moving from k to k+1 only changes values whose current value is M-1. That original value is c = M-1-k. All other values increase by 1, so their relative order is unchanged. Pairs where both elements have value c remain equal, and pairs where neither has value c are unchanged.
- **Pair flip:** For every mixed pair consisting of one c and one non-c element, the inversion status flips exactly once: if c is earlier, it was an inversion before and is not after; if c is later, it was not an inversion before and is one after.
- **Delta formula:** Let t be the number of occurrences of c and S be the sum of their 1-based positions. The number of non-c elements before c-occurrences is S - t - t(t-1)/2. The number of non-c elements after c-occurrences is tN - S - t(t-1)/2. Therefore the change is earlier_non_c - later_non_c = 2S - t(N+1).
- **Initial inversion count:** Use a Fenwick tree over values 0..M-1. For position i with value a, previous greater elements = (i-1) - prefix_sum(a+1), where prefix_sum(a+1) counts previous values <= a.
- **Loop order:** Print the current answer for k, then apply the update for c = M-1-k to obtain the answer for k+1. Do not apply an update after the last printed line. For M=1, no update is performed.
- **Complexity:** O(N log M + M) time and O(M) memory. Python integers handle the maximum answer size around N(N-1)/2 safely.
- **Validation:** Samples match by hand: sample 1 gives 3,1,1; sample 2 gives 7,3,3,1,1,5; sample 3 gives 0,6,10,12,12,10,6. Edge cases: M=1 has all B_i=0 and all answers are 0; all-equal values have t=N and S=N(N+1)/2, so every delta is 0. A brute-force O(N^2 M) reference on small random cases agrees with the sweep because the update is derived from exact pair flips.
- **Pitfalls:** Positions must be 1-based for the formula; the Fenwick prefix must include value a; the update must happen after printing; c=0 is never updated because that transition would only return to k=0 after all required outputs.
