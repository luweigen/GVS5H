- **Matching model:** Each removed adjacent pair corresponds to a noncrossing matching on original indices. Crossing pairs are impossible because elements between a pair must disappear before that pair can be removed. For odd N, the single unmatched element at 0-index r blocks pairs crossing it, so the left and right sides must both have even length; hence r is even.
- **Even segment value:** For an even segment of length 2k, orient each pair from larger to smaller. The score is the sum of k “positive” values minus the sum of k “negative” values, so it is at most the sum of the largest k values minus the sum of the smallest k values. This bound is attainable: mark the largest k values as + and the smallest k as -. Any balanced +/- sequence has a noncrossing bichromatic perfect matching: if the ends differ, match them; if the ends are the same, split at a zero prefix balance and recurse. Since every + value is at least every - value, the matching realizes the bound.
- **Odd N reduction:** Fix the final element at even prefix length p. The score is H(A[:p]) + H(A[p+1:]), where H is the even-segment value. The answer is the maximum over even p. For even N, the answer is simply H(A).
- **Heap computation:** To compute H for all even prefixes, maintain low as a max-heap using negative values for the smallest floor(i/2) seen values, and high as a min-heap for the largest ceil(i/2) seen values, with all low values <= all high values. Insert x into low if x <= current low maximum, otherwise into high. Then adjust low_size to target i//2 by moving the top element from the side that is too large to the other side. Running sums give H = sum_high - sum_low when i is even. Store res[i//2].
- **Suffixes:** H of a suffix depends only on its multiset, so run the same routine on reversed(A). rev[k] is H of the last 2k elements.
- **Combination:** For N = 2m + 1, p = 2k and suffix length = 2(m-k), so answer is max over k = 0..m of pref[k] + rev[m-k]. For N = 2m, answer is pref[m].
- **Implementation pitfalls:** Use 0-based parity carefully; p is prefix length, not 1-based index. Keep low_size exact. Moving from high to low when low_size < i//2 and from low to high when low_size > i//2 preserves the order invariant, so no extra swap is needed. Python integers handle the large sums safely.
- **Samples:** Sample 1 gives H([1,2,5,3]) = 5. Sample 2 maximum is p = 0, suffix [1,4,1,5,9,2] with H = 14. Sample 3 all equal gives 0.
- **Complexity:** Two passes, each O(N log N) time and O(N) memory; N = 3e5 is comfortably within limits.
