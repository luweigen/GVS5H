- **Graph model:** Each node has one outgoing edge to A_i, so every weak component is a directed cycle with in-trees. Cycle vertices must all have the same value, and tree edges u -> v require x_u <= x_v.
- **Cycle detection:** Use indegree pruning. Nodes with indegree > 0 after repeatedly deleting indegree-0 nodes are exactly cycle nodes; self-loops are handled naturally.
- **Tree DP:** For a non-cycle node v, let f_v[c] be the number of valid assignments in its in-tree when x_v = c. A child u contributes P_u[c] = sum_{t=1..c} f_u[t], so f_v[c] = product over children u of P_u[c], and P_v[c] = P_v[c-1] + f_v[c]. Leaves have f_v[c] = 1, hence P_v[c] = c.
- **Explicit arrays:** Store P[v] as an array of length M+1 for c = 0..M. Use array('I') rows to keep memory low; all stored values are below 998244353 and fit in 32-bit unsigned integers.
- **Leaf-to-root order:** Count non-cycle children, queue non-cycle leaves, pop and append, then decrement the parent if it is non-cycle. This gives child-before-parent order, so child rows exist when a parent row is computed.
- **Cycle components:** Traverse each unvisited cycle node and collect its immediate non-cycle children as boundary nodes. For a component, the contribution is sum_{c=1..M} product_{u in boundary} P[u][c]; if there is no boundary, the contribution is M. Multiply all component contributions modulo 998244353.
- **Implementation details:** Use 0-indexed A; children lists contain only non-cycle nodes; special-case one and two children/boundary rows to reduce loop overhead; one subtraction is enough for modular addition because both operands are already reduced.
- **Complexity:** O(NM) time and O(NM) stored entries in the worst case. With N, M <= 2025 this is about 4 million entries and a few million modular multiplications, easily feasible.
- **Checks:** Samples give 6, 2025, and 10010. A small brute-force checker enumerating all M^N sequences for small N and M matches the DP on random functional graphs.
