- **Core reduction:** Let total be the XOR of all elements. If K <= N-K, enumerate the chosen K-subsets directly. If K > N-K, enumerate the omitted N-K subsets instead; for an omitted subset with XOR x, the chosen XOR is total ^ x, since total = xor(chosen) ^ xor(omitted).
- **Enumeration bound:** C(N,K)=C(N,N-K), so with m=min(K,N-K) the number of enumerated subsets is C(N,m) <= 10^6. Also m <= 11, because m <= N/2 and C(24,12) > 10^6, so the per-subset work is tiny.
- **Implementation choices:** Use itertools.combinations on the list A. This enumerates index combinations, so duplicate values are still treated as distinct positions. Special-case m=1 (max(A) for direct, max(total ^ a) for omitted) and m=2..4 with unpacked loops; use a generic inner XOR loop for m>=5.
- **Edge cases:** K=N gives m=0 and the only valid choice is all elements, answer total. K=1 gives max(A). K=N-1 gives max(total ^ a). All-zero arrays and duplicate values are safe; ans starts at 0, which is a valid lower bound for non-negative XOR values.
- **Verification:** Sample 1: pairs give maximum 3^4=7. Sample 2: full enumeration of 4-subsets gives 2024. Edge checks: K=1 returns largest element; K=N returns total XOR; A=(1,1,2,2), K=2 returns 3; near-bound N=1414,K=2 has 998991 pairs and stays within the intended O(C(N,m)*m) budget.
