- **Core lower bound:** Each piece must move at least D = dist(S,T), so answer is at least 2D. If there are at least two shortest S-T paths, answer is exactly 2D; move the pieces along opposite shortest paths, using the first/last divergence to pass.
- **Unique shortest path:** Let P be the unique shortest path. Internal P vertices are P vertices except S,T. P-edges are edges between on-path vertices whose distS values differ by 1.
- **Internal side edge candidate:** Any non-P edge touching an internal P vertex gives a local passing gadget. Compute minL = min(distS[u]+1+distT[v], distS[v]+1+distT[u]) over such edges. If minL <= D, extra 0; if minL == D+1, extra 1; otherwise extra 2. Extra 1 corresponds to an S-T path of length D+1; extra 2 is the standard park-and-pass move.
- **Bypass candidate:** Remove all internal P vertices and P-edges, then BFS from S to T. If reachable with distance d, one piece can take that detour while the other uses P, giving extra d-D. This covers endpoint-only alternative paths and D=1 cycles.
- **Corrected endpoint waiting gadget:** For X=S, remove the first P vertex p1 (neighbor of S on P); for X=T, remove the last P vertex p_{D-1}. BFS from X in the remaining graph. Let r be the minimum dist_X[w] such that w has at least two neighbors q with dist_X[q] >= dist_X[w] (for w=X this is degree >= 2 in the remaining graph). Candidate extra is 4*(r+1).
- **Why the broader endpoint graph:** The earlier H = (G-C) ∪ {X} is too small. An alternative neighbor of S that lies in the component containing T can still be used as a one-edge parking spot. Example: S-x-T, S-leaf, and S-c-long path to T. Old H sees only the leaf and misses the answer 2D+4; removing only p1 sees both leaf and c and gives extra 4.
- **Endpoint cost justification:** To swap across endpoint X, one token must vacate X, the other enter X, then the first token must pass through X while the second vacates it again. This requires two distinct safe parking spots. The first branching/cycle at distance r forces parking at distance r+1, so both tokens make round trips of length 2(r+1), total extra 4(r+1).
- **Safety of endpoint candidates:** If the counted “forward” neighbor lies on P or is T, the candidate is dominated by an internal side edge or bypass candidate, so taking the minimum remains correct.
- **Schedules:** Internal extra 2: A goes to side vertex, B passes through internal vertex to S, A returns and finishes. Extra 1: use the length D+1 path and P, waiting at the off-path vertex if needed. Bypass: one token takes the detour, the other takes P. Endpoint: use two parking spots found by the BFS; for X=S, A parks at one, B goes to S then parks at the other, A returns and goes to T, B returns to S.
- **Complexity:** Five BFS passes (shortest-path count, distT, bypass, two endpoint BFS) plus one edge scan and two endpoint scans. O(N+M) time, O(N+M) memory.
- **Edge cases:** N=2 path gives -1; triangle with direct edge gives 3; path with internal leaf gives 2D+2; endpoint with two usable neighbors gives 2D+4; endpoint with only one simple tail gives -1 unless another gadget exists; multiple shortest paths give 2D.
- **Implementation notes:** Use list queues for speed, bytearray for on_path/internal, cap shortest-path counts at 2, delete large arrays before endpoint BFS to reduce peak memory.
