- **Interval model:** Normalize each pair to `(a, b)` with `a < b`. A subarray `[l, r]` is invalid iff it contains at least one interval, i.e. `a >= l` and `b <= r`.
- **Base count:** Sweep right endpoint `r`. Active intervals are those with `b <= r`. If their maximum left endpoint is `M`, valid starts are `l = M + 1 .. r`, contributing `r - M` (or `r` if none). Summing over `r` gives the valid count for the full pair set.
- **Gain accounting:** For a removed interval `k`, the increase at right endpoint `r` is `M(r) - M_k(r)`. This is positive only when `k` is the unique active interval with maximum `a`. Then `M_k(r)` is the second maximum distinct `a` (or `0`), so the gain is `max_a - second_a`. If the maximum `a` is shared by multiple active intervals, removing one leaves `M` unchanged, so no gain.
- **Sweep implementation:** Bucket intervals by `b`. At each `r`, insert all intervals with `b == r` before counting. Maintain a max-heap of distinct `a` values stored as negatives, `cnt[a]` = number of active intervals with left endpoint `a`, and `uid[a]` = interval id only while `cnt[a] == 1`, otherwise `-1`. Pop the top to read the second distinct `a`, then restore it. Add `r - max_a` to base; if `cnt[max_a] == 1`, add `max_a - second_a` to `gain[uid[max_a]]`.
- **Duplicates and ties:** `cnt[a]` correctly handles duplicate pairs and same-`a` different-`b` intervals. Duplicates with the same `a, b` never earn gain. For same `a` with different `b`, the earlier interval can earn gain until the later one becomes active; after both are active, neither earns for that `a`.
- **Complexity:** `O((n + m) log n)` time and `O(n + m)` memory. Python integers safely handle answers up to about `5e9`.
- **Edge cases:** `m == 0` robustly returns total subarrays; `m == 1` returns total subarrays; all duplicates can have maximum gain `0`; `second_a` sentinel is `0`; all insertions for a given `r` are processed before counting so same-`b` same-`a` duplicates are seen together.
- **Testing:** The program asserts the two provided examples plus targeted edge cases and runs a deterministic brute-force random checker for `n <= 8`, `m <= 10`, including forced duplicates. The brute force uses a bitmask of contained pairs per subarray and tries every removal.
