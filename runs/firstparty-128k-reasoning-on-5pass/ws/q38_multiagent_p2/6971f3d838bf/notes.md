- **Reduction:** Only deleting a negative value can improve the answer. For any x >= 0, every subarray in the array after deleting x maps to an original contiguous interval whose sum is at least as large, so the original Kadane answer already dominates.
- **Baseline:** Compute the non-empty Kadane maximum. If best <= 0, return best immediately: there is no positive element, and deleting a negative value cannot create a positive subarray.
- **Prefix transform:** For x < 0, let y = -x. Replacing x by 0 gives prefix A[i] = P[i] + y * C[i], where P is the original prefix sum and C[i] is the number of x occurrences before index i. Since best > 0, the maximum positive prefix difference equals the valid maximum subarray sum after deletion; all-x zero intervals are harmless.
- **Gap decomposition:** Occurrences p0 < ... < p_{m-1} split prefix indices into gaps with constant C=k: [0, p0], [p_{k-1}+1, p_k], and [p_{m-1}+1, n]. In gap k, A[i] = P[i] + y*k.
- **Gap scan:** Pairs of prefix indices in the same gap contain no x, so their sums are original subarray sums already bounded by the baseline. Only cross-gap pairs can improve. Scan gaps left to right, maintain min_seen = minimum A in all previous gaps, update ans with maxA_current - min_seen, then update min_seen with minA_current.
- **Range queries:** The first gap minimum uses pref_min[p0]. The last gap maximum uses suff_max[p[-1]+1]. Middle gaps use an iterative segment tree for range min/max over P. The total number of middle gaps over all negative values is at most n, giving O(n log n) time and O(n) memory.
- **Implementation details:** Build P and negative positions in one pass. Build the segment tree only if some negative value occurs at least twice. Use an offset variable incremented by y for each gap. Use INF = 10**30, safely above the maximum possible sum.
- **Edge cases:** n=1, all non-positive, no negatives, single occurrence, consecutive occurrences, x at array ends, zeros, all equal values, and large distinct negative values are handled. When best > 0, deleting a negative value always leaves at least one positive element, so the non-empty subarray constraint is safe.
- **Verification:** Example 1 returns 7, Example 2 returns 10. A brute-force random tester on small n and small value ranges, comparing against direct deletion plus Kadane, found no discrepancies.
