Use a sqrt decomposition over the A-prefix length. Precompute the full answer F(x,Y)=sum_{i<=x}sum_{j<=Y}|A_i-B_j| for every block boundary x=0,S,2S,...,N by maintaining a sorted copy of A[:x] and, for each boundary, scanning B in value order with a two-pointer to get each B_j's contribution, then prefix-summing over the original B order. For a query (X,Y), choose the nearer boundary (block start or end), initialize the answer with that precomputed F, and record the short remaining A-index range (at most S/2) that must be added or subtracted. Process all these short-range corrections offline by sweeping Y from 1 to N with a Fenwick tree over compressed B values, maintaining counts and sums of B_1..B_y; for each query at its Y, loop over its recorded A range and compute sum_{j<=Y}|A_i-B_j| from the count/sum of B values less than A_i. With S around 500 the total work is O(N^2/S + K*S*log N) and memory O(N+K), which fits the constraints. Use 64-bit integers for all sums.
