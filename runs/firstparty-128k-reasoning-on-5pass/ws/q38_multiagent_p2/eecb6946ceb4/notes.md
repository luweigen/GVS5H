- **Reduction:** A fine triplet is a 3-term arithmetic progression. For each midpoint B in S, count unordered endpoint pairs {A, C} in S with A + C = 2B and A != C. If h[s] is the ordered pair count, the contribution for B is (h[2B] - 1) // 2; the -1 removes the self-pair (B, B).
- **Parity split:** Endpoints must have the same parity. Write even values as 2u and odd values as 2u + 1. Let X0 have bit 19u set for even 2u, and X1 have bit 19u set for odd 2u + 1. Squaring gives H0[t] = ordered even-endpoint pairs with midpoint t, and H1[t] = ordered odd-endpoint pairs with midpoint t + 1. Answer = (sum_{B in S} H0[B] + sum_{B in S} H1[B-1] - N) // 2.
- **19-bit slots:** Each parity class has at most 500000 elements, so every convolution coefficient is at most 500000 < 2^19. Therefore no carries occur between adjacent 19-bit slots when squaring the packed integer.
- **Input parsing:** A manual byte parser with a sentinel space avoids creating a million token objects. For N <= 3000, use direct enumeration over same-parity endpoint pairs with a set membership test.
- **Main construction:** For large N, keep a present bytearray of length 1000032 and two build bytearrays of length (19 * 500000) // 8 + 4. For each x, set u = x >> 1, pos = 19u, and set the corresponding bit in build0 or build1. Track maxS.
- **Convolution:** Convert the build bytearrays to integers with int.from_bytes, square them, and convert the squares to little-endian bytes. Use blocks of 8 coefficients because 8 * 19 = 152 bits = 19 bytes. The byte length L = 19 * ceil((maxS + 1) / 8) + 4 safely covers the last partial block.
- **Extraction:** For each 19-byte block, read it as an integer, then mask and shift by 19 to obtain H0[t] and H1[t] for t = t0 .. t0 + 7. Add H0[t] when present[t] is true, and H1[t] when present[t + 1] is true. This is an aligned equivalent of the 4-byte unaligned 19-bit read and avoids per-coefficient slicing.
- **Complexity and memory:** Parsing is O(N). The big-int square is done in C on integers of about 9.5M bits in the worst case. Extraction is O(maxS / 8), about 125k blocks for maxS = 1e6. Memory is a few tens of MB: input bytes, present array, build arrays, packed integers, and square byte buffers.
- **Edge cases:** N < 3 gives 0. maxS not being a multiple of 8 is handled by the padded final block. An empty parity class gives a zero square. Self-pairs are exactly N and are subtracted before halving. Python integers handle the final answer size.
- **Pitfalls:** 18 bits would overflow for dense inputs. to_bytes length must cover the last full 8-coefficient block. Direct enumeration must only pair same-parity endpoints. Distinctness of S is assumed from the constraints.
