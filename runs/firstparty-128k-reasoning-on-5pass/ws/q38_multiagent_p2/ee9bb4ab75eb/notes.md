- **Verification harness:** The `__main__` block is only for local verification; the `Solution` class is the submission-ready implementation.
- **Implemented solution:** Trie with per-node pass-through count, depth, and the terminal node for each original index. Early return `[0] * n` when `n - 1 < k`.
- **Feasibility rule:** A prefix node `u` of depth `d` is usable after removing index `i` iff `count[u] >= k + 1`, or `count[u] == k` and `terminal[i]` is not in `u`'s subtree. In tree terms, the second case means `u` is not an ancestor of `terminal[i]`.
- **Base answer:** `base` is the maximum depth among nodes with `count >= k + 1`. These nodes remain feasible for every removal. After the early return, the root guarantees `base >= 0`.
- **Marked nodes:** Only nodes with `count == k` can contribute beyond `base`. For terminal `v`, a marked node is feasible exactly when it is not an ancestor of `v`; such nodes are strict descendants of `v` or outside the root-to-`v` path and outside `v`'s subtree.
- **Bottom-up DP:** `desc[u]` is the deepest marked strict descendant of `u`. `best_sub[u] = max(desc[u], depth[u] if count[u] == k else -1)`. Node indices increase from parent to child, so reverse index order is a valid postorder.
- **Top-down side DP:** `side[u]` is the deepest marked node that is neither an ancestor of `u` nor in `u`'s subtree. `side[root] = -1`. For child `c` of `u`, `side[c] = max(side[u], max best_sub[s] over siblings s of c)`. Top two `best_sub` values among `u`'s children give this in linear time; equal top values are handled.
- **Final answer:** `answer[i] = max(base, desc[terminal[i]], side[terminal[i]])`. Do not use `best_sub[terminal[i]]` directly, because it may include `terminal[i]` itself when `count[terminal[i]] == k`, and that node is infeasible for removing one of its own words.
- **Edge cases:** `k = 1` reduces to the maximum length of a remaining word; duplicates share the same terminal and therefore the same answer; prefix words are handled by pass-through counts; `n = k` returns all zeros.
- **Complexity:** `O(total word length + trie nodes + trie edges)` time and `O(total word length)` memory. No recursion, so no recursion-depth risk.
- **Pitfalls checked:** Parent-before-child index order justifies iterative DP; `side` excludes ancestors, not merely nodes outside the subtree; top-two selection works with `-1` sentinels and equal depths; root depth 0 gives zero when no positive prefix is feasible.
