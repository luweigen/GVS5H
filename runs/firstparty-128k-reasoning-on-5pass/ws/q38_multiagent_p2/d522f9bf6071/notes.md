- **Sample tests:** pass; no failing cases. The current code returns `[2, 3]` for example 1 and `[1, 3, 5, 6]` for example 2. Edge cases checked: shared endpoints, all overlapping, more than 4 compatible intervals, equal-weight ties across counts, point intervals, same right endpoint, and lexicographic tie directions where either the shorter or the longer max-weight array is smaller.
- **Core DP:** Sort intervals by `(r, l, original_index)`. Let `ends` be the sorted right endpoints. For interval `i`, `p[i] = bisect_left(ends, l_i)` is the number of intervals ending strictly before `l_i`, so exactly the compatible prefix.
- **State:** `weights[c][i]` and `codes[c][i]` represent the best solution using exactly `c` intervals among the first `i` sorted intervals. `weights[c][i]` is max total weight, or `-1` if impossible. `codes[c][i]` encodes the lexicographically smallest sorted original-index tuple achieving that weight.
- **Recurrence:** For interval `i` with weight `w` and original index `idx`, first copy the skip state from `i` to `i+1`. Then for `c=1..4`, if `weights[c-1][p[i]] >= 0`, candidate weight is `weights[c-1][p[i]] + w`; candidate tuple is the previous tuple with `idx` inserted in sorted order. Keep the candidate if its weight is larger, or equal and its tuple is lexicographically smaller.
- **Why exact counts:** All tuples in a state have the same length, so lexicographic order is a total order. Inserting the same new index into two sorted tuples of equal length preserves their lexicographic order, so only the best predecessor for `c-1` is needed.
- **Encoding tuples:** To save memory, a sorted tuple of length `c` is encoded in base `B = max(2, n+1)` as `a0*B^(c-1)+...+a_{c-1}`. For fixed length, numeric code order equals lexicographic tuple order. Final comparison across different counts decodes the at most 5 candidates to lists and uses Python list comparison.
- **Strict non-overlap:** Compatibility is `r_prev < l_current`. `bisect_left(ends, l_i)` excludes intervals with `r == l_i`, matching the closed-interval rule.
- **Output order:** The returned array is the chosen original indices sorted ascending. This is the lexicographically smallest permutation of any chosen set and matches the examples.
- **Final selection:** After processing all intervals, compare `c=0..4` by weight first, then by decoded list lexicographically. `c=0` gives weight 0 and empty list; positive weights make it a fallback only.
- **Complexity:** Sorting and `p` computation are `O(n log n)`. DP is `O(n * 4 * 4)` small constant because tuple length is at most 4. Memory is `O(n * 5)` integers for weights and codes plus `O(n)` auxiliary arrays.
- **Edge cases:** Single interval, all overlapping, same right endpoints, point intervals, ties in weight across different counts, and empty fallback are handled. Sentinel `-1` is safe because weights are positive, and it also works if zero weights were allowed.
