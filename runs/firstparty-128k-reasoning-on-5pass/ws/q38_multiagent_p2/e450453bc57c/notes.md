- **Decomposition:** For each length-x window, the cheapest way to make it internally equal is to change all elements to a median, so precompute its cost as the sum of absolute deviations from a median. Then choose k non-overlapping length-x windows with minimum total cost.
- **At least k equals exactly k:** All window costs are nonnegative. Any final array with more than k valid windows contains k disjoint ones, and the operations on those windows are at least their individual median costs. Conversely, modifying exactly k chosen windows to their medians is feasible.
- **Sliding median structure:** Two heaps with lazy deletion by index. `low` is a max-heap of `(-value, index)`, `high` a min-heap of `(value, index)`. Maintain logical sizes, `low_sum`, `total_sum`, `in_low`, and `removed`.
- **Heap invariant:** `size_low == size_high` or `size_low == size_high + 1`, and every active value in `low` is <= every active value in `high`. The median is the maximum active value in `low`, which is the lower median for even x.
- **Lazy deletion:** Sliding adds the new index, then removes the old index. Removal uses `in_low` to update the logical side and sums, then marks `removed[idx]`. Stale entries are popped only when they reach a heap top; cleaning does not change logical sizes or sums.
- **Rebalancing:** After add/remove, at most one active top element moves from the larger side to the smaller side. The source heap is cleaned before popping, and `in_low`/`low_sum` are updated on moves.
- **Cost formula:** With median `med`, cost is `med * size_low - low_sum + (total_sum - low_sum) - med * size_high`. Works for negative values and even windows using the lower median.
- **Selection DP:** `prev[i]` is the minimum cost for the previous number of windows in the first `i` elements. Next layer: `cur[i] = min(cur[i-1], prev[i-x] + costs[i-x])` for `i >= chosen*x`. Adjacent windows are allowed because the previous prefix ends exactly where the new window starts.
- **Complexity:** Sliding median O(n log n), DP O(k n) with k <= 15, memory O(n).
- **Edge cases:** x=n gives one window; k=1 returns the minimum window cost; adjacent windows are allowed; negative values and duplicates are handled by integer sums and index tie-breakers; stale tops are cleaned before using the median or moving elements.
- **Validation harness:** The program runs the two examples and deterministic randomized tests: 5000 cases with n<=8 and 2000 with n<=12, values in small ranges, all feasible x and k. It compares against brute force that computes each window cost by sorting the slice and enumerates all non-overlapping start sequences by DFS.
- **Validation result:** The harness reports pass; the examples return 8 and 3, and no randomized or targeted case produced a mismatch or exception.
