Process elements by value rather than by prefix. For each index i, compute dp[i], the LIS length ending at i, using a Fenwick tree over indices that stores dp values for already processed smaller values; equal values are handled as a batch so they do not extend each other. Sort queries by X and sweep X ascending, activating all positions with A_i <= X. After each activation batch, answer queries with that X by taking the Fenwick prefix maximum up to R_i, which is the maximum dp among active positions in the prefix. This yields O((N+Q)logN) time and O(N+Q) memory.
