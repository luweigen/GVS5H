- **Batch model:** Any strategy can be described by assigning each element the deletion operation (batch) that removes it. All elements in one batch have the same color. If the elements are sorted by batch, the number of adjacent swaps needed is at least the inversion count of the batch labels (weighted by element multiplicities), and sorting then deleting achieves exactly that cost. Thus the problem is minimizing #batches + inversions.
- **Run compression:** Compress A into R runs. With no swaps, cost is R. A swap can lower the total only if it reduces the eventual number of runs by 2 while costing 1, giving a net saving of 1.
- **Useful swap:** In the run sequence, a swap reduces the run count by 2 exactly for four consecutive runs y, x, y, x where the two middle runs have length 1. Swapping the two middle elements merges the y-runs and the x-runs, turning 4 runs into 2. If a middle run has length >1, the corresponding element inversions cost at least 2, so there is no positive saving.
- **Good block:** With 0-based runs, a block starting at i-1 (runs i-1, i, i+1, i+2) is good if L[i] = L[i+1] = 1, C[i-1] = C[i+1], and C[i] = C[i+2]. It contributes one saving.
- **Compatibility:** Two good blocks can both be used iff their middle-pair starts differ by at least 3. Difference 1 or 2 makes some run a middle in one block and a middle/outer in the other, which is impossible after the first reduction. Difference 3 shares only an outer run; that run may grow but can still serve as an outer run.
- **DP:** Let dp[t] be the maximum number of usable good blocks in the first t runs. For t >= 4, if runs t-4, t-3, t-2, t-1 form a good block, then dp[t] = max(dp[t-1], dp[t-3] + 1); otherwise dp[t] = dp[t-1]. The answer is R - dp[R], because each selected block adds one swap and removes two runs.
- **Partial deletions:** Deleting only part of a prefix run costs one operation and does not reduce the run count. It can at best turn a long run into a singleton to enable one reduction, for net zero. Deleting whole prefix runs only removes a prefix of the run sequence, and the best number of compatible good blocks in the suffix cannot exceed the original DP value. Splitting a run into several batches increases the batch count and weighted inversions, so it cannot improve on the whole-run reduction model.
- **Checks:** The three samples give 3, 4, and 8. Small hand cases, including sequences with long runs and partial prefix deletions, match the DP; the batch lower bound rules out interleaved swap/delete shortcuts.
- **Complexity:** O(N) time and O(N) memory per test case; total O(sum N) over all cases.
