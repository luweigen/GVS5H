- **Cost per element:** For positive x, one operation on x replaces it by floor(x / 4), and the number of further divisions needed drops by exactly one. The total divisions needed is c(x) = min{k : x < 4^k}. In integer arithmetic, c(x) = (x.bit_length() + 1) // 2 because x < 2^(2k) iff bit_length(x) <= 2k.
- **Scheduling one query:** Treat each element as a chain of c(x) unit tasks. An operation has two slots and can take at most one task from each chain. If T operations are used, necessary conditions are max c <= T and sum c <= 2T. These are also sufficient for two identical slots, so the query answer is max(max c, ceil(sum c / 2)).
- **Range maximum:** c(x) is a nondecreasing step function, so the maximum c over [l, r] is simply c(r). No search inside the range is needed.
- **Prefix sums:** c is constant k on block [4^(k-1), 4^k - 1]. prefix_cost(n) adds full blocks and the partial block containing n. Up to 1e9 there are only 15 blocks, so O(log_4 n) per prefix is easily fast for 1e5 queries.
- **Implementation:** Use top-level cost and prefix_cost. prefix_cost(0) and negative n return 0. For each query compute s = prefix_cost(r) - prefix_cost(l - 1), then add max(cost(r), (s + 1) // 2). Python integers handle the final accumulated sum.
- **Pitfalls:** Do not use floating point logs near powers of four. Handle l = 1 via prefix_cost(0). Do not forget the max with cost(r); ceil(sum / 2) alone fails when one large element dominates. Zeros may be selected as the second element, which is why the two-slot model is valid.
