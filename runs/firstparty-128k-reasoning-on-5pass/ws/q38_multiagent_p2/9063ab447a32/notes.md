- **Marginal model:** For product price p, the k-th unit adds p(2k-1) yen. These marginal costs increase per product, so an optimal purchase is a prefix of the globally sorted marginal costs; any inversion can be swapped without increasing cost.
- **Threshold counting:** For a cost threshold C, product p contributes t = (C // p + 1) // 2 units, because p(2t-1) <= C. The cost of those t units is p t^2. With frequency f, contribution is f p t^2.
- **Binary search:** Let S(C) be the total cost of all marginals <= C. S is monotone. Compress equal P_i into (p, f), sort by p. feasible(C) sums f p t^2 over p <= C, breaks at p > C, and returns False as soon as the sum exceeds M.
- **Upper bound:** With m = min P, hi = m(2 isqrt(M // m) + 1). For the minimum price, t = isqrt(M // m) + 1, so m t^2 > M; hence hi is infeasible. lo = 0 is feasible.
- **Final batch:** For the largest feasible C, compute A = sum f t and B = sum f p t^2. The next marginal for product p is p(2t+1), with t=0 when p > C. Let D be the minimum next marginal and count_D the number of products attaining it. Since C is maximal, B + count_D * D > M, so only D-cost marginals can be bought next; answer is A + min(count_D, (M - B) // D).
- **Gaps and ties:** The next marginal is not necessarily C+1; it is the minimum actual next marginal D. Multiple products can share D, and count_D handles multiplicity. If M < min_p, no unit is affordable and the formula returns 0.
- **Complexity:** Sorting and grouping O(N log N). Binary search needs at most about 47 iterations because hi <= 2 sqrt(M * min_p) + min_p < 1e14. Each feasible pass is O(U), U distinct prices, so O(N log N + U log M). Python integers are sufficient; precomputing f*p in the feasibility list saves one multiplication per iteration.
- **Implementation:** Read all ints from stdin, sort P, group duplicates. Use bit shifts for division by 2. The stock limit 10^100 is irrelevant because M bounds any per-product purchase far below it.
