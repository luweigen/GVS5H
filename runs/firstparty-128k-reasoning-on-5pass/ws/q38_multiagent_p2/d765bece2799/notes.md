- **Approach:** Keep the right-endpoint run-length deque. For each right endpoint, runs store consecutive start indices whose subarray maximum or minimum is the same value. `current` is the sum of those extrema over active starts; after capping the window to k, adding `current` to `total` accumulates all valid subarrays ending at that right endpoint.
- **Update invariant:** For maxima, run values are non-increasing from oldest to newest; the new value x converts a suffix of runs with value <= x into x. For minima, run values are non-decreasing; x converts a suffix with value >= x into x. Popped counts are merged with the new single-element start into one run.
- **Length cap:** `active` counts active starts. After inserting the new start, if `active > k`, remove one oldest start from the leftmost run, subtract its value from `current`, decrement the run count or popleft, then add `current` to `total`.
- **Duplicates:** Popping equal values merges duplicate extrema. Expiration removes exactly one start at a time by count, so no separate tie-breaking is needed.
- **Complexity:** Each run is pushed once and popped at most once per pass; expiration only touches the left end. Two passes give O(n) time and O(min(n, k)) space. Python integers safely handle totals around 1e16.
- **Sample verification:** [1, 2, 3], k=2 gives max sum 11 and min sum 9, total 20. [1, -3, 1], k=2 gives max sum 1 and min sum -7, total -6.
- **Edge cases:** k=1 reduces to 2*sum(nums); k=n disables expiration; all-equal arrays collapse to one run; negative values are safe because subtracting a negative contribution increases `current`; single elements contribute once in each pass.
- **Test harness:** The program includes a guarded self-test. It checks the samples, k=1, k=n, duplicates, negative arrays, 3000 random small arrays against brute force, and 80000-element random, k=1, all-equal, increasing, and decreasing arrays. The large k=1 case is checked against 2*sum(nums), and the large all-equal case is checked against the closed-form subarray count.
- **Verification outcome:** All assertions pass; the random brute-force comparisons match, and the 80000-element cases finish quickly, confirming linear behavior. The brute force is O(n*k) but only used for n<=9.
- **Rejected alternatives:** Per-element monotonic-stack contribution requires capped left/right pair counting; threshold union-find and divide-and-conquer are heavier. The run-length deque avoids explicit pair counting and is easier to verify.
