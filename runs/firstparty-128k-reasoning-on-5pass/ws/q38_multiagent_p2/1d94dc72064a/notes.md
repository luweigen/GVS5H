- **State abstraction:** The game only needs the number k of untouched indices, the total remaining tokens E in touched indices, and the parity class of each untouched A_i. A move on a touched index is a pass: E decreases by 1. A move on an untouched index i opens it, decreases k by 1, and adds A_i - 1 to E.
- **Terminal small k:** If k = 1, the player to move wins immediately by opening the last index. If k = 2, opening either index gives the opponent a k = 1 win, so players only use passes; the player to move wins exactly when E is odd.
- **Parity variables:** Let b_i = 1 if A_i is even and 0 if A_i is odd, because opening i changes E parity by b_i. Let O be the number of untouched odd piles, i.e. b_i = 0, and let p be E mod 2.
- **k = 3 outcome:** With three untouched piles, the player to move wins iff at least one untouched pile has b_i = p. Equivalently, they lose only when all three b_i are 1 - p. The exact magnitude of E does not change this outcome.
- **k >= 4 induction:** For k >= 4, the player to move wins iff O mod 2 != p. Opening an odd pile changes the state to (O - 1, p); opening an even pile changes it to (O, p ^ 1). In both cases the opponent is in a losing k - 1 state exactly when O mod 2 != p. A pass changes p to p ^ 1 and is also winning exactly under the same condition, so the actual size of E is irrelevant.
- **Initial position:** The game starts with k = N, E = 0, and p = 0. Therefore N = 1 is Fennec, N = 2 is Snuke, N = 3 is Fennec iff O > 0, and N >= 4 is Fennec iff O is odd.
- **Brute force validation:** A throwaway minimax over small states, with N <= 5 and A_i <= 4, using a touched mask plus the remaining A tuple, produced the same winner as the closed form for all cases. That brute force is not included in the submitted program.
- **Implementation notes:** Read all integers, count odd A_i, and branch on N. The complexity is O(N) time and O(1) extra space beyond input storage. Large A_i values matter only through parity.
