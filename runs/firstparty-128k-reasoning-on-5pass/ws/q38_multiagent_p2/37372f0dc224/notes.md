- **Reduction:** A palindrome having S as a prefix must be S plus some appended bytes. If the appended length is m, the appended part must be the reverse of S[:m], and the middle part S[m:] must itself be a palindrome. Therefore minimize m by maximizing k = n - m, the length of the longest palindromic suffix of S.
- **KMP formulation:** Let P = reverse(S). A suffix of S of length k is palindromic exactly when it equals P[:k]. Thus k is the longest prefix of P that is also a suffix of S. Compute the prefix function pi for P, then scan S with KMP state q.
- **No reset on full match:** If S is already a palindrome, the scan ends with a full match q = n. Resetting q to pi[n-1] after a full match would lose this case, so the final state is kept. The transition is while q > 0 and (q == n or P[q] != c): q = pi[q-1]; then if q < n and P[q] == c: q += 1. This also safely handles q == n if more characters were ever processed.
- **Answer construction:** With k = q, output S + reverse(S[:n-k]). The suffix S[k:] is palindromic, so the result is S[:n-k] + S[k:] + reverse(S[:n-k]), a palindrome with prefix S and minimal appended length.
- **Complexity:** O(n) time and O(n) memory for pi. Input and output are bytes; output length is at most 2n.
- **Edge cases:** n = 1 gives q = 1 and answer S. All identical characters give q = n and no appended bytes. A non-palindromic string always has at least the last character as a palindromic suffix, so q >= 1. The full-match case is handled without resetting at the end.
- **Samples and checks:** ABC gives q = 1 and ABCBA. Z gives q = 1 and Z. TREE gives q = 2 and TREERT. Additional checks: AA -> AA, AB -> ABA, ABACAB -> ABACABA, BAAA -> BAAAB.
- **Pitfalls avoided:** Do not search for a palindromic prefix; the needed suffix is at the end. Do not reset KMP after a full match at the end. Avoid index errors when q == n by guarding P[q]. Bytes indexing is used for speed.
- **Rejected alternatives:** Z-function, Manacher, rolling hash, and eertree are possible but more complex or probabilistic; KMP with a single pattern is linear, simple, and memory-light enough for 500000.
