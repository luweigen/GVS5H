- **Potential model:** Define town potentials by \(P_1=0\) and \(P_{j+1}=P_j+w_j\). A person traveling between towns \(l<r\) requires \(P_l=P_r\). For left-to-right travel, every \(P_{l+1},\ldots,P_{r-1}\) must be larger; for right-to-left travel, they must be smaller.
- **Conflict rule:** Two intervals sharing a left endpoint or sharing a right endpoint are incompatible. Properly crossing intervals are incompatible exactly when their travel directions are equal. Nested intervals and properly crossing intervals with opposite directions are compatible.
- **Online conflict detection:** Process people in input order. For each current interval \([l,r]\), only earlier intervals of the same direction can create new crossing conflicts. Report intervals in rectangles \(a<l<b<r\) and \(l<a<r<b\), then remove them because their first conflict has already been found.
- **Data structure:** For each direction, use a segment tree over left endpoints. Every nonempty segment-tree node stores all contained points sorted by `(right endpoint, person index)` and a Fenwick tree of active points. A rectangle query decomposes its left range into canonical nodes, binary-searches the right-endpoint range, and repeatedly extracts active points using Fenwick order statistics.
- **Complexity:** Each person is inserted once and removed at most once. Each update costs \(O(\log^2 N)\); each reported conflict costs the same. Rectangle decomposition costs \(O(\log N)\), excluding reported points. Total time is \(O((M+C)\log^2 N+Q)\), where \(C\le M\) is the number of removed crossing intervals. Memory is \(O(M\log N)\).
- **Subarray answers:** Let `next_conflict[i]` be the earliest later person conflicting with person `i`. A suffix minimum gives the earliest conflict among every suffix. Query \([L,R]\) is feasible exactly when that value for `L` is greater than `R`.
