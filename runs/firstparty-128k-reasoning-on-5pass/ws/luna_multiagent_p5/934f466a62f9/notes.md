- **Dominant labels:** Assign each cake a label corresponding to one maximum coordinate, with deterministic tie-breaking. Its individual maximum is `m_i`.
- **Matching reduction:** Every pair price is at most `m_i + m_j`. Cakes with equal labels attain this bound when paired together. Therefore an optimal solution uses either no cross-label pair or exactly one cross-label pair; all remaining pairs are within labels.
- **Parity:** For a selected set of `2K` cakes, the labels with odd counts are either none or exactly two. The no-cross case requires all three counts even. A single cross pair handles the two odd groups.
- **Selection query:** After forcing cross-pair endpoints, select the remaining cakes by taking the shortest global rank prefix containing the required number of non-forced cakes. Forced cakes in the prefix are removed from the prefix sum, and all forced cakes are added back.
- **Parity repair:** If the prefix has the wrong parity in two groups, repair using either one selected/unselected swap between those groups or two swaps through the third group. Forced cakes are excluded from swap candidates.
- **Endpoint candidates:** For each witness coordinate and label, all cakes near the rank boundary are retained. In regions whose selected status is fixed, the relevant endpoint score is `coordinate_t - m_i`, not merely `coordinate_t`; retaining the maximum of this corrected delta fixes the deep-region counterexample.
- **Complexity:** Each selection query is logarithmic up to constant-size operations, and the number of endpoint candidates is constant per coordinate and label. Total complexity is `O(N log N)` per test case, with linear memory.
- **Edge cases:** Duplicate cake values and coordinates are handled by indices and deterministic sorting. The method also supports `K = 1` and forced endpoints near either end of the ranking.
