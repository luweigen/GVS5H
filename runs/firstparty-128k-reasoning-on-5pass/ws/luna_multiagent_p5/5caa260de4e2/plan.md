Rewrite the segment-order contribution so that every partition contributes a base term `k * totalCost`, while each cut after position `l - 1` adds `k * (totalCost - prefixCost[l])`. This removes the need to track the number of subarrays explicitly. Use dynamic programming where `dp[r]` is the minimum cost for partitioning the first `r` elements, and transition from every previous boundary `l`. Prefix sums of `nums` and `cost` allow each transition to be evaluated in O(1), yielding an O(n²) solution with 64-bit integer arithmetic.
