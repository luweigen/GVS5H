- **Seam variables:** Use one Boolean variable for every toroidal grid seam. Let `x[i][j]` be the horizontal seam between the right edge of cell `(i,j)` and the left edge of `(i,(j+1)%W)`. Let `y[i][j]` be the vertical seam between the bottom edge of `(i,j)` and the top edge of `((i+1)%H,j)`. There are exactly `2HW` variables.
- **Cell edge mapping:** For cell `(i,j)`, its left/right/top/bottom variables are respectively `x[i][(j-1)%W]`, `x[i][j]`, `y[(i-1)%H][j]`, and `y[i][j]`.
- **Type A constraints:** A type-A tile connects adjacent edges, hence it uses exactly one horizontal edge and exactly one vertical edge. Therefore `left XOR right = 1` and `top XOR bottom = 1`. These two equations permit exactly the four adjacent-edge orientations.
- **Type B constraints:** A type-B tile connects opposite edges. Thus `left XOR right = 0`, `top XOR bottom = 0`, and `left XOR top = 1`. These equations permit exactly horizontal-only or vertical-only orientations.
- **Counting:** All constraints have form `u XOR v = c` over GF(2). A consistent connected component of the constraint graph has one free bit, hence contributes factor 2. If the parity constraints are contradictory, the answer is 0. Otherwise answer is `2^(number of DSU components) mod 998244353`.
- **DSU implementation:** A parity union-find stores XOR from each node to its parent. On adding `a XOR b = w`, find roots and their parities; if roots coincide, verify the implied equation. Otherwise merge roots with root-link parity `xa XOR xb XOR w`.
- **Torus edge cases:** For `H=2` or `W=2`, the two toroidal seams joining the same pair of cells geometrically must remain distinct variables. Indexing seams by directed cell-side position as above does this correctly.
- **Complexity:** Each case uses `O(HW)` time and `O(HW)` memory. Compact `array('i')` and `bytearray` storage avoids excessive Python memory use for up to `2HW = 2,000,000` seam variables.
