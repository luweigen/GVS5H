- **Sample execution:** Passed both supplied samples: `points=[2,4], m=3` returns `4`; `points=[1,2,3], m=5` returns `2`.
- **Exhaustive comparison:** Passed an automated brute-force comparison over 13,600 instances: `n=2..5`, every `points[i]` in `1..4`, and `m=1..10`. The brute-force enumerator retained all reachable `(position, visit-count-vector)` states through each move count and compared the best achievable minimum score against `maxScore`. No counterexample was found.
- **Target feasibility:** For a candidate score `x>0`, vertex `i` needs `ceil(x / points[i])` arrivals. Every vertex must therefore be visited, so any valid walk reaches `n-1`.
- **Baseline paths:** If the walk ends at `n-1`, the baseline left-to-right traversal takes `n` moves and visits every vertex once. If it ends at `e<n-1`, it travels to `n-1` and returns to `e`, taking `1 + e + 2(n-1-e)` moves; vertices `e..n-2` receive a second baseline arrival.
- **Extra traversals:** Each extra back-and-forth traversal of edge `(j,j+1)` costs two moves and adds one arrival to both endpoints. For residual vertex demands, choose nonnegative edge-pair counts minimizing their sum subject to each vertex's adjacent edge counts covering its residual demand.
- **MWIS reduction:** The edge-pair covering problem on a path has a dual equal to maximum-weight independent set on the path. The required minimum number of edge pairs is thus computed by prefix/suffix MWIS dynamic programming. For each possible final endpoint, combine prefix weights before it and suffix weights after it while considering whether the endpoint is included.
- **Complexity:** Each feasibility check is `O(n)` time and `O(n)` memory. Binary search over `[0, min(points)*m]` gives total complexity `O(n log(min(points)*m))`, suitable for the constraints.
