- **Core characterization:** A successful transformation partitions the initially occupied positions into consecutive nonempty groups, one per occupied target position. Pieces cannot cross or split.
- **Necessary constraints:** For a solution using `K` operations, every source assigned to target `y` must be within distance `K` of `y`. Between two neighboring groups, the gap between their boundary sources must be at least the gap between their target positions, since every operation is nonexpansive.
- **Sufficiency for `K >= 2`:** The partition constraints are sufficient for reachability in at most `K` operations. Thus minimizing the feasible radius gives the answer whenever that minimum is at least two.
- **Special cases:** Answer is `0` exactly when `A == B`. One operation cannot be decided solely by the partition/radius constraints because every piece must move according to one shared pivot; it is checked directly using prefix/suffix shifted-string conditions.
- **One-radius outcome:** If radius-one partitioning is feasible but no one-pivot operation works, the answer is exactly `2`: radius two is feasible and sufficient, while answers zero and one were excluded.
- **Fixed-radius greedy check:** Scan target positions left to right. Maintain eligible source ranges within `[target-K, target+K]`. For each group boundary choose the earliest source boundary that leaves an eligible source for the next group, then advance it until the source boundary gap meets the target gap. Earlier valid boundaries only help later constraints.
- **Complexity:** Each feasibility check is linear in the number of occupied positions. Binary search over `K` gives `O(N log N)` total time per aggregate input length and `O(N)` memory.
