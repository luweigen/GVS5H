- **Approach:** Encode the presence polynomial `f(x) = sum x^s` using fixed 20-bit fields inside one Python integer. The square then contains the exact convolution coefficient for every sum.
- **Packing:** Put the bit for input value `x` at bit offset `20*x`. A product term contributing to polynomial degree `k` is therefore located in the 20-bit field starting at bit `20*k`.
- **No carry condition:** A convolution coefficient is the number of ordered pairs of input elements with a fixed sum, which is at most `N <= 10^6`. Since `10^6 < 2^20`, every field fits without carrying into the next field.
- **Triplet count:** For each present midpoint `B`, the coefficient at degree `2B` counts ordered pairs `(A, C)` with `A + C = 2B`. It includes the self-pair `(B, B)` once, and every valid distinct endpoint pair twice. Its contribution is therefore `(coefficient - 1) // 2`; summing before division is valid because every term is even after self-pair removal.
- **Extraction optimization:** Degree `2B` begins at bit `40B = 5B` bytes, so its 20-bit coefficient is read directly from three bytes. This avoids costly repeated large-integer shifting.
- **Complexity:** Packing and coefficient extraction take `O(N)`. Integer multiplication is performed by CPython's optimized C big-integer implementation on about `20 * max(S)` bits, at most 20 million bits. Memory is linear in this bit size, with several byte/integer buffers totaling only a few tens of MB plus input storage.
- **Why not Python NTT:** Length `2^21` requires roughly 66 million butterfly operations across two forward/inverse-style transform phases, each involving Python-level loops and modular multiplication. It is typically too slow and can exceed memory limits due to millions of boxed Python integers. Big-integer multiplication moves the expensive work into optimized C code.
- **Correctness:** Each fine triplet has one unique midpoint. The convolution counts exactly its two endpoint orders, while subtracting the midpoint self-pair excludes degenerate triples.
