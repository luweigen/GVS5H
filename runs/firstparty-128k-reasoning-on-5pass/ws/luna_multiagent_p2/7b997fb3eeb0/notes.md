- **Greedy characterization:** For mochi index \(j\), let \(p_j\) be the first index with \(A_{p_j}\ge 2A_j\). Since the array is sorted, mochi \(j\) can be placed on any mochi at index at least \(p_j\). Define \(B_j=p_j-j\), using either zero-based or consistently one-based indices.
- **Query condition:** For interval \([L,R]\) of length \(M\), if \(K\) pairs are made, it is sufficient to use indices \(L,\ldots,L+K-1\) as tops and \(R-K+1,\ldots,R\) as bottoms, pairing them in order. This works exactly when \(p_j\le j+M-K\) for every \(j\in[L,L+K-1]\), equivalently \(\max B_j\le M-K\).
- **Necessity:** In any feasible set of \(K\) ordered pairs, replacing the selected tops by the earlier indices \(L,\ldots,L+K-1\) cannot increase any required \(p_j\). The \(i\)-th selected bottom is at most the \(i\)-th position among the final \(K\) indices, namely \(R-K+i\), yielding the same inequalities.
- **Important disjointness bound:** The condition above must be combined with \(K\le\lfloor M/2\rfloor\), because each pair consumes two distinct mochi. Without this bound, a sequence such as \(1,2,4,8\) would incorrectly satisfy the inequality for \(K=3\).
- **Data structure:** Build a sparse table over \(B\) for \(O(1)\) range maxima. For each query, binary-search \(K\) in \([0,\lfloor M/2\rfloor]\). The predicate is monotone because the queried range grows with \(K\), while \(M-K\) decreases.
- **Complexity:** Preprocessing takes \(O(N\log N)\) time and memory. Each query takes \(O(\log N)\) time, for total \(O((N+Q)\log N)\).
