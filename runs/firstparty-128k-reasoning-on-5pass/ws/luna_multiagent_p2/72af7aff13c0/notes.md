- **Representation:** The required sum is the weighted source-to-sink path sum in the directed acyclic grid graph. Forward values satisfy `pre[r][c] = A[r][c] * (pre[r-1][c] + pre[r][c-1])`, with the source initialized to its own value. Reverse values similarly include the current cell and count weighted suffixes to the sink.
- **Time blocking:** Operations are processed in blocks. At the beginning of each block, complete forward and reverse dynamic programs are rebuilt for the grid state after all preceding blocks.
- **Visited rectangle:** Every updated cell in one block lies inside the bounding rectangle of the walk positions in that block. Its two side lengths have total span at most the block length, so its area is `O(B^2)`.
- **Local recomputation:** Forward values inside the rectangle are copied at block start. After changing `(r,c)`, only rectangle cells southeast of `(r,c)` can change, and they are recomputed in row-major order. Values entering the rectangle from above or from the left use the fixed global forward DP.
- **Contribution decomposition:** Paths whose last rectangle cell is followed by a step below or to the right are counted using the updated local forward value and the fixed reverse value outside the rectangle. If the sink lies in the rectangle, the local sink value directly gives the complete answer. Subtracting the initial rectangle contribution from the global answer leaves paths unaffected by the block.
- **Edge cases:** No division is used, so zero values and repeated updates are handled safely. The source and sink are naturally supported, including when either lies in the block rectangle. The movement guarantee ensures every update position is valid.
- **Complexity:** For block size `B`, rebuilding costs `O(HW)` per block, while local maintenance costs `O(B^2)` per operation in the worst case. Total complexity is `O((Q/B)HW + QB^2)` and memory usage is `O(HW + B^2)`. `B=46` balances the two terms for the maximum constraints.
