- **Pair reduction:** Every pair price is the sum of one common coordinate chosen among X, Y, and Z. Thus a solution is represented by assigning each selected cake to one coordinate, with every coordinate receiving an even number of cakes. The XOR of all one-hot assignment masks must be zero.
- **Dominant baseline:** For each cake, use its maximum coordinate as its dominant value and assign it the corresponding one-hot mask. Sort cakes by decreasing dominant value. For any fixed set of reassigned special cakes, all regular cakes should be the highest-dominant available cakes.
- **At most two specials:** Since the number of selected cakes is even, the XOR of dominant one-hot masks has even Hamming weight. The required parity correction can therefore be achieved using zero, one, or two reassigned cakes.
- **One special:** Let `q = 2K - 1`. If the special cake lies before `q`, regular cake `q` replaces it; otherwise the first `q` cakes remain regular. The regular parity must be one-hot, which is exactly the assignment mask required for the special cake.
- **Two specials:** Let `q = 2K - 2`. The four positional cases are handled separately: both specials before `q`; one before `q` and the other equal to `q`; one before `q` and the other after `q`; or both at least `q`.
- **Candidate storage:** For every XOR/assignment key, only the two highest-gain candidates are retained. Two are enough because the two selected special cakes must have distinct indices.
- **Correct lookup:** Coordinate values are stored as `(X, Y, Z)` and accessed through the explicit mapping `{1: 0, 2: 1, 4: 2}`. A sufficiently small negative sentinel is used because reassignment gains may be negative.
- **Complexity:** Sorting costs `O(N log N)` per test case; all remaining processing is linear. Total complexity is `O(N log N)` and memory usage is `O(N)`.
