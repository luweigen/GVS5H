- **Visibility threshold:** For target building \(i\), using its top is optimal. Against an earlier building \(j\), the line from \((0,h)\) to \((X_i,H_i)\) must be strictly above \(H_j\), so visibility requires \(h > (X_iH_j-X_jH_i)/(X_i-X_j)\). Equality is not sufficient because touching another building counts as intersection.
- **Global answer:** The largest threshold over all earlier-target pairs is the maximum nonnegative height from which not all buildings are visible. If this maximum is negative, height \(0\) already sees every building and the answer is \(-1\). A threshold equal to zero gives answer \(0\).
- **Hull:** Process buildings in increasing coordinate order. Maintain the upper convex hull of prior points. When adding \((x,h)\), remove the previous last point while the turn cross product is nonnegative; this leaves strictly clockwise turns and discards points that can never minimize the slope to a future point.
- **Query:** For the current point, the slopes from hull vertices form a unimodal sequence. Binary search the minimum using exact cross-multiplied comparisons, avoiding floating-point errors.
- **Exact comparison:** For the selected prior point \((x_j,H_j)\), store the threshold as numerator \(xH_j-x_jH\) and denominator \(x-x_j\). Compare candidate fractions by cross multiplication, and convert to floating point only for final output.
- **Complexity:** Hull maintenance is amortized \(O(N)\), each query is \(O(\log N)\), and total complexity is \(O(N\log N)\) with \(O(N)\) memory.
