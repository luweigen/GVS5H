- **Topic:** Updates lie on one walk. For any temporal interval of length `L`, all updated cells fit in an axis-aligned rectangle whose side-length sum is at most `L+1`; its area is therefore `O(L^2)`.
- **Topic:** For a fixed rectangle, every monotone source-to-sink path visits it in one contiguous segment. Consequently, updates confined to a rectangle can be handled by rebuilding forward and backward DP only inside that rectangle, while DP values immediately outside remain valid.
- **Topic:** `fwd[v]` is the weighted sum of paths from `(1,1)` to `v`; `bwd[v]` is the weighted sum from `v` to `(H,W)`, both including the endpoint cell weights.
- **Topic:** To update one cell without modular division, compute its current total path contribution directly. The incoming sum is the sum of `fwd` values of its top and left neighbors, or `1` at the source. The outgoing sum is the sum of `bwd` values of its bottom and right neighbors, or `1` at the sink. Their product with the cell value is exactly the contribution of paths using that cell. This naturally supports zero values.
- **Topic:** At a leaf update, subtract the old contribution from the global answer, assign the new value, then add the new contribution. The leaf cell's stored DP values may become stale, but every later use is preceded by rebuilding an enclosing rectangle.
- **Topic:** A four-level temporal hierarchy uses block lengths approximately `N^(15/31), N^(14/31), N^(12/31), N^(8/31), 1`, where `N=HW`. Rebuild work is bounded by about `O(Q N^(16/31))` plus initial DP and low-order overhead.
- **Topic:** The implementation skips a redundant rebuild before the first child of every temporal node: the parent rebuild already made all DP values in that first child valid. Rebuilds are needed only between sibling children after earlier updates changed the parent rectangle.
- **Topic:** The hierarchy is recursive and uses Python recursion depth only proportional to the fixed number of hierarchy levels plus a few forced splits for small blocks.
