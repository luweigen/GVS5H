- **Algorithm:** Sweep the array from left to right. Group queries by their prefix endpoint `R`, so all queries with endpoint `R` are answered immediately after processing `A[R]`.
- **LIS tails invariant:** Maintain the standard patience-sorting array `tails`, where `tails[k]` is the minimum possible final value among strictly increasing subsequences of length `k + 1` in the currently processed prefix.
- **Update:** For each value `a`, find `pos = lower_bound(tails, a)`. Replace `tails[pos]` with `a`, or append if no such position exists. Using lower bound preserves strict increasingness because equal values do not extend an existing subsequence.
- **Query:** A subsequence whose final value is at most `X` has all its elements at most `X`, since it is strictly increasing. Thus the answer is the maximum subsequence length whose minimum feasible tail is at most `X`, equal to `upper_bound(tails, X)`.
- **Correctness:** `tails` is sorted nondecreasing. For every attainable length, its entry gives the smallest possible ending value. If `tails[k] <= X`, a length `k+1` increasing subsequence ending within the bound exists. If `tails[k] > X`, no such subsequence of that length can end at most `X`, because `tails[k]` is already the minimum feasible ending value.
- **Complexity:** Each array update and query uses binary search, for total `O((N + Q) log N)` time. Query grouping uses `O(N + Q)` additional memory; `tails` uses `O(N)` memory.
- **Sample behavior:** For the first sample, prefix tails evolve as expected and upper-bound queries produce `2`, `1`, and `2`.
