- **Brute-force validation:** Exhaustive brute-force comparison over small domains and operation counts found no counterexample. For each interval multiset, enumerate all `3^M` operation vectors, compute the covered positions directly, compare feasibility and minimum cost, and verify the emitted vector covers every position.
- **Structural reduction:** Operation 1 covers its interval and Operation 2 covers its complement. If two original intervals are disjoint, choosing Operation 2 for both covers the entire domain.
- **Cost bound:** Any feasible instance has an optimum at most 3. Cost 1 requires an interval `[1,N]`. Cost 2 can be: two disjoint intervals with Operation 2; an Operation-2 interval contained in a distinct Operation-1 interval; or two Operation-1 intervals covering `[1,N]`.
- **Cost-2 duplicate handling:** For containment, intervals are processed grouped by equal left endpoint. Strictly earlier groups use the greatest right endpoint. Within an equal-left group, the two greatest right endpoints are retained so the same operation ID is never selected twice.
- **Cost-3 characterization:** Distinct IDs `a,b,c` yield a valid cost-3 solution with Operations `2,2,1` when `L[a] >= L[c]` and `R[b] <= R[c]`. The only positions missed by the two complements are in `I[a] ∩ I[b]`, which is contained in `I[c]`.
- **Why cost 3 suffices:** Given any feasible selection with complement intervals, their intersection is determined by an interval with maximum left endpoint and one with minimum right endpoint. If no selected Operation-1 interval contains that intersection, take selected intervals covering its two endpoints; their intersection lies inside it, while an extremal complement interval contains it. This produces a cost-3 solution. If complement intervals have empty intersection, two are already disjoint and cost 2 applies.
- **Cost-3 candidate simplification:** It is sufficient to use any three globally largest-left IDs for `a` and any three globally smallest-right IDs for `b`. These always satisfy the needed inequalities for every center `c`; three IDs handle excluding `c` and the opposite chosen ID. This replaces six `O(M)` candidate arrays from the prior implementation.
- **Complexity:** Sorting is `O(M log M)`, all other processing is linear, and memory is `O(M)`.
- **Edge cases checked:** Repeated identical intervals, equal left/right endpoints, singleton intervals, a single operation, full-domain intervals, infeasible cases, and cost-3-only constructions.
