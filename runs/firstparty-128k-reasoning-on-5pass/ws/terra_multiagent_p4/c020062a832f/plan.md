Compute the inversion count for \(k=0\) using a Fenwick tree over values \(0 \ldots M-1\). When increasing \(k\) by one, exactly the elements currently equal to \(M-1\) wrap around to \(0\), while all other relative value comparisons remain unchanged. For each original value \(x\), precompute how many inversions are gained/lost when elements with that value wrap: this depends on their positions and counts of elements before/after them. Update the answer in \(O(1)\) per shift after \(O(N \log M)\) preprocessing.
