- **Functional graph structure:** Every weakly connected component of a graph with edges `i -> A[i]` contains exactly one directed cycle, with directed in-trees feeding into that cycle.
- **Cycle equality:** Inequalities around a directed cycle force all cycle values to be equal. Thus a whole cycle acts as one root variable, although contributions from trees attached at every cycle vertex must all be multiplied.
- **Indegree peeling:** Compute indegrees and repeatedly remove vertices of indegree zero. Removed vertices are exactly non-cycle vertices, and the remaining positive-indegree vertices are cycle vertices.
- **Bottom-up order:** The order in which vertices are removed is already child-before-parent for non-cycle tree edges. When a vertex is removed, every non-cycle incoming child has already contributed.
- **DP recurrence:** For a non-cycle vertex with value `v`, its DP is the product over children of `sum_{k=1..v} child_dp[k]`. Therefore a child sends its prefix-sum DP vector to its parent.
- **Memory optimization:** Do not store a full `N x M` Python integer matrix. Maintain an optional accumulator vector per vertex. A vector is allocated only after at least one child contributes; an all-one DP is represented by `None`. `array('I')` keeps stored vectors compact.
- **Vector transfer:** If a parent has no previous contribution, the child prefix vector can be transferred directly as the parent accumulator. Otherwise multiply pointwise modulo `998244353`.
- **Cycle aggregation:** For each remaining directed cycle, pointwise multiply accumulators of its cycle vertices. Summing the resulting vector gives the number of assignments for that component. If no attached tree contributes, the count is simply `M`.
- **Complexity:** Each non-cycle vertex performs `O(M)` prefix work and at most `O(M)` multiplication work; cycle aggregation is `O(NM)` in total. Overall complexity is `O(NM)` time and up to `O(NM)` compact integer storage in the worst case.
