- **Graph consistency:** Represent each constraint `A_x XOR A_y = z` as an undirected edge labeled `z`. During DFS/BFS, assign a provisional value `dist[root] = 0` and propagate `dist[to] = dist[v] XOR z`. If an already assigned vertex receives a different expected value, the constraints are inconsistent, so output `-1`.
- **All solutions in a component:** For a consistent connected component, every valid assignment is `A_v = dist[v] XOR t` for one common non-negative integer `t`. This follows because constraints determine pairwise XOR differences, while the root value remains freely selectable.
- **Minimization:** For each bit independently, if `ones` provisional values have that bit set in a component of size `S`, choosing the corresponding bit of `t` as `0` yields `ones` set bits in the answer, while choosing `1` yields `S - ones`. Set the bit in `t` exactly when `ones > S - ones`. Ties may use either choice.
- **Bit limit:** Every edge weight is below `2^30`; XOR path labels are therefore also below `2^30`. Setting any bit at position at least 30 in `t` would set that bit in every component value and strictly increase the sum, so checking bits `0..29` is sufficient.
- **Complexity:** Graph traversal is `O(N + M)`. Bit counting costs `O(30N)`. Memory usage is `O(N + M)`.
- **Edge cases:** Isolated vertices form size-one components and receive `0`. Self-loops require label `0`, automatically detected by consistency checking. Repeated edges with conflicting labels are also detected.
