- **Fixed-K feasibility:** For a proposed number of pairs `K`, necessarily `K <= floor(N/2)`. It is sufficient to use the first `K` sorted mochi as tops and the last `K` sorted mochi as bottoms. These groups are disjoint under that bound.
- **Why the selected groups are optimal:** Suppose any feasible collection of `K` pairs exists. Replacing its chosen tops by the globally `K` smallest mochi can only decrease top sizes, and replacing its chosen bottoms by the globally `K` largest mochi can only increase bottom sizes. Thus this replacement cannot invalidate `2 * top <= bottom`.
- **Ordered matching condition:** Let the chosen top sizes and bottom sizes each be sorted increasingly. A threshold compatibility condition admits a feasible matching exactly when corresponding ranks satisfy `2 * top[i] <= bottom[i]` for every `i`. Therefore the fixed-`K` predicate is `2 * A[i] <= A[N-K+i]` for all `0 <= i < K`.
- **Monotonicity:** If `K` pairs are feasible, every smaller pair count is feasible by discarding pairs. Hence binary search over `K` is valid.
- **Complexity:** One predicate check costs `O(K)`, at most `O(N)`. Binary search performs `O(log N)` checks, for total `O(N log N)` time and `O(1)` extra space apart from input storage.
- **Edge cases:** `K=0` is always feasible. Equality is allowed, so the test must use `2 * small <= large`. Python integers avoid overflow; values would also fit signed 64-bit integers.
- **Implementation:** Binary search keeps `low` feasible and `high` infeasible, initialized as `0` and `floor(N/2)+1`. The latter is outside the possible answer range.
