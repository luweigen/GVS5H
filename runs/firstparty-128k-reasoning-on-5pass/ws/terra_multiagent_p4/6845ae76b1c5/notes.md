- **Algorithm:** Use two-dimensional Mo ordering on query points `(X, Y)`. The maintained state consists exactly of active prefix multisets `A[0:cur_x]` and `B[0:cur_y]`, plus their cross sum `sum |a-b|`.
- **Query ordering:** Split the `X` axis into blocks of size approximately `N / sqrt(K)`. Sort first by `X` block and then by `Y`, alternating ascending and descending `Y` order between neighboring blocks. This reduces repeated long `Y` sweeps.
- **Fenwick contents:** Maintain one Fenwick pair `(count, value_sum)` for active `A` values and another for active `B` values. Values from both arrays are coordinate-compressed together.
- **Insertion/removal contribution:** For a value `v`, against an opposite multiset of total count `T` and total sum `S`, let `(c, s)` be the count and value sum of elements `<= v`. Its absolute-difference contribution is `v*c-s + (S-s)-v*(T-c)`. Adding an endpoint adds this amount; removing it subtracts this amount.
- **Prefix totals:** Total active counts are simply `cur_x` and `cur_y`; total active value sums are available from ordinary positional prefix sums of `A` and `B`. Therefore Fenwick trees only need to provide values ordered by magnitude.
- **Correctness invariant:** Before answering each ordered query, Fenwick A represents precisely `A_1..A_cur_x`, Fenwick B represents precisely `B_1..B_cur_y`, and `current_answer` equals the required double sum for those prefixes. Every endpoint move changes the sum by exactly the absolute-difference contribution of the inserted or removed element.
- **Complexity:** Each endpoint movement costs `O(log N)` due to Fenwick operations. With block size `S`, the standard bound is `O((K*S + N^2/S) log N)` endpoint work, minimized near `S = N/sqrt(K)`. Memory usage is `O(N)`.
