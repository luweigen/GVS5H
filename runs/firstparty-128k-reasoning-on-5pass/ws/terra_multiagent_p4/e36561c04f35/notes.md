- **Formulation:** An operation sequence can be viewed as choosing a stable target sequence of colored batches, paying one deletion per batch and one adjacent swap per inverted pair relative to the original sequence.
- **Online batch view:** Process occurrences left to right. Every occurrence is assigned either to the latest existing batch of its value or to a newly created batch. Batches are ordered by creation time. Assigning an occurrence to batch `b` creates one inversion for every previously assigned occurrence in a later batch.
- **Greedy rule:** Let `c` be the number of already processed elements in batches later than the latest batch of the current value. Reuse that batch when `c <= 1`; otherwise create a new batch. Reusing costs `c` swaps, whereas creating a batch costs one deletion. The exchange argument shows that when `c >= 2`, retaining the old batch cannot improve future cost; when `c <= 1`, reuse is optimal.
- **Data structure:** Maintain the number of assigned occurrences in every batch using a Fenwick tree. If `processed` elements have been seen, then the reuse cost of batch `b` is `processed - prefix_sum(b)`.
- **Complexity:** Each test case is processed in `O(N log N)` time and `O(N)` memory. The sum of all `N` is at most `2e5`.
- **Checks:** The algorithm gives `3` for `1212`, `3` for `1221`, `5` for `121323`, and `8` for `12121212121`.
