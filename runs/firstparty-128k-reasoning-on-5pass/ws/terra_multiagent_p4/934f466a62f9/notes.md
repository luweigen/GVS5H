- **Reduction:** Assign every chosen pair a coordinate at which its maximum is attained. Both cakes contribute that coordinate value. Conversely, cakes assigned to each coordinate can be paired arbitrarily if and only if all three coordinate assignment counts are even. Thus, select exactly `2K` distinct cakes, assign each to one of three labels, maximize assigned values, and require even label counts.
- **Baseline:** Give every cake one label attaining its individual maximum (ties may be broken arbitrarily), select the `2K` largest maxima, and sum them. This is the unconstrained optimum. Since `2K` is even, either all baseline label counts are even or exactly two labels `a,b` have odd counts.
- **Operations and losses:** A selected cake with baseline label `p` can be relabeled to `q`, giving parity edge `p-q` and loss `best[i]-value[i][q]`. Alternatively, remove a selected baseline-`p` cake and insert an unselected cake assigned to `q`; this also gives edge `p-q`, with loss `best[i]-value[j][q]`. All losses are nonnegative, including under ties, because every selected maximum is at least every unselected maximum, which is at least each coordinate of that unselected cake.
- **Path lemma:** Relative to the baseline, pair every removed selected cake with one inserted unselected cake, and include every relabel as an edge. The XOR of edge endpoints is the required parity correction. If the operation multigraph has a cycle, undo every operation on that cycle; this preserves parity, remains feasible, and cannot worsen value because all losses are nonnegative. After all cycles are removed, a forest with odd-degree vertices exactly `a,b` consists of one simple `a-b` path. With only three labels, this path is either the direct edge `a-b` or the two-edge path `a-c-b`, where `c` is the remaining label.
- **Compatibility:** An operation uses exactly one selected source cake and, for an exchange, exactly one unselected inserted cake. Two retained operations are compatible exactly when their selected source IDs differ and their nonnegative inserted IDs differ.
- **Candidate bound:** Fix a directed exchange `p -> q`. Its loss is `best[source]-value[destination][q]`, so its source and destination choices are independent: cheapest sources are selected baseline-`p` cakes with smallest `best`, and cheapest destinations are unselected cakes with largest coordinate `q`. When this operation is paired with one other operation, compatibility forbids at most one selected source ID and at most one unselected destination ID. Therefore one of the best two candidates in each respective ordered list is always available and no worse than any compatible omitted choice. Keeping three is safely sufficient. For a directed relabel `p -> q`, only its selected source ID matters; one other operation forbids at most one ID, so one of the two cheapest relabel candidates is sufficient, and three is safe. Replacing each operation in an optimal direct correction or optimal two-edge correction by these available retained candidates cannot increase loss and preserves compatibility. Cartesian-product enumeration of retained source and destination lists contains the resulting exchange.
- **Empty groups and full selection:** If `K=N/2`, there are no unselected cakes, so exchange candidate lists are empty; relabel operations remain sufficient. If odd labels are `a,b`, both corresponding selected groups are nonempty, hence a direct relabel exists and the correction minimum is never over an empty set. Empty groups only remove unavailable operations. Ties in maxima or sorting cause no issue because all threshold inequalities are non-strict.
- **Complexity:** Sorting by maximum and constructing the constant candidate lists costs `O(N log N)` per test case; correction enumeration is constant size. Total memory is `O(N)`.
- **Implementation status:** The provided code implements direct and two-edge corrections, checks source/destination identity conflicts, and uses three candidates for every relevant list.
