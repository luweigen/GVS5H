- **Potential reduction:** Let \(P_v=\sum_{j<v}w_j\). A rightward trip on interval \([l,r]\) requires \(P_l=P_r\) and all internal potentials strictly greater. A leftward trip requires \(P_l=P_r\) and all internal potentials strictly smaller.
- **Pair characterization:** A set of such interval constraints is feasible iff no incompatible pair occurs. Incompatibility arises when two intervals share their left endpoint or share their right endpoint, because endpoint equalities force equal heights while one endpoint becomes internal to the other. For strictly crossing intervals \(l_i<l_j<r_i<r_j\), they are incompatible exactly when their travel directions are equal. Nested intervals and merely touching intervals are compatible.
- **Why crossings matter:** For a crossing pair, each interval contains an endpoint of the other. If both travel right, each equality height must be strictly below the other; if both travel left, each must be strictly above the other. Opposite directions impose the same ordering and are consistent.
- **Range-query reduction:** For each person index \(j\), compute `bad[j]`, the largest earlier index incompatible with \(j\). A query \([L,R]\) is feasible iff `max(bad[L-1:R]) < L-1`.
- **Endpoint conflicts:** Scan people in input order and retain the latest index having each normalized left endpoint and right endpoint. Repeated left or repeated right endpoints directly update `bad`.
- **Crossing conflicts:** Use CDQ divide-and-conquer on input indices. At every merge, all left-side indices are earlier than all right-side indices. Detect both crossing orientations with sweeps and a segment tree keyed by the relevant town coordinate, storing maximum person index separately by direction.
- **Complexity:** CDQ uses \(O(M\log^2 M)\) time and \(O(N+M\log M)\)-scale temporary behavior; final range maximum queries use an iterative segment tree in \(O(\log M)\) each.
