- **Algorithm:** Use block decomposition on the queried prefix length `X`. For each block, the `A` prefix before the block is fixed, while only the block suffix varies.
- **Fixed prefix:** Maintain the sorted values of the fixed `A` prefix incrementally by merging the previous sorted prefix with the preceding block, avoiding repeated full-prefix sorting. Sweep `B` in value order to compute each `B_j`'s distance to the fixed prefix, then prefix-sum those contributions in original `B` order.
- **Variable suffix:** Build persistent segment-tree roots for every prefix of `B`, storing counts and value sums by compressed value. For each queried `A_i` in the current block, query the corresponding `B` prefix to obtain the count and sum of values not exceeding `A_i`; this gives its total absolute-distance contribution in logarithmic time.
- **Complexity:** Fixed-prefix processing is `O(number_of_blocks * N)`, sorted-prefix construction is `O(number_of_blocks * N)` total, and suffix queries cost `O(K * block_size * log N)`. The block size balances these terms and is approximately `N / sqrt(K log N)`.
- **Correctness details:** Persistent queries use `bisect_right`, so values equal to `A_i` are included in the lower partition and contribute zero there. Prefix and block boundaries use zero-based indices carefully; the first block has an empty fixed prefix, and the final block may be shorter.
- **Numeric safety:** Python integers and 64-bit persistent-tree sum storage safely accommodate the maximum possible answer.
