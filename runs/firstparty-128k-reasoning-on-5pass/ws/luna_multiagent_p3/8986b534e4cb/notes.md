- **Potential formulation:** Assign a potential \(x_v\) to each town and set \(w_j=x_{j+1}-x_j\). A person on \([a,b]\) requires equal endpoint potentials. For a left-to-right trip, every internal potential must be strictly larger; for a right-to-left trip, every internal potential must be strictly smaller.
- **Conflict characterization:** A feasible set is exactly a set containing no conflicting pair. Same-orientation intervals conflict when they properly cross: \(a<c<b<d\) or \(c<a<d<b\). Opposite orientations conflict when they share the same left endpoint or the same right endpoint.
- **Crossing detection:** For each orientation separately, a merge-sort tree stores intervals sorted by left endpoint with suffix maxima of right endpoints, and intervals sorted by right endpoint with prefix minima of left endpoints. This avoids incorrectly treating opposite-orientation crossings as conflicts.
- **Endpoint detection:** Index lists in each endpoint group are explicitly sorted before `bisect_right`, allowing the earliest later opposite-orientation person to be found.
- **Query reduction:** `nxt[i]` is the smallest index greater than `i` that conflicts with person `i`. An interval `[L,R]` is feasible iff it contains no such pair. Compute suffix limits with `limit[i] = min(limit[i+1], nxt[i]-1)`.
- **Complexity:** The merge-sort trees require \(O(M\log M)\) time and memory in total across both orientations. Each conflict search costs \(O(\log^2 M)\), and each query is answered in \(O(1)\).
