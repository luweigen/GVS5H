- **Core model:** For a starting slime K, the maximal final interval is the smallest stable interval containing K. An interval is stable when both adjacent outside slimes (or infinite sentinels) have size at least the interval sum. Minimality guarantees reachability: any proper subinterval inside a minimal stable interval has at least one boundary slime strictly smaller than its current sum.
- **Cartesian tree:** Build the strict max Cartesian tree by popping while `A[stack[-1]] < A[i]`. This gives heap property `parent value >= child value` and in-order indices. For any threshold T, the connected component of slimes with size `< T` containing K is exactly the subtree of the highest ancestor of K whose value is `< T`.
- **First step:** `S0[K]` is the sum between the nearest greater-or-equal elements on the left and right, computed with two monotonic stacks. If `S0 == A[K]`, no adjacent slime is strictly smaller, so the answer is `A[K]`. Otherwise `A[K] < S0`, and the first reachable component is the subtree of the highest ancestor with value `< S0`.
- **Stable ancestors:** A node is stable iff its subtree sum is at most its parent value; the root is stable. The parent is the smaller of the two outside barriers of the node’s subtree interval. The process expands upward through ancestors, and the final size is the subtree sum of the nearest stable ancestor of the first component root.
- **Path query:** During a DFS preorder, maintain the root-to-current path and `path_neg = -A` values, which are nondecreasing. `bisect_right(path_neg, -S0[K])` finds the first ancestor with `A < S0` (strict). The implementation maintains the path by popping until the parent is on top, equivalent to enter/exit markers but with fewer stack operations.
- **Subtree sums:** Instead of computing `lsub/rsub`, compute subtree sums directly: initialize `subsum = A`, then add each node’s sum to its parent in reversed DFS preorder.
- **In-place nearest stable sum:** Once a node is entered, its original subtree sum is no longer needed. Overwrite `subsum[node]` with the nearest stable ancestor’s sum. Children read `subsum[parent]` as the current nearest stable sum. The `S0` array is reused to store final answers.
- **Edge cases:** Equality is a barrier because absorption requires strictly smaller. Thus `S0` uses greater-or-equal barriers, and the path query uses `bisect_right` to enforce strict `A < S0`. Equal values in the Cartesian tree are handled by popping only strictly smaller values, making earlier equal elements ancestors and preserving the component property. Sentinels are handled by treating the root as stable. If `S0 > global maximum`, the whole array is reachable, so the answer is the total sum.
- **Complexity:** `O(N log N)` time due to binary searches on the path, and `O(N)` memory. Preallocated arrays and reuse of lists keep memory and constant factors low for `N = 5e5`.
