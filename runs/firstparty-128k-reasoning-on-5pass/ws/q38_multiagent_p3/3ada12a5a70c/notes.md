- **Perimeter mapping:** Map each boundary point to a unique clockwise coordinate t in [0,4*side): y==0 -> x; x==side -> side+y; y==side -> 3*side-x; otherwise -> 4*side-y. Corners are assigned consistently by the first matching branch, and the order is bottom, right, top, left.
- **Upper bound:** For k>=4 the answer is at most side. If D>side, no two chosen points can share a side, so four points must be one non-corner point per side. Let b,r,t,l be their distances from the shared corners in clockwise order; adjacent constraints give r>b, t+r<side, t>l, b+l>side, which imply b+t<side and b+t>side, contradiction. Also k cyclic gaps sum to 4*side, so D<=floor(4*side/k). Binary search hi=min(side,C//k).
- **Gap equivalence:** For D<=side, all pairwise Manhattan distances >=D iff every cyclic perimeter gap between consecutive selected points is >=D. Same-side and adjacent-side distances equal the perimeter arc through the shared side/corner, which is a sum of consecutive gaps; opposite-side pairs are automatically at least side apart.
- **Feasibility check:** Sort p and duplicate to p2=p+[x+C]. For D=0 return True. For D>0 build nxt[i]=first j>i with p2[j]>=p2[i]+D using a monotone two-pointer over 2n. For each start s, greedily jump k-1 times via nxt; if any jump reaches index >=s+n, that start fails. If k points fit and p2[s]+C-p2[last]>=D, the wrap gap is valid and D is feasible.
- **Greedy correctness:** For a fixed start, the earliest possible next point minimizes the last index and maximizes the wrap gap; if any k-point sequence exists from that start, the greedy sequence also exists. Trying all starts handles the circular wrap.
- **Complexity:** Sorting O(n log n). Each check O(2n + n*k); with n<=15000, k<=25, and about 31 binary-search steps, this is around 12 million simple operations and O(n) memory.
- **Validation:** The guarded __main__ self-test runs the three examples, exhaustive cross-check over all subsets for side 1 and 2, full boundary sets for side 1..4 with k=4 and k=n, and 30 deterministic random subsets for side<=4. Brute force precomputes pairwise Manhattan distances and enumerates combinations, with early break when a pair distance cannot improve the current best. No failures were found, so the algorithm was left unchanged.
