- **Chosen method:** Use the wrap-delta method. Compute the inversion count for k=0 once, then update it for each cyclic shift by adding the precomputed delta of the value that wraps from M-1 to 0.
- **Delta derivation:** When original value p is currently M-1 and wraps to 0, only pairs containing exactly one p change. If p is before a non-p element, an inversion becomes a non-inversion, contributing -1. If a non-p element is before p, a non-inversion becomes an inversion, contributing +1.
- **Delta formula:** For each occurrence of p, delta[p] adds earlier_non_p and subtracts later_non_p. Equivalently, delta[p] = sum over positions of p of (number of earlier elements not p) - (number of later elements not p).
- **Delta computation:** One left-to-right scan accumulates earlier non-p counts using total_seen - count_seen[x]. One right-to-left scan subtracts later non-p counts using total_seen - count_seen[x]. This is O(N).
- **Transition order:** The answer for k=0 is the Fenwick inversion count. For k=1, add delta[M-1]; for k=2, add delta[M-2]; ...; for k=M-1, add delta[1]. delta[0] is not applied because no output is needed for k=M. The sum of all deltas is zero, so applying delta[0] would return to the k=0 answer.
- **Fenwick details:** Values are 1-indexed as x+1. Prefix sum up to x+1 gives the number of previous elements <= x, so previous greater elements = i - prefix_sum. This gives the k=0 inversion count in O(N log M).
- **Edge cases:** M=1 works because there are no transitions and all values are equal, so the answer is 0. Duplicates are handled correctly because same-value pairs are excluded from non-p counts. Absent values have delta 0. Python integers safely handle counts up to about N^2.
- **Verification:** Samples 1, 2, and 3 were checked manually and match the expected outputs. Small random brute-force checks comparing direct inversion counts for every k with the cumulative delta method agree for tiny N and M. Edge cases such as all equal values, N=1, and M=1 are consistent.
- **Complexity:** Time O(N log M + N + M), memory O(N + M). This is well within the constraints for N, M <= 2e5.
