- **Model:** The operation is an adjacent transposition at edge i with cost i. Sorting a permutation requires every initially inverted pair to cross once, but the total cost depends on which edge each pair crosses.
- **Potential function:** For any permutation Q, let R_p be the number of earlier elements smaller than Q_p. Define F(Q)=sum_p (p(p-1)/2 - R_p(R_p+1)/2). For the sorted permutation R_p=p-1, so F=0; each term is nonnegative.
- **Lower bound:** Swapping adjacent values x,y at edge i affects only positions i and i+1. If x>y, F decreases by A+1, where A is the number of elements before position i that are smaller than x; since A<=i-1, the decrease is at most i. If x<y, F increases, so the decrease is negative and also at most i. Therefore every swap of cost i reduces F by no more than i, and any sorting sequence has total cost at least F(initial).
- **Achievability:** Insertion sort from left to right (equivalently, always swap the leftmost adjacent inversion) attains the bound. When P_i is inserted into the sorted prefix, it crosses previous larger elements from largest to smallest. At each such swap at edge i, all i-1 elements to the left are smaller than the left element, so F drops exactly i. Hence the minimum cost is F(P).
- **Closed form:** For original 1-indexed position i, let r be the number of previous values smaller than P_i. The element crosses edges r+1 through i-1, contributing sum_{e=r+1}^{i-1} e = i(i-1)/2 - r(r+1)/2. Sum this over all i.
- **Computation:** Use a Fenwick tree over values 1..N. For i=1..N, query prefix sum x-1 to get r, add the contribution, then add x to the tree. Complexity O(N log N), memory O(N).
- **Size:** The worst case is reverse order, giving sum_i i(i-1)/2 = N(N+1)(N-1)/6, about 1.33e15 for N=2e5, so 64-bit arithmetic is enough; Python integers are safe.
- **Validation:** Samples match. A brute-force Dijkstra over all permutations up to N=6 (720 states, adjacent swaps with costs 1..5) agrees with the formula for every state. Edge cases: sorted gives 0, N=2 gives 0 for (1,2) and 1 for (2,1), reverse uses the closed form.
- **Pitfalls:** Use 1-indexed positions; query x-1 for strict smaller; do not simulate swaps one by one; keep all arithmetic in integer division.
