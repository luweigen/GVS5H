- **Core reduction:** A 400 number has exactly two distinct prime factors and every prime exponent is even. Therefore it is exactly a perfect square `x^2` where `x` has exactly two distinct prime factors.
- **Search bound:** Since `A <= 10^12`, any valid square root satisfies `x <= 10^6`. The program reads all queries first and uses `limit = isqrt(max(queries))`, so precomputation is never larger than necessary.
- **Distinct factor sieve:** A `bytearray` stores the number of distinct prime divisors. For each `p` from 2 to `limit`, if `cnt[p] == 0`, then `p` is prime, and we increment `cnt[m]` for every multiple `m` of `p`. This works because every composite number has already been touched by a smaller prime factor.
- **Bytearray safety:** The maximum number of distinct prime factors for `n <= 10^6` is 7, because `2*3*5*7*11*13*17 = 510510` and multiplying by the next prime exceeds `10^6`. Thus values never exceed 255.
- **Candidate list:** Collect `x*x` for all `x` with `cnt[x] == 2`. Since `x` is iterated in increasing order, the resulting list of squares is automatically sorted, so no separate sort is needed.
- **Query handling:** For each query `A`, `bisect_right(values, A) - 1` gives the index of the largest 400 number not exceeding `A`. The constraints guarantee an answer exists, but the code also guards against an empty result for robustness.
- **Complexity:** Precomputation is `O(limit log log limit)`, with roughly 3 million multiple increments at `limit = 10^6`, plus `O(limit)` to build the list. Each query is `O(log M)`, where `M` is the number of 400 numbers, about 200k. Memory is `O(limit + M)`.
- **Edge cases:** `A = 36` returns 36. Non-square `A` correctly falls back to the previous square. `10^12` is valid because `10^6 = 2^6 * 5^6`, so its square has exactly two distinct prime factors with even exponents.
- **Sample check:** The logic yields `400`, `36`, `36`, `1000000000000`, and `123454321`. The last value is `11111^2`, and `11111 = 41 * 271`, so it has exactly two distinct prime factors.
