- **Core objective:** After grinding, each pair has final sum H, so total final length is N*H. Since cost is initial total minus final total, minimizing cost is equivalent to maximizing feasible H.
- **Fixed-H constraints:** For a chosen H, the final upper length u_i must satisfy 0 <= u_i <= U_i and u_i >= H - D_i, while adjacent upper lengths must differ by at most X.
- **Necessity of the bound:** For any feasible H and any indices i, j, we have H = u_i + d_i <= D_i + u_i. By the Lipschitz condition, u_i <= u_j + X*|i-j| <= U_j + X*|i-j|. Therefore H <= D_i + min_j(U_j + X*|i-j|). Taking the minimum over i gives H <= min_i(D_i + f_i), where f_i = min_j(U_j + X*|i-j|).
- **Sufficiency of the bound:** Let H* = min_i(D_i + f_i). The sequence f_i is X-Lipschitz and satisfies f_i <= U_i. Define u_i = min(f_i, H*). The pointwise minimum of an X-Lipschitz sequence and a constant is still X-Lipschitz, so the u_i satisfy the smoothness condition. Also u_i <= U_i and u_i <= H*. Since H* <= D_i + f_i, we get u_i >= H* - D_i, so d_i = H* - u_i is between 0 and D_i. Thus H* is feasible and optimal.
- **Computing f_i:** f_i is the minimum of left-side and right-side contributions. Forward pass: left[i] = min(U[i], left[i-1] + X), giving min over j <= i. Backward pass: right[i] = min(U[i], right[i+1] + X), giving min over j >= i. Then f_i = min(left[i], right[i]).
- **Implementation details:** Use sys.stdin.buffer.read().split() for fast input. Store U, D, and left. The backward pass only needs a running right value. Python integers safely handle the answer, which can exceed 32-bit range.
- **Complexity:** O(N) time and O(N) memory.
- **Edge cases:** Large X makes the smoothness constraint irrelevant, yielding f_i = U_i and H = min_i(U_i + D_i). Small X propagates low upper caps across positions. All values remain integers, so no floating-point arithmetic is needed.
