- **Verification:** Provided examples pass: `(10, 20)` returns `2`, and `(1, 15)` returns `10`. Brute-force comparisons over `1..2000`, random intervals up to `100000`, and edge cases such as `l == r` and zero-containing boundaries match the digit DP. No mismatch was found, so the current approach is kept.
- **Zero digits:** Any positive integer containing a zero has digit product `0`, and `0` is divisible by its positive digit sum. Therefore all zero-containing numbers are beautiful. The DP only counts zero-free numbers as possible bad numbers and prunes `d == 0` once a number has started.
- **Prefix reduction:** The answer for `[l, r]` is the interval length minus `bad(r) - bad(l - 1)`, where `bad(N)` counts positive zero-free numbers `<= N` whose digit sum does not divide their digit product.
- **Digit DP state:** `dp(pos, tight, started, s, e)` processes digits left to right. `s` is the current digit sum, and `e` is the capped exponent vector of the digit product for primes `2, 3, 5, 7`.
- **Caps:** For `r < 10^9`, the maximum digit sum is `81`. The caps `(6, 4, 2, 2)` cover the maximum required exponents for sums up to `90`: `2^6 = 64`, `3^4 = 81`, `5^2 = 25`, `7^2 = 49`. Capping is safe because stored exponents are `min(actual, cap)`, and final required exponents never exceed the caps.
- **Terminal check:** If the number has not started, it is `0` and not bad. If the digit sum has a prime factor outside `{2, 3, 5, 7}`, it is bad. Otherwise it is bad exactly when some required exponent of the sum exceeds the stored capped product exponent.
- **Leading zeros:** Leading zeros keep `started = False` and are not treated as actual zero digits. This correctly handles numbers with fewer digits than `N`.
- **Complexity:** There are at most 9 relevant digit positions. The state space is small because the exponent vector has only `7 * 5 * 3 * 3 = 315` capped combinations, and the digit sum is at most `81`. The cached DP is fast for the two `count_bad` calls.
- **Edge cases:** `count_bad(0)` returns `0`. Single-digit numbers are beautiful. `l == r` works by the prefix difference. Numbers like `10`, `20`, `100`, and `1000` are beautiful and are excluded from the bad count.
