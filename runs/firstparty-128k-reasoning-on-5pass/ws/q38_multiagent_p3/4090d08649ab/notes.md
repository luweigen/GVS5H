- **Core reduction:** For a subarray, an operation can erase exactly a consecutive interval of values that are all present. Therefore the minimum number of operations is the number of connected components of the set of distinct values on the integer value line. Equivalently, each component can be counted by its maximum value x, where x is present and x+1 is absent.
- **Right-endpoint formula:** For a fixed right endpoint R, let last(x) be the last position of value x in A[1..R], with sentinel last(0)=last(N+1)=0. For a left endpoint L, value x is a component right endpoint in A[L..R] iff last(x+1) < L <= last(x). Hence the sum of f(L,R) over all L is T_R = sum_x max(0, last(x) - last(x+1)). The required answer is sum_R T_R.
- **O(N) update:** When appending A_R = v at position i, only last(v) changes from p to i. Let a = last(v-1) and b = last(v+1). The term for x=v changes from max(0, p-b) to i-b. The term for x=v-1 changes from max(0, a-p) to 0 because a < i. All other terms are unchanged. Thus delta = i - b - max(0, p-b) - max(0, a-p). Update T by delta, set last[v]=i, and add T to the answer.
- **Implementation details:** Use 1-based positions. Allocate last with length N+2 so indices 0 and N+1 are valid sentinels. Read all input tokens from sys.stdin.buffer. Python integers are arbitrary precision, so no overflow handling is needed. Do not clamp T or delta; T_R can decrease when a newly added value bridges two previously separate components for many left endpoints.
- **Pitfalls:** Use the old p = last[v] before overwriting last[v]. Do not coordinate-compress values, because adjacency is by actual numeric difference 1. Handle v=1 and v=N through the sentinel entries. The per-step delta may be negative, and that is correct. The final answer is the accumulated sum of T_R over all R, not the final T_R.
- **Validation:** The formula matches the samples: [1,3,1,4] gives T sequence 1,3,5,7 and answer 16; [3,1,4,2,4] gives answer 23. Small brute force over subarrays, maintaining the set of present values and the component count, can cross-check random tiny cases.
- **Alternative approaches, superseded:** Offline distinct-minus-edges and gap counting are also linear but more complex. Fenwick range updates over left endpoints are correct but slower. Brute force is only useful for validation. The online last-occurrence sweep is the simplest and fastest approach.
