- **Problem:** K-th largest value of `A_i B_j + B_j C_k + C_k A_i`, with `N <= 2e5`, `K <= 5e5`, all values positive.
- **Monotonicity:** Sort each array descending. Increasing any index cannot increase the value, so `(0,0,0)` is the maximum.
- **Truncation:** Let `m = min(N, K)`. If `K < N`, then `m = K`; any triple with a coordinate at least `m` has `m` triples inside the `m`-cube with that coordinate replaced by `0..m-1` and value at least as large, so it cannot affect the K-th value. If `K >= N`, no truncation is needed.
- **Tree:** Use a unique-parent tree over the `m`-cube. Parent of `(i,j,k)` is `(i-1,j,k)` if `i>0`, else `(0,j-1,k)` if `j>0`, else `(0,0,k-1)`. Children are `(i+1,j,k)`; if `i==0`, also `(0,j+1,k)`; if `i==0 and j==0`, also `(0,0,k+1)`. Parent value is always at least child value.
- **Best-first search:** Root is the 1st largest. The heap starts with the root’s three children. Each iteration pops the next largest node and pushes all of its children. After `K-2` pops, the heap top is the K-th largest value.
- **Bug fix:** The old code called `heappop` first and then used `heapreplace` to insert a child. That removed an unrelated frontier node instead of the already popped node. The fixed code uses `heappop` for the current node and `heappush` for every child, so no frontier node is lost. `heapreplace` is no longer used.
- **Key packing:** Store `key = (delta << total) | code`, where `delta = root - value` and `code = i + j*2^shift + k*2^(2*shift)`. Use `shift = bit_length(m-1)`. Parent code is smaller than child code, so equal deltas are ordered safely.
- **Delta increments:** Store `delta` instead of full values. Child along A adds `(A_i - A_{i+1}) * (B_j + C_k)`, along B adds `(B_j - B_{j+1}) * (A_i + C_k)`, along C adds `(C_k - C_{k+1}) * (A_i + B_j)`. Precompute first differences; this uses one multiplication per child.
- **Axis order:** The expression is symmetric in the three arrays, so any permutation is safe. The i-axis is expanded for every popped node, j only when `i==0`, and k only when `i==0,j==0`. Sort arrays by first-axis drop `(first - second) * (sum of other two maxima)` ascending to put the smallest primary-axis drop on i.
- **Shortcuts:** `K == 1` is handled directly. If `countAmax * countBmax * countCmax >= K`, the answer is the root value. If `K >= m^3`, the answer is the minimum value in the truncated cube.
- **Performance:** Complexity is `O(N log N + K log K)` time and `O(N + K)` memory. Heap size stays bounded by about `2K` because each pop removes one node and adds at most three children. Packed integer keys keep heap entries compact.
- **Samples:** Expected outputs are `31`, `30000`, and `689589940713840351`. Sample 1 and sample 2 were hand-traced with the fixed heap logic; sample 3 follows the same general path.
