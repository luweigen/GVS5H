Process the queries offline in increasing R, maintaining the patience-sorting LIS tails for the current prefix. Let tails[l] be the minimum possible ending value of a strictly increasing subsequence of length l, with INF for impossible lengths. When A_R is added, find the first tail >= A_R and replace it, which is a point update in a segment tree over tail lengths. For a query (R,X), after prefix R is processed, the answer is the largest l with tails[l] <= X, because the subsequence achieving tails[l] then has all elements <=X. Group queries by R and answer them during the sweep, using segment-tree searches for first >= value and rightmost <= X. This gives O((N+Q) log N) time.
