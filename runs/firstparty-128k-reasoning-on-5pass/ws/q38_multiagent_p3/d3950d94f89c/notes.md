- **Sample tests verdict:** PASS. The included harness runs the two examples plus targeted cases: all-duplicates chain, unique chain, star, n=2 unique/duplicate, tie cases, root/duplicate blockers, and single node; all expected outputs match.
- **Chosen approach:** O(n) iterative DFS from root 0, maintaining the current root-to-node path distances and the deepest occurrence depth for each value.
- **State:** `last_depth[val]` is the deepest depth of `val` on the current path before the current node is added; `path_dist[d]` is the weighted distance from root to the current path node at depth d; `parent_start` is the highest valid start depth for the parent.
- **Start recurrence:** For node v with value x and previous occurrence depth p, valid starts form the suffix `[max(parent_start, p + 1), depth]`. The code uses `prev >= parent_start ? prev + 1 : parent_start`, with root start fixed to 0.
- **Why one candidate per endpoint:** Edge lengths are positive, so for a fixed endpoint the highest valid start gives the strictly longest path ending there. Any lower start is shorter and cannot be a global longest path, so evaluating only the highest valid start is sufficient for both maximum length and minimum node count on ties.
- **Answer update:** Append the current distance before evaluating. Candidate length is `dist - path_dist[start]`, candidate node count is `depth - start + 1`. Update on greater length; on equal length keep the smaller node count.
- **DFS state management:** Enter events compute start, append distance, update the answer, record the previous `last_depth`, push an exit event, then push child enter events. Exit events restore the previous occurrence depth and pop the distance. LIFO order ensures all children finish before the node exit.
- **Edge cases covered:** single-node paths, all duplicates yielding `[0, 1]`, duplicate root/child, duplicate sibling values, previous occurrence above the current blocker, ties between 2-node and 3-node longest paths, n=2, and n=1 if encountered.
- **Complexity:** O(n + max(nums)) time and memory, effectively O(n) under the given constraints.
- **Pitfalls avoided:** Use node depth for node count and weighted distance for length; restore `last_depth` to the previous occurrence rather than simply -1; do not evaluate before appending the current distance; skip the parent edge; tie-break only on equal length.
