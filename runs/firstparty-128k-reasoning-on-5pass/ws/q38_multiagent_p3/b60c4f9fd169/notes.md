- **Problem:** decide whether the Levenshtein edit distance between two strings is at most K, with K <= 20 and lengths up to 500000.
- **Core algorithm:** Landau-Vishkin furthest-reaching edit distance. Use diagonal d = y - x, where x is the position in S and y in T. For each edit count e, keep only the furthest x reachable on each diagonal.
- **Recurrence:** from e-1 to e, substitution comes from the same diagonal d and advances x by 1; insertion comes from d-1 and keeps x; deletion comes from d+1 and advances x by 1. After taking the maximum reachable x for diagonal d, extend it by the exact longest common prefix.
- **Boundary conditions:** substitution requires old x < n and old y < m. Insertion requires old y < m, but old x may already be n. Deletion requires old x < n and old y <= m, allowing deletion after T has ended.
- **Trimming:** first reject if the length difference exceeds K. Then remove the common prefix, and then the common suffix of the remaining strings. This is safe for edit distance and often reduces the work to the region between the first and last necessary edit. If one trimmed string is empty, the answer is Yes because the remaining length equals the original length difference, which is already <= K.
- **Exact LCP:** no hashing is used. Cache results by (x, y). Compare 8192-byte chunks using bytes.startswith, which performs C-level comparison. If a chunk mismatches, convert both chunks to little-endian integers, xor them, and use the lowest set bit to locate the first differing byte. The same method handles the final shorter remainder.
- **Complexity:** there are at most (K+1)^2 = 441 LCP calls for K=20. Each LCP scans only matching chunks, and chunk comparisons are done in C. The Python-level work is small, so the solution is fast for the maximum constraints.
- **Implementation details:** read input as bytes, use a dp list of length 2K+1 with offset K, guard diagonal indices, and check success immediately whenever a state reaches (n, m).
