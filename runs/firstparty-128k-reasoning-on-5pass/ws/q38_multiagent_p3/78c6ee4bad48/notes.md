- **Gap model:** Represent the sorted coordinates by consecutive gaps d_k = p_{k+1} - p_k for 1-based k = 1..N-1. For four consecutive pieces with gaps a, b, c, the operation fixes the outer two pieces and reflects the middle two across their midpoint. The new sorted gaps become c, b, a, so the operation swaps d_i and d_{i+2} while leaving d_{i+1} unchanged.
- **Invariants:** The leftmost coordinate p_1 never changes. Each operation swaps two gaps of the same 1-based parity, so the multiset of odd-indexed gaps and the multiset of even-indexed gaps are invariant.
- **Reachability:** For every adjacent pair in the odd-index gap subsequence, choosing the smaller index i performs that adjacent swap; similarly for the even-index subsequence. Therefore every permutation inside each parity class is reachable.
- **Objective:** If p_1 is fixed, then p_j = p_1 + sum_{k<j} d_k. Summing over all pieces gives total sum = N p_1 + sum_{k=1}^{N-1} (N-k) d_k. Thus each gap has weight N-k, which decreases as k increases.
- **Optimal assignment:** For each parity class independently, assign larger gaps to smaller weights to minimize the weighted sum. Since positions k increase while weights N-k decrease, sorting each parity gap list ascending and pairing it with increasing k is optimal by the rearrangement inequality.
- **Implementation:** gaps[0::2] are the 1-based odd-index gaps, and gaps[1::2] are the 1-based even-index gaps. Sort both ascending. Add N * X[0], then add (N-k) * gap for k = 1,3,5,... using odd gaps and k = 2,4,6,... using even gaps.
- **Complexity:** Sorting the two parity lists takes O(N log N) time and O(N) memory, which is fine for N <= 2e5. Python integers handle the large coordinate sums safely.
- **Edge cases:** N=4 works with one odd pair and one even gap. Coordinates may be large, but no floating point is needed because the final answer is an integer and the gap formulation avoids midpoints.
