- **Problem:** Given sorted positive sizes, form the maximum number of disjoint pairs where the smaller/top size times 2 is at most the larger/bottom size.
- **Algorithm:** Let `m = N // 2`. Use pointer `i = 0` over the first half and pointer `j = m` over the second half. If `2 * A[i] <= A[j]`, count a pair and advance both pointers; otherwise advance `j`. Print the count.
- **Correctness sketch:** For any feasible set of `K` pairs, sort their tops `t_1..t_K` and bottoms `b_1..b_K`. A valid matching implies the sorted pairing is valid: if `2*t_i > b_i`, then the `i` smallest bottoms could only be matched to fewer than `i` sufficiently small tops, a contradiction. Also `t_i >= A[i]` and `b_i <= A[N-K+i]`, so feasibility implies `2*A[i] <= A[N-K+i]` for all `i < K`. Conversely, those inequalities directly give `K` valid pairs. The greedy count is the largest `K` with this property: if the property holds for `K`, the greedy pointer for the `t`-th top is at most `N-K+t`, so it finds `K` matches; if greedy finds `c` matches, its chosen bottoms can be shifted right to the last `c` elements, giving the property for `c`.
- **Why first half:** At most `floor(N/2)` pairs can be made. The prefix/suffix condition shows an optimal solution can be represented with small tops matched to sufficiently large bottoms, so scanning the first half against the second half is sufficient.
- **Complexity:** `O(N)` time and `O(N)` memory for the input list; `N <= 5e5`, so this is easily fast enough.
- **Implementation details:** The input is guaranteed sorted, so no explicit sort is needed. Use integer comparison `2 * A[i] <= A[j]` to avoid floating point. Read all tokens from stdin for speed.
- **Edge cases:** `N = 2`, odd `N`, no valid pair, duplicates, and large values up to `1e9` are handled by the same loop; positive sizes mean equal sizes never form a pair.
