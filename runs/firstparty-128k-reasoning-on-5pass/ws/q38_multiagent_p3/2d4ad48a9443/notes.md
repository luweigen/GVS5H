- **Cost model:** For a subarray [l, r], the cheapest non-decreasing final array is the running prefix maximum from l. Minimum operations = sum of those prefix maxima - sum of original values. This cost is monotone: extending right cannot decrease it, shrinking left cannot increase it, so a two-pointer scan is valid.
- **Next greater records:** Let ng[i] be the nearest index j > i with nums[j] > nums[i], or n. For a start l, the prefix-max records are l, ng[l], ng[ng[l]], ... . Record p contributes nums[p] over p..min(ng[p]-1, r). Equal values are handled by popping <= in the right-to-left monotonic stack, so equals do not create new records.
- **Binary lifting:** up[0][i] = ng[i], contrib[0][i] = nums[i] * (ng[i] - i). For t > 0, up[t][i] = up[t-1][up[t-1][i]] and contrib[t][i] = contrib[t-1][i] + contrib[t-1][up[t-1][i]]. Sentinel n maps to itself with zero contribution. LOG = (n+1).bit_length() is enough to represent any chain length.
- **Cost predicate:** For r1 = r + 1, start pos = l and total = 0. From high t to low, if up[t][pos] <= r1, add contrib[t][pos] and move pos; those record segments all end inside [l, r]. Stop when pos >= r1. If pos < r1, add the partial segment nums[pos] * (r1 - pos). The subarray is too expensive iff total > k + sum(nums[l..r]). Early exit when total already exceeds this limit is safe because the remaining prefix-max sum is nonnegative.
- **Two-pointer:** For each right endpoint, advance left while the predicate is true; then every start in left..right is valid, so add right - left + 1. Single elements are always valid for k >= 0.
- **Complexity and memory:** The current implementation is O(n log n) time and O(n log n) memory, not the O(n) active-record method from the original plan. It is still within constraints for n=1e5. Contributions are at most about 1e14, and the answer is at most about 5e9, so 64-bit arithmetic is sufficient.
- **Edge cases:** n = 0/1 handled directly; all equal values give ng = n and one record; strictly increasing arrays have zero cost; when r = n - 1, jumps to sentinel n are allowed and add full segments; pos == r1 means the next record starts just after the subarray, so no partial contribution is added.
