- **Core identity:** Swap the order of summation over arrangements and unordered cell pairs. For N = m*n cells, any fixed unordered pair of distinct cells is contained in exactly C(N-2, k-2) valid k-cell arrangements. Therefore the answer is C(N-2, k-2) times the sum of Manhattan distances over all unordered cell pairs.
- **Manhattan decomposition:** Manhattan distance separates into row and column parts. For rows, each pair of rows with distance d contributes n^2 cell pairs, and the sum of distances over all row pairs is m(m^2-1)/6. For columns, each pair of columns contributes m^2 cell pairs, and the sum of distances over all column pairs is n(n^2-1)/6.
- **Closed form:** The total distance over all unordered cell pairs is n^2 * m(m^2-1)/6 + m^2 * n(n^2-1)/6. Multiplying by C(N-2, k-2) gives the final answer.
- **Modular arithmetic:** Use MOD = 1_000_000_007, a prime. Since N <= 100000 < MOD, factorial and inverse-factorial combinations are valid. Use inv6 = pow(6, MOD-2, MOD) to divide by 6 modulo MOD. Reduce m and n modulo MOD before squaring to keep intermediate values small.
- **Combination computation:** C(N-2, k-2) = fact[N-2] * invfact[k-2] * invfact[N-k] modulo MOD. Precomputing factorials up to N takes O(N) time and memory, which is safe because N <= 100000.
- **Edge cases:** If m = 1 or n = 1, the corresponding row or column pair-distance sum is zero. If k = 2 or k = N, the binomial coefficient is 1. The smallest case N = 2, k = 2 works because fact[0] and invfact[0] are defined.
- **Complexity:** O(m*n) time and O(m*n) memory per call due to factorial precomputation; the formula itself is O(1). This is well within the constraint m*n <= 100000.
- **Verification:** The included guarded self-test checks the two provided examples and brute-force compares the formula for all small m,n in 1..3 and random small boards with at most 12 cells. The self-test does not affect normal use of the Solution class.
