- **Approach:** For each right endpoint, maintain the sum of minima and the sum of maxima over all active left endpoints, i.e. all subarrays ending here with length at most k. Add both running sums to the answer.
- **Min deque:** Stores contiguous groups of left endpoints as [value, count], with values strictly increasing from front to back. When adding x, pop back groups with value > x, accumulate their counts, merge with an equal back group if present, and add x times the accumulated count to min_sum.
- **Max deque:** Symmetric to the min deque, with values strictly decreasing from front to back. When adding x, pop back groups with value < x, merge equal values, and update max_sum.
- **Window bound:** After adding the new right endpoint, if i >= k the temporary active set has k + 1 left endpoints. The oldest left endpoint is always in the front group, so subtract one occurrence of the front value and decrement or pop the front count.
- **Duplicates:** Merging equal values is safe because equal minima or maxima contribute identically and preserves the ordered partition of left endpoints.
- **Complexity:** Each group is created once and popped from the back at most once; front removals total at most n. Time is O(n), memory is O(n) worst case and O(k) when the window is small.
- **Verification:** The program includes a brute-force O(n*k) checker and runs the two examples, single-element, k=1, k=n, k larger than n, all-equal, zero, negative, duplicate, increasing, decreasing, alternating, and large all-equal cases. It also runs fixed-seed random tests with small, medium, and large-value arrays.
- **Result:** All examples and edge cases match brute force; the random comparisons report no failures. The large all-equal cases use the closed-form count of subarrays of length at most k to avoid quadratic checking.
- **Edge cases:** k=1 leaves only single-element subarrays after removal; k=n never removes; all-equal arrays collapse into one group; negative values work unchanged; Python integers safely handle large totals.
- **Implementation detail:** Mutable list entries in the deques allow in-place count updates at the front and back without replacing deque elements.
