- **Core model:** Sort intervals by right endpoint, keeping original 0-based index. Strict non-overlap means a new interval can only follow intervals whose right endpoint is strictly less than its left endpoint; `bisect_left(ends, l)` gives that compatible prefix length.
- **DP state:** `W[k][j]` and `T[k][j]` store the maximum weight and lexicographically smallest sorted tuple of original indices for exactly `k` intervals among the first `j` sorted intervals. `W[0][j]=0`, `T[0][j]=()`; impossible states use `-1` and `None`.
- **Recurrence:** For each sorted interval `j`, first carry the skip state from `j-1` for `k=1..4`. Then for each `k`, if `W[k-1][p]` is feasible, form a take candidate by adding the current weight and inserting the current original index into `T[k-1][p]`. Keep the candidate with larger weight, or lexicographically smaller tuple on ties.
- **Prefix compatibility:** Any feasible set contained in prefix `p` is compatible with an interval whose left endpoint is greater than every end in that prefix. Future feasibility from a state depends only on the prefix index, not on the particular chosen intervals, so one best state per prefix/count is sufficient.
- **Lexicographic safety:** For equal-length sorted tuples `A < B` and any disjoint set `F`, `sorted(A∪F) < sorted(B∪F)` because the smallest index where `A` and `B` differ remains the smallest differing index in the unions. Thus keeping only the lexicographically smallest max-weight tuple per exact-count prefix state is safe, including when the future count can vary.
- **Final selection:** Weights are positive, so count 0 is never optimal. Compare exact counts `1..4` by weight first, then by Python tuple order, which matches the problem's variable-length lexicographic rule, including shorter prefix being smaller. Return the winning tuple as a list.
- **Boundary handling:** `bisect_left` excludes intervals ending exactly at `l`, so shared endpoints are overlapping. Because `l <= r`, `p` is always before the current interval. Intervals with equal right endpoints are mutually incompatible; processing order within the same right endpoint does not affect correctness.
- **Implementation details:** The code sorts by `(r, l, original_index)` and uses `5 x (n+1)` tables plus a small tuple `insert` helper. Complexity is O(n log n) time and O(n) memory.
- **Brute-force validation:** A fixed-seed randomized harness in `__main__` compares against exhaustive subset enumeration for n up to 8, with targeted styles for n=1, all overlapping, shared endpoints, equal right endpoints, equal weights, and different-length optimal ties. All explicit and random checks pass; no algorithmic changes were needed.
