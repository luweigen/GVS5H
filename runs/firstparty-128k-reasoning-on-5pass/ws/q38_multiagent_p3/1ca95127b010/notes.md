- **Validation:** The existing N<=10 BFS validator was run for all X,Y and all 2^N strings. It partitions strings by connected components under both operations and compares that partition with the invariant signature used by the solver. No counterexample was printed; the validator passed.
- **Random cross-check:** A separate random cross-check script was run, generating many small cases (N up to 8/10, random X,Y,S,T) and comparing the solver's answer to BFS reachability. All checks passed; no counterexample.
- **Operation view:** Each operation swaps adjacent blocks 0^X and 1^Y. It preserves the number of 1s, the relative order of all 1s, and the relative order of all 0s.
- **Invariants:** The kth 1 position modulo X and the kth 0 position modulo Y are invariant. Also, for 1s, the sums of floor(pos/X) grouped by 1-index modulo Y are invariant up to adding the same integer to every group; for 0s, the sums of floor(pos/Y) grouped by 0-index modulo X are invariant up to adding the same integer to every group. The solver normalizes each group vector by subtracting its first group.
- **Why bucket terms are needed:** Ordered residues alone are not sufficient. For N=6, X=1, Y=3, strings 001011 and 000111 have the same ordered residues, but 001011 is isolated while 000111 is movable; their one-bucket differences differ.
- **Sufficiency:** The oriented rewrite 1^Y0^X -> 0^X1^Y is terminating because the sum of 1 positions increases, and it is locally confluent because the left side has no nonempty border. Hence each equivalence class has a unique normal form. The checked invariants are preserved and determine that normal form; the exhaustive small-case checks support this.
- **Early exits:** If S==T, answer Yes. If the number of 1s differs, No. If X+Y>N, or total 1s < Y, or total 0s < X, no operation can ever be performed, so the answer is exactly S==T.
- **Complexity:** The final solver does two linear scans and O(N) memory: it stores the residue sequences for S and two bucket arrays for S and T. Time O(N), memory O(N).
