- **Problem model:** A final value `y >= x` covers a target `t` iff `t` divides `y`. For a chosen subset of targets, the cheapest final value is the smallest multiple of their lcm that is at least `x`, with cost `(L - x % L) % L`.
- **DP state:** `dp[mask]` is the minimum cost after processing a prefix of `nums` so that targets in `mask` are covered. Each element is either unused or assigned to one nonempty subset of still-uncovered targets, which enforces that each original element is used at most once.
- **Why only uncovered bits:** If a target is already covered, making the current element also a multiple of it only increases or keeps the required lcm, so the round-up cost cannot decrease. Any redundant coverage can be removed from one element without increasing total cost.
- **Cost cap:** Because `target.length <= nums.length`, assigning distinct `nums` elements to target entries gives a feasible solution with total cost at most `sum(target) - len(target)`. Thus `INF = sum(target) - len(target) + 1` safely prunes useless huge-lcm transitions.
- **Complexity:** With `target.length <= 4`, there are at most 16 masks and at most `3^4 - 2^4 = 65` disjoint `(mask, sub)` transition pairs. The solution is `O(n * 3^t)` time and `O(2^t)` memory, easily within `n <= 5 * 10^4`.
- **Test scope:** The program runs the three provided examples, a set of edge cases, 1000 randomized small cases against an independent brute-force oracle, and a maximum-size performance test with `n = 50000`, `t = 4`.
- **Brute-force oracle:** It uses the proven cost bound `C = sum(target) - len(target)`, enumerates `x` and all multiples of target values in `[x, x + C]`, computes the exact coverage mask of each candidate final value, and combines masks with a separate DP. This does not reuse the solution’s lcm-subset cost formula.
- **Examples:** All three examples pass: `[1,2,3], [4]` gives 1; `[8,4], [10,5]` gives 2; `[7,9,10], [7]` gives 0.
- **Edge cases:** Already-satisfied targets, one element covering all targets, target value 1, duplicate targets, large lcm subsets, nums values larger than targets, and many unused nums elements all pass. Duplicate target bits can be covered by the same final value, consistent with example 2 where one value 10 covers both 5 and 10.
- **Randomized checks:** 1000 random cases with `n <= 6`, `t <= 4`, and values up to 8 were compared to the brute-force oracle. No mismatches were found.
- **Performance:** The maximum-size test uses `nums = [1] * 50000` and `target = [9999, 10000, 9998, 9997]`. It completes quickly, well under the 10-second guard, and returns 39990.
- **Failures:** No failures were found.
