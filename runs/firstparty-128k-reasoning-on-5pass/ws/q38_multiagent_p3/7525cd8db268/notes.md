- **Core count:** For each right endpoint e, a subarray [s, e] is invalid iff s <= l for some normalized pair (l, r) with r <= e. Invalid starts form the prefix 1..M_e, where M_e is the maximum active left value. Valid subarrays ending at e are e - M_e, so the base count with all pairs is sum_e (e - M_e).
- **Marginal gain:** Removing one pair changes M_e only when that pair is active and its left value is the unique maximum active left. In that case the gain at e is max1 - max2, where max2 is the largest active left smaller than max1, or 0 if none exists. The answer is base plus the maximum total gain over all removable pairs.
- **Sweep invariant:** After inserting all pairs with right endpoint <= e, max1 = M_e, max2 = second largest distinct active left, cnt1 = number of active pairs with left equal to max1, and owner = pair id if cnt1 == 1, otherwise -1.
- **Insertion rules:** If l > max1, set max2 = max1, max1 = l, cnt1 = 1, owner = id. If l == max1, increment cnt1 and clear owner. If max2 < l < max1, set max2 = l. Otherwise no change.
- **Batching:** All pairs with the same right endpoint must be inserted before adding base and gain for that endpoint. This correctly handles ties and simultaneous activations within the same batch.
- **Duplicates:** Duplicate conflicting pairs are separate removable elements. If two active pairs share the current maximum left value, cnt1 > 1 and neither receives gain at that endpoint. A later duplicate of the current maximum can suppress gain for that left value until a larger left value appears.
- **Owner tracking:** owner is meaningful only when cnt1 == 1. A new larger maximum makes the old maximum the new max2 and gives ownership to the new pair. A duplicate of the current maximum sets owner to -1.
- **Complexity:** Time O(n + m), memory O(n + m). The answer can be about 5e9 for n = 1e5, so Python int is sufficient.
- **Superseded approach:** The earlier segment-tree/lazy assignment plan is unnecessary; the one-pass max/second-max sweep is sufficient and simpler.

- **Pitfalls:** Normalize each pair to l < r; do not add gain per insertion inside a batch; max2 is the second distinct left value, not the second pair; use 0 as the sentinel for no active left; handle m == 0 defensively even though constraints have m >= 1.
