- **Depth model:** For x > 0, one floor division by 4 reduces the number of divisions needed to reach zero by exactly one. Define d(x) = 0 for x = 0, and for x >= 1, d(x) is the smallest k such that x < 4^k. Equivalently, d(x) = k on the block [4^(k-1), 4^k - 1].
- **Per-query formula:** For an interval [l, r], treat each value x as an independent chain of d(x) unit tasks. One operation can decrement at most two positive chains by one. Pairing a positive element with a zero is allowed, so once any zero exists, a single positive chain can be processed alone.
- **Lower bounds:** Total tasks S require at least ceil(S / 2) operations because each operation handles at most two tasks. The longest chain requires at least M operations because a chain can be decremented at most once per operation.
- **Sufficiency:** Let T = max(ceil(S / 2), M). We need to assign each chain's d(x) tasks to T time slots, at most one task per chain per slot, and at most two tasks per slot. This is a complete bipartite b-matching problem. The conditions total demand <= 2T and each demand <= T are sufficient. If S is odd, there is exactly one one-task slot; it can be placed after the first chain completes, so the requirement to choose two positive elements before any zero exists does not invalidate the formula.
- **Maximum depth:** d(x) is nondecreasing, so the maximum depth in [l, r] is simply d(r).
- **Prefix sums:** Precompute powers p[i] = 4^i up to just above max r. Let pref[i] = sum_{x=1}^{4^i - 1} d(x). Then pref[0] = 0, and pref[i] = pref[i - 1] + (4^i - 4^(i-1)) * i. For n > 0, find i = bisect_right(powers, n) - 1, so 4^i <= n < 4^(i+1). Then prefix(n) = pref[i] + (n - 4^i + 1) * (i + 1).
- **Depth by binary search:** With powers = [1, 4, 16, ...], d(x) = bisect_right(powers, x) for x >= 1. This counts powers of 4 not exceeding x and avoids floating-point logarithm errors.
- **Complexity:** Precomputation is O(log_4 max_r), about 16 steps for 1e9. Each query uses a few binary searches and O(1) arithmetic, so total time is O(Q log max_r). Memory is O(log max_r). Python integers safely handle the large sums.
- **Edge cases:** l = 1 uses prefix(0) = 0. If r is exactly a power of 4, bisect_right places it in the next depth block, e.g. d(4) = 2 and prefix(4) = 5. Constraints guarantee l < r, so the array has at least two elements and zero-pairing is always possible when needed.
- **Validation:** The provided examples match: [[1,2],[2,4]] gives 1 + 2 = 3, and [[2,6]] gives 4. A small brute-force check over depth tuples for tiny intervals, where each operation decrements two distinct positions, matches the formula with no failures.
