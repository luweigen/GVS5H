- **Gap model:** Let the sorted coordinates be p_1 < ... < p_N and define 1-based gaps d_j = p_{j+1} - p_j. For an operation on four consecutive pieces with gaps a, b, c, the two middle pieces are reflected across the midpoint of the outer pieces. Their new sorted positions produce gaps c, b, a. Thus the operation exactly swaps d_i and d_{i+2}, leaving d_{i+1} unchanged.
- **Invariants:** The leftmost coordinate p_1 is never moved. Only gaps whose indices have the same parity are swapped, so the multiset of odd-indexed gaps and the multiset of even-indexed gaps are invariant.
- **Reachability:** In the subsequence of odd-indexed gaps, allowed swaps are between positions 1 and 3, 3 and 5, etc. In the subsequence of even-indexed gaps, allowed swaps are between positions 2 and 4, 4 and 6, etc. These are adjacent transpositions inside each parity subsequence, so they generate all permutations within that parity class. Therefore every gap arrangement preserving the two parity multisets is reachable.
- **Objective function:** The sum of coordinates is N * p_1 + sum_{j=1}^{N-1} (N - j) * d_j. In 0-based gap index i, the weight is N - 1 - i.
- **Optimization:** For each parity class, the corresponding weights decrease from left to right. By the rearrangement inequality, the weighted sum is minimized by pairing larger weights with smaller gaps. Hence each parity class should be sorted in ascending order from left to right.
- **Indexing detail:** 0-based even gap indices correspond to 1-based odd gap indices, and 0-based odd gap indices correspond to 1-based even gap indices. Sorting gaps[0::2] and gaps[1::2] independently is correct.
- **Implementation:** Read all integers, compute gaps from consecutive input coordinates, sort the two parity slices, then accumulate N * X_1 plus the weighted assigned gaps. Python integers safely handle the maximum answer size.
- **Complexity:** Sorting the two parity lists takes O(N log N) time and O(N) memory, which is sufficient for N up to 2e5.
- **Validation:** Sample 1 gives gaps [4, 2, 3], sorted parity gaps even [3, 4], odd [2], assigned [3, 2, 4], answer 21. Sample 2 gives gaps [1, 5, 4, 4, 2], sorted parity gaps even [1, 2, 4], odd [4, 5], assigned [1, 4, 2, 5, 4], answer 41. N=4 edge cases and large coordinate values behave correctly because the formula uses only integer gap arithmetic.
