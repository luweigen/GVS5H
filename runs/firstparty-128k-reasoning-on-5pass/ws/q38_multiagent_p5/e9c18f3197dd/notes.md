- **Model:** Each final nums value can satisfy any subset of target positions for which it is a multiple. For a starting value x and target subset mask, the cheapest final value is the next multiple of lcm(mask), with cost `(L - x % L) % L`.
- **State:** `dp[mask]` is the minimum number of increments after processing a prefix of `nums` so that the target bits in `mask` are satisfied. Since `target.length <= 4`, the table has at most 16 entries.
- **Transition:** For each `x`, start with `new_dp = dp[:]` to allow leaving `x` unused. For every finite old `mask`, choose a nonempty `add` submask of `full ^ mask`, and update `new_dp[mask | add]` with `dp[mask] + cost_x[add]`. Using the old `dp` as the source prevents the same nums element from being used twice in one step.
- **Why only unsatisfied bits:** Adding already satisfied targets cannot reduce cost because the lcm can only increase, so the next required multiple is no closer. Redundant coverage can be dropped from later elements in some optimal solution.
- **Accidental extra satisfaction:** If the next multiple for a subset also satisfies extra targets, including those extra targets has the same cost, because the chosen value is then also a multiple of the larger lcm and no earlier larger-lcm multiple exists.
- **Precomputation:** `lcm[mask]` is built from the least significant set bit. `transitions[mask]` stores all nonempty submasks of the complement. For `m = 4`, there are only 65 transitions per nums element.
- **Cost cap:** Since `nums.length >= target.length`, one feasible solution assigns distinct nums elements to target positions, each costing less than its target value. Thus the answer is strictly less than `sum(target)`, so `INF = sum(target) + 1` is safe and keeps values small.
- **Complexity:** Time is `O(n * 3^m + n * 2^m)` and memory is `O(2^m)`. With `n <= 5 * 10^4` and `m <= 4`, this is only a few million operations.
- **Edge cases verified:** duplicate targets, target containing 1, already satisfied targets, large lcm values, one element covering all targets, and cases where splitting targets across multiple elements is cheaper.
- **Pitfalls avoided:** in-place DP reuse of the same element, greedy closest-multiple choices, summing independent per-target minima, and treating duplicate target values as requiring distinct multiples when one multiple can satisfy all duplicate positions.
