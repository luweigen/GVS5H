
## ideation
A connected subgraph of a tree is effectively determined by a connected vertex set: if two chosen vertices are in the same connected subgraph, the unique path between them in the original tree must also be chosen. Therefore the problem is to choose the largest connected vertex set whose internal degrees are all 1 or 4, with at least one vertex of degree 4.

The core difficulty is that the degree condition is exact and local, while the chosen vertices must form one connected subtree. A vertex can either be a leaf or a four-branch vertex, and the number of incident chosen edges available to its neighbors depends on that choice. Since N is up to 2e5, the intended solution should be a linear or near-linear tree DP rather than exponential search.

A very important structural observation is the alkane formula. If a valid alkane has C vertices of degree 4 and L vertices of degree 1, then L = 2C + 2, so the total number of vertices is 3C + 2. Thus maximizing the total number of vertices is equivalent to maximizing C, the number of degree-4 vertices. Call these degree-4 vertices core vertices.

In any alkane, the core vertices form a connected set in the original tree. The path between two core vertices cannot pass through a leaf or any non-core vertex, because an internal vertex on that path would have degree at least 2 in the alkane and therefore would have to have degree 4. For a core vertex v, every adjacent core vertex must be connected to it in the alkane, so v can have at most 4 core neighbors. It also must have original degree at least 4, because it needs four selected incident edges.

Conversely, any connected set C of original vertices satisfying two conditions can be extended to an alkane: every vertex in C has original degree at least 4, and every vertex in C has at most 4 neighbors inside C. For each v in C, choose 4 - deg_C(v) neighbors outside C as leaves. These outside neighbors are distinct because C is connected in a tree. This reduces the problem to finding the largest connected set of eligible vertices, where eligible means original degree at least 4, and the induced degree inside the chosen set is at most 4.

This suggests several distinct approaches.

First, a core/skeleton DP is very promising. Root the tree arbitrarily. For each vertex, compute the best connected core set inside its subtree that includes the vertex and assumes the parent is also in the core; then the vertex may include at most 3 eligible child core sets. Also compute the best connected core set where the vertex is the highest core vertex; then it may include at most 4 eligible child core sets. Combine children by taking the largest valid values up to the cap. The maximum core count gives the final answer by the formula, or -1 if no core vertex can be chosen. Pitfalls include using original degree for eligibility rather than child count, using “up to” the cap rather than exactly the cap, ignoring invalid children, maintaining top three or top four values, and converting the core count to the final vertex count only at the end.

Second, a one-pass highest-vertex branch DP can directly maximize vertices without using the alkane formula. Root the tree. For each vertex, compute the best valid hanging piece in its subtree when the edge to the parent is selected. Such a piece’s root must have either 0 selected child branches, making it a leaf, or exactly 3 selected child branches, making it degree 4. Also track the best hanging piece that already contains a degree-4 vertex. A complete alkane has a highest vertex: if that vertex is degree 4, choose 4 child hanging pieces; if it is a leaf, choose 1 child hanging piece that contains a degree-4 vertex. Pitfalls include distinguishing hanging pieces from complete alkanes, handling the topmost-leaf case, tracking whether a branch contains a degree-4 vertex, and using top-k selection correctly.

Third, the supplied directed-edge rerooting DP is valid but heavier. Define values for every directed edge representing the best valid piece on the target side when the edge is selected, with the target having degree 1 or 4, and a separate value forcing the target to have degree 4. Compute parent-to-child values bottom-up and child-to-parent values top-down. The final answer can be obtained by rooting the alkane at a degree-4 vertex and taking four incident branch values, or by an equivalent leaf-neighbor formulation. Pitfalls include needing values in both directions, excluding the incoming edge when forcing degree 4 at a vertex, keeping top values with identities to handle exclusion, using invalid markers carefully, avoiding double counting, and ensuring at least one degree-4 vertex.

Fourth, a general finite-state tree DP is possible. For each vertex, keep states for whether the parent edge is selected, how many child edges are selected, and whether a degree-4 vertex has appeared. Combine children with a small knapsack or top-k selection, then keep only states that can lead to final degrees 1 or 4. This is more general but more error-prone. Pitfalls include state design, enforcing connectedness, ensuring that a vertex with parent edge not selected is the unique topmost vertex of the whole alkane, and avoiding disconnected child components.

Common implementation concerns include avoiding deep recursion for 2e5 nodes, maintaining top-k child values efficiently, and clearly separating invalid states from valid zero values if zero is used as a sentinel.
