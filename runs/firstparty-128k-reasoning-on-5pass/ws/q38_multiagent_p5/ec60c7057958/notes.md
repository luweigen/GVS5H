- **Core approach:** Lexicographic unranking. The only state needed is the remaining odd/even counts and the parity required at the next position; exact identities do not affect the number of valid completions.
- **Completion count:** For a suffix of length `L` starting with parity `p`, the number of `p` slots is `(L + 1) // 2` and the other parity has `L // 2` slots. If the remaining counts do not exactly match these slot counts, the count is `0`. Otherwise the count is `fact[rem_odd] * fact[rem_even]`, capped.
- **Capping:** Use `LIMIT = 10**15 + 1`. Factorials and products are capped at `LIMIT`. Since `k <= 10**15`, any capped count is strictly larger than `k`, so it is safe to treat it as “large enough” and never skip such a block.
- **Greedy selection:** At each position, scan unused numbers from `1` to `n` in ascending order. Position `0` allows both parities; later positions allow only the parity opposite the previous choice. For each allowed candidate, compute the number of valid completions after choosing it. If `k > count`, subtract `count`; otherwise fix the candidate and continue. If no candidate is fixed, return `[]`.
- **Why scanning is correct:** All valid permutations with a fixed prefix form a contiguous lexicographic block. Scanning candidates in ascending order and subtracting block sizes is standard k-th permutation unranking. This also avoids the pitfall of grouping by starting parity for even `n`; first values `1, 2, 3, ...` are interleaved correctly.
- **Complexity:** `O(n^2)` time because each of the `n` positions scans up to `n` candidates; `O(n)` space for factorials and the used array. `n = 100` is tiny.
- **Edge cases handled:** `n = 1`; `k` out of range; zero-count candidates such as even-first choices when `n` is odd; `k` equal to the total number of valid permutations; large `n` where factorials exceed the cap.
- **Verification included:** The program has a silent `__main__` block asserting the given examples, small edge cases, `k = total` for `n = 4, 5, 6`, `k > total`, `n = 100, k = 1`, and a valid `n = 100, k = 10**15` result. It also brute-forces all alternating permutations for `n <= 6` and checks every `k`.
