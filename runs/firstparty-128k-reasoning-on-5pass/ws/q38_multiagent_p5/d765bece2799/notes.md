- **Decomposition:** The answer is `sum_minima + sum_maxima` over all subarrays of length at most `k`. The two parts are independent and can be computed by two symmetric passes.
- **Online deque invariant:** For each right endpoint `r`, the deque stores groups `(value, count)` in order of left endpoints from oldest to newest. For minima the values are strictly increasing; for maxima they are strictly decreasing. `count` is the number of left starts in that group, and `running` is `sum(value * count)` over the deque.
- **Update rule:** When `x = nums[r]` arrives, the new left start `r` has value `x`. For minima, every suffix group with value `>= x` becomes `x`; pop those groups, add their counts to `cnt`, and subtract their old contributions from `running`. For maxima, use value `<= x`. Append `(x, cnt)` and add `x * cnt` to `running`.
- **Length at most k:** Before removal at step `r`, the deque covers left starts `max(0, r-k)` through `r`. If `r >= k`, the oldest start `r-k` is no longer valid; remove it from the front group by subtracting its value once and decrementing the count, popping if it reaches zero. Then `running` is exactly the sum for all valid subarrays ending at `r`, so add it to the pass total.
- **Duplicates:** Popping `>=` for minima and `<=` for maxima merges equal values into the new group. This is safe because the stored value is the actual min/max value, not a unique index; equal values have the same contribution.
- **Complexity:** Each group is appended once and popped from the back at most once; front removals are `O(1)` per right endpoint. Two passes give `O(n)` time and `O(n)` worst-case memory.
- **Overflow:** Python integers are unbounded. The maximum magnitude is about `2 * 1e6 * n(n+1)/2`, around `6.4e15` for `n = 80000`, so 64-bit arithmetic would also be sufficient.
- **Tests:** The file includes brute-force comparison for the two examples, `k=1`, `k=n`, all-equal arrays, negative values, and seeded random small/medium arrays. Tests run only when executed as a script.
