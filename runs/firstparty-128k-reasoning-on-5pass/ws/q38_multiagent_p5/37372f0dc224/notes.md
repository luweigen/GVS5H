- **Chosen method:** Use KMP. Let `R = reverse(S)`. Compute the prefix function for `R`, then scan `S` as text against pattern `R`. The final matcher state `q` is the longest prefix of `R` that is also a suffix of `S`.
- **Why this gives the answer:** A suffix of `S` of length `l` is palindromic iff it equals its reverse. The reverse of that suffix is exactly `R[:l]`. Therefore the longest palindromic suffix length is the longest prefix of `R` that is a suffix of `S`.
- **Construction:** If that length is `l`, append the reverse of the remaining prefix: `S + reverse(S[:n-l])`. This is minimal because any palindrome having `S` as a prefix must leave a palindromic suffix of `S` of length at least `n - appended_length`.
- **Implementation details:** Read input as bytes for speed. A Python list of integers for the prefix function is fine for `n <= 500000`. The scan intentionally does not reset a full match; since pattern and text have the same length, `q == n` can only happen after the last character, so no out-of-bounds access occurs.
- **Pitfalls avoided:** Resetting `q` after a full match would incorrectly reduce `l` for already-palindromic strings. The appended part is the reverse of the unmirrored prefix, not the reverse of the palindromic suffix.
- **Rejected alternatives:** Z-function requires careful position mapping for suffixes ending at the end. Manacher is more complex. Rolling hash is probabilistic. Eertree is overkill. KMP is deterministic, linear, and simple.
- **Complexity:** Time `O(n)`, memory `O(n)`. Output length is at most `2n`, which is safe.
