- **Game model:** Let b_i = A_i - 1. Opening a pile consumes one token and adds b_i extra moves to the pool of already opened piles. The game ends immediately when the last unopened pile is opened, so any remaining extra moves on that final pile are discarded.
- **State abstraction:** For k unopened piles, t available extra moves, and e = number of odd b_i among unopened piles, equivalently the number of even A_i among unopened piles, only parities matter for k >= 4. A pass decrements t by 1. Opening a pile with b parity p changes k to k-1, t to t+p, and e to e-p, so the parity of k + e + t always toggles.
- **Induction for k >= 4:** A position is losing iff k + e + t is even. For k >= 5, both passing and opening toggle this parity, so the claim follows from the k-1 case. The base k = 4 is checked against the exact k = 3 outcomes: k = 3 is losing only when the three b_i are all odd and t is even, or all even and t is odd; mixed parities are always winning. This verifies all e = 0..4 cases for k = 4.
- **Small cases:** k = 1 is always winning by opening the last pile. k = 2 is losing iff t is even, so the initial t = 0 position is losing. k = 3 initial is losing only when all A_i are even, i.e. all b_i are odd; otherwise it is winning.
- **Final rule:** For N = 1, Fennec wins. For N = 2, Snuke wins. For N = 3, Snuke wins iff all three A_i are even. For N >= 4, Fennec wins iff (N + E) is odd, where E is the number of even A_i.
- **Complexity:** O(N) time and O(1) extra memory beyond input parsing. This easily handles N up to 2 x 10^5 and A_i up to 10^9.
- **Test verdict:** Sample 1, N=3 and A=(1,9,2), gives Fennec. Sample 2, N=2 and A=(25,29), gives Snuke. Sample 3, N=6 and A=(1,9,2,25,2,9), gives Snuke. Edge cases: N=1 always Fennec; N=2 always Snuke; N=3 all even gives Snuke while any mixed parity gives Fennec; N=4 with E=0,1,2,3,4 gives Snuke, Fennec, Snuke, Fennec, Snuke. All match the implemented rule.
