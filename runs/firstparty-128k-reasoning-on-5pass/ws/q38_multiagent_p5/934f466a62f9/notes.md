- **Reduction:** A pair price is the maximum of three coordinate sums. This is equivalent to choosing 2K cakes and assigning each chosen cake to X/Y/Z, with each color used an even number of times, maximizing the sum of assigned coordinate values. Pairing cakes inside each color gives a real pairing with price at least that sum, and any real pairing can be converted to such an assignment with equal total by choosing a maximizing coordinate per pair.
- **WQS/Aliens trick:** Let f(k) be the optimum for k pairs. The value function is concave for this complete-graph nonnegative matching / parity-selection structure. Penalize each pair by integer p. For a selected cake assigned to coordinate v, raw adjusted gain is 2*v - p, so a pair contributes 2*(pair_value - p). Binary search the largest integer p whose optimal pair count is at least K. If D is the optimal adjusted value at that p, the answer is (D + 2*p*K)//2.
- **Encoding and scaling:** Use BASE = 1 << 17, larger than max N = 1e5. Encode a DP state as raw_adjusted_value * BASE + selected_count, so max first compares value, then count. Per-cake encoded add is (2*v - p)*BASE + 1. Precompute the p-independent part as (v << 18) + 1 because 2*v*BASE = v << 18. In calc, subtract p << 17 from each precomputed gain.
- **DP:** Eight parity masks for X/Y/Z. Transition is new[m] = max(old[m], old[m^1]+a, old[m^2]+b, old[m^4]+c). The implementation is fully unrolled with manual comparisons to avoid many max() calls. Final mask 0 gives D = d0 >> 17 and pair_count = (d0 & (BASE-1)) >> 1.
- **Binary search bounds:** pmax = max(top1+top2 for each coordinate) is the maximum possible single-pair price. At p = pmax+1 every nonempty feasible selection has negative adjusted value, so count is 0. At p = 0, nonnegative values allow augmenting any feasible selection to the maximum even count without decreasing value, so count is at least K.
- **Shortcuts:** K == 1 is just pmax. If K == N//2, the required count is the maximum feasible even count, so one DP pass with p = 0 gives the exact answer as D//2. If pmax == 0, answer is 0.
- **Performance:** Total N is 1e5. Worst case uses about 31 DP passes over all items. Items are stored as a list of 3-tuples of precomputed encoded base gains to make each pass a single list iteration. Shortcuts remove DP work for K=1 and maximum K.
- **Testing:** Sample 1 and Sample 2 match the expected outputs. A small brute-force random check comparing all pairings for tiny N against the DP/WQS logic was used during development. The final program is stdin/stdout only and does not print self-test results.
