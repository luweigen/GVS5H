- **Core reduction:** For a query segment of length M, K pairs are possible iff the K smallest elements can serve as tops and the K largest as bottoms. In sorted order this is equivalent to A[l+t] <= A[r-K+1+t]/2 for t=0..K-1.
- **g array:** g[i] is the smallest d>=1 with A[i+d] >= 2*A[i]; if no such d exists, use N-i. Because A is sorted, a top at i works for a given K exactly when g[i] <= M-K. Therefore K is feasible iff max(g[l:l+K]) + K <= M.
- **Sentinel safety:** If no double exists, N-i is still larger than any valid distance M-K for a top i in a prefix of length K<=M, since i+M-K <= r <= N-1.
- **Monotonicity and cap:** max(g[l:l+K]) + K is nondecreasing in K. The segment-tree search finds the largest K satisfying it; the disjointness cap K <= M//2 is applied afterwards. If the search returns a larger K, all smaller K are feasible, so capping is safe.
- **Segment tree max_right:** Each node stores the maximum g in its interval and the number of real leaves in it. A custom ACL-style max_right from l carries current max and current length. A node can be skipped if max(current_max, node_max) + current_len + node_len <= M; otherwise descend to the first failing leaf. Padded leaves have length 0 and max 0.
- **Complexity:** g is built in O(N) with a two pointer because 2*A[i] is nondecreasing. Each query is O(log N), total O((N+Q) log N), memory O(N).
- **Implementation details:** Use 0-based indices, compare 2*A[i] with A[j] (no floating point), fast read().split(), preallocated output, and join with newlines. The max_right predicate is mx + len <= M; no explicit half cap inside the tree.
- **Pitfalls checked:** off-by-one in the bottom index (distance M-K), integer half equivalence, K cap for odd/even M, sentinel for missing doubles, and padding in the segment tree.
