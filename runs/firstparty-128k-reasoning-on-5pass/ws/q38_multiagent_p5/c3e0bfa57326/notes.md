- **Reachability:** In a Dyck word, every valid substring is a consecutive block of sibling matched pairs. Mirroring such a block reverses the sibling order and mirrors each sibling subtree, so the unordered rooted forest of matched pairs is invariant. Mirroring a two-sibling block and then mirroring the two resulting siblings individually gives an adjacent swap while preserving their internal embeddings; single-sibling mirrors and induction give all internal embeddings. Thus reachable strings are exactly the plane embeddings of the initial unordered forest.
- **Parsing:** Scan S with a stack. Each `(` creates a node; if the stack is nonempty, append the node to the parent’s children, otherwise append it to roots. Each `)` pops. Children are stored in original left-to-right order. Node indices increase along root-to-leaf paths, so processing indices in reverse is bottom-up.
- **Type canonicalization:** For each node in reverse creation order, sort its children’s type IDs and use the tuple as a dictionary key. A new key receives the next integer ID. This is exact AHU-style canonicalization; tuple equality avoids hash-collision concerns. The leaf type is the empty tuple.
- **Counting DP:** Precompute factorials and inverse factorials up to the number of pairs m. When a new type is created, compute `ways[t] = fact[d] * prod invfact[mult] * prod ways[child]^mult`, where d is the total number of children and mult is the multiplicity of each child type. Child ways are already known because all children are processed before their parent. Existing types are reused without recomputation.
- **Top level:** Treat the roots as children of a virtual root. Sort the root type IDs and apply the same multinomial formula: `fact[r] * prod invfact[mult] * prod ways[type]^mult`. If there are no roots, the answer is 1.
- **Complexity:** Parsing is O(N). Type processing is O(sum d log d + total child-type list length), which is O(N log N) worst-case and easily fine for N <= 5000. Memory is O(N).
- **Edge cases:** Empty forest gives 1. Deep nesting is handled iteratively, so recursion depth is not an issue. Identical subtrees are correctly quotiented by factorial of their multiplicities. The modulus is prime and all factorials used are below it, so inverse factorials exist.
