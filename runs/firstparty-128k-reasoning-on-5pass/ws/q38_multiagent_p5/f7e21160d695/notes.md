- **Core reduction:** f(x, y) is the minimax edge weight on a path, i.e. the smallest threshold t such that x and y are connected using only edges of weight at most t. In Kruskal order, this is exactly the weight when their DSU components first merge.
- **Matching view:** We need a minimum-sum perfect matching between K A-tokens and K B-tokens with cost f. The cost structure is an ultrametric induced by the Kruskal merge hierarchy.
- **Greedy state:** For each DSU component keep charge = (#A in component) - (#B in component). Initially charge[v] is the net count at vertex v. When an edge of weight w merges roots with charges cu and cv, the number of pairs that can be finalized at cost w is dec = (|cu| + |cv| - |cu+cv|) // 2. Add dec*w and store charge cu+cv in the new root.
- **Why dec:** If charges have opposite signs, dec is min(|cu|, |cv|); if same sign, dec is 0. It is also half the drop in potential P = sum |charge| over current components, so the total dec over all unions equals the number of nonzero-cost matched pairs.
- **Optimality proof sketch:** For threshold t, let D(t) = 1/2 * sum_C |charge_C(t)| over components of the subgraph with edges <= t. Any matching must have at least D(t) pairs with cost > t, because a component with surplus c must send at least |c| endpoints outside. Hence total cost is at least the integral of D(t) over t. Kruskal decreases D by dec at weight w, and the integral of this step function equals sum dec*w, so the greedy attains the lower bound.
- **Equal weights:** Processing same-weight edges in any order is safe. The sum of dec for all unions at one weight depends only on the partition before and after that weight, because dec is half the potential drop and the potential telescopes.
- **Implementation details:** Read all integers with map(int, sys.stdin.buffer.read().split()). Store edges as (w, u, v) and sort. Use DSU with iterative path halving and union by size. Use Python int for the answer; the maximum is about K * 1e9 <= 2e14. Duplicates in A or B are handled naturally by net charges. Zero-charge vertices must remain in the DSU because they can be connectors.
- **Pitfalls avoided:** Do not use the additive tree-distance formula (sum edge weight * side balance); that solves sum-of-edges path cost, not maximum-edge path cost. Do not rely on stale charge or size values of non-roots. No recursion is needed.
- **Complexity:** O(M log M + (N + M) alpha(N)) time and O(N + M) memory.
