- **Testing harness:** The program includes the current `Solution`, a brute-force checker, and a `run_tests` entry point. It checks the three provided examples, all digit strings of length 1 through 5, 5000 random digit strings of length 1 through 8 with a fixed seed, and targeted edge cases.
- **Mismatch reporting:** Any mismatch is printed with the string, expected brute-force value, and actual solution value. If no mismatches occur, the program prints a final all-pass message.
- **Brute-force method:** For each start index, it builds the substring value incrementally and tests `value % last_digit == 0` only when the last digit is non-zero. This correctly handles leading zeros.
- **Example verification:** The examples are checked against the stated outputs: `"12936"` should be 11, `"5701283"` should be 18, and `"1010101010"` should be 25.
- **No mismatches expected:** The solution logic was verified case by case. The exhaustive length-5 tests cover all short interactions among the prefix counters, last-two-digit rules, last-three-digit rules, zeros, and leading zeros.
- **Digit case summary:** Digits 1, 2, and 5 make every substring ending there valid. Digits 3 and 6 use prefix digit sums modulo 3. Digit 9 uses prefix digit sums modulo 9. Digit 4 uses the single-digit case plus the last-two-digit rule. Digit 8 uses single-digit, last-two-digit, and last-three-digit rules. Digit 7 uses a normalized modular prefix.
- **Normalized prefix for 7:** Since 10 is invertible modulo 7 with inverse 5, `norm7` maintains `numeric_prefix * 5^length mod 7`. A substring ending at `i` is divisible by 7 exactly when the current normalized prefix equals a previously stored normalized prefix.
- **Counter initialization:** `cnt3[0]`, `cnt9[0]`, and `cnt7[0]` start at 1 to represent the empty prefix before the first character.
- **Update order:** For each character, the prefix values are updated first, then the answer for the current ending digit is added, and only then the frequency counters are incremented. This avoids counting an empty substring.
- **Zeros:** Substrings ending in 0 are ignored, but zero characters still update all prefix counters and the previous-digit variables. This is necessary for later substrings with leading zeros.
- **Complexity:** The solution runs in O(n) time and O(1) extra memory. The test harness is intentionally small; exhaustive length 5 means 111110 strings, which is still fast for a local verification script.
