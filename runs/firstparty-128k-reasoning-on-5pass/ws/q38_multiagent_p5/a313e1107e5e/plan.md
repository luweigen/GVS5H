Process the queries offline in increasing order of their prefix length R. Maintain the standard LIS patience array `tails`, where `tails[k]` is the minimum possible ending value of a strictly increasing subsequence of length k in the current prefix. Because any strictly increasing subsequence whose last value is at most X has all of its values at most X, the answer to a query is exactly the number of entries in `tails` that are <= X. For each new element `A_i`, update `tails` using `bisect_left`, and answer all queries with that R using `bisect_right`. This yields O((N + Q) log N) time and O(N + Q) memory.
