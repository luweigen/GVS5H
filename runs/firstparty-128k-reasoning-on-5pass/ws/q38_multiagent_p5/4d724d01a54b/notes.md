- **Core invariant:** For each value v, let m_v be the number of smaller values initially to its right. Among values <= v, v's initial rank is v - m_v and its final rank is v.
- **Lower bound:** A swap changes v's rank only when v swaps with a smaller value. If v moves right, its rank increases by 1 and the cost is its current position, which is at least its current rank. If v moves left, its rank decreases and only forces extra right moves later. To go from rank v - m_v to rank v, the walk must include right steps starting at every rank v - m_v, ..., v - 1, so the total cost is at least the sum of those ranks.
- **Attainability:** Process values from N down to 1. After larger values are fixed in the suffix, the prefix contains 1..v in their initial relative order. Move v right to position v, swapping only with smaller values. Its position equals its rank at that moment, so the costs are exactly v - m_v through v - 1.
- **Formula:** For each v, the contribution is an arithmetic series with m_v terms: first = v - m_v, last = v - 1, so contribution = m_v * (2*v - m_v - 1) // 2.
- **Computation:** Scan P from right to left with a Fenwick tree over values. For current v, m = prefix_sum(v - 1) counts smaller values already seen, i.e. to the right. Add the contribution, then update v. Complexity is O(N log N), memory O(N).
- **Samples:** 3 2 1 gives m_3 = 2 and m_2 = 1, answer 3 + 1 = 4. 2 4 1 3 5 gives m_4 = 2 and m_2 = 1, answer 5 + 1 = 6. 1 2 gives all m_v = 0, answer 0.
- **Brute-force verification:** A Dijkstra search over permutations with adjacent-swap edge weights i matches the formula for all permutations up to N = 5; N = 6 is also feasible but unnecessary given the proof.
- **Edge cases and size:** Sorted input gives answer 0. Reverse input gives sum_{v=1}^N v(v-1)/2, about 1.33e15 for N = 2e5, safely within Python int and 64-bit range.
- **Pitfalls:** Do not weight initial inversions by fixed positions; costs change dynamically. Use query(v - 1), not query(v), and keep the Fenwick tree 1-indexed. The product in the contribution is always even, so integer division is exact.
