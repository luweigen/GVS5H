- **Core cost:** For a fixed subarray `nums[l..r]`, the cheapest non-decreasing sequence obtainable by increments only is the running maximum sequence. Therefore minimum operations = sum of prefix maxima inside the subarray minus sum of original elements.
- **Record chain:** For fixed `l`, the prefix maximum changes only at strictly greater records. Define `nxt[i]` as the first index `j > i` with `nums[j] > nums[i]`, or `n` if none. The chain `l, nxt[l], nxt[nxt[l]], ...` gives exactly the record positions.
- **Strict greater tie handling:** Equal values do not change the running maximum, so jumps must be to strictly greater elements. The right-to-left monotonic stack pops while `nums[stack[-1]] <= nums[i]`, which correctly skips equal values and finds the next strictly greater index.
- **Contribution of a record:** Record `i` is the maximum on `[i, nxt[i] - 1]`, so its full contribution is `nums[i] * (nxt[i] - i)`. For a query ending at `r`, all records whose next record is `<= r` contribute fully; the final record with next record `> r` contributes `nums[i] * (r + 1 - i)`.
- **Binary lifting definitions:** `up[p][i]` is the index after `2^p` next-greater jumps from `i`. `path_sum[p][i]` is the sum of full contributions for those `2^p` records. Base: `up[0][i] = nxt[i]`, `path_sum[0][i] = nums[i] * (nxt[i] - i)`. Recurrence: with `mid = up[p-1][i]`, `up[p][i] = up[p-1][mid]` and `path_sum[p][i] = path_sum[p-1][i] + path_sum[p-1][mid]`. Sentinel `n` has `up=n` and `path_sum=0`.
- **cost(l, r) query:** Start at `i = l`. For levels from high to low, if `up[p][i] <= r`, add `path_sum[p][i]` and move `i = up[p][i]`. After the loop, add the truncated final record contribution. Subtract the ordinary element sum using prefix sums. This is `O(log n)`.
- **Jump condition subtlety:** Use `up[p][i] <= r`, not `< r + 1` with a jump to `r + 1`. If a block would end exactly at `r + 1`, do not jump it; the final truncated term correctly handles the last record.
- **Two-pointer counting:** For fixed `l`, cost is non-decreasing as `r` increases. When `l` increases, cost for the same `r` cannot increase, so the maximal valid `r` is non-decreasing. Sweep `l`, extend `r` while `cost(l, r + 1) <= k`, and add `r - l + 1`. Single-element subarrays have cost 0, so the loop always terminates safely.
- **Complexity:** Computing next greater is `O(n)`. Building the lifting table is `O(n log n)`. The sliding window performs at most about `2n` cost queries, each `O(log n)`, so total time is `O(n log n)`. Memory is `O(n log n)`.
- **Integer sizes:** Prefix-max sums and element sums can reach about `1e14`, so 64-bit storage is needed for `path_sum`. The final answer can reach about `5e9`, so Python int is used for the answer.
- **Implementation choices:** Use `up` as lists for fast access and `path_sum` as `array('q')` levels to keep memory low. `LOG = max(1, n.bit_length())` is sufficient because queries never need to jump all the way to sentinel `n` when `r < n`.
- **Edge cases covered:** `n = 1`, all equal, all increasing, all decreasing, `k = 0` in tests, large answers, and equal-value tie handling. The query never sets `i = n` because jumps require `up[p][i] <= r < n`.
- **Testing:** The included self-test checks the two examples, deterministic edge cases, and many random small arrays against an `O(n^2)` brute force that maintains running maximum and sums. It uses a fixed seed and raises an assertion on mismatch, with no output on success.
