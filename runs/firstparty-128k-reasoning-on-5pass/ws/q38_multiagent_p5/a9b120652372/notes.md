- **Model:** Pieces keep their left-to-right order. A final state is an order-preserving surjection from the M initial pieces to the K ones of B; the first and last pieces end at b[0] and b[-1], so d1=b[0]-a[0], dM=b[-1]-a[-1] and base=max(abs(d1),abs(dM)) is a lower bound.
- **Necessary conditions:** K<=M and dM<=d1 (final span not larger than initial span). If K==1, gathering all pieces at b[0] always takes base operations.
- **Gap assignment:** Let g[i]=a[i+1]-a[i], h[j]=b[j+1]-b[j]. Choose K-1 increasing A gaps as boundaries between consecutive B positions; h[j] must be <= chosen g[i]. All other A gaps are collapsed to zero. S[i]=g[i]-final gap is the gap decrease; S[i]=0 exactly when the chosen A gap equals the B gap.
- **Parity feasibility:** A zero S gap is a barrier that can never be decreased. Therefore every positive run of S strictly between two zero S gaps must have even total. This is equivalent to all zero S boundaries having the same displacement parity. For an exact match of B gap j to A gap i, that displacement parity is (b[j]-a[i])&1. Hence any feasible assignment has all exact matches with one common parity.
- **Greedy check(p):** Scan B gaps left to right and keep the last chosen A gap. For each h[j], take the first later A gap with g>h or g==h and (b[j]-a[i])&1==p. If none, fail. Earliest valid gap dominates because it leaves a suffix of A gaps for the remaining B gaps. This is O(M+K).
- **Base versus base+1:** In a base-length schedule the tight endpoint(s) force the adjacent end run to have even total. Thus the common exact parity must be P: d1&1 if d1+dM>0, dM&1 if d1+dM<0, and d1&1 if d1+dM==0. If check(P) succeeds, answer is base; otherwise if check(1-P) succeeds, answer is base+1; if neither succeeds, impossible.
- **Implementation details:** Use 0-based positions; parity of differences is unchanged. Read all tokens with split and skip the N token. Extract ones with list comprehensions over bytes (c==49). Run check(P) first to often avoid the second check. Total complexity O(sum N), memory O(max N) for the position lists.
- **Pitfalls:** Do not apply the parity test to g>h choices; negative displacements are fine with &1; span condition is d1<dM, not comparing spans directly; K==1 bypasses gap checks; M=K still works with the same greedy matching.
