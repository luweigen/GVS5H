- **Core idea:** Map each boundary point to a perimeter coordinate p around the square. The problem becomes selecting k points on a circle of circumference 4*side so that all relevant boundary gaps are large enough.
- **Why answer is at most side:** If k selected points have minimum Manhattan distance D, then every clockwise boundary gap between consecutive selected points is an axis-aligned path, so each gap is at least D. The k gaps sum to 4*side, hence k*D <= 4*side. Since k >= 4, D <= side. This justifies binary searching only [0, side].
- **Perimeter equivalence for D <= side:** For two boundary points, Manhattan distance >= D is equivalent to circular perimeter distance >= D when D <= side. On the same or adjacent sides, perimeter distance equals Manhattan distance. On opposite sides, Manhattan distance is at least side, so it is automatically at least D; perimeter distance is also at least side.
- **Feasibility check:** Sort p once. Duplicate it as p2 = p + [x + 4*side for x in p]. For candidate D, compute next[i] as the first index with p2[next[i]] >= p2[i] + D using a two-pointer sweep. From each start i, greedily jump k-1 times. If the final index cur is before i+n and p2[cur] <= p[i] + 4*side - D, the wrap gap is also at least D, so D is feasible.
- **Greedy correctness:** Choosing the earliest possible next point is optimal because it leaves the most remaining perimeter for the remaining selections and cannot make the final wrap gap worse.
- **Implementation details:** Use the given corner assignment order: y == 0, then x == side, then y == side, else x == 0. This gives unique p values in [0, 4*side). A quick reject k*D > 4*side is safe. D == 0 is trivially feasible. The limit i+n prevents selecting the duplicate of the starting point.
- **Complexity:** Sorting is O(n log n). Each feasibility check is O(n + n*k). With n <= 15000, k <= 25, and about 30 binary-search steps, this is comfortably fast in Python.
- **Validation:** The included main runs the three provided examples and 200 random small cases against brute force over all combinations. It raises on mismatch and is silent on success.
- **Superseded plan:** The earlier DP/segment-tree approach is unnecessary under the given k >= 4 constraint.
