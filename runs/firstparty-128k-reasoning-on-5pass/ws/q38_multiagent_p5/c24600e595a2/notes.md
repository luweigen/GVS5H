- **Cost view:** Total cost is the sum over bits of C_i times the number of operation-end states in which that bit is 1. This makes flip order the only coupling between bits.
- **Canonical schedule:** A 0-to-1 flip before a 1-to-0 flip can be swapped with that 1-to-0 flip and strictly lowers cost, so all off-flips precede all on-flips. Extra flips are dominated: mandatory D/U bits need one flip, common-1 bits need at most one off/on cycle, and common-0 bits never flip. In the off phase larger C goes first; in the on phase smaller C goes first by adjacent swaps.
- **Partition:** D is A=1,B=0; U is A=0,B=1; P is A=B=1. Let m=|D|+|U|. For a chosen set S of k common-1 bits, total operations are m+2k. Unselected P bits stay 1 for all operations.
- **Pair-min function:** pm(T) is the sum over unordered pairs of min(weight). For an off set R, the cost while removing R in descending order equals pm(R). For an on set Q, the cost while adding Q in ascending order equals pm(Q)+sum(Q).
- **Formula:** With S selected, sumS=sum(S), F(k)=(m+2k)(Psum-sumS)+sumU+sumS+pm(D∪S)+pm(U∪S). The sumU+sumS term is the extra own-weight contribution of every turned-on bit.
- **Top-k selection:** For fixed k, if x<y and x is selected but y is not, swapping them changes the pm terms by at most (m+2k-2)(y-x), while the sum term changes by -(m+2k-1)(y-x). Thus the larger weight is always at least as good, so the optimal S for each k is the k largest P weights.
- **Incremental update:** Add P weights in descending order. pm(A∪{x})-pm(A)=sum_{y in A} min(x,y). For fixed D or U, query(arr,x)=sum_{y<x} y + x*count_{y>=x}, computed with an ascending sorted array and prefix sums. Previous selected P weights are all >=x, so they contribute x*(k-1) to both pmD and pmU.
- **Initial pair-min:** If arr is sorted ascending, pm(arr)=sum_i arr[i]*(n-1-i). A common off-by-one is using i instead of n-1-i.
- **Edge cases:** Empty D/U/P work; m=0 gives answer 0 because F(k)>0 for k>0; ties are handled by bisect_left putting equal weights in the y>=x part; Python int avoids overflow.
- **Validation:** The code contains a disabled Dijkstra brute force over 2^N states for small random cases. Normal execution reads standard input, partitions, scans k, and prints only the answer.
