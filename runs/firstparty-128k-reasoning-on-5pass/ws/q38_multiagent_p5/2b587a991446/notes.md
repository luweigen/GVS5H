- **Core formula:** Let `d` be the shortest S-T distance and fix one shortest path `P`. If possible, the answer is `2*d + min(e1, e2)`; if both are infinite, print `-1`. The term `2*d` is the unavoidable lower bound from the two net displacements.
- **E1 definition:** Run BFS from `S` with `T` forbidden and from `T` with `S` forbidden. For every vertex `v` not on `P`, if both distances `a` and `b` are finite, then `a + b` is the length of an S-T walk that uses `v` and does not visit the opposite endpoint early. Its excess is `a + b - d`.
- **E1 coverage:** This covers alternative shortest paths (excess `0`), chords, branches or cycles attached to internal vertices of `P`, and any useful structure that connects both sides without passing through `S` or `T` internally.
- **E1 feasibility:** One token can follow the walk of length `a + b`, while the other follows `P`. Their union contains a detour or cycle, so the two walks can be interleaved in opposite directions without extra moves. If `e1 == 0`, two shortest paths exist and `2*d` is attainable.
- **E2 definition:** For each endpoint `e` in `{S, T}`, BFS in the subgraph obtained by deleting all `P`-vertices except `e`. If a reached vertex `u` has at least two BFS children, i.e. neighbors at distance `dist[u] + 1`, then it is a passing gadget at distance `r = dist[u]`. Candidate excess is `4*r + 4`. Take the minimum over both endpoints.
- **Why child count works:** In the rooted endpoint component, a simple path has no vertex with two BFS children and cannot let two tokens pass. Any branch or cycle creates such a vertex; a same-level edge implies an ancestor with two children. Thus the condition is necessary and sufficient for that endpoint component to be usable.
- **Why 4r+4:** To use endpoint `e`, one token must move from `e` to `u` and then to one child, while the other token moves from the other child through `u` to `e` and continues. Then the first token returns through `u` to `e`. Each token pays a detour of `2*r + 2`, total `4*r + 4`.
- **One endpoint is enough:** A single endpoint gadget suffices. Using both endpoints cannot beat the closer one because `4*min(rS, rT) + 4 <= 2*(rS + rT) + 4`.
- **Path dependence:** If `e1 == 0`, the answer is `2*d`, independent of the chosen shortest path. If `e1 > 0`, no other shortest path exists, so `P` is unique and the endpoint/internal classification is well-defined. Banning `P`-vertices in E2 is safe because any useful structure touching an internal `P`-vertex is already counted by E1.
- **Impossibility:** If both `e1` and `e2` are infinite, the relevant graph is path-like: `P` plus only simple tails at endpoints. The tokens cannot pass. This includes all simple paths and trees of maximum degree `2`.
- **Stress verification:** The optional stress mode compares `compute_answer` with exact state BFS on all connected simple graphs up to `N=6`, checking both orientations of `S,T`, and on random connected graphs with `N=8`. All cases matched; the stress run finishes with ok.
- **Complexity:** The solver uses a few BFS passes and adjacency scans: `O(N + M)` time and `O(N + M)` memory. The stress mode is only for local verification and is not run by the judge.
- **Samples:** Sample 1 has `e1 = 1`, answer `2*1 + 1 = 3`. Sample 2 has no E1/E2 gadget, answer `-1`. Sample 3 has `e1 = 0`, answer `2*2 = 4`.
