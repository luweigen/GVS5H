- **Interpretation:** The answer is a set of at most four non-overlapping intervals. For any chosen set, sorting its original indices ascending gives the lexicographically smallest permutation, so DP states store sorted original-index tuples.
- **Compatibility:** Intervals overlap if they share any point, so a previous interval is compatible with the current one only when its right endpoint is strictly less than the current left endpoint.
- **Ordering:** Sort intervals by right endpoint, then left endpoint. For sorted interval `j`, `p[j] = bisect_left(ends, lefts[j])` is the number of intervals ending strictly before `lefts[j]`. Because `lefts[j] <= rights[j]`, all such intervals appear before `j`, so there is no cyclic dependency.
- **DP state:** For exact count `c` and prefix `i` (first `i` sorted intervals), store the maximum total weight and the lexicographically smallest sorted original-index tuple achieving it. Infeasible states use weight `-1` and tuple `None`. Count `0` is weight `0` and empty tuple for every prefix.
- **Transition:** For prefix `i` and interval `j = i - 1`, skip keeps `curr[i - 1]`. Take is possible only if `prev[p[j]]` is feasible; its weight is `prev_w[p[j]] + weights[j]`, and its tuple is `prev_t[p[j]]` with `orig[j]` inserted in sorted order. Choose the better candidate by larger weight, then smaller tuple.
- **Layering:** Run counts `1` through `4`. The previous count layer provides `prev_w` and `prev_t`; the current layer is built left to right. After each layer, `curr[n]` is the best exact count, and the layer becomes `prev` for the next count. Only two layers are kept.
- **Tie safety:** If two max-weight previous tuples `T1` and `T2` have `T1 < T2`, inserting the same new index `x` and sorting preserves `T1' <= T2'`. Therefore keeping only the lexicographically smallest max-weight tuple per prefix is sufficient.
- **Final tie:** Compare counts `0..4` by maximum weight, then by Python tuple lexicographic order. Python tuple order matches the problem: if one tuple is a prefix of another, the shorter one is smaller.
- **Correctness sketch:** An optimal exact-`c` set in prefix `i` either excludes interval `i - 1` or includes it. If it includes it, all other intervals must come from prefix `p[i - 1]`, and the best such combination uses the best exact-`(c - 1)` state there. Induction over prefixes and counts proves optimality.
- **Edge cases:** Touching endpoints are excluded by `bisect_left`. Same right endpoints cannot be combined because `p` is before all of them. Infeasible higher counts remain `-1`. Variable final length is handled by tuple comparison.
- **Complexity:** Sorting is `O(n log n)`. Four passes over `n` with tuple insertion of length at most `4` give practical `O(n)` time after sorting. Memory is `O(n)` for weight/tuple reference arrays plus `O(n)` small tuples per active layer, fine for `n <= 5 * 10^4`.
