- **Orientation:** Keep the smaller dimension as the number of rows `R = min(H, W)`. If `H > W`, transpose the grid: new `(r,c)` is original `(c,r)`. Remap moves: original `L/R/U/D` become new `U/D/L/R` respectively when transposed; otherwise unchanged.
- **DP definitions:** `F[c][r]` is the sum of products of monotone paths from `(0,0)` to `(r,c)`, including `(r,c)`. `G[c][r]` is the sum of products from `(r,c)` to `(R-1,C-1)`, including `(r,c)`. Recurrences are multiplicative and use only the previous column / next column and the row above / below.
- **Answer representation:** For a cut between columns `c` and `c+1`, the total answer is `sum_r F[c][r] * G[c+1][r]`. If `c` is the last column, the answer is `F[c][R-1]`. The maintained `ans` is updated by point-update deltas instead of recomputing the dot product.
- **Delta update:** If cell `(r,c)` changes by `delta`, the answer changes by `delta * p * s`, where `p` is the sum of prefix products to the cell excluding the cell, and `s` is the sum of suffix products from the cell excluding the cell. This avoids division and handles zeros safely.
- **Invariant:** After each query, `F` is correct for all columns up to Takahashi’s current column, and `G` is correct for all columns from the current column onward. This is enough for all future local updates.
- **Vertical update:** The updated column is the current column. Both `F[c]` and `G[c]` are correct before the update. Compute `p` and `s` in O(1), update `ans`, then propagate the change downward in `F[c]` and upward in `G[c]`. Total touched rows is at most `R`.
- **Right move:** Enter column `c = cur+1`. `F[c]` may be stale, so recompute the whole `F[c]` from `F[c-1]` and current `A[c]`. While recomputing, obtain `p` at the updated row. `G[c]` is correct before the update, so after computing `s`, update `G[c]` partially upward from the updated row.
- **Left move:** Enter column `c = cur-1`. `G[c]` may be stale, so recompute the whole `G[c]` from `G[c+1]` and current `A[c]`. While recomputing, obtain `s` at the updated row. `F[c]` is correct before the update, so after computing `p`, update `F[c]` partially downward from the updated row.
- **Boundary virtual values:** For `p`, use `1` at the start cell `(0,0)`, and only the above term in the first column. For `s`, use `1` at the end cell `(R-1,C-1)`, and only the below term in the last column.
- **Partial propagation:** If `F[c][r]` changes by `dF`, then for `i > r`, the change is multiplied by `A[c][i]`. If `G[c][r]` changes by `dG`, then for `i < r`, the change is multiplied by `A[c][i]`. Break early when the propagated delta becomes zero.
- **Complexity:** `HW <= 200000`, so `R <= 447`. Initial DP is O(HW). Each query costs O(R) with a small constant: one full column recompute for horizontal moves plus one partial update, or two partial updates for vertical moves. Memory is O(HW).
- **Implementation details:** Store columns as lists for fast inner-loop access. Precompute small range objects for row loops. Use direction maps by ASCII code. Keep all values modulo `998244353`; sums of two modulo values are reduced by one subtraction.
