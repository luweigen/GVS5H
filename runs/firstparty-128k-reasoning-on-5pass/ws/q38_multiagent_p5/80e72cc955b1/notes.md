- **Core cost:** For a positive integer x, t(x) is the number of times x must be selected until it becomes zero. This is the smallest k such that x < 4^k, equivalently the count of powers 1, 4, 16, ... that are <= x.
- **Operation effect:** One operation can select at most two positive elements and reduces the total remaining required selections by at most 2. Zero elements can be selected as harmless fillers, so the lower bound is ceil(D / 2), where D is the total required selections over the interval.
- **Bottleneck check:** For valid queries with l < r, the maximum t(x) in [l, r] is t(r). If r is not a power of 4, then t(r - 1) = t(r), so D >= 2M and ceil(D / 2) >= M. If r is a power of 4, then t(r - 1) = M - 1, so D >= 2M - 1 and ceil(D / 2) = M. Thus the single-element bottleneck never exceeds ceil(D / 2), and the minimum operations for the query is exactly ceil(D / 2).
- **Prefix formula:** Since t(x) counts powers of 4 not exceeding x, S(n) = sum_{x=1}^n t(x) = sum_{p <= n} (n - p + 1), where p ranges over 1, 4, 16, ... . For n <= 0, S(n) = 0.
- **Powers:** Precompute powers of 4 up to max r. For the given constraint r <= 10^9, there are only 15 such powers, with the last being 268435456 and the next exceeding 10^9.
- **Query evaluation:** For each [l, r], compute D = S(r) - S(l - 1), then add (D + 1) // 2 to the answer. Python integers safely handle the large total.
- **Edge cases:** l = 1 is handled by S(0) = 0. Exact powers of 4 are handled correctly by the inclusive term n - p + 1. No floating-point logarithms are used, avoiding precision issues near powers of 4.
- **Complexity:** Time is O(Q * log_4(max_r)), which is about 3 million small loop iterations for Q = 10^5 and max_r = 10^9. Extra space is O(log_4(max_r)) for the powers list.
- **Pitfalls avoided:** Do not assume one operation can divide the same element twice. Do not use float logs. Do not forget that zeros can be used as fillers. Do not use exclusive range bounds incorrectly. Do not iterate over every integer in large intervals.
