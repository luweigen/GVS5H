- **State:** `G(i,c,k)` is the minimum cost to transform `caption[i:]` when the previous character is `c` and the current run length is `k`, capped at 3. Base at `i=n` is valid only for `k=3` with cost 0.
- **Transitions:** If `k=1` or `k=2`, the next character must be `c` to avoid ending a run of length 1 or 2. If `k=3`, the next character may be `c` (continue) or any `d != c` (start a new run with `k=1`).
- **Choice compression:** Only `k=3` states need a stored decision; `k=1/2` are forced. Store one byte per `(i,c)` for `i=1..n-1`, using 255 for impossible states. This reduces memory from O(n*78) integers to O(n*26) bytes.
- **Switch optimization:** For each position `i`, compute the best and second-best values of `cost(i,d)+G(i+1,d,1)` over `d`, keeping the smallest character for ties. For previous character `c`, use best1 unless `c` is best1’s character, in which case use best2. This gives O(1) best switch per `c`.
- **Tie handling:** Initial first character is chosen by scanning `c` ascending and updating only on strictly smaller total cost. For `k=3`, if same-character and switch costs tie, choose the smaller current character. Top-two tracking keeps the smallest character for best and second-best values.
- **Reconstruction:** Choose the smallest first character achieving the global optimum, then follow stored choices. When `k<3`, the character is forced to be `prev`; when `k=3`, use the stored byte. This greedy reconstruction is valid because each stored choice is the smallest current character preserving optimal suffix cost.
- **Edge cases:** `n<3` is impossible. `n=3,4,5` force one run because a switch would leave fewer than 3 positions for the new run. `n=6` allows the first switch at index 3. For `n>=3`, all-same-character strings are always possible, so DP should never return empty except for `n<3`.
- **Validation:** Fixed examples, n=1/2/3/4/5 edge cases, median-interval tie cases such as `azaz`, `aabb`, `yyzz`, and multi-run tie cases such as `ababab`, `bababa`, `azazaz`. Exhaustive binary strings length 1..8, ternary strings length 3..6, and random full-alphabet strings length 3..8 plus length 9 are checked against brute force over all good strings.
- **Performance:** A deterministic length-50000 tie-heavy input `azaz...` is used. The result is checked for length and the good-caption run property, and the transformation cost is printed.
- **Complexity:** O(n*26) time and O(n*26) bytes for choices plus O(26) DP row memory. For n=50000 this is about 2.6 million inner DP iterations and about 1.3 MB of choice storage.
- **Result:** The previous full-row DP was replaced by this equivalent choice DP. It is faster to reconstruct and uses much less memory while preserving lexicographically smallest minimum-cost behavior.
