- **Core idea:** Each query is a 2D prefix over the implicit matrix |A_i - B_j|. Split both index prefixes into complete blocks of size S and small remainders.
- **Block choice:** Use M = min(N, isqrt(K//2)+1), S = ceil(N/M), and F = N//S complete blocks. The final partial block, if any, is always treated as remainder.
- **Tables:** PA[y][i] stores the sum over the first i A-elements against the first y complete B-blocks. PB[x][j] is symmetric. Both are stored as array('q') rows of length N+1. G[x][y] = PA[y][x*S] gives the complete-block answer.
- **Table build:** For each complete opposite block, update per-element contributions f. Sort the current sequence by value once, then for each sorted block use a two-pointer scan to get p = count(block <= a) and prefix sum. Contribution is a*(2p - s) + total - 2*sum_le. Accumulate f in original index order with itertools.accumulate and store as array('q').
- **Query base:** xb = X//S, yb = Y//S, sa = xb*S, sb = yb*S. Answer starts with G[xb][yb], then adds PA[yb][X]-PA[yb][sa] for A-remainder vs B-full, and PB[xb][Y]-PB[xb][sb] for B-remainder vs A-full.
- **Remainder handling:** Remainders are prefixes of one A-block and one B-block. Group queries by (xb, yb), then cache identical (rA, rB) pairs.
- **Small remainder method:** For a unique pair, if one side has length 1 use a direct loop; otherwise sort the two slices and merge. Merge maintains processed counts/sums: taking u adds u*cntV - sumV, taking v adds v*cntU - sumU. Total sums give O(1) tails, and separated ranges are handled by direct formulas.
- **Large group sweep:** If many unique pairs share the same block pair, sweep one dimension. Maintain acc over the opposite prefix, add rows or columns, and answer needed prefix sums. Choose sweep when estimated cost (maxR+uniqueR)*maxC or (maxC+uniqueC)*maxR is below the per-pair sum and there are at least 16 unique pairs.
- **Complexity:** Precompute is about O(F*N + N log N) per table with F ~ sqrt(K), and O(F*N) 64-bit memory, roughly 110 MB worst-case. Remainder work is bounded by about O(K*S) in the per-query path, and can be reduced by the sweep path.
- **Overflow:** Maximum answer is N^2 * 2e8 = 2e18, safely inside signed 64-bit, so array('q') is safe.
- **Edge cases:** Block-boundary prefixes have zero remainder. If N is not divisible by S, F = floor(N/S) and the last partial block is handled by remainder terms. Zero remainders are skipped.
- **Implementation notes:** Read all input at once, delete the raw data list, and delete PA/PB/G after base answers are computed to free memory before remainder processing.
