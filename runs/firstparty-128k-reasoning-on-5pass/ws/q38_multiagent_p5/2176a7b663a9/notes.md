- **Core reduction:** An edge exists exactly when one interval is strictly to the left of the other. Since all vertex weights are positive, an optimal path can be assumed simple, and any path can be shortened to at most three edges for overlapping query endpoints.
- **Disjoint endpoints:** If the queried intervals are disjoint, the direct edge exists and is optimal because any longer path adds positive-weight vertices.
- **Two-edge case:** If the queried intervals overlap, a two-edge path exists exactly when some vertex is completely left of both intervals or completely right of both. This is answered by `min(prefR[min(L_s, L_t) - 1], suffL[max(R_s, R_t) + 1])`.
- **Containment case:** If one queried interval contains the other, any longer path forces either the first or last internal vertex to be disjoint from both endpoints, so a two-edge path exists and dominates all longer paths.
- **Crossing case:** For `L_s < L_t <= R_s < R_t` or the symmetric order, a shortest path without a two-edge shortcut has first internal vertex with `L` in `[R_s + 1, R_t]` and last internal vertex with `R` in `[L_s, L_t - 1]`. Every such pair is mutually disjoint and forms a valid three-edge path.
- **Independent minima:** The two crossing range minima can be taken independently because no interval can satisfy both separated coordinate conditions, so the chosen intermediates are automatically distinct and valid.
- **Data structures:** Use two iterative segment trees over coordinates `1..2N`, one keyed by `L` and one keyed by `R`, storing minimum vertex weight per coordinate. Also use prefix minima over `R` and suffix minima over `L` for the outside-union two-edge check.
- **Strict inequalities:** Intervals are closed, so touching at an endpoint is not disjoint. Use strict comparisons for edges, and convert outside conditions to `R <= x - 1` and `L >= x + 1`.
- **Query mapping:** Segment tree queries are implemented as 0-indexed half-open ranges. Inclusive 1-indexed `[ql, qr]` becomes `query(ql - 1, qr)`. For crossing, this gives `segL.query(R_s, R_t)` and `segR.query(L_s - 1, L_t - 1)` in the first orientation.
- **Complexity:** Preprocessing is `O(N log N)` because `M = 2N`. Each query uses at most two segment-tree range minima, so total query time is `O(Q log N)`. Memory is `O(N)`.
