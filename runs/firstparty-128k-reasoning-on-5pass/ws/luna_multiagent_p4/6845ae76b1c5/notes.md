- **Method:** Partition each queried prefix of `A` into a complete prefix ending at a block boundary and one partial suffix. Complete-prefix contributions against every prefix of `B` are computed by sorting the complete `A` values and scanning sorted `B`. The partial suffix is evaluated element by element using persistent value-frequency trees for prefixes of `B`.
- **Block size:** `block = max(1, floor(N / sqrt(4K)))`. This is smaller than the usual `N/sqrt(K)` choice, reducing the number of persistent-tree queries. The preprocessing cost increases by only a constant factor.
- **Persistent tree:** `roots[y]` stores counts and sums of values in `B[:y]`. For a value `v`, querying the count and sum of values `<= v` gives the absolute-difference sum in logarithmic time. `bisect_right` ensures values equal to `v` belong to the lower partition.
- **Complexity:** With block length `L`, preprocessing is `O(N^2/L)` plus persistent-tree construction `O(N log N)`, and query work is `O(KL log N)`. With the selected `L ≈ N/(2sqrt(K))`, this is approximately `O(N sqrt(K) log N)` time in the dominant terms.
- **Memory:** The persistent segment tree uses `O(N log N)` nodes. Four Python lists store node links, counts, and sums; this is the main memory cost. Other arrays use `O(N + K)` memory.
- **Edge cases:** Boundary zero, exact block endpoints, `N=1`, duplicate values, equal values, and full prefixes are supported. Python integers safely handle the maximum answer.
