- **Greedy structure:** For any interval, if \(k\) pairs are possible, they can also be formed by using the \(k\) smallest mochi as bottoms and the \(k\) largest mochi as tops, pairing them in order. Replacing a bottom by a smaller mochi and a top by a larger mochi cannot break compatibility.
- **Compatibility preprocessing:** For each index \(i\), compute \(p_i\), the first global index whose size is at least \(2A_i\), using `bisect_left`. A bottom at \(i\) can pair with any top at index at least \(p_i\). Zero-based indices are used.
- **Feasibility criterion:** For a query interval \([l,r]\) of length \(m\), using the first \(k\) elements as bottoms and the last \(k\) as tops requires \(p_i \le r-k+1+(i-l)\) for every \(i\in[l,l+k)\). Equivalently, \(\max(p_i-i)\le m-k\).
- **Monotonicity:** As \(k\) increases, the maximum over the first \(k\) values never decreases while \(m-k\) decreases, so feasibility is monotone. Binary search finds the largest feasible \(k\).
- **Range maximum queries:** A sparse table over \(p_i-i\) answers each required maximum in \(O(1)\). Preprocessing costs \(O(N\log N)\), and each query costs \(O(\log N)\) for binary search.
- **Edge cases:** Duplicate sizes are handled by `bisect_left`, enforcing the non-strict condition \(A_j\ge 2A_i\). Since all sizes are positive, a mochi cannot be both bottom and top in a valid pair. The answer is bounded by \(\lfloor m/2\rfloor\).
