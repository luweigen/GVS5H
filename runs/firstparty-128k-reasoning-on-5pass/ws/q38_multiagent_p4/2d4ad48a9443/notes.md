- **Core reduction:** For a subarray, the minimum number of increments is the sum of its prefix maxima minus the sum of its elements. The pointwise minimal non-decreasing final array is obtained by setting each position to the running maximum.
- **Monotonicity:** For fixed left, extending right adds max(previous maximum, new value) - new value, which is nonnegative, so cost is nondecreasing in right. For fixed right, moving left right cannot increase any running maximum and removes the old first element, so cost is nonincreasing in left. Therefore valid starts for each end form a suffix and a left pointer only moves forward.
- **Record chain:** The running maximum changes only at next strictly greater elements. Starting at l, the record indices are l, ng[l], ng[ng[l]], ... . A record at p contributes nums[p] for positions p through min(ng[p], r+1)-1. Equal values are not new records, so ng is strict.
- **Next greater:** Compute ng right-to-left with a monotone stack, popping while nums[stack[-1]] <= nums[i]; sentinel n means no greater element.
- **Binary lifting:** up[t][i] is the 2^t-th next record after i. sum_w[t][i] is the sum of full contributions of those 2^t records, where a full contribution of p is nums[p] * (ng[p] - p) when ng[p] < n. Build level t from t-1 by composing up and adding sums; sentinel n maps to itself with zero sum.
- **Cost oracle:** To compute cost(l,r), start cur=l and total=0. For levels high to low, if up[t][cur] <= r, add sum_w[t][cur] and set cur=up[t][cur]. At the end cur is the last record <=r; add the clipped contribution nums[cur]*(r+1-cur). Subtract prefix[r+1]-prefix[l]. This is O(log n).
- **Two-pointer sweep:** For each right, advance left while cost(left,right)>k, then add right-left+1. Total cost calls are O(n), giving O(n log n) time.
- **Memory:** Use array('i') for up and array('q') for sum_w and prefix. 64-bit is safe because the largest running-maximum sum is at most 1e5 * 1e9 = 1e14.
- **Implementation details:** 0-indexed indices with sentinel n; prefix is 1-indexed; levels are stored as arrays and iterated high to low via a prebuilt tuple of (up, sum) pairs.
- **Edge cases:** Single elements have cost 0. All equal arrays have one record. All increasing arrays jump through every index. All decreasing arrays use only the first record. k=0 works. The answer can exceed 32-bit.
- **Verification:** The included main block runs the two examples, deterministic edge cases, larger increasing/decreasing sanity checks, and an O(n^2) brute checker on small and moderate random arrays. The brute force accumulates running maximum and operations for each left and breaks when operations exceed k.
