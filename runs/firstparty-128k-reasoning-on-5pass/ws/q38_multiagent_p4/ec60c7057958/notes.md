- **Parity-only counting:** After a valid prefix, the parity of every remaining slot is forced. If unused odd/even counts match the forced slot counts, completions are `rem_odd! * rem_even!`; otherwise 0.
- **count_suffix helper:** For `m` remaining slots and `next_parity`, required odd slots are `(m+1)//2` if next is odd else `m//2`; required even slots are the complement. It returns the factorial product when counts match, 1 when `m==0`, else 0.
- **Capping:** `CAP = 10**15 + 1` is strictly above max allowed `k`. Factorials, products, and totals are capped at `CAP`. For `k <= 10**15`, capped comparisons are safe: a capped block is always large enough to contain the requested offset.
- **Greedy unranking:** At each position, scan unused values in increasing order. Enforce opposite parity to the previous value after position 0. For each feasible candidate, compute its completion block; subtract if `k` is larger, otherwise fix the candidate. This preserves lexicographic order because all completions of a smaller next value precede all completions of a larger next value.
- **First-position handling:** No previous parity constraint. The suffix count after the first candidate enforces the rest. For odd `n`, even first values naturally have zero completions; for even `n`, both parities are feasible. A precheck sums first-position blocks and returns `[]` if `k` exceeds the capped total.
- **Adjacency pitfall:** `count_suffix` only validates the suffix after the candidate, so the candidate itself must be explicitly checked against the previous parity. Without this, same-parity candidates can be incorrectly counted.
- **State and complexity:** Maintain `used`, `used_odd`, `used_even`. Total odds `(n+1)//2`, evens `n//2`. Each position scans up to `n` values, so time `O(n^2)`, space `O(n)`, easily within `n=100`.
- **Edge cases:** `n=1` gives `[1]` for `k=1` and `[]` for `k>1`; `n=2` has `[1,2]` and `[2,1]`; added guard returns `[]` for `k<1`; if no candidate is selected, return `[]` as a safeguard.
- **Validation performed:** The program asserts the three examples. It brute-forces all permutations for `n=1..8`, filters alternating ones in lexicographic order, and compares `permute(n,k)` for every valid `k` plus one out-of-range `k`.
- **Rank checker:** `rank_alternating` recomputes the exact 1-based lexicographic rank of a valid alternating permutation by summing exact completion counts for smaller unused candidates at each position. It is cross-validated against brute force for `n=1..8`.
- **Boundary validation:** For `n=100, k=1`, result is `[1..100]` and exact rank is 1. For `n=100, k=10**15`, result is a valid alternating permutation and exact rank is exactly `10**15`. Also checked `k=10**15-1` and `n=99, k=10**15`.
