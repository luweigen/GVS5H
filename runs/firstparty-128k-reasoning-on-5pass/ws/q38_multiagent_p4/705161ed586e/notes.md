- **Model:** A good caption is a sequence of maximal runs, each length at least 3. The only state needed while scanning left to right is the current run character and its capped length: 1, 2, or 3 meaning at least 3.
- **Cost:** Changing a character to a target letter costs absolute alphabet distance; precompute a 26 by 26 distance table.
- **Impossibility:** If n < 3 no run can reach length 3, return empty. For n >= 3 all 'a' is always reachable, so a solution exists.
- **DP definitions:** dp1[i][c], dp2[i][c], dp3[i][c] are minimum costs to fill positions i..n-1 given an open previous run of character c with capped length 1, 2, or at least 3. Base: dp3[n][c]=0, dp1[n][c]=dp2[n][c]=INF.
- **Recurrences:** dp1[i][c]=cost(i,c)+dp2[i+1][c]; dp2[i][c]=cost(i,c)+dp3[i+1][c]; dp3[i][c]=min(cost(i,c)+dp3[i+1][c], min_{x != c} cost(i,x)+dp1[i+1][x]).
- **Switch optimization:** For each i, compute A[x]=cost(i,x)+dp1[i+1][x]. Track smallest value min1, second smallest min2, count of min1, and one argmin. Then min over x != c is min1 unless c is the unique argmin, in which case it is min2. This keeps each position O(26).
- **Storage:** Use three flat array('i') tables of length (n+1)*26. INF=1e9 is safe because maximum real cost is 25*5e4=1.25e6; cap additions involving INF back to INF so values stay in 32-bit range.
- **Reconstruction:** total is min_x cost(0,x)+dp1[1][x]. Scan x from 'a' to 'z' and keep the first minimum to choose the lexicographically smallest first character. Then move forward with remaining optimal cost rem. For k=1 or k=2 the character is forced. For k=3 scan letters 'a'..'z' and take the first y with cost(i,y)+next == rem, where next is dp3[i+1][y] if y equals the current run character, otherwise dp1[i+1][y].
- **Lexicographic proof:** The DP values define a DAG of optimal-cost transitions. Choosing the smallest current character that preserves the optimal remaining cost, then repeating, yields the lexicographically smallest optimal string because future possibilities depend only on the current state.
- **Edge cases:** n=3,4,5 force one run; n=6 is the first length allowing 3+3; the last one or two positions cannot start a new run because dp1/dp2 at n are INF. Unreachable states, for example k=3 before position 3, may have finite values but are not used by any path from the initial state.
- **Validation:** Examples pass. Small brute-force enumeration of all good strings for n <= 8, plus edge cases n=1..7, all same, all opposite, and large all-same strings, confirms cost and lexicographic tie handling.
- **Pitfalls:** Do not forget dp3[n][c]=0; do not allow a switch to the same character as a new run; cap INF additions; use compact arrays to avoid memory blowup; break lexicographic ties by greedy equality with stored DP values, not by cost alone.
