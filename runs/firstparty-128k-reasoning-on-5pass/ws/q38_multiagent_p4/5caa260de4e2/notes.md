- **Reduction:** For cuts `0 = p0 < p1 < ... < pm = n`, segment `t` contributes `(P[p_t] + k*t) * (Q[p_t] - Q[p_{t-1}])`. The `k*t` part can be separated: `k * sum_t t * (Q[p_t] - Q[p_{t-1}]) = k * Q[n] + k * sum_{s=1}^{m-1} (Q[n] - Q[p_s])`. Thus each internal cut `p_s` adds a fixed penalty `k * (total_cost - Q[p_s])`, independent of later cuts.
- **DP state:** `dp[i]` is the minimum, over partitions of prefix `0..i-1`, of the non-`k` segment contributions plus penalties for all internal cuts strictly before `i`. `dp[0] = 0`. The endpoint `i` itself is not penalized yet; if it later becomes an internal cut, its penalty is added in the next transition.
- **Transition:** For each `i`, choose previous cut `p < i`. The last segment contributes `P[i] * (Q[i] - Q[p])`. If `p > 0`, `p` is an internal cut in the final partition, so add `k * (Q[n] - Q[p])`. Therefore `dp[i] = min_{p<i}(dp[p] + P[i]*(Q[i]-Q[p]) + (k*(Q[n]-Q[p]) if p>0 else 0))`. The answer is `dp[n] + k*Q[n]`, adding the base `k * total_cost` present in every partition.
- **Implementation:** Build prefix sums `P` and `Q` of length `n+1`. Use a simple `O(n^2)` scan. Initialize the best value for `p = 0` as `P[i] * Q[i]`, then scan `p = 1..i-1`. Python integers handle the large values safely.
- **Validation:** Example 1 returns `110`, example 2 returns `985`, and the `n=1` case `nums=[5], cost=[2], k=3` returns `(5+3)*2 = 16`. The included runtime checks verify these.
- **Pitfalls:** Do not use the segment sum of `nums`; use the global prefix `P[i]`. Do not penalize `p = 0` or the final endpoint `n`. Do not forget the final `+ k * Q[n]`. Do not use the prefix total `Q[i]` for the cut penalty; the penalty must use the full array total `Q[n]` because a cut shifts all later cost, not just the current prefix.
- **Complexity:** `O(n^2)` time and `O(n)` extra space. With `n <= 1000`, this is about half a million transitions, easily fast enough.
- **Alternative approaches:** A two-dimensional DP over number of subarrays is also possible but requires convex hull or Monge optimization. The cut-penalty telescoping removes the segment-count dimension and is simpler and less error-prone.
