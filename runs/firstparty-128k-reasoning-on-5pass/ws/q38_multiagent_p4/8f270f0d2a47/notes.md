- **Prefix count:** The answer is `F(r) - F(l - 1)`, where `F(n)` counts beautiful positive integers from `1` to `n`. `F(n)` returns `0` for `n <= 0`.
- **Zero digit shortcut:** Any positive number containing a real zero has digit product `0`, and `0` is divisible by its positive digit sum. Therefore, once a zero is chosen after the number has started, all valid suffixes are beautiful and can be counted immediately.
- **Suffix counting after zero:** If the DP is still tight and the bound digit is `0`, the number of valid suffixes is `suffix_value + 1`. If the prefix has already become smaller than the bound, the number of suffixes is `10^(remaining positions)`.
- **Leading zeros:** The state uses `s = 0` to mean "not started yet". Leading zeros do not affect the digit sum or product and do not trigger the zero shortcut. At the terminal position, `s = 0` represents the number `0` and is not counted.
- **Zero-free numbers:** Under the constraints, a zero-free number has at most 9 digits, so its digit sum is at most `81`. Its digit product can only contain prime factors `2, 3, 5, 7`.
- **Capped exponents:** Track the exponents of `2, 3, 5, 7` in the digit product, capped at `(6, 4, 2, 2)`. These caps are safe because the maximum required exponents for any sum `<= 81` are `v2(64)=6`, `v3(81)=4`, `v5(25)=2`, and `v7(49)=2`.
- **Terminal classification:** A zero-free number is beautiful exactly when the prime factorization of its digit sum is covered by the tracked product exponents. If the sum has any prime factor other than `2, 3, 5, 7`, it is impossible.
- **State encoding:** The DP state is `(pos, tight, s, code)`, where `code` encodes the four capped exponents in mixed radix `(7, 5, 3, 3)`, giving `315` possible codes. This keeps the memoization key small.
- **Precomputation:** `next_code[code][d]` gives the updated capped exponent code after appending digit `d` for `d = 1..9`. `good[s][code]` is a precomputed terminal table for sums `1..81`.
- **Transitions:** If `s == 0`, choose a leading zero or start the number with a digit `1..limit`. If `s > 0`, choose a real zero and use the shortcut, or choose a digit `1..limit` and update `s` and `code`. Tightness is preserved only when the chosen digit equals the current bound digit.
- **Verification:** Examples pass: `l=10, r=20` gives `2`; `l=1, r=15` gives `10`. Small checks: `F(9)=9`, `F(10)=10`, `F(20)=11`, `F(22)=12`, `F(30)=13`. The two-digit zero-free beautiful numbers are `22, 36, 44, 63, 66, 88`, so `F(99)=24` and `F(100)=25`.
- **Complexity:** The worst-case state bound is small, roughly `10 * 2 * 82 * 315`, with at most `10` transitions per state. The actual reachable state count is much smaller, so the solution easily handles `n < 10^9`.
