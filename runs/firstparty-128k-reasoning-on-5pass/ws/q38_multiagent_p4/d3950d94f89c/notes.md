- **Sample run:** The included main block prints exactly two lines: `[6, 2]` then `[0, 1]`.
- **Confirmation:** Example 1 returns `[6, 2]`, matching the expected output. Example 2 returns `[0, 1]`, matching the expected output.
- **Core invariant:** For the current root-to-node path, `start[node]` is the smallest depth from which a downward path ending at `node` has all unique values. It equals `max(second_last_depth[value] + 1)` over values on the path, or `0` if no value has a second occurrence.
- **Recurrence:** When entering node `v` with value `x`, only `x` can change the second-last occurrence state. The previous deepest occurrence `prev = last_depth[x]` becomes the new second-last occurrence for `x`, so `start[v] = max(start[parent], prev + 1)`. This is O(1) and rollbackable.
- **Evaluation:** Edge lengths are positive, so the longest special path ending at `v` starts at the highest valid ancestor `path[start[v]]`. Its length is `dist[v] - dist[path[start[v]]]`, and its node count is `depth[v] - start[v] + 1`. Update the global best by length, then by smaller node count on ties.
- **Iterative traversal:** Use enter/exit stack events. On enter, append the node to `path`, record `last_depth[x]`, push an exit event with the previous `last_depth[x]`, then push child enter events. On exit, restore `last_depth[x]` and pop `path`. This keeps `path` indexed by depth and avoids recursion limits.
- **Data structures:** Adjacency list, `last_depth` sized `max(nums) + 1` initialized to `-1`, and arrays `depth`, `dist`, `start`. Time is O(n), memory is O(n + max(nums)).
- **Edge cases:** Single-node paths are covered by initializing the answer to `[0, 1]` and by nodes where `start[node] == depth[node]`. Duplicate values on an edge force the path to start at the child, yielding length `0` and node count `1`. The root uses `parent_start = 0`. The code also guards `n == 0`.
- **Why the samples pass:** In Example 1, the best length `6` is found for endpoint `5` with start depth `2`, giving path `2 -> 5` with `2` nodes, and for endpoint `4` with start depth `0`, giving path `0 -> 1 -> 4` with `3` nodes. The minimum node count among length-`6` paths is therefore `2`. In Example 2, both nodes have value `2`, so every multi-node path is invalid and the answer remains `[0, 1]`.
- **Superseded approaches:** A max-heap over second-last depths is unnecessary because the valid start depth is monotone along each root-to-leaf path and can be maintained with one rollbackable integer.
