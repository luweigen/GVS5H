- **Reformulation:** The required matrix is equivalent to deleting N-1 edges so that every remaining connected component is a path on exactly K vertices. Total vertices are M=NK.
- **Forced edge status:** For any edge, removing it splits the tree into two sides. If the edge is cut, both sides are unions of whole K-vertex paths, so both side sizes are multiples of K. If the edge is kept, it lies inside one K-vertex path and splits that path into two nonempty parts of sizes a and K-a, so both side sizes are nonzero modulo K. Hence an edge is kept in every valid decomposition iff its side size is not divisible by K. Since M is a multiple of K, checking the rooted subtree side is enough.
- **Algorithm:** Read all tokens, build 1-indexed adjacency. Root at 1 with an iterative parent-before-child order. Accumulate subtree sizes bottom-up. For each non-root v, mark edge (v,parent[v]) kept iff sz[v] % K != 0, and count kept degrees. If any kept degree exceeds 2, answer No. Then traverse kept-edge components using the original adjacency and kept flags; each component must have size exactly K.
- **Sufficiency:** The kept-edge set is uniquely forced. It is a subgraph of a tree, so it is acyclic. Maximum kept degree at most 2 makes every connected component a path or isolated vertex. Requiring component size K makes each component a valid K-vertex path, and the components partition all M vertices into N paths.
- **K=1:** All subtree sizes are 0 modulo 1, so no edge is kept; every component is a single vertex of size 1, so the same checks return Yes.
- **Complexity:** O(M) time and O(M) memory, with M=NK<=2e5. Iterative rooting and component traversal avoid recursion depth issues.
- **Implementation details:** Bulk-read all input tokens for speed and whitespace robustness. Use bytearray for kept and seen flags. Store kept status at the child endpoint. Do not build a separate kept adjacency; during traversal, a child edge is kept iff kept[child] is set, and a parent edge is kept iff kept[v] is set. Delete data, sz, order, and kept_deg when no longer needed.
- **Safety checks:** If the rooted order does not cover all M vertices, print No (should not happen for a valid tree). The degree check is on kept degree, not original degree. Component size must be exactly K, not merely a multiple of K.
- **Edge cases:** N=1 reduces to checking whether the whole tree is a path. The root may be internal to a kept path, so root kept degree 2 is allowed. Isolated vertices are only valid when K=1.
- **Superseded approach:** The bottom-up closed/open DP is not needed; the edge-modulo characterization gives a direct check.
- **Sample behavior:** Sample 1 keeps three disjoint edges of size 2. Sample 2 creates a kept component of size 6 or a kept degree 3, so No.
