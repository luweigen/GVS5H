- **Feasibility target:** For X > 0, vertex i needs k_i = ceil(X / points[i]) = 1 + d_i landings, where d_i = (X - 1) // points[i]. X = 0 is trivial. If m < n, answer is 0; if m == n, answer is min(points) because the only all-visiting walk of length n is the straight walk.
- **Fixed final position f:** To visit every vertex and end at f, edge i must be crossed at least 1 if i < f, and at least 2 if i >= f and f < n - 1. The minimal crossing skeleton has base = 2n - 1 - f moves. It visits vertices f..n-2 twice and all other vertices once; for f = n - 1, every vertex is visited once.
- **Extra visits as edge bounces:** Additional crossings of edge i come in pairs y_i, adding 2 moves and one visit to both endpoints. Deficits after the skeleton are e_i = d_i for i < f, e_i = max(0, d_i - 1) for f <= i < n - 1, and e_{n-1} = d_{n-1}. We need y_{i-1} + y_i >= e_i.
- **Path covering dual:** Minimizing sum y_i over path edges with those constraints is dual to maximum-weight independent set on the path with vertex weights e_i. The path incidence matrix is integral, so the MWIS value is the exact minimum bounce count.
- **All final positions in one pass:** Precompute suffix DP for low weights: suf0[i] is best on [i..n-1] with i not selected, suf1[i] best with i selected. Sweep f left to right maintaining prefix DP for high weights d_i on [0..f-1]: p0/p1 for last vertex not/selected. Combine as max(p0 + max(suf0[f], suf1[f]), p1 + suf0[f]). f = 0 uses the suffix only.
- **Feasibility check:** For each f, minimal moves = base + 2 * S(f). Feasible if any value is <= m. Binary search X in [min(points), m * min(points)]; the lower bound is feasible when m >= n, and the upper bound follows because the minimum-point vertex can be visited at most m times.
- **No capping needed:** The total-landing bound sum k_i = n + sum d_i <= m is checked before DP. It implies sum d_i <= m - n, and every MWIS weight is <= d_i, so all DP values are <= m (<= 1e9). This removes the previous m // 2 + 1 capping and its edge-case subtleties; exact integer DP is safe and faster.
- **Validation:** Examples return 4 and 2. Brute-force DFS over all valid walks for n = 2..5 and m = 0..15 with small/random point arrays matches the DP. Edge cases checked: m < n -> 0, m = n -> min(points), n = 2 explicit visit-count formula, all equal points, middle-point advantage for m = n + 1, and large m cases such as n = 2 equal points giving floor(m / 2). No mismatch found.
- **Complexity:** O(n log(m * min(points))) time and O(n) memory. The total-landing check often prunes high mid values early.
