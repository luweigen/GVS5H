- **Core reduction:** Let p_j be the 0-indexed positions of the ones, for j = 0..K-1. If the final contiguous block of K ones starts at L, the j-th one must move to L+j. The adjacent-swap cost is sum |p_j - (L+j)| = sum |(p_j - j) - L|.
- **Median solution:** Define q_j = p_j - j. Since p_{j+1} >= p_j + 1, the sequence q is nondecreasing. The sum of absolute deviations is minimized at any median, so choose m = q[K//2] and output sum(abs(x - m) for x in q).
- **Validity of L:** For each j, p_j >= j and p_j <= N-K+j, so q_j lies in [0, N-K]. Therefore the median is always a feasible block start, and no clamping is needed.
- **Order preservation:** Adjacent swaps do not require one 1 to pass through another. Labeling the ones left-to-right and matching the j-th original one to the j-th target slot is optimal, which justifies the sorted absolute-distance formulation.
- **Samples verified:** 0101001 gives q = [1, 2, 4], median 2, answer 3. 100 gives q = [0], answer 0. 0101001001 gives q = [1, 2, 4, 6], median 4, answer 7.
- **Edge cases:** K = 1 gives one q value and answer 0. All ones gives q all zeros and answer 0. A single one among zeros gives answer 0. Alternating strings work, for example 10101 gives q = [0, 1, 2], median 1, answer 2. For even K, any median in the middle interval is optimal; using the upper median q[K//2] is safe.
- **Complexity:** O(N) time and O(K) memory, where K <= N <= 5e5. Python integers avoid overflow, and the answer can exceed 32-bit range.
- **Pitfalls:** Mixing 0-indexed and 1-indexed positions is the main off-by-one risk. If using 1-indexed positions, the adjusted value would be p - (j+1). Do not count zeros inside a candidate window directly; the cost is a one-dimensional transportation/displacement cost.
- **Cross-check formula:** The same answer can be computed from gaps of zeros between consecutive ones. For the gap g_i after the i-th one, using 0-indexed i, add g_i * min(i+1, K-i-1). This matches the median solution on the samples and small cases.
