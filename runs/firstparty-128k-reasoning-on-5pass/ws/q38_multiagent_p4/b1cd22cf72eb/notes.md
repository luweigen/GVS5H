- **Cost reduction:** Since only reductions are allowed, the cost for any final valid state is the initial total length minus the final total length. If the common sum is H, the final total length is N*H, so minimizing cost is equivalent to maximizing feasible H.
- **Fixed H constraints:** For a chosen H, final upper tooth i must satisfy 0 <= a_i <= U_i and 0 <= H - a_i <= D_i, i.e. max(0, H - D_i) <= a_i <= min(U_i, H). Adjacent upper teeth must differ by at most X.
- **Envelope idea:** Ignoring lower-tooth lower bounds, the maximum possible upper value at position i under the U_i caps and X-Lipschitz adjacency is E_i = min_j (U_j + X * |i - j|). This is computed by a forward pass left[i] = min(U_i, left[i-1] + X) and a backward pass right = min(U_i, right + X), then E_i = min(left[i], right).
- **Upper bound on H:** In any feasible solution, a_i <= U_j + X * |i - j| for every j, so a_i <= E_i. Also H = a_i + b_i <= a_i + D_i <= E_i + D_i. Therefore H <= min_i(E_i + D_i).
- **Achievability:** Let H* = min_i(E_i + D_i). Choose a_i = min(E_i, H*). Then a_i <= U_i and a_i <= H*. Since H* <= E_i + D_i, we also have a_i >= H* - D_i, so b_i = H* - a_i satisfies 0 <= b_i <= D_i. The function E is X-Lipschitz, and taking min with a constant preserves the X-Lipschitz property, so adjacent differences are at most X. Thus H* is feasible and optimal.
- **Implementation:** Store U and D, compute total, compute left array, then scan backward maintaining right and the minimum candidate H. Use Python integers; values fit easily, but total can exceed 32-bit range.
- **Complexity:** O(N) time and O(N) memory, which is safe for N up to 2e5.
- **Edge cases:** Final tooth lengths may become zero. H is always nonnegative in valid states. Large X makes the envelope close to the original U values, while small X propagates nearby small U values strongly.
- **Sanity check:** Tracing the four samples with this algorithm gives 15, 0, 5999999994, and 9460 respectively.
