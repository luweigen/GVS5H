- **Model:** Each element x needs t(x) selections, where t(x) is the number of powers 1, 4, 16, ... not exceeding x, i.e. its base-4 digit length. One selection replaces x by floor(x / 4), reducing its remaining required selections by exactly 1.
- **Scheduling bound:** For a query, the elements form independent chains of lengths t(l), t(l+1), ..., t(r). One operation can take at most one selection from two chains. Therefore T operations are possible iff T is at least the longest chain M and 2T is at least the total work S. These conditions are sufficient by a bipartite b-matching/Hall argument: each chain needs t_i distinct operation slots, each slot has capacity 2; for any subset of k chains, demand is at most M <= T when k = 1 and at most S <= 2T when k >= 2.
- **Zero filler:** An operation must select two array elements. If a slot has only one nonzero task, use a zero as the second element. This is always feasible because l < r, so the array has at least two elements. If S is odd and T = ceil(S/2), the single one-task slot can be placed last, and at least one other chain finishes before it. If T = M > ceil(S/2), keep one maximum chain in every slot and schedule another chain early so a zero exists for later one-task slots.
- **Range aggregation:** S = sum_{x=l}^r t(x) = sum over powers p = 1, 4, 16, ... with p <= r of the count of x in [l, r] with x >= p. That count is r - max(l, p) + 1. M = t(r), which is exactly the number of such powers p <= r.
- **Formula:** The minimum operations for one query are max(M, ceil(S/2)) = max(m, (total + 1) // 2). Sum this over all queries.
- **Implementation:** For each query, loop p = 1, 4, 16, ... while p <= r, accumulate total and m, then add max(m, (total + 1) // 2). This uses only integer arithmetic and avoids floats/logs.
- **Edge cases:** l = 1 is handled naturally by p = 1. Powers exactly equal to l or r are included correctly because the condition is x >= p. If r < 4, m = 1. Python integers handle the final sum safely.
- **Sample tests:** Both provided examples pass: [[1, 2], [2, 4]] gives 1 + 2 = 3, and [[2, 6]] gives 4.
- **Complexity:** There are at most 15 powers of 4 up to 1e9, so the runtime is O(Q * 15), about 1.5 million iterations for the maximum constraints, with O(1) extra space.
