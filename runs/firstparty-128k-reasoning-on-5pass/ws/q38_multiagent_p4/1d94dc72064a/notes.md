- **Game compression:** A first touch of an untouched index with value x removes it from the untouched set and adds x - 1 future moves, or passes, on that index. Only the parity of x matters: odd x adds an even number of passes, even x adds an odd number. The game ends immediately when the last untouched index is touched, so passes remaining after that are irrelevant.
- **State:** It is enough to track k = number of untouched indices, o = number of untouched indices currently odd, and the pass supply class: Z = zero passes, O = odd positive passes, E = even positive passes. For k = 1, the player to move wins by touching the last index.
- **Two-untouched base:** With k = 2, any first touch gives the opponent the last index, so touching is always bad. Only passes matter: Z is losing, O is winning, and E is losing. This is independent of o.
- **Three-untouched base:** Direct evaluation gives: o = 0 has Z losing, O winning, E losing; o = 1 or o = 2 are winning in all classes; o = 3 has Z winning, O losing, E winning. In particular, from the initial zero-pass state with N = 3, Fennec wins exactly when o > 0. If an odd index exists, touching it leaves a losing k = 2 state for Snuke. If all are even, touching an even leaves a winning k = 2 odd-pass state for Snuke.
- **Large-k induction:** For k >= 4, the following holds: Z and E are winning exactly when o is odd; O is winning exactly when o is even. This is proved by induction using the k = 3 table. From Z, touching an odd changes o to o - 1 and keeps the pass class Z/E, while touching an even keeps o and moves to O; a losing state for the opponent exists exactly when o is odd. From O, passing moves to E/Z, touching an odd moves to O with o - 1, and touching an even moves to E with o; a losing state for the opponent exists exactly when o is even. From E, passing moves to O, touching an odd moves to E with o - 1, and touching an even moves to O with o; a losing state for the opponent exists exactly when o is odd.
- **Initial state:** The game starts with zero passes, so for N >= 4 Fennec wins iff the initial number of odd A_i is odd.
- **Final rule:** N = 1 gives Fennec; N = 2 gives Snuke; N = 3 gives Fennec iff at least one A_i is odd; N >= 4 gives Fennec iff the count of odd A_i is odd.
- **Complexity:** Count odd values in O(N) time and O(1) extra memory. This easily handles N up to 2 x 10^5 and A_i up to 10^9.
- **Verified cases:** Sample 1 has N = 3 and odd count 2, so Fennec. Sample 2 has N = 2, so Snuke. Sample 3 has N = 6 and odd count 4, so Snuke. Edge cases: N = 1 always Fennec; N = 2 always Snuke; N = 3 all even gives Snuke while any odd gives Fennec; N >= 4 with even odd count gives Snuke and odd odd count gives Fennec.
