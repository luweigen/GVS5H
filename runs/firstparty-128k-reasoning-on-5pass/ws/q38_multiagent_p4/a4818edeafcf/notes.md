- **Problem:** Maximize the sum of distinct counts over three non-empty contiguous parts of a length-N sequence, with N up to 3e5 and values bounded by N.
- **Submitted identity:** For fixed right cut j and left cut i < j, P[i] + distinct(A[i+1..j]) = P[j] + G_j(i), where P[t] is the prefix distinct count and G_j(i) counts values whose first occurrence is <= i and whose last occurrence within A[1..j] is > i.
- **Sweep invariant:** Process positions j = 1..N-1. For each value, maintain first and last occurrence up to j. A value contributes 1 to G_j(i) exactly on the interval i in [first, last-1]. When value a appears at j with previous last prev, its interval extends from [first, prev-1] to [first, j-1], so add 1 to i in [prev, j-1]. First occurrences add nothing because their interval is empty.
- **Difference indexing:** Represent left cuts i = 1..N-2 by p = i-1, so n = N-2 leaves. Adding i in [prev, j-1] is a difference update +1 at p = prev-1 and -1 at p = j-1 if that position is inside the array. The code uses L = prev-1, R = j-1, and applies the -1 only when R < n.
- **Segment tree:** Stores sum of the difference array over each node and the maximum prefix sum over each node. Empty prefix is allowed: leaf pref = max(0, D), internal pref = max(pref_left, sum_left + pref_right). Root pref[1] is max G_j(i) over represented i.
- **Why global max is safe:** For i >= j, no value can satisfy i < last occurrence up to j, so G_j(i) = 0. Valid G values are nonnegative, so including invalid zero positions does not overestimate the maximum.
- **Indexing details:** P[j] is distinct A[1..j]. S[k] is distinct A[k..N], computed right-to-left; suffix after cut j is S[j+1]. Valid right cuts are j = 2..N-1; the loop processes j = 1..N-1 and evaluates only j >= 2.
- **Edge cases:** N=3 works with n=1 and size=1, where the leaf is also the root. All values same gives answer 3; all values distinct gives answer N. Both are handled by early exits. If ans reaches N, stop early because each segment distinct count is at most its length, so the total cannot exceed N.
- **Complexity:** O(N log N) time and O(N) memory. The segment tree size is the next power of two at least N-2, at most 524288 for N=3e5, so each tree array has about 1,048,576 entries.
- **Earlier plan status:** The lazy range-add segment tree over V_i = P[i] + distinct(A[i+1..j]) is equivalent but not the submitted implementation. The submitted code uses the difference/max-prefix identity, which avoids explicit lazy range additions.
