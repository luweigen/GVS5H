- **Monotonicity:** After sorting A, B, C in non-increasing order, f(i,j,k)=A_iB_j+B_jC_k+C_kA_i is non-increasing in each index. Differences are negative drops times positive coefficients: increasing i changes by -(A_i-A_{i+1})(B_j+C_k), similarly for j and k.
- **Truncation:** Keep M=min(N,K) elements from each array. If a coordinate is at least K, replacing it by any of the first K indices does not decrease the value. Replacing outside coordinates one by one shows no outside triple can have a value above the K-th largest, and any outside triple attaining the K-th value forces a tied triple inside the truncated box. Thus the K-th largest value is unchanged.
- **Spanning tree:** Parent of (i,j,k) is (i-1,j,k) if i>0, else (i,j-1,k) if j>0, else (i,j,k-1). Every parent has value at least its child. Canonical children are (i+1,j,k), (i,j+1,k) only when i=0, and (i,j,k+1) only when i=j=0. This gives a spanning tree of the M^3 grid with no duplicate insertions.
- **Best-first correctness:** The tree is heap-ordered by value. After popping a node, its canonical children are pushed. For any unpopped node, the first unpopped node on its path to the root is already in the heap and has value at least as large. Therefore the heap maximum is always the largest unpopped value, so popping K times yields the K-th largest value.
- **Encoding:** b=max(1,(M-1).bit_length()), code=(j<<2b)|(i<<b)|k. The heap key is ((LIMIT-value)<<3b)+code, where LIMIT is the root value. Python's min-heap then pops larger values first, with code as a deterministic tie-breaker. Parent code is always smaller than child code, so tie order is also topological.
- **Fast value propagation:** Store d=LIMIT-value in the high bits. For a child, d_child = d + drop * coefficient. Specifically: i+1 uses (A_i-A_{i+1})(B_j+C_k); j+1 at i=0 uses (B_j-B_{j+1})(A_0+C_k); k+1 at i=j=0 uses (C_k-C_{k+1})(A_0+B_0). Adjacent drops are precomputed to avoid recomputing full products.
- **Complexity:** Sorting is O(N log N). The heap performs K pops and at most 3K pushes, so O(K log K) time and O(K) heap memory, plus O(M) array memory. With K<=5e5 and M<=2e5 this is practical.
- **Edge cases:** N=1/K=1 works with M=1 and one pop. K=N^3 works because M=N and the tree has exactly M^3 nodes. Duplicates are handled naturally: drops are zero, values tie, and code order enumerates distinct triples. Large values are safe in Python integers; the maximum value is below 64-bit signed range as well.
