Transpose the grid so that H is the smaller dimension and map the movement directions accordingly. Work on anti-diagonals s = r + c; let P_s[r] be the sum of products of paths from the start to the cell on diagonal s, row r, excluding that cell, and S_s[r] be the analogous sum from that cell to the end, excluding it. Changing a cell (s, r) changes the total answer by (new - old) * P_s[r] * S_s[r]. Store P and S for all diagonals but keep them lazily valid: P_s depends only on earlier diagonals, while S_s depends only on later diagonals. Maintain a prefix frontier P_front and a suffix frontier S_back; an update at diagonal d invalidates P to the right and S to the left, so set P_front = d and S_back = d when the value actually changes. Because the walker changes diagonal by ±1, before each update we recompute at most one P diagonal (when moving to larger s) or one S diagonal (when moving to smaller s), giving O(min(H, W)) per query and naturally handling zeros.
