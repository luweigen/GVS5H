- **Approach:** Binary search the answer L because feasibility is monotone: if some final string has maximum run length at most L, the same string is also valid for any larger L.
- **Feasibility DP:** For fixed L, process the string left to right. State is (last bit, current run length r <= L). Store the minimum flips needed to reach each state. Initialize the first position by choosing bit 0 or 1. For each next original bit, choose target bit c: if c equals the last bit, extend the run only if r + 1 <= L; otherwise start a new run of length 1. Add 1 flip exactly when c differs from the original bit.
- **Pruning:** Use INF = numOps + 1 and discard any transition whose cost exceeds numOps. Feasibility is true if any final state has cost <= numOps.
- **Complexity:** Each feasibility check is O(n * L) time and O(L) memory. Binary search adds O(log n) checks, so worst-case is about O(n^2 log n), easily fine for n <= 1000.
- **Edge cases:** n = 1 always returns 1. numOps = 0 returns the original maximum run length. If the minimum flips to either alternating string is <= numOps, the answer is 1. The upper bound can be the original maximum run length because doing nothing is always allowed.
- **Pitfalls:** Flips can create new long runs, so checking only original runs is insufficient. The operation budget is at most numOps, so use <= rather than ==. Flipping the same index twice is never useful, so Hamming distance to a target string is the correct cost model.
- **Tests:** The included harness checks the three provided examples, a few large all-zero sanity cases, and exhaustively compares against brute force for all binary strings of length 1 through 8 and all numOps values. Brute force enumerates all flip masks, computes the resulting maximum run, and takes prefix minima over flip counts.
