- **Core decomposition:** Split both original index sequences into blocks of size S. For a query (X,Y), write X = fa*S + ra and Y = fb*S + rb. The answer is the sum of four disjoint parts: full A blocks vs full B blocks, partial A prefix vs full B blocks, full A blocks vs partial B prefix, and partial A prefix vs partial B prefix.
- **Block preprocessing:** For every block store its original segment, sorted values, prefix sums of sorted values, total sum, and length. This allows sum |x - values in block| in O(log block) using bisect and prefix sums.
- **Full-full part:** While sweeping A blocks, compute F[a][b] = sum over full A block a and full B block b. Build a 2D prefix over F to answer full-full in O(1).
- **Partial A vs full B:** Group queries by their partial A block. For each such A block, sweep B blocks. For each B block, compute C[ra] = sum over the first ra original elements of the A block vs the whole B block. Add C[ra] to every query in the group with fb > b. This is the offline sweep for A-prefix-vs-full-B.
- **Full A vs partial B:** Symmetric. Group queries by partial B block. For each B block, sweep A blocks and compute D[rb] = sum over the first rb original elements of the B block vs the whole A block. Add D[rb] to queries with fa > a.
- **Partial-partial residual:** Group queries by block pair (fa,fb). For small groups or small products, compute directly or by sorting the two prefixes and using a two-pointer absolute-difference sum. For heavy repeated block pairs, sweep one dimension and maintain a prefix row/column, answering all queries at that prefix in O(1).
- **Block size tuning:** The theoretical balance is S ~ N/sqrt(K). In Python, a slightly larger factor (about 1.8) reduces the number of bisect-heavy block-pair sweeps while keeping residual sorting acceptable. S is capped to [1, N].
- **Residual light method:** If ra*rb is small, use direct nested loops. Otherwise sort the two prefixes (with caching when memory-safe) and compute the all-pairs absolute sum by scanning sorted values with a pointer and running sum.
- **Residual heavy method:** If a block pair has many queries and max_ra*LB or max_rb*LA is small enough, process queries sorted by one prefix length. Maintain the previous prefix row/column and add one original element at a time, updating the prefix array in O(other block length).
- **Boundary cases:** If X or Y is exactly a block boundary, the corresponding remainder is zero and that part is treated as full blocks. The last block may be shorter; remainders can equal the last block length. Full block counts can equal the number of blocks.
- **Complexity:** Roughly O((N/S)^2 * S) for block-pair sweeps plus O(K*S log S) for residual sorting/two-pointer, with low memory. All sums fit in 64-bit mathematically, but Python integers are used safely.
- **Performance choices:** Direct residual threshold is max(2000, S). Caching sorted prefixes is enabled only when the estimated cached memory is modest. Heavy residual precomputation is capped to avoid large S^2 work when K is small.
