Use the given sorted order and the fact that a valid pair always has the smaller mochi on top. Restrict attention to the first N//2 mochi as possible tops and the remaining mochi as possible bottoms, since any feasible K pairs can be represented using the K smallest and K largest mochi. Sweep with two pointers: i over the top half and j over the bottom half, pairing the smallest available top with the smallest bottom that satisfies 2*A[i] <= A[j]. If the current bottom is too small, advance j; if it works, count a pair and advance both pointers. This greedy is optimal because a bottom that cannot support the current smallest top cannot support any later top, and using the smallest feasible bottom preserves larger bottoms for larger tops. The algorithm runs in O(N) time and O(1) extra space, and integer arithmetic safely handles the size bound.
