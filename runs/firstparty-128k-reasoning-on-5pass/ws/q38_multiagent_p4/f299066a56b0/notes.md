- **Problem structure:** The array is already sorted. A valid kagamimochi always uses the smaller mochi as the top, and the condition is exactly `2 * top <= bottom`.
- **Half restriction:** It is sufficient to consider the first `N // 2` mochi as possible tops and the remaining mochi as possible bottoms. If an optimal matching uses a top from the second half, some first-half mochi is either unused or used as a bottom. Swapping roles preserves validity because smaller tops are easier to place and larger bottoms are easier to support. Repeating this moves all tops into the first half, and similarly all bottoms can be moved into the second half.
- **Greedy correctness:** With tops in the first half and bottoms in the second half, both sides are sorted. For each top in increasing order, use the smallest unused bottom that can support it. If the current bottom is too small, it cannot support any later, larger top, so it is discarded. If it works, pairing it with the current smallest top is safe because later tops need at least as large a bottom; exchanging bottoms in any optimal solution shows no loss.
- **Algorithm:** Two pointers: `i` scans candidate tops from `0` to `N // 2 - 1`, and `j` scans candidate bottoms from `N // 2` to `N - 1`. Increment `ans` and both pointers when `2 * A[i] <= A[j]`; otherwise increment only `j`.
- **Complexity:** The loop advances `i` or `j` each iteration, so it is `O(N)` time and `O(1)` extra space beyond the input array.
- **Integer safety:** Use `2 * A[i] <= A[j]` instead of floating-point division. Values up to `10^9` are safe in Python.
- **Edge cases:** `N = 2` checks the only possible pair. All equal values give `0` because `2x <= x` is false for positive `x`. Odd `N` works because the bottom half has size `ceil(N / 2)`, at least as large as the top half.
- **Verification:** Sample 1 gives `3`, sample 2 gives `0`, sample 3 gives `6`. Manual edge cases such as `[1, 2]`, `[1, 1]`, `[1, 1, 2, 2]`, and `[2, 3, 4, 5, 6]` behave as expected.
