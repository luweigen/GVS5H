- **Core reduction:** For a sorted interval of length M, K pairs are possible iff the K smallest elements can be matched with the K largest elements in order: A[L+t] <= A[R-K+1+t]/2 for t=0..K-1. This follows from sorting any feasible tops/bottoms and using the fact that the K smallest are no larger than any chosen K tops, while the K largest are no smaller than any chosen K bottoms.
- **Global threshold array:** Let f[i] be the first global index with A[f[i]] >= 2A[i], or N if none. f is nondecreasing because A and 2A[i] are nondecreasing. Compute it in O(N) with a two-pointer scan, forcing j >= i+1. Define h[i]=f[i]-i, the minimum offset needed for A[i] to have a valid bottom.
- **p formulation:** Put p=M-K. Then K pairs are feasible iff p >= ceil(M/2) and h[i] <= p for every i in [L, R-p]. The answer is M-p, so we need the minimal p.
- **Direct minimal-p formula:** For query [L,R] (0-based), let end=R+1 and j=bisect_right(f, end, L, end), the first index in [L,R] with f[i] > end (or end if none). For i<j, f[i] <= end, so h[i] <= end-i. For i>=j, h[i] > end-i, and such an index can be a top only if p >= end-j. Also, if p >= end-j then the top range [L,R-p] ends before j, and the h-condition is equivalent to p >= max h over [L,j). Hence p_extra = max(rmq(L,j), end-j), and p=max(ceil(M/2), p_extra). Answer M-p.
- **Implementation details:** Use 0-based indices. Build an iterative segment tree for range maximum over h. Query half-open [L,j). Use bisect_right, not bisect_left, because f[i]=end is still "not beyond the interval" and belongs to the left part. If j=L, the RMQ is empty and p_extra becomes M, giving answer 0. If j=end, the second term is 0.
- **Edge cases:** All equal values give f[i]=N and answer 0. No valid pair in a subinterval gives j=L or h[L]=M, answer 0. Full range has end=N, so f[i]=N is treated as <= end; the max h term correctly forces p large enough to exclude tops with no bottom. Odd/even lengths are handled by p>=ceil(M/2), i.e. K<=floor(M/2).
- **Verification:** Checked against a brute force that, for small random sorted arrays and edge cases, tries K from floor(M/2) down to 0 and verifies the prefix/suffix inequality. Also checked samples, all equal, no valid pair, odd/even lengths, and full range. A naive greedy that pairs the smallest remaining top with the largest remaining bottom is not a correct brute force for this ratio condition; the prefix/suffix check is the safe oracle.
- **Complexity:** f scan O(N), segment tree build O(N), each query O(log N) for bisect plus O(log N) for RMQ, total O((N+Q) log N) time and O(N) memory.
