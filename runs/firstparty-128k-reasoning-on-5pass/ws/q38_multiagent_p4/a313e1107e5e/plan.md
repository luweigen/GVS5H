Process the queries offline in nondecreasing R_i. Maintain a max Fenwick tree over compressed A values, where each position stores the longest strictly increasing subsequence in the already processed prefix that ends with that value. When adding A_i, compute its candidate length as 1 plus the prefix maximum over values strictly smaller than A_i, then apply a point max-update at A_i's rank. For each query whose R_i equals the current prefix, answer by taking the prefix maximum over all compressed values <= X_i, located with binary search. This yields O((N+Q) log N) time and O(N+Q) memory.
