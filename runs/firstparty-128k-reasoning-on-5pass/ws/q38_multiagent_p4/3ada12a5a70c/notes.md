- **Geometry reduction:** Map each boundary point to a perimeter coordinate `p` on a circle of circumference `C = 4 * side`. Use bottom `y=0 -> x`, right `x=s -> s+y`, top `y=s -> 3s-x`, left `x=0 -> 4s-y`, with corner priority matching the code so coordinates are unique.
- **Key equivalence:** For any threshold `D <= s`, two boundary points have Manhattan distance `< D` iff their circular perimeter distance is `< D`. If the circular gap is `< D <= s`, the shorter arc lies on one side or through one adjacent corner, where Manhattan distance equals arc length. If Manhattan distance is `< D <= s`, the points cannot be on opposite sides, and for same/adjacent sides the shorter perimeter arc equals the Manhattan distance.
- **Answer cap:** For `k >= 4`, the maximum possible minimum Manhattan distance is at most `s`. If two selected points share a side, their distance is at most `s`. If one point is chosen per side, assuming all four adjacent-side distances are `> s` leads to contradictory inequalities. Equivalently, four points on a circle of circumference `4s` cannot all have circular distance `> s`.
- **Feasibility check:** Sort perimeter coordinates and duplicate them with `+C`. For fixed `D > 0`, compute `nxt[i]` as the first index with coordinate at least `p2[i] + D` using a two-pointer scan over `2n`. For each start `i`, the last chosen point must be at most `p2[i] + C - D` so the wrap-around gap is at least `D`. Greedily jump through `nxt` while staying within that limit; if `k` points are reached, `D` is feasible.
- **Greedy correctness:** With the first point fixed and an upper bound `limit`, choosing the earliest possible next point is optimal by exchange: the `r`-th greedy point is no later than the `r`-th point of any feasible selection. Trying every point as the first selected point covers every circular subset by cutting the circle at a selected point.
- **Old DP issue:** The previous chain DP was not safe. Same-chain transitions carried the opposite-chain last point without rechecking its distance to the new point, and minimum-value dominance fails for negative endpoints: a larger negative opposite-chain coordinate helps future same-chain negative points, while a smaller one helps future opposite-chain points. The circle reduction avoids this state-space issue entirely.
- **Complexity:** Preprocessing is `O(n log n)`. Each feasibility check is `O(n + n*k)` because the `nxt` scan is linear and each start performs at most `k-1` jumps. Binary search over `[0, s]` gives `O((n + n*k) log s)`, easily within `n <= 15000` and `k <= 25`.
- **Edge cases:** `D = 0` is trivially feasible. Exact distances are allowed, so use `>=` for the next-point target and `<=` for the wrap limit. Corners are assigned one perimeter coordinate by priority, so `p` values are unique. Opposite-side pairs have circular distance at least `s`, matching the Manhattan lower bound `s` for all searched `D <= s`.
- **Samples:** The examples map to circle points and produce outputs `2`, `1`, and `1`. The equivalence proof also covers brute-force random tests for small side lengths.
