- **Core observation:** At floor level `t`, free walkway movement is possible exactly inside connected components of blocks with building height at least `t`. For two blocks, the maximum floor where they can be connected is the maximum bottleneck value over grid paths, where a path's value is its minimum building height.
- **Maximum spanning tree:** Assign each adjacent grid edge `(u,v)` weight `min(F[u], F[v])`. A maximum spanning tree preserves maximum bottleneck values: the minimum edge weight on the tree path between two vertices equals their best possible bottleneck value in the original grid.
- **Query formula:** Let `T` be the bottleneck between endpoint blocks. They can meet freely at level `min(T,Y,Z)`. Thus the minimum stair count is `abs(Y-Z) + 2 * max(0, min(Y,Z)-T)`. If the blocks are identical, the answer is simply `abs(Y-Z)`.
- **LCA implementation:** Root the maximum spanning tree. Binary lifting stores both the `2^k` ancestor and the minimum tree-edge weight on the corresponding upward path. The bottleneck is obtained while lifting both endpoints to their LCA.
- **Complexity:** There are fewer than `2HW` grid edges. Kruskal costs `O(HW log(HW))`; preprocessing lifting tables costs `O(HW log(HW))`; each query costs `O(log(HW))`.
- **Memory:** Grid edges are encoded as single integers instead of tuples. Tree adjacency and lifting tables use `array('i')` to avoid excessive Python object memory.
