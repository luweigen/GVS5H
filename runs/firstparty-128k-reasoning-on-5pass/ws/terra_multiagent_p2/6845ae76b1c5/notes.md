- **Approach:** Use index block decomposition instead of two-dimensional Mo. Partition one sequence into blocks. For each complete block, compute its contribution against every prefix of the other sequence, then add that value to all queries containing the complete block.
- **Symmetry:** The expression is symmetric in `A` and `B`. Choose whether to block original `A` or original `B` based on estimated remainder work. Swapping also swaps every query coordinate.
- **Complete block computation:** Sort values in the current block. Sweep the other sequence in globally value-sorted order. For each value `v`, maintain count and sum of block values `<= v`; this gives the sum of absolute differences from `v` to all values in the block in `O(1)` amortized sweep time. Write these values back in original index order and prefix-sum them.
- **Partial block computation:** For the fewer than `block` remaining elements of each query, evaluate each element against the requested prefix of the other sequence using a persistent segment tree. Each version represents one prefix and stores counts and value sums by compressed value.
- **Absolute-value formula:** Given a multiset with `c` elements and sum `s`, and values `<= v` having count `cl` and sum `sl`, its total distance from `v` is `v*cl-sl + (s-sl)-v*(c-cl)`.
- **Persistent tree:** Each prefix insertion copies `O(log N)` nodes. A query for count and sum of values `<= v` also costs `O(log N)`. Array-backed storage reduces memory substantially compared with Python object nodes.
- **Complexity:** With block size `S`, complete-block preprocessing is `O(N^2/S + N log S)`, distributing full block answers costs `O(KN/S)`, and partial blocks cost `O((sum query remainders) log N)`. The adaptive selection balances these terms. Memory is `O(N log N)` for the persistent tree plus `O(N)` auxiliary arrays.
- **Arithmetic:** Python integers handle all answer sizes safely; persistent node sums are stored in signed 64-bit arrays and remain below about `2e13`.
