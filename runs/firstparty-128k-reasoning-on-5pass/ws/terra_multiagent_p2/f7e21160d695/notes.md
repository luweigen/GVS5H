- **MST minimax property:** For any two vertices, the minimum possible maximum edge weight on a graph path equals the maximum edge weight on their path in any MST. Kruskal’s process also directly represents this: two vertices first become connected exactly at their minimax value.
- **Matching invariant:** After processing all merges performed so far, each DSU component retains unmatched occurrences from at most one of the two sequences. Any possible A-B pairs internal to that component have already been matched at the smallest threshold at which they could connect.
- **Merge operation:** When components merge through an edge of weight `w`, add their residual A and B multiplicities, cancel `min(totalA, totalB)`, and charge `w` for every canceled pair. Such pairs cannot have cost below `w`, because the two previous components were disconnected before this merge, and they can achieve cost `w`.
- **Equal edge weights:** Processing equal-weight Kruskal edges one at a time is valid. All newly connected pairs formed through any order among those edges have identical cost equal to that common weight, so the total charge is unaffected.
- **Multiplicity:** A and B are sequences, not sets; counts per vertex must be maintained. The guarantee that no A occurrence vertex equals any B occurrence vertex ensures no initial zero-cost cancellation is needed.
- **Complexity:** Sorting edges costs `O(M log M)`. DSU operations cost `O((N+M) alpha(N))`. Memory use is `O(N+M)`.
- **Integer range:** The answer may reach about `K * 10^9`, so it requires 64-bit arithmetic; Python integers handle this safely.
