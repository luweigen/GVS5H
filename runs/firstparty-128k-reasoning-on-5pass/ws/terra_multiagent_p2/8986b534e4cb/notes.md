- **Prefix-sum formulation:** Define `P[v] = w_1 + ... + w_{v-1}`. For a right-moving person on `[l,r]`, the condition is `P[l]=P[r]` and `P[x]>P[l]` for `l<x<r`. For a left-moving person, it is `P[l]=P[r]` and `P[x]<P[l]` for `l<x<r`.
- **Forbidden pairs:** Two intervals are incompatible if they have the same geometrical left endpoint, the same geometrical right endpoint, or they strictly cross while having equal travel direction. The common-endpoint condition is direction-independent. Opposite-direction strict crossings are feasible.
- **Mixed-direction check:** For crossing intervals `a<c<b<d`, a right-moving `[a,b]` and a left-moving `[c,d]` both imply the same ordering between their endpoint-value components, rather than opposite order. Thus a mixed crossing itself does not create a contradiction.
- **Why longer strict cycles do not add conflicts:** Contract all equal endpoint pairs. A strict inequality edge arises only when an endpoint/component lies in another interval’s interior. At every shared endpoint, avoiding the common-left/common-right forbidden pattern forces equality edges to continue geometrically from left to right. Consequently, any attempted directed strict cycle must contain a reversal of ordering induced by two strictly crossing intervals of the same direction; that pair is already forbidden. Therefore the pairwise characterization is sufficient, not merely necessary.
- **Sliding window:** Feasibility is hereditary. Maintain the largest feasible suffix ending at each person index `r`; `boundary[r]` is its smallest index. On inserting person `r`, remove from the left until it has no forbidden pair with the active set. Each interval is inserted and removed once.
- **Query criterion:** A query `[L,R]` is feasible iff every suffix boundary in that range is at most `L`, i.e. `max(boundary[L..R]) <= L`. A max segment tree answers this in `O(log M)`.
- **Crossing data structure:** For each direction separately, active normalized intervals are points `(l,r)`. A new `[l,r]` crosses an old interval iff there is a point in either rectangle `x<l<y<r` or `l<x<r<y`. The offline Fenwick-of-Fenwicks supports updates and rectangle existence in `O(log^2 N)`.
- **Complexity:** Construction uses `O(M log N)` coordinate storage. Window processing is `O(M log^2 N)`, and queries cost `O(Q log M)`.
