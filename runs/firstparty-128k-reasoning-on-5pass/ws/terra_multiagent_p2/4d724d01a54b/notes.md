- **Optimality via largest element:** Let the current permutation have length `m`, and let the largest value `m` initially be at position `k`. It must end at position `m`. Viewing its position as a walk on the line, every path from `k` to `m` has cost at least `k + (k+1) + ... + (m-1)`, the cost of moving directly right through every boundary once. Any detour adds positive-cost edge traversals.
- **Deletion lower bound:** Delete value `m` from any sorting sequence. Every swap not involving `m` becomes a valid adjacent swap in the permutation of `1..m-1`. If its original boundary was right of `m`, deletion decreases its generator index by one; otherwise it stays unchanged. Thus its cost after deletion is never larger. Consequently, if `F(P)` is the optimum cost and `Q` is `P` with `m` deleted, then `F(P) >= sum_{i=k}^{m-1} i + F(Q)`.
- **Construction attaining recurrence:** First swap the largest element rightward immediately, through boundaries `k,k+1,...,m-1`. This is always inversion-decreasing, costs exactly the unavoidable sum, leaves `m` fixed at the end, and leaves exactly `Q` in the first `m-1` positions. Recursing proves the lower bound tight. This gives a rigorous weighted-Coxeter normal-form proof without relying only on local braid orientations.
- **Insertion-sort form:** Processing original elements left to right and inserting each new value into the sorted prefix is also optimal. For the element at original position `j`, let `r = 1 + #{ earlier values smaller than it }`, its rank among the first `j` elements. It moves left across boundaries `j-1,j-2,...,r`, costing `r+(r+1)+...+(j-1)`.
- **Equality to the largest-first normal form:** Write `T(t)=t(t+1)/2`. The insertion total is `sum_x [T(pos[x]-1)-T(r_x-1)]`, where `r_x=1+#{values smaller than x occurring before x}`. The largest-first recurrence total is `sum_x [T(x-1)-T(r_x-1)]`. Since the positions `pos[x]` are a permutation of `1..N`, `sum_x T(pos[x]-1)=sum_x T(x-1)`, so these totals are equal. Hence the insertion sequence attains the proven optimum.
- **Computation:** Scan positions from left to right with a Fenwick tree over values. For current value `x`, query the count of previous values smaller than `x`; then `r=count+1`, and add `T(j-1)-T(r-1)`. Complexity is `O(N log N)` time and `O(N)` memory. Python integers safely handle the cubic-scale answer.
