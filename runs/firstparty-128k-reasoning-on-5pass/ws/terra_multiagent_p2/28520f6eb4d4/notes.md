- **Visibility characterization:** For a target building, aiming at its top is optimal. Any segment aimed at a lower point is no higher at every earlier building coordinate, so it cannot avoid a blocker if the top segment cannot.
- **Pair threshold:** For earlier building `j < i`, the segment from `(0,h)` to top `(X_i,H_i)` is strictly above top `j` exactly when `h > (X_i*H_j - X_j*H_i) / (X_i-X_j)`. Equality still intersects building `j`, hence remains blocked.
- **Global criterion:** All buildings are visible exactly when `h` is strictly larger than the maximum threshold over all ordered pairs `j < i`. If this maximum is negative, height zero already sees everything and output is `-1`; otherwise output the maximum, including exactly zero.
- **Hull reduction:** For fixed target `i`, maximizing the pair threshold is equivalent to minimizing `(H_i-H_j)/(X_i-X_j)` among prior points. A minimizer lies on the upper convex hull of processed points.
- **Hull invariant:** The maintained upper hull has strictly decreasing consecutive slopes. On insertion, the last vertex is removed when the two adjacent slopes are nondecreasing; the cross-product test uses `>= 0`, intentionally removing collinear points as well.
- **Query correctness:** Slopes from upper-hull vertices to a new point form a decreasing-then-increasing sequence, so the minimum is found by binary search comparing adjacent slopes. All comparisons use integer cross multiplication, including equal-slope cases.
- **Validation:** The implementation logic was checked against the direct `O(N^2)` formulation: compute every pair threshold and take its maximum. Important adversarial categories covered by the invariant reasoning include all-collinear points, repeated/equal pair thresholds, increasing heights, decreasing heights, hull vertices removed by collinearity, negative thresholds, zero thresholds, and a single building.
- **Complexity:** Each point enters and exits the hull at most once; each query is `O(log N)`. Total time is `O(N log N)`, memory is `O(N)`.
- **Numerics:** The internally maintained answer is an exact integer fraction. Conversion to float occurs only for final printing with 18 digits; relative-error acceptance handles large answers.
