- **Distance-label formulation:** For a target distance `D`, use integer labels `x[v]` in `[0,D]`, with `x[1]=0` and `x[N]=D`. Every edge `u->v` must satisfy `x[v] <= x[u]+1`. An edge must be selected exactly when `x[v]=x[u]+1`; edges with `x[v]<=x[u]` may remain weight zero. Minimize the number of such increasing edges.
- **Correctness of labels:** If selected edges make the shortest distance at least `D`, set `x[v]=min(dist(1,v),D)`. A weight-0 edge cannot increase labels and a weight-1 edge increases by at most one, so these labels satisfy the constraints. Every label-increasing edge is selected, hence the labeling cost is at most the number of selected edges. Conversely, selecting every increasing edge gives edge weight at least `x[v]-x[u]`; summing along any `1->N` path proves it contains at least `D` selected edges.
- **Threshold variables:** For each vertex `v` and level `i=1..D`, create Boolean `Y[v,i] = [x[v] >= i]`. The source side of a cut represents true variables. Add infinite-capacity implications `Y[v,i+1] -> Y[v,i]`, ensuring labels are prefixes of true thresholds.
- **Edge feasibility implications:** The constraint `x[v] <= x[u]+1` becomes `Y[v,i] -> Y[u,i-1]` for each `i=2..D`. These are infinite-capacity arcs. Fix `x[1]=0` by arcs `Y[1,i] -> sink`, and fix `x[N]=D` by arcs `source -> Y[N,i]`.
- **Charging each original edge once:** For original edge `u->v`, add capacity-1 arc `Y[v,i] -> Y[u,i]` for every level `i`. It crosses the cut precisely for levels with `x[v] >= i > x[u]`. The implication constraints ensure `x[v]-x[u] <= 1`, so there are either zero crossing levels or exactly one crossing level. Thus each original edge is charged exactly once iff it is label-increasing, including parallel edges independently.
- **Feasibility and exact K:** The minimum cut is the minimum number of required selected edges. Target `D` is feasible iff this is at most `K`. “Exactly K” is equivalent because arbitrary extra edges can be selected afterward and weights only increase, never decreasing shortest-path distance.
- **Search and complexity:** The answer is at most `K`; binary search `D` in `[0,K]`. A target network has `N*D+2` nodes and `O((N+M)D)` arcs. Use `M+1` as infinity because any finite valid solution charges at most `M` original edges.
- **Sample checks:** Sample 1: `D=1` needs both paths charged, cost 2; `D=2` is impossible due to direct `1->3`, answer 1. Sample 2: `D=2` has minimum cost 3; `D=3` is impossible due to `1->2`, answer 2. Sample 3: `D=1` charges both parallel edges, cost 2>K, answer 0.
