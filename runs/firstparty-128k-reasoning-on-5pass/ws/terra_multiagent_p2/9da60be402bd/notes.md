- **Product-state model:** A state `(u, v)` represents the endpoints of an inner palindrome path. If there is an edge `x -> u` and an edge `v -> y` with the same character, then wrapping them around that inner palindrome produces a palindrome path from `(x, y)` whose length is two greater.
- **Centers:** Every `(i, i)` has answer `0` because the empty path is a palindrome. Every existing graph edge `(i, j)` has answer at most `1`, because its one-character label is a palindrome.
- **Traversal direction:** Start from centers and expand outward. From `(u, v)`, use incoming edges into `u` and outgoing edges from `v` grouped by equal character.
- **Shortest-path correctness:** Transitions always add exactly `2`. Initial distances are `0` or `1`, covering even and odd palindrome lengths respectively. A FIFO queue initialized with all zero-distance states before all one-distance states processes states in nondecreasing distance, since generated distances are respectively `2, 3, 4, ...`.
- **Data structures:** `incoming[character][destination]` stores predecessors and `outgoing[character][source]` stores successors. Distances are stored in a flattened array indexed by `u * N + v`.
- **Complexity:** There are at most `N^2` states. Generated transitions are Cartesian products of matching incoming/outgoing neighbor lists. The worst case is `O(N^4)`, acceptable for `N <= 100` with compact lists and early termination once all states are discovered.
- **Edge cases:** Self-loops remain distance `0` on diagonal states, despite also being one-edge palindrome centers. Unreachable states remain `-1`. Paths may repeat vertices and edges, which is naturally supported by the state traversal.
