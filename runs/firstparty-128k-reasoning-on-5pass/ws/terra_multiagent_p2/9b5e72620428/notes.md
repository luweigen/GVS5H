- **Fixed common sum criterion:** Fix a proposed common sum `S`. Every originally fixed value in either sequence must be at most `S`, since its partner must be non-negative. Let `p` and `q` be the numbers of fixed entries in `A` and `B`. At least `K = max(0, p + q - N)` fixed `A` entries must be paired with fixed `B` entries: there are only `N-q` unknown `B` positions available to absorb fixed `A` values, and symmetrically for fixed `B` values.
- **Matching formula:** For fixed `S`, a fixed value `a` in `A` can be paired with a fixed value in `B` only if that value equals `S-a`. Thus these value classes are independent, and the maximum number of disjoint fixed-fixed pairs is `sum_a min(countA[a], countB[S-a])`. This is a maximum matching because each `a` class has exactly one possible complementary `B` class.
- **Sufficiency proof:** If the matching count is at least `K`, select `K` or more disjoint fixed-fixed pairs. All remaining fixed `A` entries can be placed at distinct unknown `B` positions, and all remaining fixed `B` entries can be supplied by distinct unknown `A` entries; the inequalities follow from the definition of `K`. Set each such unknown partner to `S-fixed_value`. Pair any remaining unknown entries with values `0` and `S`. Hence the criterion is both necessary and sufficient.
- **Candidate sums:** If `K=0`, choose any `S` at least all fixed values, so the answer is always `Yes`. If `K>0`, a feasible sum must contain at least one fixed-fixed pair and therefore must equal `a+b` for a fixed distinct value `a` of `A` and fixed distinct value `b` of `B`. Sums below the largest fixed input value are discarded.
- **Aggregation:** For every distinct-value pair `(a,b)`, create one record for `s=a+b` whose weight is `min(countA[a], countB[b])`. Summing these weights for equal `s` exactly computes the matching formula. It is incorrect to add `countA[a]*countB[b]`, because one fixed element can participate in only one pair.
- **Complexity and memory:** There are at most `U_A U_B <= 4,000,000` records. A Python dictionary with millions of integer keys and values can consume several hundred MB. The solution stores packed 64-bit records in `array('Q')`, requiring about 32 MB, plus a similarly sized radix-sort buffer. Three 16-bit radix passes sort the records in `O(U_A U_B)` time and roughly 70 MB auxiliary memory. The packed low field uses 11 bits because every contribution is at most `N <= 2000`.
