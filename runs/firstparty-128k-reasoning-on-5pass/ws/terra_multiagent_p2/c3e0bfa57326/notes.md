- **Tree model:** Add a virtual root whose children are the top-level primitive balanced components. Every matched parenthesis pair is a node, and its immediate enclosed primitive components are its ordered children. A valid contiguous substring is exactly a consecutive interval of children of one node, including the virtual root.
- **Effect of one operation:** Reversing and complementing a valid substring reverses the selected consecutive child interval. Simultaneously, every selected child subtree is mirrored recursively: its children are reversed at every depth. Thus it preserves every subtree's unordered rooted-tree shape.
- **Pure sibling reversal:** Select a consecutive interval of siblings. After this operation, each selected child is still a valid subtree, so apply the operation separately to each selected child subtree. Each child is mirrored twice, restoring its original ordered internal structure, while the interval of siblings remains reversed. Hence any consecutive sibling interval can be reversed without modifying any child subtree.
- **Reachability:** Reversing adjacent siblings is a special case of pure interval reversal. Adjacent swaps generate all permutations, so children of every node can be permuted arbitrarily. These permutations can be performed independently at arbitrary nodes because each operation acts only within the selected node's child interval.
- **Invariant:** An operation only reorders siblings and mirrors selected subtrees. Both actions preserve the unordered type of every node's subtree. Therefore no reachable result can have a different unordered rooted forest from the input.
- **Exact characterization:** The reachable strings are exactly all plane embeddings of the input's unordered rooted forest: independently choose an ordering of the children of every node, including the virtual root.
- **Counting:** For a node with degree `d`, whose child unordered subtree types have multiplicities `c_1, c_2, ...`, the number of distinct child orders is `d! / product(c_i!)`. Multiply this over all real nodes and the virtual root. Identical child unordered types must not be distinguished, since swapping them produces the same parenthesis string.
- **Canonical types:** Process nodes bottom-up. A node's unordered type is the sorted tuple of its children's canonical type IDs. Intern equal tuples in a dictionary. Since nodes are created on `'('`, all children have larger indices than their parent, so reverse node-index order is a valid bottom-up traversal.
- **Complexity:** There are at most `N/2 + 1` nodes. Sorting all child-ID lists costs `O(N log N)` total in the worst case, and memory is `O(N)`.
