- **Reduction:** A fine triplet is a three-term arithmetic progression. For a present middle value `B`, endpoints satisfy `A + C = 2B`.
- **Convolution formula:** With indicator polynomial `f[x]`, coefficient `(f*f)[2B]` counts ordered endpoint pairs summing to `2B`. For a present `B`, it contains one self-pair `(B,B)`. Each proper endpoint pair appears in both orders, so its triplet contribution is `(conv[2B] - 1) // 2`.
- **Dynamic transform size:** The NTT length is now the smallest power of two strictly greater than `2 * max(S)`. This prevents cyclic wraparound while avoiding the former unconditional `2^21` allocation and work. Examples: sample 1 (`max=8`) uses 32, sample 2 (`max=500000`) uses 1048576, and sample 3 (`max=19`) uses 64.
- **Input memory:** The input bytes are scanned twice. The first scan obtains `max(S)` before allocating the polynomial; the second fills a `bytearray` membership table and the polynomial. This avoids retaining a list of up to one million Python integers.
- **NTT implementation:** The forward transform uses decimation-in-frequency and returns bit-reversed output. The inverse uses decimation-in-time and accepts that bit-reversed order. Therefore explicit bit-reversal permutations are unnecessary, reducing substantial Python-level overhead.
- **Exactness:** Modulus `998244353` supports lengths through `2^23`, including the worst necessary `2^21`. Every convolution coefficient is at most `N <= 10^6`, far below the modulus, so modular output equals the exact integer coefficient.
- **Complexity:** Time is `O(M log M)`, where `M` is the selected transform length; memory is `O(M + max(S))`. In the worst case `M=2^21`. Python NTT at that size remains computationally heavy, but removing bit reversal and dynamically shrinking `M` addresses the major avoidable cost; the worst case still performs about two full transforms plus pointwise squaring.
