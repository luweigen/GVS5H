- **Window equalization cost:** A length-`x` window is made constant with minimum unit-edit cost equal to its sum of absolute deviations from any median. The lower median at rank `(x + 1) // 2` is used.
- **Fenwick window maintenance:** Values are coordinate-compressed. One Fenwick tree stores frequencies and another stores value sums. For every sliding window, `kth(median_rank)` finds its median coordinate in `O(log n)`.
- **Cost formula:** With `m` as median, values at most `m` have count/sum `left_count,left_sum`, and total window sum `total_sum`, cost is `m*left_count-left_sum + (total_sum-left_sum)-m*(x-left_count)`. Including all duplicate medians on the left is valid because their contribution is zero.
- **DP indexing:** `prev[p]` stores the minimum cost for exactly `chosen-1` non-overlapping windows in prefix `nums[:p]`. For a final window ending at prefix length `p`, it is `nums[p-x:p]`, its cost index is `p-x`, and the preceding windows must lie in `nums[:p-x]`. Thus transition is `cur[p] = min(cur[p-1], prev[p-x] + costs[p-x])`.
- **At least versus exactly:** All per-window costs are nonnegative, so a minimum solution with at least `k` windows can be represented by exactly `k` selected windows after discarding extras.
- **Verification:** Sample 1 produces `8`; sample 2 produces `3`. Edge cases validated conceptually include `x=n,k=1`, all equal values yielding zero, even `x` with either middle value as optimal target, duplicate median values, and the tight packing case `k*x=n`.
- **Complexity:** Window-cost computation is `O(n log n)`. DP is `O(nk)` with `k <= 15`. Memory is `O(n)` plus compressed Fenwick trees.
