- **MST bottleneck property:** For any vertices `x, y`, the minimax value `f(x, y)` equals the maximum edge weight on the unique `x-y` path in any minimum spanning tree. This follows from Kruskal connectivity: `x` and `y` first become connected when all edges up to weight `f(x,y)` are available.
- **State per DSU component:** Store `balance = unmatched_A_count - unmatched_B_count`. After all possible matches internal to a component have been made, it contains occurrences of at most one type, so this signed value fully represents its unmatched occurrences.
- **Initialization:** Add `+1` for every occurrence in sequence `A` and `-1` for every occurrence in sequence `B`. Repeated vertices are naturally handled. The condition `A_i != B_j` for all pairs ensures no vertex initially contains both types, so no zero-cost initialization matches are needed.
- **Kruskal transition:** On a successful union of components with balances `x` and `y` at edge weight `w`, if their signs differ, match `min(abs(x), abs(y))` occurrences and add `w * min(abs(x), abs(y))` to the answer. The merged balance is `x + y`. Equivalently, if explicitly retaining residual counts `(A_left, B_left)` and `(A_right, B_right)`, the number matched is `min(A_left, B_right) + min(B_left, A_right)`.
- **Correctness invariant:** After each successful Kruskal union, every DSU component has internally matched as many A/B occurrences as possible using only vertices in that component, at minimum total bottleneck cost. Its remaining occurrences are exactly represented by its signed balance.
- **Why greedy matching is optimal:** Before two Kruskal components merge, no path between them has bottleneck below `w`. At their merge, every cross-component pair that can be matched has bottleneck exactly `w`. Any opposite residual occurrences left unmatched cannot be matched outside at a lower cost, while matching them now cannot prevent a cheaper future match. Therefore all possible opposite residual pairs should be matched immediately.
- **Equal edge weights:** Processing equal-weight successful unions in any order is valid. Every newly connected pair at that stage has bottleneck at most the common weight, and all matches formed during that weight contribute that same value. Different union orders only change which equal-cost pairs are selected, not the total optimal cost.
- **Complexity:** Sorting costs `O(M log M)`. DSU operations cost `O(M alpha(N))`. Memory usage is `O(N + M)`.
