- **Approach:** Use a KMP automaton for `str2`. After each generated character, the automaton state records the longest suffix that is a prefix of `str2`; completing a full match identifies exactly whether the length-`m` window ending at this position equals `str2`.
- **Window enforcement:** The window starting at index `i` completes when writing output position `i + m - 1`. For that output position, require a KMP occurrence exactly when `str1[i] == 'T'`, and require no occurrence when `str1[i] == 'F'`.
- **States:** Only KMP states `0..m-1` are stored. When a match reaches state `m`, mark an occurrence and immediately fall back to `pi[m-1]`, allowing overlapping matches.
- **Backward DP:** `dp[pos]` is a bitmask of automaton states from which suffix positions `pos..L-1` can be completed legally, where `L = n + m - 1`. The terminal mask allows every state.
- **Transition optimization:** For each source state, precompute a bitmask of destinations reachable by any letter, and another reachable by a non-matching letter only. For an `F` constraint, a state is feasible iff its non-match destination mask intersects `dp[pos+1]`. This gives approximately `O(L*m)` DP work rather than `O(L*m*26)`.
- **`T` optimization:** A match can only complete when the current KMP state is `m-1` and the appended letter is the last character of `str2`. Thus a `T` DP row has at most one feasible source state.
- **Reconstruction:** Starting from state zero, test letters `'a'` through `'z'` and choose the first transition satisfying the current completed-window rule whose next state is feasible in `dp[pos+1]`. This produces the lexicographically smallest accepted string.
- **Complexity:** Time is `O((n+m)*m + m*26)` and memory is `O(n+m + m*26)`, with DP rows stored as Python integer bitmasks.
