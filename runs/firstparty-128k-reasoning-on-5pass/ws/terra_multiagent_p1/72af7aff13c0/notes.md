- **Small-dimension exact method:** When `min(H,W) <= 6`, represent each column (or row after conceptual transposition) as a lower-triangular transfer matrix. A segment tree maintains the ordered product. A cell update rebuilds one transfer matrix and updates the tree. This is fully correct, handles zero values, and costs `O(K^3 log(max(H,W)))` per update for `K=min(H,W)`.
- **Fallback method:** For larger dimensions, updates are processed in temporal batches. At batch start, full forward and backward path DPs are computed.
- **Rectangle decomposition:** All changed cells in a batch are inside their bounding rectangle. A monotone path either avoids the rectangle or enters it once and exits it once. The contribution of paths avoiding it is fixed during the batch.
- **Local recomputation:** After each update, DP is recomputed only inside the batch rectangle, using fixed forward values on its north/west boundary and fixed backward values after its south/east exits.
- **Zero handling:** Both methods use additions and multiplications only; no modular division is used.
- **Fallback batching:** A batch is extended while `batch_length * bounding_rectangle_area <= H*W`, except that a two-update batch is allowed. This is effective for walks concentrated in small regions, rows, or columns.
- **Limitation:** The fallback rectangle batching does not establish a strong worst-case bound for a long diagonal-like walk in a large two-dimensional grid. The small-dimension transfer-matrix branch resolves skinny-grid cases but not all possible large-grid adversarial trajectories.
