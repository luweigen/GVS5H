- **Indexing:** Use zero-based element indices. Let `i` be the first cut position, so the left subarray is `A[0:i]`; let `p` be the last index of the middle subarray, so the second cut is `j = p + 1` and the middle subarray is `A[i:p+1]`. Valid states have `1 <= i <= p <= N-2`.
- **Maintained DP value:** For every active first cut `i`, maintain `V[i] = distinct(A[0:i]) + distinct(A[i:p+1])` while sweeping `p` from left to right. The desired candidate at this `p` is `max_i V[i] + suffix_distinct[p+1]`.
- **Initialization and activation:** Initially no first-cut positions are active. At sweep step `p`, activate position `i = p` by assigning it `prefix_distinct[p]`. Before appending `A[p]`, its middle segment is empty; its one required contribution is then added by the same range update used for all positions. Earlier updates never reach this newly activated position because every earlier update ended at an index smaller than `p`.
- **Range update:** Let `x = A[p]` and `q = last[x]`, where `q` is the latest occurrence before `p`, including index `0` before the sweep begins. Appending `x` adds one distinct value to middle segment `A[i:p+1]` exactly when `q < i`: if `i <= q`, an earlier `x` remains in the middle segment; otherwise it does not. Among active cuts, update `i` in inclusive interval `[max(1, q+1), p]` by `+1`.
- **Suffix values:** Precompute `suf[k] = distinct(A[k:N])`. For each sweep endpoint `p`, the right subarray begins at `p+1`, so add `suf[p+1]`.
- **Data structure:** A lazy segment tree stores active `V[i]` values, with inactive leaves set to negative infinity. It supports range increment, point assignment for activation, and obtains the best active value directly from the root maximum.
- **Correctness:** The invariant holds after processing each `p`: activation gives the correct left contribution for new cut `i=p`, and the range update increments exactly those middle segments for which `A[p]` is newly distinct. Thus every active leaf equals the score of its corresponding left and middle subarrays. Adding the independently computed suffix distinct count yields the exact score for every partition whose second cut is `p+1`. Sweeping all `p=1..N-2` considers every valid pair of cuts, so the maximum is optimal.
- **Complexity:** Prefix/suffix preprocessing is `O(N)`. There are `O(N)` point assignments and range additions, each `O(log N)`, for total `O(N log N)` time and `O(N)` memory.
