- **DP state:** `dp[parity][product]` is a bitset of reachable alternating sums for non-empty subsequences. `parity` is the selected subsequence length modulo 2; an even length means the next appended element is added, odd length means it is subtracted.
- **Bitset range:** Any alternating sum lies in `[-12*n, 12*n]`. Bit index `sum + 12*n` represents a sum. A mask after left shifts prevents bits outside this range from being retained.
- **Transitions:** For every input value, snapshot both DP product arrays before transitions. This guarantees each array element is used at most once. For nonzero `x`, append every feasible old state with product `p` to product `p*x`; shift its sum bitset left for even parity and right for odd parity.
- **Singletons:** Add `[x]` only when `x <= limit`, avoiding infeasible product indexing. Its parity is odd and alternating sum is `x`.
- **Zero handling:** Appending zero maps every existing product to zero, does not change alternating sum, and flips parity. OR all snapshot bitsets of each parity into the corresponding zero-product destination. Add singleton `[0]` with sum zero.
- **Validation:** Sample cases produce `6`, `-1`, and `9`. Out-of-range target sums return `-1` immediately. `nums=[2], k=2, limit=1` returns `-1`. `nums=[0], k=0, limit=1` returns `0`. Product-one paths work: `nums=[1,1], k=0, limit=1` returns `1`.
- **Complexity:** There are at most `limit + 1 <= 5001` product states and bitsets of at most `3601` bits. Each nonzero element processes at most `limit//x + 1` products; snapshots cost `O(limit)`. This is acceptable for `n <= 150`, with bitwise operations efficiently implemented in Python.
- **Answer:** Scan products from `limit` down through zero and return the first product whose parity bitsets contain the target-sum bit.
