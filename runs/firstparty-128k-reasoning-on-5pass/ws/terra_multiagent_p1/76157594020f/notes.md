- **Verification:** The supplied implementation matches all three sample cases: `"000001", 1 -> 2`, `"0000", 2 -> 1`, and `"0101", 0 -> 1`.
- **Brute-force result:** Exhaustive comparison against reachable strings obtained by flipping every subset of positions with at most `numOps` flips finds no counterexample for small binary strings. The binary-search/run-splitting result agrees with brute force.
- **Approach:** Binary search the minimum feasible maximum run length in `[1, n]`. Feasibility is monotonic because relaxing the permitted run length cannot make a previously feasible result infeasible.
- **Limit 1:** A binary string with all runs of length at most one is alternating, so only `"0101..."` and `"1010..."` need consideration. Count mismatches with both targets and check whether the smaller count is at most `numOps`.
- **Limit at least 2:** For an original maximal equal-character run of length `r`, the minimum required flips is `r // (limit + 1)`. Flipping appropriately spaced interior positions partitions the run into segments no longer than `limit`.
- **Formula validation:** A run of length `limit` needs zero flips, while length `limit + 1` needs one. For longer runs, each flip can introduce a separator and create one additional allowed segment, yielding the stated floor formula.

- **Complexity:** Each feasibility check is `O(n)`, with `O(log n)` binary-search iterations, for `O(n log n)` time and `O(1)` auxiliary space.
- **Edge cases:** Single-character strings return one. With zero operations, the answer is the original maximum run length. Already alternating strings return one. A sufficiently large budget returns one exactly when one alternating target is reachable.
