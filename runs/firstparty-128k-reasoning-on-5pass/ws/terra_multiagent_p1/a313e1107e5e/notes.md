- **Observation:** For an increasing subsequence whose final value is at most `X`, all preceding selected values are automatically at most `X`. Thus each query asks for the maximum ordinary LIS-ending DP value among prefix elements having value at most `X`.
- **DP:** Let `dp[i]` be the maximum length of a strictly increasing subsequence ending at `A[i]`. Then `dp[i] = 1 + max(dp[j])` over prior elements with `A[j] < A[i]`.
- **Data structure:** Coordinate-compress only values from `A`. A Fenwick tree stores the maximum DP value for each value coordinate across all processed positions. It supports prefix maximum queries and point maximum updates in `O(log N)`.
- **Duplicate handling:** For `A[i]` at compressed position `p`, compute `dp` from `query(p - 1)` before updating `p`. Excluding `p` enforces strict increase, so equal values never extend one another. Updating by maximum preserves the best subsequence ending at that value.
- **Offline query order:** Sort queries by `R`. Sweep array positions once until the current processed prefix has length `R`; the Fenwick tree then represents exactly all elements in that query prefix.
- **Query bound conversion:** `bisect_right(compressed_values, X)` gives the count of array values at most `X`, which is the Fenwick prefix endpoint. Query values need not be included in compression.
- **Complexity:** Compression costs `O(N log N)`. Sorting queries costs `O(Q log Q)`. The sweep performs `N` updates and `N` DP queries, while each original query performs one Fenwick query, for total `O((N + Q) log N)` time and `O(N + Q)` memory.
