- **Canonical matching:** For an interval \([L,R]\) containing \(m\) mochi, \(K\) pairs are possible if and only if the first \(K\) mochi of the interval can be paired, in increasing order, with the last \(K\) mochi. If any valid selection of \(K\) top and \(K\) bottom mochi exists, replacing its tops by the globally smallest \(K\) interval elements only decreases top sizes, and replacing its bottoms by the globally largest \(K\) interval elements only increases bottom sizes. Sorting both sides preserves feasibility for the threshold condition.
- **Partner transformation:** Define `partner[i]` as the smallest global index \(j\) such that \(A_j \ge 2A_i\), or \(N\) if none exists. For fixed interval start \(l\), length \(m\), and candidate \(K>0\), canonical pair number \(t\) uses top index \(i=l+t\) and bottom index \(l+m-K+t\). It is valid exactly when `partner[i] <= l + m - K + t`. Since \(i=l+t\), this becomes `partner[i] - i <= m - K`.
- **Fixed-\(K\) predicate:** With `d[i] = partner[i] - i`, candidate \(K\) is feasible exactly when `max(d[l : l+K]) <= m-K`. This is a static range maximum query on the first \(K\) positions of the interval.
- **Monotonicity:** If \(K\) is feasible, then \(K-1\) is feasible: its checked range is shorter and its threshold \(m-(K-1)\) is one larger. Therefore binary search over \(0 \ldots \lfloor m/2\rfloor\) returns the maximum feasible number of pairs.
- **Range maximum structure:** A sparse table supports each half-open range maximum query in \(O(1)\): for range length \(x\), use two overlapping blocks of size \(2^{\lfloor\log_2 x\rfloor}\). Building it costs \(O(N\log N)\) time and memory.
- **Partner computation:** Because both \(A_i\) and \(2A_i\) are nondecreasing, all earliest partner positions are found by one nondecreasing two-pointer scan in \(O(N)\). Integer comparison `A[p] < 2*A[i]` avoids floating point issues and correctly allows equality.
- **Complexity:** Sparse-table preprocessing is \(O(N\log N)\). Each query performs \(O(\log N)\) binary-search iterations with \(O(1)\) feasibility checks, giving \(O(Q\log N)\). Total is \(O((N+Q)\log N)\) time and \(O(N\log N)\) memory.
- **Sample verification:** The implementation yields sample 1 outputs `2, 3, 1, 0, 5` and sample 2 outputs `0, 0, 0, 0, 2, 6, 0, 1, 1, 0, 0, 0, 3, 5, 0`.
