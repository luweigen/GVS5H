- **Canonical bit behavior:** A `0 -> 0` bit is never flipped. A mandatory `1 -> 0` bit is flipped off exactly once, and a mandatory `0 -> 1` bit is flipped on exactly once. A correct-one bit is either untouched or flipped off once and restored once.
- **Operation order:** Every removal is optimally before every addition. Removals are ordered by decreasing weight, while additions are ordered by increasing weight.
- **Optional correct-one bits:** If exactly `s` correct-one bits are temporarily turned off, an exchange argument selects the `s` largest weights. Thus sort these weights descending and test every prefix.
- **Fixed-prefix cost:** Let `I` be the initial total active weight. For removal weights in descending order, `cost_remove = q * I - T_remove`, where `T_remove = sum(w * number_of_removal_weights_less_than_or_equal_to_w)`. For additions in ascending order from base active weight `S`, `cost_add = q * S + T_add`, where `T_add = sum(w * number_of_addition_weights_greater_than_or_equal_to_w)`.
- **Correct incremental removal update:** On inserting weight `x`, `T_remove` increases by `x * (count_existing_<=x + 1) + sum_existing_>x`. The prior implementation incorrectly added the sum of all existing weights.
- **Correct incremental addition update:** On inserting weight `x`, `T_add` increases by `x * (count_existing_>=x + 1) + sum_existing_<=x`. The prior implementation incorrectly added the sum of all existing weights.
- **Data structure:** Coordinate-compress `C`, use two Fenwick trees storing counts and weight sums. Each insertion and prefix candidate costs `O(log N)`, yielding `O(N log N)` total time and `O(N)` memory.
- **Validation:** The corrected formula yields sample 1 value `16`, handles already-equal arrays with answer `0`, and supports all mismatch-direction combinations.
