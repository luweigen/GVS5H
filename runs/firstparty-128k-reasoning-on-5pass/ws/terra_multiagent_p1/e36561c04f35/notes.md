- **Run potential:** Compress the array into maximal equal-value runs. Let its number of runs be `R`. Deleting an entire first run costs one operation and decreases `R` by one. Partial deletion is never useful in an optimum, because it costs an operation while leaving the run structure unchanged.
- **Beneficial swaps:** Swapping adjacent elements decreases the run count by at most two. A swap decreasing it by two has exactly the local run form `X, Y, X, Y`, where both middle runs are singletons. Swapping the middle elements changes it into `X, X, Y, Y`, reducing the run count by two.
- **Cost relation:** If a swap reduces runs by `d`, its contribution relative to deleting runs separately is `1-d`. Thus only `d=2` swaps strictly improve the answer. Non-improving swaps can be removed or bypassed in an optimal sequence, so the problem is to maximize the number of beneficial local reductions.
- **Initial valid starts:** A reduction starting at compressed-run index `i` is valid exactly when `vals[i]==vals[i+2]`, `vals[i+1]==vals[i+3]`, and `lens[i+1]==lens[i+2]==1`.
- **Compatibility:** A reduction at start `i` removes runs `i+1` and `i+2`, while its outer runs `i` and `i+3` remain. Therefore another initial reduction can coexist with it iff its start differs by at least three. Start `i+3` is compatible and shares the outer run at `i+3`. Starts `i+1` and `i+2` use removed runs and are impossible.
- **No new useful starts:** After a reduction, the surviving outer runs become longer, so they cannot serve as singleton middle runs of a newly-created reduction. Any reduction that remains possible was already valid on the initial compressed run sequence and simply has to avoid removed middle runs.
- **Greedy maximality:** This becomes selecting the maximum number of valid start indices with pairwise distance at least three. Selecting the earliest available valid start is optimal by the standard interval-greedy exchange argument: any solution’s first selected start is no earlier, and replacing it by the earliest valid start cannot reduce room for later starts.
- **Algorithm:** Scan compressed runs left to right. On a valid start, count one reduction and advance by three; otherwise advance by one. The answer is `R - reductions`.
- **Validation finding:** The linked-list queue implementation was more complicated than needed. Different arbitrary reduction orders are not confluent in general, but the leftmost greedy order is maximal. For example, an alternating run sequence has overlapping valid starts; choosing an interior one can block more later reductions, whereas choosing the leftmost starts yields the optimum.
- **Complexity:** Run compression and the greedy scan are both `O(N)` per total input collection, with `O(N)` memory.
