Use the sorted order of the mochi sizes and observe that each pair must use a smaller mochi from the first portion and a larger mochi from the second portion. For a candidate number \(K\), greedily match the \(K\) smallest available mochi as tops with the next \(K\) mochi as bottoms, checking whether each top is at most half its corresponding bottom. Binary search the maximum feasible \(K\), or equivalently use a two-pointer greedy scan to find the maximum directly. The algorithm should run in \(O(N\log N)\) time with \(O(1)\) extra space aside from input storage.
