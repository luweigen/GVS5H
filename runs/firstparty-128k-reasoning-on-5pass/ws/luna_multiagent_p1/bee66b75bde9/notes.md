- **Model:** Let \(R_x\) be the number of black cells in row \(x\). The row condition means row \(x\) consists of black cells in columns \(1\) through \(R_x\), followed by white cells.
- **Column condition:** The columns also have black prefixes exactly when \(R_1 \ge R_2 \ge \cdots \ge R_N\). Thus the problem becomes finding a nonincreasing integer sequence \(R_x\) with \(0 \le R_x \le N\).
- **Cell constraints:** A black cell \((x,y)\) requires \(R_x \ge y\). A white cell requires \(R_x \le y-1\). For each mentioned row, aggregate these into a lower bound \(L_x\) and upper bound \(U_x\).
- **Sparse handling:** Unmentioned rows have bounds \([0,N]\) and need not be stored. Sorting the mentioned row indices is sufficient; gaps can always be filled with values between the neighboring chosen prefix lengths.
- **Greedy feasibility check:** Scan mentioned rows from top to bottom while maintaining the largest possible value for the current row. At row \(x\), update `current = min(current, U_x)`. If `current < L_x`, no nonincreasing assignment can satisfy the constraints. Otherwise retaining this largest possible value is optimal for all later rows.
- **Correctness:** Choosing a smaller value at any processed row can only make later lower-bound constraints harder, so the greedy maximum choice loses no feasible solution. Internal conflicts \(L_x > U_x\) are rejected directly.
- **Complexity:** Aggregation is \(O(M)\), sorting mentioned rows is \(O(M \log M)\), and memory usage is \(O(M)\). Boundary values \(0\), \(N\), empty rows, full rows, and \(N=1\) are handled naturally.
